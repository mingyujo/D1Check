## 구현한 두 후보

### AP_FREE_INITIAL

기존 초기화는 첫 부하전 표본 `y0`를 정확한 초기곡선 값으로 고정하고 유효유휴R/초기잠재H 두 값을 추정한다. 새 후보는 같은 사전 표본에 `T_pre(t)=R+A exp(-beta Δt)+Hfirst convolution(beta,30,Δt)`를 맞춰 R/A/Hfirst를 추정한다. 첫표본도 다른 표본처럼 잔차를 가질 수 있게 했다.

마지막 부하전 관측AP는 기존처럼 실제 전파 시작값으로 연결한다. Hlast=Hfirst exp(-duration/30)이며 beta/k/g0/잠재30초/상태별 열입력은 원모형과 같다. AP 곡선을 사후 평행이동하지 않는다. R는 주변온도가 아니며 H는 실측 내부온도가 아니다. 초기조건 추정 파라미터가 한 개 늘었지만 새로운 물리 열상태나 열회로는 추가하지 않았다.

개발9의 정규화 설계 조건수는 약9.8–10.9였다. 수치 rank3은 확인됐지만 실제 숨은 열상태 식별·새 기기 전이를 인증하지 않는다. 자유 초기값이 평균오차를 줄이는 사례는 첫 표본 고정의 영향과 양립하지만, **첫 표본이 잘못된 센서값이었다거나 AP 오차의 보편 원인이라는 증거는 아니다.**

별도 opt-in API `tools.d1_optional_preload_ap.forecast(..., initializer='free-first-preload-v1')`를 구현했다. 원모형 SHA와 네 지원 상태를 확인하고, 초기화/전파/버전/사용 입력 종료시각을 반환한다. 명시적 선택이 없거나 미지원 상태면 거절한다. 원 시뮬레이터·RL 기본 경로는 바뀌지 않는다.

### E_PRE_TRANSIENT

부하전 전력 −20..30초에 `P_pre(t)=B+Z exp(-(t+20)/30)`를 맞춰 유효기준B와35초 예상전력P35를 구한다. 35초 이후의 유휴성분은 `B+(P35−B)exp(-(t−35)/30)`이며 기존 상태별 추가전력을 더한다. 원0..35초 회계는 유지하고 이후 에너지 적분은 연속이다. 유휴 전력값 자체는35초 경계에서 기존 평균과 다를 수 있으며 새로운 모형 가정이다.

30초는 이전 추세 후보와 같은 고정 가설이며 실제 하드웨어 전력 시간상수로 식별한 값이 아니다. 부하전 rank/count/coverage·양의 전력 조건을 확인하고 결측/비양수/미식별은 unavailable로 남긴다. clipping·0채움·추가계수 조정을 하지 않는다. 이 후보는 평균오차가 커져 제외했다. 준비 중 전력 변화가 이후 배경 변화를 설명한다는 가설은 이번 자료에서 지지되지 않았다.

두 구조의 단순 조합은 별도 진단행으로 공개했지만 세 번째 구조를 적합하거나 조합을 선택하지 않았다.

## 유휴·잔열 오차에 대해 해결한 것과 남은 것

최신 관측AP 시작값을 유지한 채 R/H 추정의 첫값 고정만 바꿔 지속부하의 부하·냉각 경로 오차를 줄인 사례를 재현했다. 단순한 시작온도 평행이동이 아니라 전파되는 유효기준/잠재초기값 추정의 차이다. 기본 물리계수·실제 요청 점유·상태 전환·관측창은 같다.

새확인30초C0의 반대 냉각방향은 그대로1/6이다. 부하전 온도가 평탄해도 이후 유휴 기준의 변동을 알 수 있다는 증거가 없고, 이 후보가 숨은 내부열·미관측 주변/시스템 상태를 완전히 설명하지 못한다. 과거확인5의 부하후 전력/AP 상승도 큰 잔차로 남았다. 구현결함이나 특정 외부 원인으로 확정하지 않는다.

전력에서 부하전 추세를 미래로 연장하는 것과 실제 부하후 배경 소비를 예측하는 것은 다르다. 이 정보 공백을 메우려고 평가 전류를 입력으로 넣거나 전력계수를 사후 조정하지 않았다. 0.9초 기록으로 개별 짧은 요청 소비전력을 따로 식별했다는 주장도 없다.

## 완료와 적용

결론은 **특정 조건에서만 개선**이다. 실제 AP 오차 감소 후보와 재사용 API를 원본과 분리해 구현·평가했다. 전력 후보는 제외하며 AP 후보도 일반 채택을 보류한다. 원모형 SHA `5682082a936b7c83efeee747ceeb64fd0c64f0bef8765bbf1b90b807db872db2`, 기본 시뮬레이터·RL·strict·experiment_ready=false를 보존한다. 이번 결과로 정책 효과·열→처리시간·S26/NPU·SOC/사용시간·절대J 정확도를 검증했다고 하지 않는다.

추가 관측 없이 남은 공백은 **부하전 수준·추세가 비슷해도 달라지는 부하후 유휴 기준을 예측 입력에서 구분할 수 있는가**다. 첫값 고정 해제만으로 해결되지 않은 C0와 배경상승 사례가 근거다. 향후 필요한 관측 질문을 특정했지만 새 실측 계획·반복수·예산·claim은 만들지 않았다.

다음 단계도 모형 보완으로 한정한다. 현재 AP 후보의 예측/초기상태 정보를 별도 API로 재현할 수 있고, 일반 적용은 새로운 독립 확인 전 보류한다. **추가 근거 없이 이번 평가에 잘 맞도록 초기화 강도/시간상수/지원 범위를 다시 탐색하지 않는다.** 정책 비교로 목표를 바꾸지 않는다.
