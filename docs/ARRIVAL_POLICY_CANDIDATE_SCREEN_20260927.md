# 합성 도착 PC 정책 후보 선별 — 2026-09-27

**판단:** 다음 비교의 핵심 후보는 개발 때 고정한 **B2**, 기존 **B3**, 그리고 CPU 긴급우선이다. 고정 분리는 긴급 응답의 극단을 보여 주는 대조로 유지한다. 현재 **P는 재현용으로 보존하되 추가 튜닝·Android 확대 후보로 우선하지 않는다.** 이는 서비스 허용 위반율이나 에너지·AP 계수가 확정되지 않은 상태의 개발 단계 선별이며 최종 정책 채택이나 실기기 우월성 판정이 아니다.

## 비교의 동일성·지원 범위

입력은 기존 [간섭 진단의 정책별 CSV](results/arrival_diagnostic_02/interference_metrics.csv)만 재집계했다. low/queue/burst × 평가 seed 201–205 × **동일 실현 간섭 1/1.5/2**마다 24요청(긴급 6, 일반 18), CAL-03 동결 개발 벡터, 같은 PC 시간 비용과 완료 경계를 사용한다. P는 기존 **예상 간섭 1.5** 행만 본 비교에 사용했다. 예상 간섭을 실현값에 맞춘 별도 P는 진단용 완벽 정보 가정이므로 후보 성능에 섞지 않았다. 모든 행은 각 seed의 예정 요청 24/24 완료, 미완료 0이다. 이 PC vector에는 실패·거절 경로가 없어 기기 실패율을 평가할 수 없다. 긴급 1.5초·일반 6초는 연구용 요청별 기한이며 전체 요청 100% 기한 준수나 최종 서비스 합격 기준은 아니다.

| 정책 | 이 PC 코드의 배정·대기·병행 동작 | 판단 범위 |
|---|---|---|
| CPU 긴급우선 | CPU만, 긴급 먼저, 전체 직렬 | 단순 안전 대조; GPU 사용의 비용·효과 대조 |
| 고정 분리 | 긴급 CPU / 일반 GPU, 긴급 먼저 | 두 lane 사용의 긴급 지연 극단 대조; 일반 손실 포함 |
| B2 | 개발 단계에서 미리 선정한 분류 GPU / 탐지 CPU, 허용 병행, 4초 aging | 강한 정적 기준. 평가 조건별 재선정 없음. 이 역방향 overlap의 기기 에너지·AP는 미측정 |
| B3 | 단독 프로파일 예상 종료에 따른 CPU/GPU 선택, 상위 요청의 lane을 기다릴 수 있음, 허용 병행 | PC 동적 기준. Android active 경로로 검증된 정책 아님 |
| P | B3와 같은 후보/큐 규칙에 예상 병행 손해 1.5를 더함; 바쁜 lane을 기다릴 수 있음 | 현재 P는 **에너지·AP를 결정에 사용하지 않음**. 과거 결과 재현용 |

이 표의 병행은 PC 탐색의 지원 가정이다. 반대 방향의 고정 CC_DG 실측 전력·열 계수를 B2의 분류 GPU＋탐지 CPU에 전용하지 않는다. `strict` 모드의 CPU fallback/직렬화 결과와 이 `explore` 비교를 합치지 않았다.

## 응답·완료의 비지배 결과

판정은 긴급 seed별 완료 P95의 5-seed 평균, 긴급 기한 위반 건수, 일반 평균응답의 5-seed 평균, 일반 기한 위반 건수, 미완료 건수를 **동시에 최소화**하는 정확한 수치 비교다. 동률은 서로를 지배하지 않는다. 표의 숫자는 *평균 지표의* 비지배 정책이며, 배포 가능한 시나리오별 oracle이 아니다. seed별 비지배 횟수와 절대값·분모·지배 정책은 [CSV](results/arrival_policy_screen_01/policy_screen.csv)에 있다.

| trace | 실현 1.0 | 실현 1.5 | 실현 2.0 |
|---|---|---|---|
| low | CPU·B3·P 동률 | CPU·B3·P 동률 | CPU·B3·P 동률 |
| queue | B2·B3·고정 분리 | B2·B3·고정 분리·P | B2·CPU·고정 분리 |
| burst | B2·B3·고정 분리 | B2·B3·고정 분리 | B2·CPU·고정 분리 |

low의 P 동률은 차별적 효과가 아니다. queue/1.5에서 P는 긴급 P95 평균 **1014.0ms**로 B3 **1053.7ms**보다 빠르지만 일반 평균 **4150.6ms**는 B3 **4024.3ms**보다 느리다. 일반 기한 위반은 둘 다 **17/90**, B2는 **20/90**이나 긴급 P95 **425.9ms**다. 이 P 비지배는 seed **2/5**에서만 유지되어 전체 seed 우세가 아니다. 실현 2.0의 queue·burst에서 P는 평균 응답·위반 지표 모두 다른 후보에 지배되고 긴급 위반도 각각 **3/30, 5/30**이다. CPU·B2·B3·고정 분리는 조건마다 상충한다. 고정 분리의 긴급 P95는 빠르지만 queue/1.5 일반 위반 **60/90**으로 크다. 따라서 합의되지 않은 위반 허용률이나 가중치를 만들어 한 정책을 종합 1위로 선언하지 않는다.

## 에너지·열 후보는 별도 층

[공통 120초 에너지 가정 CSV](results/arrival_diagnostic_02/energy_boundaries.csv)는 idle·단독·병행 기기 전체 전력의 미보정 가정을 적용한 **사후 회계**다. 예컨대 queue/실현1.5, idle 1W·단독 2W에서 P−B3의 seed별 에너지 차이는 병행 2W 가정 시 **+0.297~+0.710J**, 3W 시 **−1.693~+0.230J**로 방향이 바뀔 수 있다. P−B2도 2W **−0.267~+0.105J**, 3W **+5.546~+6.281J**다. 가정한 2~3W는 실기기 가능 범위가 아니다. [AP 민감도](results/arrival_diagnostic_02/ap_sensitivity.csv)는 P−B3만 있으며 초기 AP와 병행 평형 가정에 따라 부호가 달라진다. 다른 정책 쌍의 AP 경로는 기존 결과만으로 판단 불가다. 따라서 응답 지배를 모든 에너지·열 목적의 지배로 확대하지 않으며, 전력·AP 가정의 순위 역전도 실제 절감으로 부르지 않는다.

**다음 행동 하나:** B2·B3·CPU 긴급우선의 공통 요청·공통 관측창에서 에너지·AP 선택을 뒤집는 상태를 먼저 명시하고, 실제 선택에 필요한 **기기 전체 idle·단독·해당 방향의 병행 전력과 대응 AP 경로**만 별도 계측 대상으로 좁힌다. 특히 B2의 분류 GPU＋탐지 CPU overlap은 현재 고정 CC_DG의 반대 방향이라 전용할 수 없다. 이는 측정 목적 결정이며 준비된 12세션 계획의 자동 실행 제안이 아니다. Android active B2/B3 배정, 지원 조합·lane 해제, 독립 확인과 상태별 전력·열 모형 검증도 실기기 발열·배터리 최적화 주장 전에 필요하다. P 튜닝은 다음 행동이 아니다.
