# 유휴 전력의 시간·이력 PC 판독 — 6세션, 새 계수 미채택

**미래 유휴 전력을 부하 전 평균 하나로 고정하는 기존 가산 후보는 새 L에서도 악화했다.** 6세션에서 유휴 전력의 시간 변화를 관측했지만 시간·AP·부하 이력의 영향을 분리하는 전용 가능한 계수는 식별하지 못했다. 새 모형 적합으로 이 공백을 숨기지 않는다. [고정창·그림·현재 출력 범위](results/resident_history_01/index.html).

착수 HEAD `cccbe63a2779a00a84d96ba96e8182f8fba511ff`, 요청 브랜치·실제 원격 일치·clean. 사용자 “진행하자”의 다음 PC 작업만 수행했으며 ADB/기기조회/설치/추론/실측/빌드/새 기기 계획/claim0이다. 다른 worktree와 기존 결과는 보존했다.

## 자료와 분석 경계

[기존 4세션 후보 판독](RESIDENT_POWER_CANDIDATE_PC_20261001.md)과 [완료 C/L 대조03](RESIDENT_CONTROL_RUN03_20261001.md)을 재사용했다. 네 loaded 세션＋C 무부하＋L 부하＝6세션이며 모두 결과를 이미 본 자료다. 이번 모형 구조 판독에서는 모두 사후 개발/평가 자료로 표시한다. 원래 개발/확인 자료 역할·모형 동결 시점·독립 확인 기록을 변경하지 않는다.

- [계약](results/resident_history_01/contract.json)을 새 계산 전에 고정했다. 창은 pre5–30/late90–120/cooling150–180/common0–120초, 추가 기술적 표시는0–180초의 고정10초 bin. 좋은 창/계수를 골라내는 탐색0.
- 전류 raw=mA 조건부·전압을 기존 trapezoid 방식으로 적분했다. Android snapshot/read 중간시각과 기존 AP bracket 정렬을 보존했다. power2.5초/AP10초 최대공백, 끝 외삽/0채움/창 이동 없음.
- 유휴 창은 실제 lane과4resident/active0를 함께 확인한다. 적분에 쓰이는 양 끝 표본 및 표본 사이의 짧은 활성 구간도 검사해 활성 비용이 유휴 창에 섞이지 않게 했다. 이는 새 분석기의 적격성 처리이며 과거 실행이나 수치를 수정한 것이 아니다.
- 10초 bin은 약10개의 조회 표본을 확보하는 기술적 집계다. 센서 내부 갱신시간·요청별 전력 식별·독립 반복·정상상태 보장을 뜻하지 않는다.
- 기존4세션 APK는 `747ce77e…43f6180`, 새 C/L는 `3d8ea871…4e94c2`다. 같은 모형/입력/resident 근거는 기존 계약을 연결하고 APK·계측 프로토콜 그룹은 분리했다. 두 그룹의 계측 비용이 같다고 보정하거나 차감하지 않는다.

C/L의 전후 변화 차이 **−0.202361W**는 이전 보고서와 정확히 같다. L의 사전 전력이 C보다0.223911W 높고 초기AP/배터리/이전 이력·순서가 다르다. 한 무부하 세션과 고정 C→L 순서로 시간 경과·등록 부하·숨은 열 상태·주변/네트워크·센서/OS 변화의 영향을 분리할 수 없다. 같은 초기AP로 맞췄다고 같은 내부 이력이 되는 것도 아니다. AP를 주변 온도로 간주하거나 새 온도→W/스로틀 곡선을 넣지 않는다.

냉각후기150–180초 전력 전체값은 C만 적격이며 다른5세션은 끝 bracket 부족으로 null이다. CG_DC 전이는 이 창 AP 자체는 bracket이 있어 평균28.628°C를 별도로 산출했지만 전력J는 null이다. 에너지와 AP 적격성을 하나로 합치지 않았다. 특히 새 L의0.176161초 전력 결측/AP 끝 bracket 부재를 이전 결과 그대로 보존했다.

## 기존 가산 후보를 새 L에 적용한 결과

새 후보를 만들지 않고 기존 `RESIDENT-PRELOAD-OFFSET-01`의 식·20초 prefix/2.5초 안전 여유·정보시점 계약을 그대로 사용했다. `P_candidate(s)=P_frozen(s)+B_pre−P_frozen(idle)`이며 원래 상태 증분은 유지한다. 계수 재적합0, 미래 관측 전력/AP를 예측에 사용하지 않았다.

새 L의 prefix는12.825527–31.833471초,20표본/span19.007945초, B_pre **1.340620W**다. 고정 pre5–30초1.195793W와 다른 창이며 두 값을 교체하지 않는다. 미래 점수를 좋게 만들려고 prefix/창을 조정하지 않았다. 정보시점은 첫 dispatch35.008415초, 점수창은 **35.008415–120초(84.991585초)**다. 후보의 전체120초 예측은 null이다. 점수는 실제 미래 lane 일정이 주어진 조건부 계산이며 예정 도착부터의 온라인 예측이 아니다. ## 모형 판정과 시뮬레이터 연결

**채택 판정:** 일정한 prefix 가산 후보 미채택을 유지한다. 원래 동결 W/AP·기존 AP 후보·strict/default/experiment_ready=false 불변. 한 C 세션의 들쭉날쭉한 곡선을 시간보정표로 이식하거나 몇 개의 통계 표본으로 숨은 이력 계수를 적합하지 않았다. 수학적으로 임의 곡선을 맞출 수 있다는 것과 새로운 실행에 전용할 수 있다는 것은 다르다.

## 남은 한 공백과 종료 조건

정책 대기 비용을 새 일정에서 예측하려면 **허용된 부하 전 관측과 등록 부하 이력만으로 이후 유휴 비용을 독립 실행에서 예측할 수 있는가**가 남았다. 현재 자료는 한 C 대조와 이미 본 loaded5세션이며 초기 배경·프로토콜/날짜·부하 길이가 달라 특정 시간상수나 온도/이력 항을 독립 확인하지 못한다. 후보를 추가로 탐색해 맞는 결과를 만드는 것은 종료 조건이 아니다.

이 공백은 유휴가 긴 공통창에서 먼저 끝내기/기다리기의 J 차이를 바꾸므로 정책 선택에 영향이 있다. 기존 active 상태 계수를 모두 버리거나 모든backend/전체6세션을 재수집할 이유는 아니다. 해결 범위는 동일한 지원 resident·준비·관측 경로에서 전후 유휴와 실제 lane/AP/전류·전압/환경 이력을 기록하고, 먼저 선택·동결한 최소 모형의 **새 실행** 예측−관측을 고정창에서 판독하는 것이다. 미래 AP/전류를 예측 입력으로 넣지 않고 개발·독립 확인 역할을 나눠야 한다. 정확도 허용폭/반복 수/예산을 이번 자료만으로 보장하지 않는다.

이번에는 이 질문의 새 실측 계획/claim을 만들지 않았고 자동 실측도 없다. **다음 PC 작업 하나는 제한 시뮬레이터의 정책 판독에서 서비스 결과와 동적 J/AP 미판정을 함께 제시하도록 현재 결과 본문을 정리하는 것이다.** 추가 후보를 만들거나 동일 대조를 무조건 반복하는 다음 단계가 아니다.

## 검증과 재현

이전4세션 원문 해시와 새 C/L artifact/thermal 해시를 기존 요약과 대조해 상대시각 입력을 추출했다. 기존4세션 candidate 점수·원래6세션120초 관측J·새 C/L 고정창은 일치한다. CSV 재현 byte 일치·그림 검토 완료, 두freeze SHA 불변. [검증 JSON](results/resident_history_01/verification.json).
