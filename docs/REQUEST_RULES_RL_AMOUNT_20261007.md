# 기존 규칙 재조합과 PPO 학습량 비교 결과

2026-10-07, **RULES-RL-AMOUNT-10 완료**. [오프라인 결과 화면](results/request_ppo_01/rules_rl_amount_v1/index.html) · [계약·재현](results/request_ppo_01/rules_rl_amount_v1/README.md) · [전체 정책별 판독](results/request_ppo_01/rules_rl_amount_v1/policy_summary.csv).

**학습량을 늘려 일부 실행의 서비스와 검증 적격성은 개선됐지만, 강한 규칙보다 우월한 적격 PPO 정책은 찾지 못했다.** 검증 선택 정책의 적격 수는3→3→4→4개였다. 적격 정책의 SHARED_EFT 대비 공동 비악화·엄격 공동 감소는 네 학습량 모두0건이다. 일부 부적격 정책의 조건별 이득을 지우지 않으며, 이것을 정책 전체의 채택 근거로 사용하지 않는다. 수렴이나 강화학습 일반의 실패를 선언하지 않는다.

## 1. 재조합은 개선됐는가

같은 기존 beam·EFT 후속·서비스/J/AP guard에서 추가 WAIT 없이 이미 도착한 최대3요청의 순서와 지원 backend를 비교했다. A는중간 prefix 판정/beam폭8/node64, B는완성 조합 후 같은 판정이다. CCD24·CDD12개 조합이며 탐지GPU를 추가하지 않았다. 미래 도착·seed·trace명·실현 비용을 콜백에 제공하지 않았다. 과거4요청/WAIT beam과 비교 범위 차이를 밝혔다.

작은 개발12조건에서 EFT를 선택·동결한 뒤 확인12조건에 적용했다. EFT/A/B 총72환경 실행이다. 원seed는 이미 노출됐고3요청 동시 도착을 새로 구성한 진단이므로 새 독립 holdout으로 부르지 않는다. 확인에서A는EFT와 같았다. B는평균J−0.064737이지만 긴급P95+207.681ms·AP최고+0.00007157°C, AP면적 차이0이었다. 모두3/3완료·기한 충족이지만 응답과 AP의 대가가 있어 공동 우월성은 아니다.

실제 사례(확인610720001/CCD/mean): EFT/A는 C0 CPU→C1 CPU→D2 CPU로 순차 배정했다. B는 C0 GPU와 D2 CPU를 같은37.370190초에 실행하고 C1을 GPU로 보냈다. [작은 실제 일정·결정](results/request_ppo_01/rules_rl_amount_v1/representative_recombination.json).

큰 최종 주96조건에서는 모든 규칙이 전량·기한을 충족했다. 아래는B−A의 같은 입력 평균 차이다.

## 2. 중간 가지치기가 놓친 유효 조합이 있었는가

**있었다.** 첫3요청 동시 도착 결정에서 완성 후에는 동일 guard를 통과하지만 중간 prefix가 guard에서 탈락한 조합96건(개발48·확인48)을 저장 자료로 재현했다. beam폭/보존 제한만으로 놓친 경우는 이첫결정 감사에서0건이었다. 조합 발생 건수이며 독립표본96개가 아니다. [분기별 원인과 완성 점수](results/request_ppo_01/rules_rl_amount_v1/branch_audit.json).

원 raw 로그에는 명시적 reference incumbent가 aliased 후보 목록에 들어가 완성 조합 수에 섞이는 집계 문제가 있었다. 원자료와 실제 선택/절대 지표는 보존하고, 감사에서 길이3인 유일 완성 조합만 세었다. 이 수정은 집계이며 정책을 바꿔 재실험하지 않았다.

작은 A/B 각각36실행의 실제 예측 projection은1,572/1,140회, Windows callback 총시간은1.424/1.041초, 최대41.981/41.692ms였다. 두 탐색의 교차 진단과 서로 다른 후속 상태를 포함하므로 순수 알고리즘 속도 우월성이나 기기 에너지 절감으로 환산하지 않는다. 큰 일정에서는 첫 행동만 실행하고 다시 판단하므로 국소 guard가 전체 J/AP의 전역 보장은 아니다.

## 5. seed별 결과는 일관적인가

일관적인 단조 개선은 없었다. HEAD/11은 주 조건 성적이 사실상 유지됐고, HEAD/23은 마지막 정책의 에너지·열·응답이 변동했다. HEAD/37은 초기 서비스가 크게 개선됐지만 선택 정책의 시험 서비스는77→93→93→88조건으로 마지막에 회귀했다. QUEUE/23은 적격 선택을 확보했지만 마지막 정책은 회귀했다. QUEUE/37은 선택 정책이96→96→96→80조건으로 악화됐다.

6실행은3개 초기화seed×2개행동변형이며 독립seed6개가 아니다. 같은 도착 입력을 대응하고 처리문맥3개를 민감도로 사용했다. 서로 다른 기기 반복이나 새로운 독립 holdout으로 일반화하지 않는다.

## 6. RL은 강한 규칙·재조합보다 나았는가

8,192의 검증 적격best4개는 SHARED_EFT·EFT_REFERENCE·A·B 어느 강한 기준에도 주 조건 공동 개선0건이었다. QUEUE/11·23 best는 SHARED_EFT와 주96조건의 보고 지표가 같았다. HEAD/11·23 best는 SHARED_EFT 대비 J+0.003038/최고AP−0.000779/면적−0.041776/긴급P95+23.292ms의 작은 상충이었다.

## 7. 에너지·AP 이득에 응답·완료 손실이 있었는가

모든10,560논리적 평가행에서 예정 작업 자체는 완료됐다. 완료량 감소를 절감으로 쓰지 않았다. 다만 기한 미준수와 응답 악화가 있었으므로 완료P95와 전체 예정 요청 성공률을 함께 보고한다. 예를 들어QUEUE/11의4,096 latest는평균J−0.269432였지만AP최고+0.048266/면적+2.707091/긴급P95+491.228ms이고 전량·기한은80/96조건이었다.

과부하queue/burst96조건은현재모형의필수CPU수요로전량기한충족이불가능한별도층이다. 모든정책의전량·기한충족조건은0이며, 실패·지각을 원2,304요청 분모로비교했다. 이것을 처리 가능한 low/sustained 주96조건과 섞어 전체정책 승리를 만들지 않는다.

J는동결기기전력계수와시간문맥가정의0–120초모형값, AP는35–180초모형값이다. 작은 차이를 실기기에서 구분 가능한 절감으로 표현하지 않는다. 기존4쌍의예정도착J차이예측−관측은−12.893~+10.209J였으나, 이범위를새정책의신뢰구간/오차상한으로사용하지않는다. AP의실기기표본창도완전히같지않다. [기존근거 경계](results/method_followup_01/README.md).
