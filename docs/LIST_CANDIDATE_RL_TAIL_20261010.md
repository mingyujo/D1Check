## 토론에서 확인한 문제

V2의 저장 비L0 선택264건 모두 짧은 예측창 peak AP를 낮추면서 창 끝 AP를 높였다. J는263건 동률이었다. 실제 AP악화9조건의 최고점은 모두120초 이전이라 **180초 꼬리 누락만을 단일 원인으로 해석하지 않는다.** 지속 부하의 GPU 분류·실제 병행 증가와 반복 선택 후 후속 부하가 함께 달라졌다.

모바일 AI는 공통창·정수 AP 표본·당시 공개 열 관측의 정합을 요구했다. 산업공학 AI는 현재 도착 큐의 L0 후속 처리를 계산하고 현재 합법 자원에 즉시 배정할 것을 요구했다. RL AI는 같은 후보 비학습 대조, 실제 샘플링 마스크/확률의 저장, 새 schema·Adam·RNG와 실제 재개 검증을 요구했다. 첫 의견→상호 반론→구체안→작성 코드의 독립 검토를 수행했다. AI 관점 검토이며 인간 전문가 인증이 아니다.

끝AP까지 하드필터로 추가하면 저장 상태의 비L0 대안이 모두 사라졌다. 이를 자동 성공해법으로 선택하지 않았다. 과거 `.292~.386초` credit 반례도 GPU 분류 대기와 관련되어 D-only `.5초` 확대 근거로 쓸 수 없으므로 이번 행동 확대는0이다.

물리적으로 불가능한 행동의 일관된 확률 처리는 [invalid action masking 연구](https://arxiv.org/abs/2006.14171)를 참고했다. 예측 허용 제한의 실제 안전성을 이 논문이 보장하는 것은 아니다. [잔차 RL 연구](https://arxiv.org/abs/1812.03201)는 기본 제어와 학습 보완의 분리라는 개념 참고이며, 이 프로젝트의 이산 후보 선택을 로봇 연속제어 알고리즘의 동일 재현이라고 부르지 않는다.
