# 등록회복 전체의 기준전력 정보 보완 결과

**기존 자료만으로 일부 유휴 에너지 오차를 줄였다. 다만 전체 모형 교체는 보류한다.** 시작 전 등록회복 전체 전력과 CPU를 사용한 후보를 실제 구현하고, 개발6/이미 본 확인6을 모두 평가했다. 확인6의 작업 후 유휴 J 평균 절대오차는2.921→2.176J로25.5% 감소했다. 반면 전체120초의 최악오차와 정책 차이 오차는 일부 악화했다. AP·동결값·기본 시뮬레이터·RL·strict는 변경하지 않았다.

## 이번에 바꾼 정보와 고정한 방법

[직전 후보](CPU_PREBASELINE_RESULTS_20261010.md)는 마지막20초 CPU를 미래 기준으로 유지해 확인 에너지 오차가 악화했다. 이번에는 **이미 등록된 conditioning96 lane 해제 후 회복→본 작업 전** 기록에서 반복되는 수준을 추정한다. 새로 가열·조회·실측한 것이 아니다.

- 입력은 등록회복 시작 이후의 완전한5초 bin 전체, 마지막 경계30초다. 원점에 맞춘 첫 불완전 bin만0.010–0.195초 제외했으며 결과에 따라 창을 선택하지 않았다. 회복30 조건90초/18bin, 회복180 조건240초/48bin이다.
- 기존 `P50=평균전력[-20,30]`과 비교해 `FULL_MEAN=등록 pre 전체 평균전력`을 별도 비교 계산한다. 이 비교로 긴 관측창의 효과와 CPU 정보의 효과를 분리한다.
- 후보 하나는 `FULL_CPU=P_full_mean + b×(pre CPU 중앙값−pre CPU 평균)`이다. CPU는 같은 pre 구간의 `other core seconds/wall second`다. 시간 가중 중앙값은 일시적인 급증에 덜 민감한 **운영상 대푯값**이며 진짜 지속부하·주변온도·내부 열 상태·미래 CPU의 실측값이 아니다.
- b 하나만 개발 pre 전력/CPU의 세션 내 중심화·동일 세션 가중 비음수 최소제곱으로 추정한다. 반대 회복시간 블록 제외2＋최종개발6 전체1, 정식 추정3회다. 미래 유휴 전력을 학습 표적으로 쓰지 않았다. 창·중앙값·계수 제약을 결과를 보고 바꾸지 않았다.
- 보정은35..120초에만 적용한다.0..35초는 기존 P50 회계를 유지한다. 공통120초와 이후85초를 따로 보고, horizon 밖 적용이나 음수 전력 clipping은 허용하지 않는다. 기존4상태 전력·AP 계수 및 AP power proxy는 그대로다.

[실행 전 분석 계약](results/registered_baseline_01/analysis_contract.json) / [입력·경계·해시 동결](results/registered_baseline_01/run_v1/registration.json). 최종 b=0.3589381908W/(core seconds/second), 회복30 제외0.5264012521/회복180 제외0.2788897873이다. 개발 pre 전력 잔차 RMSE0.105162W이며 회복시간에 따른 계수 차이도 숨기지 않는다. 수치 추정 가능성을 인과적 CPU 전력 계수 식별로 해석하지 않는다.

## 개선 근거와 반례: 같은 C0에서도 다르다

### 확인 회복30 C0: 일시 활동에 덜 민감한 초기값의 국소 개선

- 기존 P50 1.052720W, 전체 pre 평균1.022969W, CPU 후보0.999696W. 이후 관측 평균0.978522W는 **평가 목표**이며 예측 입력에는 넣지 않았다.
- pre 전체 CPU 평균0.333533, 중앙값0.268695 core seconds/second다. 이전50초의 높은 CPU 평균0.392132와 비교해 일시적인 급증의 반영을 줄였다. 이는 중앙값이 실제 미래 부하와 항상 같다는 증명이 아니다.
- 미래35..120초 부호 오차는 **+6.306905→+1.799850J**로 감소했다. 전체120초는+4.420600→−0.086455J다.
- **전체0.086J에는 상쇄가 있다.**0..35초의−1.886306J는 그대로이고 이후+1.799850J와 합쳐진다. 단순 상쇄만의 성과는 아니지만 전체 값만으로 거의 완벽한 예측이라 하지 않는다.

### 확인 회복180 C0: 전체 과거 평균도 미래 기준이 아닐 수 있다

P50 0.987687W보다 전체 pre 평균1.005968W가 높았다. CPU 중앙값 보정 후에도1.003384W로 미래 관측0.955015W보다 높다. 전체 절대오차2.764→4.098J로 악화했다. 미래 CPU 평균0.272450은 pre 중앙값0.277976과 유사했지만 전력 기준 차이는 남았다. CPU 시간 수준만으로 전체 기기 전력을 설명하거나 미래 기준값을 식별할 수 없다는 기록상의 반례다. 특정 앱·무선·GPU·센서 내부 원인을 확정하지 않는다.

새 방법은 이 회복180 사례에서 직전 후보의8.566J보다는 작지만, **원식의2.764J보다 나쁘다.** 이미 기각한 후보를 이기는 것과 원식 개선을 구분한다. [누적잔차 그림](results/registered_baseline_01/figures/C0_energy_residual_paths.png).

## AP 초기정보 보완과의 공동 판독도 완료

다음 준비로 미루지 않고 [저장된 AP 곡선 결합](results/registered_baseline_01/joint_v1/all_sessions.csv)까지 수행했다. AP는 이미 추정된 동일 LOAD_SLOW/동일 마지막 초기AP·시각·계수에서 짧은 pre와 등록유휴 전체 pre를 비교한다. **원 동결 AP 수식과의 비교는 아니다.** AP를 재추정·재생하지 않고35..120초에 존재하는 같은 관측 표본만 점수화했다.

확인6의 이 고정 AP 후보 MAE는0.26518→0.21160°C다. 이전 보고서의35..세션끝(약180초)0.22962→0.16630°C와 시간창이 다르며 혼용하지 않는다. 에너지는0..120초다. 원 에너지계수 기준으로 J 절대오차와 AP MAE가 함께 감소한 세션은1/6, δ=0 에너지계수 기준은2/6이다. AP 최대/최고값 오차도 전량 표에 보존했다. 좋은 ID를 사후 실행 선택기로 만들지 않았고 모든 출력·최악값·정책 차이가 개선됐다는 의미도 아니다.

## 구현·가용성과 검증

실제 lane 일정이 주어진 **조건부 비용 재생**이다. 예정 도착부터 일정·응답을 만드는 종단간 예측을 새로 생성하거나 검증한 것이 아니다. 사건 시각상 pre 입력은30초까지이고 가정한 예측 발행 경계는35초다. 그러나 Perfetto CSV는 종료 후 export이므로 그때 실시간 파일이 전달됐다는 보장은 없다. live CPU 전달 기능은 미구현이며 기존 앱·RL 입력을 바꾸지 않았다.

- 새 경계 단위시험7건 통과: 고정 전체창·미래입력 차단·개발 역할·동일 세션 가중·미식별·중앙값·opt-in·horizon·부분가산성·소비분석 중복 차단.
- 기존3방법의12세션/모든창 수치를1e−12J 이내로 재현했고, 작업＋유휴의 부호 잔차가 동일85초 잔차와1e−9J 이내로 일치했다. 센서 결측을0으로 채우거나 적분창을 이동하지 않았다.
- 모든 conditioning96 lane 해제가 pre 시작보다 앞임을 확인했다.8CPU 완전 coverage·unknown0·원 export hash·BOOTTIME 정렬을 유지했다. 기존 raw/trace/export120파일과 원식/AP/전력후보 bytes 불변을 검증했다.
- 정식 추정3회/이차 추정0/AP 추정0. 기기/ADB/설치/추론/실측/빌드/새계획/claim/환경배치0. 원자료·실패·소비계획과 다른 정책 작업·사용자 변경을 보존했다.

## 완료 판정과 사용 범위

결론은 **특정 조건에서만 개선**이다. 더 긴 사전 기록과 CPU 대푯값으로 유휴 평균 오차 및 회복30 C0의 미래 구간 오차를 줄일 수 있다는 근거를 확보했다. 전체관측 평균·최악값·정책 차이에는 반례가 남아 기본 교체는 보류한다. 관측 조건과 실제 일정이 주어진 오프라인 진단 예제/재생은 사용할 수 있지만 온라인 배정·미지원 상태·작은 J/AP 차이 최적화에 자동 적용하지 않는다.

AP 모델이나 이전 초기정보 보완의 결과는 이번에 재계산·교체하지 않았다. 새 정확도 PASS·물리적 평형/주변온도 식별·배터리 수명·SOC·정책 절감·S26 전이는 주장하지 않는다. A24 current raw=mA와 절대J 미인증, strict 및 `experiment_ready=false`를 유지한다.

이번 시험은 이 후보·비교 계산·AP 공동 판독까지 완료했고 추가 창·계수·후보 반복은 종료한다. 다음 PC 질문 하나는 **회복180에서 CPU 수준만으로 설명하지 못한 기준전력 차이를, 이미 기록된 부하 전 AP 냉각 추세와 함께 설명할 수 있는가**다. 유휴 오차가 줄었다는 사실과 아직 설명하지 못한 기준값을 분리하며 다시 포괄적 감사나 같은 B2 실측으로 돌리지 않는다. 새 실측 계획·자동 재보정은 만들지 않았다.
