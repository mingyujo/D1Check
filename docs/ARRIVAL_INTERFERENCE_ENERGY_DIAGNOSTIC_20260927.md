# 예상/실현 간섭과 에너지·AP 경계: 별도 PC 진단

**판정:** 예상 간섭의 오차만으로 현재 P의 손실을 설명할 수 없다. 실현 간섭 2.0을 P가 정확히 안다는 진단 가정에서도 queue·burst의 응답 손실이 남는다. 반면 간섭 1.0에서 예상도 1.0이면 P와 B3의 일정은 같아진다. 에너지/AP의 우열은 미측정 상태 계수와 seed에 민감하다. 실기기 정책 우월성·열 제약 준수·절대 배터리 절감은 판정하지 않는다. [오프라인 진단 탭·CSV·PNG/SVG](results/arrival_diagnostic_02/README.md).

## 결과 전 고정한 비교와 출처

[CONFIG.json](results/arrival_diagnostic_02/CONFIG.json)은 결과 생성 전에 low·queue·burst, 기존 평가 seed 201–205, 실현 간섭 `1/1.5/2`, P 예상 간섭 `1/1.5/2`의 3×3 표를 고정했다. 예상2.0은 기존 P에 쓰인 값이 아니라 기존 실현 간섭 탐색 범위 안의 **새 진단점**이다. 기존 P는 예상 1.5이며, 예상=실현은 **간섭계수에 한해 완벽한 정보를 주는 진단 가정**이다. 미래 처리시간·pair 손해 전체의 오라클은 아니다. B3·CPU_URGENT·FIXED_SPLIT·기존 개발 선정 B2를 같은 실현 간섭/입력에서 비교했다. 별도 `tools/d1_arrival_diagnostic.py`만 추가했으며 기존 정책·CAL-03 동결 설정·960평가/126개발 배치·`sensitivity.csv`를 수정하거나 재실행하지 않았다. 이번 실행은 PC 모형 **315개 작은 조합**(3시나리오×5 seed×3실현×[P 예상3+기준4])이며 독립 기기 표본은 0이다. 동일 seed의 실현 vector를 정책·설정에 키로 맞췄다. 기존 `choose`는 `predicted_interference`를 P의 pair 예상 `extra+harm`에만, 실현 `rate`는 `interference`를 동시 EXECUTING 처리율에만 적용한다. 후자의 값이 전자의 값을 자동으로 갱신하지 않는다.

| 시나리오/실현 | 기존 P 예상1.5의 P−B3 긴급 P95 / 일반 평균 (ms, 5 seed 평균) | 예상=실현 P의 차이 | 기한·미완료 판독 |
|---|---:|---:|---|
| low / 1·1.5·2 | 모두 0 / 0 | 모두 0 / 0 | 이 입력에서는 일정 동일 |
| queue / 1 | +198.62 / +349.62 | 0 / 0 | 예상 과대의 대기 손실 |
| queue / 1.5 | −39.73 / +126.28 | 동일 | 긴급 개선·일반 손실의 상충 |
| queue / 2 | +150.36 / +244.79 | +150.36 / +443.00 | 긴급 미충족 +10.00%p, 일반 +8.89%p (예상 일치도 동일) |
| burst / 1 | +15.47 / +187.92 | 0 / 0 | 예상 과대 손실 |
| burst / 1.5 | +48.41 / +126.34 | 동일 | 일반 미충족 +2.22%p |
| burst / 2 | +4802.96 / +298.08 | +2213.56 / +661.57 | 예상 일치에서도 긴급 +23.33%p·일반 +8.89%p |

위는 각 seed의 지표 차이를 평균한 **PC 진단값**이다. 긴급 P95는 완료 긴급6건/seed의 nearest-rank, 일반 평균은 완료 일반18건/seed이며, 기한 미충족률은 예정 전체 분모다. 표의 모든 조합은 24/24 완료·미완료0이지만 모형에 확률적 실패 경로가 없다는 한계가 있다. 각 seed 차이의 최소·최대와 나머지 3×3 칸은 `interference_paired.csv`, `interference_summary.csv`, heatmap에 보존한다. queue/실현1.5에서 CPU 긴급우선은 긴급595.5ms·일반4446.9ms, 고정 분리는206.9/8715.3ms, 선정 B2는425.9/4138.7ms, B3는1053.7/4024.3ms, P는1014.0/4150.6ms다. 정적 B2를 약화하지 않았고 단일 지표의 P−B3 개선을 종합 우위로 부르지 않는다.

대표 queue/seed201/실현2.0의 200ms 긴급 요청에서 B3는 GPU가 비어 있어 약200.300ms에 배정한다. P는 예상도2.0으로 **맞춰도** GPU pair 손해 665.384ms를 점수에 더해 바쁜 CPU를 우선하고, GPU가 유휴인 채 기다렸다가 약629.848ms에 배정한다. 이 요청의 응답은 B3 544.546ms, P 974.094ms다. 예상1.0이면 B3와 같은 시각·GPU를 택한다. 이는 P의 현재 점수/선두 요청 대기 규칙이 만드는 **모형상 구조적 선택**이지, 실측 병행 간섭의 참값이나 실제 기기 손실 원인의 확정이 아니다. `representative_queue_decisions.json`에 후보 점수·대기 이유·lane·요청 경계를 보존했다.

## 사후 공통창 에너지와 AP

기존 일정의 lane 점유를 120초 전체에서 idle·단일·pair로 분할하면, **일정을 고정할 때** `E = t_idle P_idle + t_single P_single + t_pair P_pair`다. 따라서 두 정책 차이는 다른 두 전력을 고정하면 병행 전력에 선형이다. 코드·작은 수동식·CSV 검증에서 이를 확인했고 `Δt_pair=0`이면 경계가 없거나 두 일정이 동일하다고 표시한다. queued 상태는 해당 기기 전체 상태에 한 번만 청구하며 0W로 채우지 않는다. pair 전력도 단독 전력을 합산하지 않는다. 전력 0.8–1.2W idle, 1.8–2.2W 단일, 2/3W 병행은 **미보정 스트레스 값**이며 물리적 가능 범위가 아니다. [조건·단위](results/arrival_diagnostic_02/CONFIG.json)에 3개의 idle/single 짝과 병행2값을 사전 고정했다.

기존 P 예상1.5 대 B3, 실현1.5, idle1W·단일2W에서 low는 5 seed 모두 일정·에너지 동일(경계 없음)이다. queue의 병행2W 차이는 seed별 **+0.297~+0.710J**, 평균 +0.538J(+0.410%, B3 대비); 3W에서는 **−1.693~+0.230J**, 평균 −0.555J(−0.391%)다. 0 교차점은 seed별 **2.151, 3.477, 3.479, 3.136, 2.155W**다. 3W에서도 5 seed 중 3개는 P 에너지가 더 높다. burst는 2W에서 +0.197~+0.581J, 3W에서 −0.529~+0.302J로 한 seed만 방향이 뒤집힌다. idle/single 짝을 0.8/1.8→1.2/2.2W로 바꾸면 queue seed201 경계가 **1.951→2.351W**로 변한다. 이는 상태별 전력 모두가 경계에 영향을 준다는 산술 결과다. 공통 120초에서 정책당 약 130J대의 가정 소비와 비교하면 차이가 대체로 1% 미만인 조건이 많아, 현재 근거로는 선택이 어렵다. 조건별 절대·상대차와 B3뿐 아니라 CPU/고정분리/B2 대비 경계도 CSV에 있다.

AP는 기존 `d1_energy_thermal.py`의 상태별 **1차 전이**를 사후 적용했다. 초기29/31°C, idle 평형29°C, 단일34°C, pair30/42°C, 시상수60초는 미보정 탐색 축이다. AP 센서값을 BAT/표면온도나 공식 한도로 해석하지 않는다. 실현1.5·초기29°C의 queue에서 P−B3 AP 최고차는 pair 평형30°C일 때 seed별 **+0.085~+0.137°C**(평균+0.106), 42°C일 때 **−0.212~−0.024°C**(평균−0.101)로 뒤집힌다. 5초 경로 점의 최대 절대차도 평균 약0.103/0.107°C로 CSV에 남겼다. 초기31°C에서는 같은 두 가정의 최고차 평균 +0.036/−0.115°C다. 이는 측정된 열계수 범위가 아니며 열 상태가 실행시간·정책에 피드백되지 않아 열 제약 스케줄러를 검증하지 못한다.

기존 고정870건 A24 운영 자료의 resident 유휴 전력은 조건부 약1.10–1.16W이고 공통480초 **episode 평균**은 약1.51–1.58W다. 이 전체 평균은 현재 도착 일정의 idle·단독·pair **상태별 전력**이나 2.151W 동률점의 기기 가능성을 식별하지 못한다. 기존 A24 전류 mA 해석과 절대 J 정확도도 미인증이다. 고정870건·MobileNet 열계수를 도착 결과에 전용하지 않았다.

## 다음 판정 경계

실제 서비스 제약이나 목적함수가 없어 종합1위를 고르지 않는다. **다음 한 행동은** 공통창 에너지와 긴급/일반 기한 중 무엇을 제약으로 둘지 기존 연구 계약에 맞춰 명시하고, 이 조건에서 P와 B3가 실제 선택 후보인지 먼저 판정하는 것이다. 둘 다 후보이고 0 교차 근처의 에너지 부호가 선택을 바꿀 때에만, 같은 두 모델의 임의 도착 **idle·단일·실제 병행 기기 전체 전력**을 동일 관측창에서 식별하는 최소 측정이 도움이 된다. AP 최고 제약을 선택 조건으로 쓸 경우에만 대응 AP 시간 응답의 독립 근거가 추가로 필요하다. 준비된 12세션 Android 계획을 이 진단의 자동 다음 단계로 채택하지 않는다. 기존 FAIL·동결값·원자료·종료 계획과 `experiment_ready=false`를 유지한다.
