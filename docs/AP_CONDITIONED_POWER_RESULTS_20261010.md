# 시작 전 AP 냉각과 기준전력 오차의 연결 시험

**AP 냉각 정보를 추가한 단순 전력 후보는 에너지 평균 오차를 줄이지 못했다. 그러나 AP 예측오차와 AP→전력 연결의 전이 오류를 서로 다른 C0 기록에서 분리했다.** 후보·동일창 CPU 대조·전량 평가·그림·진단을 완료하고 새 후보는 미채택한다. 원자료·동결 모형·기본/RL/strict·experiment_ready=false는 유지한다.

## 실행 전에 고정한 최소 변경

[직전 결과](REGISTERED_BASELINE_RESULTS_20261010.md)의 회복180 C0에서 CPU 수준과 전력이 따로 움직이는 오차를 대상으로 한다. [사전 계약](results/ap_conditioned_power_01/analysis_contract.json)에 후보 하나와 AP 가용성에 맞춘 CPU-only 비교를 고정했다.

```text
P_baseline(t) = pre 같은창 평균전력
              + b_CPU × (pre CPU 중앙값 − pre CPU 평균)
              + b_AP × (T_idle_predicted(t) − pre 같은창 평균 AP)
```

- 기존 등록회복의5초 bin과 공유된 raw AP를 사용했다. AP가 양쪽에서 관측되지 않은 첫5초 bin만 제외하여 전12가85/235초 동일창을 사용한다. 새 CPU-only와 CPU＋AP는 완전히 같은 행으로 추정한다. 창/온도/좋은 세션을 결과에 맞춰 고르지 않았다.
- AP 평균은10초 이하 공백의 유효 pre 표본 사이를 같은 시간축에서 선형 적분한다. AP 조회 종료와 전력 오른쪽 bracket은35초 이전이다. 결측·미관측 endpoint를0으로 채우지 않는다. Android BOOTTIME 상대시각이며 host wall clock과 섞지 않았다.
- 에너지 계수는 pre 전력에 대해 세션 중심화·동일 세션 가중으로 추정한다. CPU 계수는 비음수, AP 계수는 부호를 허용하는 **관측 관계**다. 물리적 누설전력·주변온도 계수를 주장하지 않는다.2변수 후보/1변수 대조 각각 반대 회복시간 제외2＋최종개발6 전체1, 총6회 추정이다. 미래 전력/온도나 확인 표적은 추정에 없다.
- 미래 AP는 **작업이 없다고 가정한 고정 AP 초기경로**다. 이미 계산해 보존한 registered_idle_pre의 R/H/마지막AP·시각을 재사용하고, 원β0.0459325203와 준비τ30초를 유지한다. AP fit/새R/H추정0이다. R은 유효기준 추정량이며 실제 주변온도가 아니다.
- 대상 작업의 새 가열을 이 기준전력 보정에 더하지 않는다. 이는 준비 이력의 냉각 성분만 보는 제한된 후보다. 모든 실행 상태의 실제 온도→전력 되먹임으로 확대하지 않는다. 실제 lane 상태의 기존4전력 계수는 원식/δ=0 두 종류를 모두 고정·보고하며 최선 head를 선택하지 않는다.
-35..120초만 보정하고0..35초 P50 회계는 유지한다. AP 초기경로 적분은 해석식이며 β=1/τ 한계도 처리한다. 내부 극값까지 검사해 전체 horizon에서 비양수 전력이면 계산 불가다. clipping하지 않는다.

최종 CPU＋AP 계수는 b_CPU=0.551253929W/(core seconds/second), b_AP=0.174689724W/°C다. AP 계수는 반대 block 제외에서0.119946/0.221932로 달랐다. scaled condition1.01881로 수치적2열 rank는 확보했지만, 인과적 열→전력 관계나 조건 간 안정성 인증이 아니다. 개발 pre 잔차 RMSE는0.104184W다.

## 어느 부분이 틀렸는가: 온도 예측과 전력 연결을 분리

후보의 AP 미래 경로가 틀린 것인지, AP 경로가 정확해도 전력 연결이 틀리는지 구분하기 위해 [추가 산술 진단 계약](results/ap_conditioned_power_01/attribution_contract.json)을 먼저 남겼다. 같은 고정 계수로만 분해하고 추가fit0이다. 원래 미래 AP를 모른 채 생성한 예측은 보존했다.

**진단용 미래 AP 대입은 예측이 아니다.** 대상작업0의4C0에서만 실측 AP를 사후 대입해 관계식의 한계를 검사했다. 부하가 있는8세션의 실측온도를 ‘무부하 기준’에 대입하지 않았다. 이 값은 실행기/후보/선택/기본/RL에 전달되지 않는다.

### 회복180: 미래 AP를 알아도 관계식 잔차가 남는다

pre 전체 시작→마지막 AP는28.7→29.2°C로 **0.5°C 상승**했다. 작업시작 이후 관측은29.2→28.6°C로 냉각했지만, 미래 평균28.71384°C는 pre 평균28.64132°C보다 여전히 높다. 따라서 b_AP>0인 새 관계식은 전력/J를 올리는 방향이다. ‘이후 냉각’이라는 방향만으로 pre 평균 대비 전력이 낮아져야 한다고 처리할 수 없다.

CPU-only 대비 추가J 변화+1.75193J 중 AP 항+1.74917J/CPU 기울기 변경+0.00276J다. 관측 미래 AP를 정확히 안다고 가정해도 AP 항은+1.07672J이며 미래 J 잔차4.72683J가 남는다. AP 경로 예측오차만의 문제라고 설명할 수 없다. pre AP와 전력의 동시 관계를 미래 기준부하로 전용하는 **단순 연결 구조/기준값의 한계**다. 실제 원전력 오차·센서 절대오차·다른 활동을 포함한 잔차이므로 숨은 원인을 AP 누설·무선·GPU 하나로 확정하지 않는다.

이미 있는4C0의 같은85초 CPU 기록도 [별도 산술 계약](results/ap_conditioned_power_01/covariate_attribution_contract.json)으로 대조했다. 회복180의 CPU 대푯값 예측오차 기여는0.36634J이며 **미래 AP와 해당 CPU 비율을 둘 다 알고 대입해도4.36049J가 남았다.** 현재 포함한 두 입력의 미래값만 더 정확하게 얻는 것으로 이 관계식의 잔차를 없앨 수 없다는 근거다. 기기 전체의 모든 상태를 안다는 뜻이 아니며 전이/기준값/빠진 활동·주파수/계측 요인을 특정하지 않는다. [4개 진단 전량](results/ap_conditioned_power_01/covariate_v1/C0_covariate_oracle.csv). 이 대입 역시 예측에 사용하지 않았다.

### 회복30: 고정 AP 초기경로가 실제와 반대 방향이다

기존 초기경로는29.118→29.294°C로 올라가고 관측은29.3→28.9°C로 내려간다. 미래 평균 오차0.21327°C를 b_AP×85초로 연결하면3.16680J가 된다. 실제 AP를 진단용으로 대입하면 부호 잔차가−0.23965J로 줄어, 이 사례에서는 **AP 초기경로의 잘못된 반응이 에너지 보완을 가로막는 기여**를 확인했다. 미래온도를 미리 안다고 가정한 결과를 사용 가능한 개선으로 채택하지 않았다.

즉 두 문제가 공존한다. 회복180은 AP경로만 더 정확해져도 단순 전력 연결이 해결되지 않는다. 회복30은 현재 AP 초기화/유효기준의 방향 오차가 에너지식에 증폭된다. 기존 원식의 모든 오차를 이 둘로 설명했다는 뜻이나 내부 물리 원인을 확정한 뜻은 아니다. ## 구현·자료 처리·현재 제한

같은 pre AP를 시간 적분하고, 기존 BOOTTIME 입력과 마지막 초기AP/시각을 유지했다. 이전 원경로/전체CPU의 동일 세션 J를1e−12 이내로 재현했고, 작업/유휴의 합과85초 전체가1e−9J 이내로 일치한다. 적분 경계·단위·lane 매핑을 바꿔 오차를 줄이지 않았다. 이번 시험에서 기존 처리 결함은 발견하지 않았고 새 방정식/초기정보 사용의 효과로 분리한다.

새7단위검증 통과: APbracket/gap/미래표본, 개발역할/rank/부호제약, analytic integral/같은 rate/가산성, 내부 음수전력·짧은query에서도 전체horizon 검사,미래센서독립,소비분석 차단. source/input/candidate hash를 동결·검증했고 원식/AP/기존후보·원자료/실패/소비계획/다른작업은 보존했다.

W 진단표는35..120초 예측 평균과 실제lane 해제 후 평균의 창을 명시하고, 같은 post-lane 창의 해석적 예측 평균을 별도로 추가했다. 초기 draft/source는 `source_snapshots/`에 보존했다. 이는 표시 경계의 보완이며 기존 J/AP 오차·후보계수·예측은 변경하지 않았다.

이 결과는 **실제 일정이 주어진 오프라인 조건부 비용 계산**이다. 예정 도착부터 일정/응답을 만드는 종단간 예측이나 live 배정은 새로 검증하지 않았다. trace CSV는 종료 후 export였고 pre 사건시각과 실제 전달시각을 구분한다. API는 명시 opt-in이며 기본/RL환경과 별도다. 미래 실측 AP/전력은 오차 평가·진단에만 있고 예측 입력에는 없다.

정식fit6/추가fit0/APfit0/새AP 초기화0,기기/ADB/설치/추론/실측/빌드/새계획/claim/환경배치0이다. A24 current raw=mA/절대J 정확도 미인증·S26계수 비혼합·strict/experiment_ready=false는 유지한다. [버전·명령·해시 검증](results/ap_conditioned_power_01/verification.json) / [실제 분석 receipt](results/ap_conditioned_power_01/run_v1/receipt.json).

## 완료 판정과 다음 한 가지

**이번 후보는 미채택이다.** 단순 AP 계수를 추가하면 전체 오차가 줄어든다는 가설은 이 자료에서 지지되지 않았다. 숫자를 반환할 수 있음·수치적 rank 확보·관측 범위·예측 검증·정책 차이 판정을 분리했다. 이 작업으로 AP 예측 방향오차와 전력 관계식의 전이 문제를 구체적 반례로 구분했으며, 추가 실측부터 해야 한다고 결론 내리지 않았다.
