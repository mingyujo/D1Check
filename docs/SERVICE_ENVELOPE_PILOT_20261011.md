# 서비스 기준 정렬과 새 리스트·PPO 파일럿

사용자의 “그거까지해야지”는 실험 묶음 완료에 그치지 않고, 같은 완료 요구와 응답 기한을 유지하면서 열·에너지를 줄이는 목표까지 이어가라는 지시로 해석했다. 이미 종료한 실행의 예산·결과·체크포인트는 보존하고 별도 정책과 실행 ID를 등록했다. 기준 HEAD는 `11c450018e6f6bf4b33d3034ef8c8c04f7ac63a6`이다.

이 문서는 통합 범위 기록이다. 각 실행의 결과 전 등록·시각·source SHA·입력·예산은 `output/service_envelope_20261011_v1/registration.json`과 `output/service_joint_rl_20261011_v1/registration.json`이 원본이다. 통합 문서 작성 전에 완료된 PC 비교를 다시 사전등록했다고 표현하지 않는다.

## 수정하는 문제와 보존하는 기준

- 이전 공개 상태 반례에서 GPU 분류＋CPU 탐지는 물리적으로 실행할 수 있었지만, L0의 개별 긴급 응답보다 느리다는 예측 제한으로 제외됐다. 물리적 불가와 예측 성능 제한을 구분한다.
- 새 기본·복귀·예측 후속·학습 참조는 자체 `JointList`다. 현재 도착한 큐에 대해 최대 네 CPU/GPU 호환 EDD 배정안을 비교한다. 기한 실패·지각, 현재 큐 소진 예상시각, AP/J 순서로 선택하는 제한적 근사이며 전체 최적해라고 부르지 않는다. Band는 비교군으로만 남긴다.
- 비용 리스트와 PPO는 같은 유한 후보와 서비스 예측 보호를 공유한다. 예측 보호는 미래 기한의 보장이 아니다. 기존 개별 긴급 응답 무악화 제한을 제거하되, 현재 큐 서비스·P95·CPU만 가능한 요청의 응답을 새 참조와 비교한다.
- 새 PPO는 같은 자체 masked PPO를 사용하되 참조·마스크·목적 의미가 달라진 별도 설계다. 원 512 learner의 Adam/RNG를 이어 쓰지 않고 새 weights로 시작한다. 이는 순수 학습량 또는 알고리즘 우열 비교가 아니다.
- 목적 v2의 비용 채널은 `[참조 대비 J, 절대 미완료, 절대 긴급 실패, 절대 일반 실패, 참조 대비 양의 P95 차이/1500ms]`다. AP 주보상·단위·할인·초기 승수는 유지한다. 절대 실패와 참조 초과 실패를 이중 합산하지 않는다.
- CPU/GPU 두 과업, 기존 기한·품질·완료 경계·AVAILABLE·모형 계수·지원 조합·최종 strict 판정은 유지한다. NPU·선점·주파수·전력 제한·새 모델을 추가하지 않는다. `experiment_ready=false`와 기존 앱 기본을 보존한다.

## 유한 실행 범위

| 과제 | 계획과 상한 | 평가 입력 |
|---|---|---|
| 새 JointList/CostList | 예정 248환경, 상한384환경, 학습0, 등록 후20분·마지막3분 저장 | 개발24은 이미 본 자료, 새 확인 `833110101..104` ×4부하×3문맥=48조건, Band/Triton/JointList/CostList |
| 새 PPO | 예정500환경, 상한512환경·192학습, 등록 후20분·마지막3분 저장 | learner11/23/37 공통32→64, 시간 부족 시 세 seed 모두32; 확인은 같은833 자료48조건 |
| 조건부 A24 재생 | 최대2세션·본192＋warmup16추론, 설치0, 20분·마지막3분 저장 | 결과 전에 고정한96요청/350ms 입력; 새 정책과 Band 일정이 다르고 기존 실행·지원·저장 게이트를 통과할 때만 실행 |

학습 입력 `834010001..008` 및 다음 등록 seed, 개발 자료, 새 확인 seed를 구분한다. 두 PC 과제의 확인 자료 공유는 함께 계획한 대응 비교다. 원본 등록 후 탐지된 충돌은 결과를 읽기 전의 공동 등록 영수증으로 남기며 seed를 교체하지 않는다. 각 과제의 실제 소비만 한 번씩 더한다. 기존 계보 기저는13,813환경/2,989학습이며 과거 모든 PPO의 프로젝트 총합은 아니다.

실제 fresh runner의 세 모델은11/23/37로 각각 초기화한 뒤 하나의 전역 sampling RNG를 round-robin으로 공유했다. 독립적인 세 학습 sampling stream으로 실행했다고 표현하지 않는다. 같은 연장은 세 payload와 공유 RNG·전체 실행순서를 함께 보존해야 한다.

정책 파일의 표시 한 줄 변경이 RL source 잠금과 겹쳤다. 원 bytes·새 bytes·차이·의미 불변 검사를 보존하고 같은 clock/소비를 유지하는 수정 영수증으로 재개한다. 실행 중 정책 의미를 바꾸거나 등록·예산을 초기화하지 않는다.

## 판정과 마무리

전체 예정 요청의 완료·실패·기한·긴급 P95를 먼저 비교한다. 서비스 손실 또는 처리량 감소에 따른 비용 감소를 우위로 판정하지 않는다. 원래 단위의 AP/J와 조건별 결과를 사용하고 기존 strict 기준을 완화하지 않는다. 유망 후보가 없으면 실측을 중복 실행하지 않고 차단 원인과 필요한 다음 검증을 남긴다.

현재 A24 AP25.5°C는 해당 개발 초기 AP 관측 최저25.9°C보다 낮다. 온도 하나의 관측 범위도 연속 지원 보장을 뜻하지 않으며, 범위 밖 상태를 검증된 정책 효과로 부르지 않는다. HAL AP를 최고 표면 온도나 안전 기준으로, current 기반 조건부 J를 교정된 절대 에너지로 바꾸어 표현하지 않는다.

완료 산출물은 별도 설정·입력·원장·체크포인트·검사 영수증·조건별 CSV·그림·오프라인 화면과 통합 판정이다. 연구 목표가 입증되지 않으면 명확하게 미입증으로 남긴다. 사용자 미커밋 파일·HTML/PDF·다른 worktree·원자료는 보존하고 이번 소유 파일만 Git에 반영한다.

## 추가 진단 후의 단일 V2 후보

V1의 저장된 예측에서 비용 개선 후보가 성능 제한 전866개, 후0개로 집계됐다. 이 후보 수는 독립 시행 수가 아니다. 현재 학습의 마스크를 도중에 바꾸지 않고, 각 제한의 탈락 원인과 구체적 반례를 먼저 분석한다.

최종 기한·완료·P95와 AP/J 예측 조건은 지키지만 개별 CPU-only 응답이 참조보다 느리다는 이유만으로 제거된 후보가 확인되면, 별도 V2에서 그 제한을 기존 절대 기한·실패·지각 기준과 정렬한다. 참조의 긴급 P95 순위도 현재 큐 소진 ECT보다 앞에 놓는다. 원 V1/RL source·배운 actor·최종 판정은 수정하지 않는다. V2 actor 평가는 이번에 추가하지 않는다.

별도 `service_envelope_v2_20261011_v1`의 조건부 상한은192환경/학습0, 15분·마지막3분 저장이다. 단일 후보의 gate2＋이미 본 개발24＋새 확인48×Band/Triton/CostV2 세 역할144＋대표1=예정171환경이다. 새 확인 seed는 `835110101..104`이며 등록 직전 사용 이력을 다시 검사한다. 개발에서 명백한 서비스 손실이 나오면 확인을 보류한다. 구체적 반례가 없으면 추가 실행0으로 진단만 마친다. 미래 도착을 모르는 현재 큐 예측과 실제 전체 trace 서비스 준수는 별도 검증이다.
