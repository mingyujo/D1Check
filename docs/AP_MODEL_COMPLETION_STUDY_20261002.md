# AP 모형의 개발부터 독립 확인까지 끝내는 제한 실측 계획

2026-10-02 · 기준 HEAD `1f828ae07160cd8edf60ef0d101fb72291637046`

**권고는 최대 12세션: 개발 6 → PC 추정·동결 → 독립 확인 6이다.** 기존 통합 대조 6만 끝내고 다음 작은 진단을 결정하는 방식에서, 확인 입력·모형 후보 수·종료점을 지금 정하는 방식으로 바꾼다. 실측 승인이 아니라 연구 계획이다. 이번 ADB/설치/추론/실측/Run/실행 claim은 0이다.

**현재 상태는 DESIGN_FIXED_EXECUTION_NOT_APPROVED다.** 기존 첫 6세션 수집기는 준비됐으나 새 추정·동결과 확인 6세션 실행 연결은 아직 구현·진입 검증이 필요하다. 이 문서를 12세션 실행 가능 판정으로 쓰지 않는다. 첫 6세션도 전체 분석·확인 경로를 PC에서 완성하기 전에는 시작하지 않는 것을 권고한다. 기존 미소비 계획을 실패·stopped로 바꾸거나 파일을 수정하지 않았다.

## 1. 이번에 완성하려는 모형을 명확히 제한한다

대상은 A24의 같은 네 resident runtime·8 warmup·분류 GPU＋탐지 CPU 배정에서 **등록된 짧은 24요청 묶음의 시작·분할 시점과 초기 준비 이력이 바뀔 때 AP 경로를 예측하는 조건부 모형**이다. 실제 lane 일정과 부하 전 AP를 입력으로 쓴다. 임의 도착부터 일정을 생성하는 종단간 모형, CPU 정책과의 일반 자원 선택, 모든 초기 온도, 주변 온도/내부 열 상태 식별, 스로틀 곡선은 이번 완료 범위가 아니다.

이 범위 제한을 사용자 몰래 ‘원래 연구 전체 완성’으로 부르지 않는다. 제한된 일정/서비스 시뮬레이터와 CPU/B2 직접 비용 대조는 이미 사용할 수 있다. 이번 계획은 그보다 넓은 **AP 예측의 실제 범위와 실패 경계**를 얻기 위한 것이다. CPU/B2 전체의 열 기반 우열은 별도 근거 없이는 여전히 판정하지 않는다.

기존 근거는 다시 수집하지 않는다.

- [준비 이력 후보와 두 독립 확인](AP_MEMORY_CONFIRM_RUN01_20261002.md): MAE 약 0.179/0.190°C, 실제 일정·부하 전 AP 조건부. 정확도 허용폭이 정해진 PASS가 아니며 후기 방향·크기가 미해결이다.
- [β/k 사후 보완](results/ap_rate_identification_01/README.md): 7개 부하 자료 최고오차 악화로 미채택. C 무부하에서도 작은 비단조 변화가 있어서 부하 gain 하나로 원인을 설명할 수 없다.
- [기존 통합 대조](results/ap_background_contrast_01/README.md): 같은 APK의 C/+35/+65 순서 대조와 원문 회수 경로를 재사용한다. 이미 본 다른 APK/다른 이력의 C를 새 개발 대조로 섞지 않는다.

## 2. 두 묶음을 사전에 정한다

| 단계 | 고정 순서 | 자료 역할 | 해결할 질문 |
|---|---|---|---|
| 개발 6 | C → L35 → L65 → L65 → L35 → C | 구조 판별＋별도 후보 개발 | 본 작업 없는 배경 변화, 같은 부하를 30초 늦췄을 때의 반응, 앞뒤 반복의 차이 |
| PC 동결 | 적격성 → 한 후보군 추정 → 선택/중단 → 해시 | 기기 부하 없음 | 어떤 식·계수·초기화·범위를 확인할지 확정 |
| 확인 6 | C → L50 → SPLIT → SPLIT → L50 → C | 동결 후 새 세션, 재적합 금지 | 보지 않은 중간 시점과 분할 이력, 별도 시점의 무부하 예측 |

C는 본 요청 0이며 runtime·warmup은 나머지 조건과 같다. L은 기존 burst/seed201 CG_DC 24요청이다. **B2 queue201의 반복이라고 하지 않는다.** 예정 도착 0–4.840초·모델·입력·backend·우선순위·deadline을 보존하고 실행 허용 시각만 사전 변환한다.

- L35: 원래 허용 시각 35.000300–46.260403초.
- L65: 모든 허용 시각 +30초.
- L50: 모든 허용 시각 +15초. 개발 두 시점의 중간이지만 그 사실만으로 예측 정확도가 보장되지는 않는다.
- SPLIT: ordinal 0–11은 그대로, 12–23만 +30초. 첫 그룹은 35.000300초, 두 번째 그룹은 약 68.0403초부터 허용된다. 이름만 보고 두 번째가 정확히 65초라고 해석하지 않는다. 두 그룹 내 상대 일정은 유지한다.

실제 호출시간·겹침은 맞추지 않는다. 예정 도착은 이전 완료와 독립적이고 추가 가열·sleep·호출은 없다. 두 번의 조건은 순서 대비와 재현 차이 관찰용이다. 2반복이 정밀도/신뢰구간/통계적 안정성을 보장한다는 근거는 없다. 각 조건의 평균 순번 3.5는 **선형 순번 변화만 산술적으로 균형**시킨다. 비선형 환경 변화·실제 벽시계 추세·carryover·숨은 잔열은 제거되지 않는다.

12세션은 이 설계의 상한이지 ‘성공할 때까지 12번’이 아니다. 자료나 식별 실패면 더 적게 종료한다. 개발만으로 목적을 이뤘다고 확인을 건너뛰어 새 후보를 검증 완료로 표시하지 않는다.

여기서 독립 확인은 모형 선택·적합에서 분리한 새로운 실행 자료라는 뜻이다. 같은 폰에서 연속 실행한 세션들이 확률적으로 독립·동일분포라고 가정하지 않는다. 두 블록의 날짜·배터리·초기 AP·준비 이력과 차이를 함께 공개한다.

## 3. 관측창·환경·초기화

한 세션의 baseline 30＋common 120＋cooling 60 = 210초를 유지한다. AP는 기존 약 2–3초 관측과 조회 괄호를 그대로 기록한다. ±0.05°C는 0.1°C 보고값에 대한 **반올림 민감도 가정**일 뿐 센서 정확도 인증이나 잡음 신뢰구간이 아니다. 짧은 요청 또는 1–2초 병행의 독립 전력 계수를 추정하지 않는다.

시간을 늘리는 것 자체를 식별의 대안으로 쓰지 않는다. 현재 창은 이미 문제를 관측한 common150–175초를 포함하고 τ30을 고정한 후보를 평가하기 위한 것이다. 그보다 느린 미지의 평형/시정수까지 식별하는 설계는 아니다. 그런 항이 필요하다고 드러나면 이번 범위를 미식별로 종료한다. 등록된 수십 초 대기는 열 반응을 구분하기 위한 입력이며 온라인 정책의 응답 요구를 만족하는 실행으로 주장하지 않는다.

모든 조건에서 baseline 이후→common +35초 전에 조회 괄호 전체가 들어온 AP만 초기화에 쓴다. ≥55초/≥15표본/공백≤10초의 기존 기준을 유지한다. L65·L50의 추가 대기 AP나 확인의 부하 후 AP를 초기화/재보정에 쓰지 않는다. 마지막 초기화 AP를 상태 anchor로 사용하고 그 뒤 연속 전파한다. 시작 AP를 주변 온도·평형 온도로 대체하지 않는다.

판독은 common +35초 이후부터 실제 냉각 종료까지이며 공통 시각 90–115/120–145/150–175초 변화와 실제 마지막 lane 해제 후 구간도 별도로 보고한다. C에는 가짜 lane 해제 원점을 만들지 않는다. 전류·전압으로 common 120초 전체 J도 보존하되 AP 개선을 에너지 정확도 개선으로 바꾸지 않는다.

같은 기기·APK·입력·runtime·warmup·화면·관측 주기를 유지한다. 폰의 위치/거치·케이스·실내 장소·주변의 강한 열원·직사광 여부·측정 전 등록 외 사용과 블록 간 충전 여부를 기록한다. 주변 온도계가 없으면 unknown이며 AP/BAT를 주변 온도로 대신하지 않는다. 90초 세션 간 자연 대기는 열 초기화의 증명이 아니다. 무선/화면 설정 변경·임의 가열·추가 warmup·온도 맞추기 대기는 금지한다.

실행 gate는 기존 현재 A24/설치본/서명/단일 transport·비충전·배터리≥20%·BAT≤35°C·thermal0·화면/메모리/warmup 품질을 그대로 쓴다. numeric AP 유효성·신선도는 필수, 32.5°C 개발 하한은 실행 gate로 복원하지 않는다. 초기 AP 개발 범위 밖이면 적용 범위 밖으로 분리하고 결과에 맞춰 strict를 넓히지 않는다. thermal0이 스로틀 부재의 증명은 아니다.

## 4. 후보를 결과가 나온 뒤 계속 추가하지 않는다

비교 기준 M0는 현 준비 이력 후보 `d885b87c…c1466`을 그대로 둔다. 사전에 허용하는 보완 M1은 **하나의 수식군**뿐이다.

```text
u(t) = 원래 상태 AP 기울기 − 원래 resident_idle 기울기
T' = β(E − T) + k·u + H
H' = −H/30 + g·u/30
```

- τ=30초·상태별 상대 기울기는 고정. 개발할 값은 β, k≥0, g≥0. M0는 β=기존값/k=1/g=0이다.
- β는 기존값의 0.2–5배 로그61점(중심 기존값 정확 포함), 각 점의 k/g는 두 비음수 선형 계수로 계산한다. 새 격자 확대·후보 수식 추가·뉴럴넷 탐색은 없다. 세션별 MSE를 동일 가중 평균하므로 센서 표본이 많은 세션이 더 큰 반복 수를 얻지 않는다.
- 각 β에서 **각 세션의 +35초 전 AP만** E/H 초기화에 쓴다. E/H는 관측 가능한 입력에서 만든 유효 상태이지 실제 주변/내부 온도 아니다. C의 관측 잔차를 L의 미래 예측에 빼서 맞추지 않는다.
- 준비된 통합 수집기는 원래 M0 판독을 변경 없이 수행한다. 그 6개 원본을 별도 PC 개발 분석에서 M1에 사용하는 역할을 지금 선언한다. 기존 수집 계약의 동결 계수나 실행 중 판독은 바꾸지 않는다.

개발의 전체 profile·정규화 민감도 rank·경계해·세션 하나 제외 시 계수/예측 변화를 남긴다. full numerical rank는 실용 식별이나 물리적 유일성의 충분조건이 아니다. 무부하는 k/g 정보를 제공하지 않으며 부하 자료도 둘을 구분하지 못할 수 있다. 그 경우 null/미식별로 끝내고 같은 부하를 더 반복해 해결한 척하지 않는다.

**선택 규칙도 사전 고정한다.** 식별된 M1의 세션 제외 예측에서 개발 조건별 평균 MAE·최대 절대오차·최고 절대오차가 M0보다 모두 나쁘지 않고 적어도 하나 개선될 때만 M1을 동결한다. 이는 상대 개선 선별 규칙이며 정확도 합격선이 아니다. 식별은 됐지만 이 규칙을 만족하지 못하면 M0를 유지한다. M1이 미식별/β격자 경계라면 격자를 늘리지 않고 확인 이전에 종료한다. 선택 모형의 C 방향이 반올림 민감도를 고려해도 명백히 반대면 역시 종료한다. 방향 구간이 0을 포함하면 ‘방향 미식별’이며 방향 재현 성공으로 세지 않는다.

확인 전에 선택 수식·계수·초기화·분석 코드·입력·지원 범위·개발 inventory·선택 이유의 해시를 고정한다. 확인의 예측 생성 시점과 사용한 입력 범위를 저장한다. 확인 6세션은 그 후에만 수집한다. 확인을 본 뒤 후보/계수/창/threshold를 바꾸지 않는다. 모두 결과를 본 과거 자료는 설계 근거로만 쓰며 새 독립 확인 분모에 넣지 않는다.

## 5. 무엇을 보고 종료하는가

| 층위 | 완료 판정 | 불충족 시 |
|---|---|---|
| 자료 적격성 | 예정 0/24 분모, 실제 lane/정상 cleanup, AP 괄호·공백·창·초기화 적격 | 해당 블록과 전체 연구 중단, 부분 원본/소비/오류 보존; 대체 없음 |

| 정책 차이 | 등록된 비교에서 오차·실행 간 차이를 함께 제시; 차이가 불확실성에 묻히면 순위 미판정 | 작은 차이를 ‘승리’로 만들지 않음 |

수치 근거 없는 ‘MAE 0.5°C면 완성’ 같은 새 합격선을 만들지 않는다. 정확도 허용 기준은 null이며 확인된 잔차와 지원 조건이 산출물이다. 관측 최악오차는 보편 오차 보장/신뢰구간이 아니다. 작은 열 차이를 구분할 근거가 없으면 대시보드가 순위를 반환하지 않아야 한다. 평균 개선으로 최고온도/방향 실패를 숨기지 않는다.

**이 연구의 마지막은 성공·한정 지원·미식별 중 하나의 최종 판정이다. 13번째 세션은 없다.** 새 후보가 실패하면 M0의 기존 제한 근거와 완료된 시뮬레이터를 유지하고 해당 확장만 미지원으로 닫는다. 새 물리 항이 필요하다는 결론까지는 가능하나 그 자리에서 다음 실측을 생성하지 않는다. 모든 내부 물리 원인을 알아내는 것을 완료 요건으로 두지 않는다.

각 블록의 산식은 preflight600＋6×(stage120＋poll485＋회수50＋cleanup45)＋5×90이다. AP/화면/listing 주기와 개별 timeout은 [기존 상세 계약](results/ap_background_contrast_01/README.md)을 바꾸지 않는다. 새 polling이나 timeout 확대는 없다. 다음 세션의 실행·회수·cleanup 예약이 부족하면 시작하지 않는다.

두 블록 사이 PC 추정·동결에는 **작업 관리 상한 60분**을 제안한다(알고리즘 소요 보장 아님). 따라서 승인 후보의 누적 작업 상한은 **3시간55분**이다. 고정 관측42분을 전체 예상시간으로 쓰지 않는다. 과거 두 세션 시간으로 동일 길이 블록을 단순 환산한 기기 작업 참고값은 두 묶음 약63분이지만 준비/실패/새 확인을 보장하지 않는다. 충분히 시간을 잡으려면 **반나절을 확보하되 3시간55분 누적 작업 상한 안에서 종료**하는 운영을 권고한다.

PC 구현·사전 검증 시간은 위 실측 작업 예산에 들어 있지 않다. 블록 사이 충전/연결 복구 등 사용자가 준비하는 공백은 별도 기록하고 벽시계 종료 보장으로 말하지 않는다. 충전 중 측정은 하지 않으며 블록 중 실패한 계획을 충전 후 재개하지 않는다. 첫 블록 종료와 앱 프로세스 부재를 확인한 뒤 PC 동결한다. 두 번째는 현재 환경/설치본 gate를 새로 확인한다.

## 7. 실행 전 남은 PC 구현을 하나의 묶음으로 끝낸다

**기기 실행 이전에 모두 필요:**

1. 위 한 후보군의 동등한 선형 전파/비음수 적합·세션 제외·미식별/방향 중단·동결 파일 생성 구현 및 합성 정답/원문 fixture 검증. 물리 계수는 이 단계에서 기존 자료로 다시 맞추지 않는다.
2. C/L50/SPLIT 확인 manifest·설치 없는 수집 분기·동결 해시 연결·실제 진입 경로·시간/명령 예약·중복/재실행 차단 검증. 확인 입력과 예산은 지금 고정하고, 확인 계획에는 개발 후 생성한 모형의 정확한 해시를 바인딩한다. 실행 중 예산·입력을 새로 고르는 것이 아니다.
3. 개발 실패/미식별이면 확인 호출0, 확인 중 재보정0, 부하 후 AP가 예측 입력으로 유입되지 않음, 누락을0으로 채우지 않음, 원래 오류와 회수/cleanup 오류 분리까지 검증. 두 블록의 별도 ID·registry·receipt와 연구 전체 진행 기록을 연결한다.

같은74e APK의 0/24요청·release gate·분할 입력 기능을 재사용할 설계다. 새 APK가 필요한 사실은 현재 없지만 새 host 진입의 검증 전까지 실기기 호환성을 완료로 표시하지 않는다. 실행기나 모형 적합이 아직 연결되지 않았으므로 **추측한 12세션 Run 명령을 제공하지 않는다.** 기존 6세션 Run을 두 번 호출하는 방법도 아니다. 이 PC 묶음 완료 후 두 단계의 정확한 명령·해시·예산을 한 번에 승인받아 진행할 수 있도록 한다.
