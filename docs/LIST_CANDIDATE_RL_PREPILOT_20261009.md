## 1. 유망성과 채택을 나누고 에너지 단독 개선도 허용

같은 조건·같은 상대 기준b에서 `ΔA=Aπ−Ab`, `ΔJ=Jπ−Jb`를 계산한다. 서비스와 전체 예정량을 먼저 확인한 뒤 다음으로 분류한다. AP는 같은 동결모형의 최고AP 채널이다.

| 서비스가 유지된 수치 결과 | 분류 |
|---|---|
| ΔA<0, ΔJ=0 | 열 감소형 유망 |
| ΔA=0, ΔJ<0 | 에너지 감소형 유망 |
| ΔA<0, ΔJ<0 | 공동 감소형 유망 |
| 한 축<0, 다른 축>0 | 상충 후보·공동 비악화 통과 아님 |
| ΔA=ΔJ=0 | 동률·개선 확인 없음 |
| 개선축 없이 한 축이라도>0 | 비용 악화 |

서비스 실패는 비용 분류에 앞서 탈락, 값null/수치 불명은 미판정이다. 한 기준의 AP 개선과 다른 기준의 J 개선을 합치지 않는다. 평균이나 최고 학습seed로 일부 실패를 숨기지 않는다.

**수치 유지 기준은 새epsilon0**이다. Δ≤0은 비악화, Δ=0은 동일, Δ<0은 같은모형의 수치 감소다. 모델/input/preload/창과 task·backend·dispatch·lane_available의 canonical 비용 원장이 같으면 공통 결정적 회계로 한 번 계산해 비용 동률로 처리한다. 서비스 경계/실패/P95는 별도로 원장 전체에서 확인한다. 다른 원장은 정식 평가기의 full-precision 차이를 보고, 재합산/순서 감사에서 부호가 불안정하면 `numerically_undetermined`로 통과시키지 않는다. 감사 대상·불명 규칙은 실행 전에 등록한다. 과거fastforecast3.55e−15나 Run05 C0의 오차를 허용손실로 가져오지 않는다. 이것은 물리 온도·에너지 유지의 입증이 아니다.

유망성의 조건 집합을 다음처럼 사전 고정했다.

- **유지 집합M:** 개발24/확인48의 low·queue·burst·sustained 전조건. 학습seed11/23/37 전부가 L0/Band/Triton 각각 대비 전량·서비스·AP/J 비악화. low/sustained는 기존1.5/6초 목표에서 `F=U=N=0`도 요구한다.
- **개선 집합G:** low 또는 sustained라는 같은 부하family 하나가 모든 등록 도착trace×3실행문맥×3학습seed×각 기준에서 AP/J 비악화와 적어도 한축 엄격 감소를 보인다. 두family 모두 열 감소할 필요는 없다. 동률인 low를 유지하며 sustained의 에너지형만 반복되는 후보도 통과 가능하다.
- **최종 확인:** 개발에서 통과한 family 목록을 새 확인 전에 동결하고, 새4도착trace에서도 같은 반복성·전체M을 요구한다. 개발통과는 유망성이고 새 확인은 검토조건 내 방법론 채택 근거다. 실제 앱 기본 정책을 자동 바꾸지 않는다.

원 AP주보상+signed J는 유지한다. AP가 같고 J가 감소하면 λJ>0일 때 에너지 개선 신호가 있으나 λJ=0이면 AP목적에서는 동률이다. AP항/J항/서비스벌점/λ를 따로 기록한다. gate 개정을 학습목적 변경·수렴·에너지형 발견 보장으로 해석하지 않는다.

## 2. 같은 후보 비학습 선택기의 서비스 계산을 고정

미배정 두head를 각각 독립적으로 예측하면 둘이 같은CPU를 동시에 쓰는 낙관성이 생긴다는 산업공학 반론을 모바일/RL이 수용했다. **현재 owned 작업+선택atom을 고정한 뒤 현재 미배정 C/D head만 고정EDD 순서로 한 번 가상 회계**한다. 순열·최적화·전체 큐·Band suffix·미래 도착·실제 예약은 없다. 원v4의 제한을 이 좁은 서비스 회계에 한해 명시적으로 개정한다. AP/J proxy에는 가상 후속 작업을 넣지 않는다.

`t`=현재, `a_q`=도착, `d_q=a_q+D_q`, `μqb`=원동결mean 5phase, `Lqb=Σμqb`, 분류응답 `ρCb=Σ앞2phase`, 탐지응답 `ρDb=Σ앞3phase`다. 현재 owned의 phase j는 **기존 dispatch A 기준 누적평균**에서 `A+Σμ[:j+1]>t`, `A+Σμ>t`일 때만 유효하고, 예상lane끝은 `A+Σμ`다. 평균phase/총 종료에 도달했는데 실제로 소유 중이면unknown이다. 잔여0·다른문맥·실현비용으로 대체하지 않는다. public phase_since부터 평균을 새로 시작하는 추정법은 이번에 채택하지 않았다.

선택atom의 실제 즉시 jobs는t에 고정한다. 미배정head release `e_q`는t 또는 그head에 선언한hold끝이다. 혼합 분류GPU+탐지hold0.125초에서 탐지CPU를 GPU0.305초 종료까지 강제 지연시키지 않는다.

```text
미배정 head 순서: (절대기한, 도착, ordinal, ID)
s_qb = 가장 이른 s >= e_q:
       [s, s+Lqb)가 owned/atom/앞서가상배정한head와
       같은lane 또는 미지원병행으로 겹치지 않음
b* = argmin(s_qb+Lqb, CPU 동률우선)
예상응답 Rq = s_qb* + rho_qb*
예상lane끝 = s_qb* + Lqb*
```

앞head의 virtual 점유를 뒤head에 반영한다. 이를 정확한 **동결mean 가정의 구간 회계**라고 부르며 실제 미래응답 보장으로 부르지 않는다. RL후보와 비학습 선택기는 같은 함수로 `(Rq−a_q)/D_q`와 `(d_q−Rq)/D_q`를 받는다. absent만0이고 present 예측불명은known=false/null이다.

비학습 선택기 순위는 다음risk5→atom의span최고AP→끝AP→J→L0동률→고정signature다.

```text
late_q = I[Rq > dq]; tardy_q = max(0,Rq-dq)/Dq
E(a) = max(관측 긴급P95/1.5초, C_head 예상응답latency/1.5초)
관측0건이면 C 예측만; C없으면 이 항 비적용
e_U(a) = max(0, E(a)-E(L0))  # 이미 정규화: 다시1.5로 나누지 않음
risk5 = (late_C,late_D,tardy_C,tardy_D,e_U)
```

risk4만 쓰면 모두기한내인 동안 짧은대기가 낮은 단원비용 때문에 반복선택될 수 있다. 모든 응답을 항상 최소화하는 새항 대신, 기존 긴급P95 비악화 목표의 **공개 긴급응답 위험proxy**를 추가한 절충이다. 관측P95 아래에는 대기 여지가 남는다. 현재head의mean 예측·미응답 owned/미래 요청 누락 때문에 전체episode P95의 상한/보장은 아니다. 다른기간/작업량 proxy의 편향이 완전히 사라진 것도 아니다. 실제선택분포·반복대기·전체KPI와 강한 비교군을 보고한다. 이 순위로 RL물리mask를 좁히지 않는다.

서비스/비용 예측불명은 **물리 bank의L0**로 복귀한다. 실제 빈 지원 자원·호환성으로 runnable head를EDD/backfill하고 신규작업mean 5phase ECT/CPU동률로 고른다. 탐지CPU 평균초과가 빈GPU 분류 실행까지 막는 old global-idle 동작을 복사하지 않는다. 물리행동이 없을 때만 공개event를 기다리며 예상release로 실제lane을 풀지 않는다.

## 3. 확인 대조와 예산을 명시

비학습 선택기를 개발24뿐 아니라 새 확인48조건에1회씩 포함한다. 같은48행을 RL3seed와 각각 대응시켜 **144개차이**를 만들며 환경48회를144회로 세지 않는다. median은 보조요약이며 seed통과를 대신하지 않는다.

동일후보 RL기여는 고정선택기도 같은 서비스조건을 충족하는 셀에서 원단위AP/J 비악화+엄격축으로 판정한다. 선택기의 미완료/서비스악화로 비용이 낮으면 RL의서비스회복·비용상충을 따로 적고 무조건 비용우위라고 부르지 않는다. 둘다 최종 기준을 통과하고 동률이면 **더 단순한 비학습 방법을 우선 추천**하며 RL필요성이 입증됐다고 하지 않는다. 범위는 이 고정선택기와 검토조건 대비이고 강화학습 일반의 우월성이 아니다.

## 4. 표현성은 구체 결과로 확인

기존성공3원장은 별도 known-success coverage로 두고, intent가없어 완전한행동재현PASS라고 하지 않는다. 각 primitive의 포함/제외/불명을 head·자발대기credit·병행구성·실제소유·timer도달성·canonicalization별로 분류한다. raw 큐대기0.25초초과를 credit위반이라고 단정하지 않는다.

독립적으로이미소비된개발조건에서35/60/90/110초이후첫공개decision과 최초bothhead/CPU전용owned+GPUfree/PAIR가능/credit0를 사전규칙으로선정한다. 중복제거·조건당최대8·없음null, 개선/승자/최종좋은3조건을선정에사용하지않는다. 공개journal없음은재구성/불명으로표시한다. 새로운훈련/확인자료를튜닝에전용하지않고 구현gate32 native시작상한안에검사호출·실패를모두계상한다.

**정적공개정보별칭 반례를 찾았다.** 현재C1기한t+0.4, D1기한t+0.85이고 뒤C2의기한만 A=t+0.5/B=t+1.0으로다르다. 원1.5초offset과FIFO를지키고 최근8도착은동일하게둘수있어, 명시된현재head/개수/최근8특징에는이차이가없다. 동결mean에서PAIR뒤C2최속응답은약0.599초라A를놓치지만, C1CPU먼저→C2GPU+D1CPU는C2약0.459초/D1약0.785초로세기한을지킨다. B에서는PAIR경로의세요청증분J가약0.04325J낮다([검산값](results/list_candidate_rl_prepilot_02/verification.json)).

이는 **세요청 산술과 특징정의의누락 후보**다. 실제encoder tensor 바이트동일/도달가능성/뒤요청전량/전체P95·120초J·180초AP의검증은아니다. 그짝을구현gate에서재현하고개선가능선택이바뀌면 뒤C기한같은최소공개특징만보완한다. 이번에상태차원/대기한도/행동을자동확대하지않는다. private 미래/실현문맥만다른oracle행동은 feature결함증거가아니다.
