## 최종 새 2회 결과

주평가는 예정 요청으로 원서비스 일정부터 예측하는 B다. AP는 공통 원점 35..180초 관측 경로의 MAE, 에너지는 0..120초의 예측−관측 절대오차다. 각 세션 오차를 같은 비중으로 평균했다. °C/J/ms를 하나의 임의 점수로 합치지 않는다.

여기서 v2 비용도 동일한 원서비스 일정에 적용해 계수 차이를 비교했다. v2 자체 서비스 예측은 최종 B 비교의 일정으로 사용하지 않았다. 실제 측정 일정을 입력한 조건부 A의 AP 평균도 0.396996→0.204271°C로 줄었으며, A의 에너지 절대오차는 양쪽 1.850187J다. A는 미래 실측 일정을 아는 진단이며 운영 예측 입력으로 사용하지 않는다.

평균 개선이 모든 온도 지표의 개선을 뜻하지 않는다. CPU 최대 절대오차는 0.760387→0.928872°C, 피크 온도 절대오차는 0.010240→0.226540°C로 악화했다. PAR 최대오차는 1.109456→0.955959°C, 피크오차는 0.287532→0.052710°C로 개선했다. 새 기준은 AP 평균 감소와 에너지·서비스 동등성이며, 최악 시점 비악화를 요구한 기준은 아니다.

## 무엇을 바꿨는가

열·에너지·검증 AI 역할 3개가 두 차례 토론했다. 회복 자료만으로 맞춘 v2 계수를 혼합 도착에 적용한 전이 문제를 확인하고, 기존 개발 17세션/5자료군에 동일 비중을 주어 기존 계수 쪽으로 규제한 후보를 비교했다. 총 542회 head 적합 후 온도 λ=0.1, 초기 잔열 규제 α=0.5를 동결했다. 빠른 감쇠와 느린 시간상수는 상속값이며 물리적 식별 완료를 주장하지 않는다.

열 계수의 상태 순서는 분류CPU/탐지CPU/분류GPU/분류GPU＋탐지CPU/느린 항이다. 최종 계수는 `[0.1164670534, 0.1282327589, 0.0833649400, 0.1999760156, 0.0056142731]`이다. 추론 시점 전 온도·전력·알려진 점유 이력과 예정 요청만 입력하며 미래 실측 온도/전력/실제 일정은 예측 함수에서 금지한다.

초기 v3의 에너지 보정은 새 독립 4회에서 실패했다. 그 뒤 열 계수는 그대로 두고, 원 JSON의 전력 계수를 직접 복사해 에너지 gain=0으로 복원했다. λ=100 표시는 API를 위한 값이며 에너지 재적합·수축을 실행하지 않았다. 원서비스를 그대로 쓰며 열이 에너지·일정·처리시간에 되먹임되지 않는다. 따라서 같은 입력과 일정에서 `J(t)=P_pre·t＋점유벡터·원전력계수`가 양쪽 동일하다.

이 조립은 첫 4회 결과를 본 뒤의 사후 보완이다. hybrid 자체의 새 동결 뒤 CPU/PAR 각 1회를 전향 확인했고 추가 적합은 0회다. 모형 SHA-256은 `6dd806bc30c5d69dd07237dc8fbe0bc09ed90a86fede4d86294ae14be2eb1196`, hybrid 동결 SHA는 `900b5a0f356758f8727ea307f60f959d3ab768de5715f652dab255e064ddd266`이다.

## 첫 v3 실패와 증거 경계

| 첫 독립 4회 B 평균 | 원모형 | 온도·에너지 보정 v3 |
|---|---:|---:|
| AP MAE | 0.417352°C | 0.233666°C |
| 에너지 절대오차 | 3.555364J | 7.340075J |

사전 기준인 **AP·J 모두 감소는 FAIL**이며 그대로 보존한다. 첫 4회의 AP 감소는 그 실측 전에 동결된 개별 열 head의 확인 근거다. 사후 조립한 hybrid 전체의 독립 확인으로 전용하지 않는다. 새 2회는 별도 기준인 AP 평균 감소＋원 에너지·서비스 동등성을 충족했다. 좋은 결과만 남기는 재실측이나 확인 자료로 재학습은 하지 않았다.

개발 nested CV의 원모형/규제 사전계수는 일부 과거 개발 자료를 이미 보았다. 따라서 개발 수치를 전체 모형의 완전 독립 OOF 성능이라고 부르지 않는다. 새 2회도 정책마다 1회이므로 통계적 유의성·다른 부하/기기 일반화는 미확정이다. 온도 예측 개선과 정책 우월성·온도에 따른 속도 회복을 구분한다.
