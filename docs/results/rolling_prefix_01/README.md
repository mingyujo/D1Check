# 실제 첫 선택을 검증하는 공동 롤링 호라이즌

작업 ID `IE-ROLLING-PREFIX-GUARD-02`. 개발 진단에서 확인한 **후속 계획의 AP 이득을 첫 선택의 이득으로 간주하는 문제**에 한 가지 검사만 추가한다. 원계획을 버리거나 후보 선별을 결과에 맞춰 바꾸지 않는다.

## 결과와 권고

**실제 첫 선택 검사로 예측 평가의 불일치를 보완했지만, 전체 정책 교체 기준은 통과하지 못했다.** 개발24조건에서 양 기준 비악화18조건으로 적격 없음(`selection.chosen=null`)을 확인 전에 동결했다. 확인 후 조건/후보를 다시 고르지 않았으며 Band 연구기준과 기본 정책을 유지한다.

P95/최고AP는 조건별 값의 평균이다. 총완료와 기한 내 완료를 구분한다. Band와 후보의 일반 실패24건은 남아 있고 Triton은21건이므로 양 기준의 전 서비스 요구를 만족했다고 표현하지 않는다. 각 정책1584건·전체 확인7,920건은 모두 완료했다.

첫 선택 검사683회 중44회를 차단했다. 원 공동 계획과 새 후보의 원장은6조건에서 달랐다. 원 공동 계획의 Band 대비 긴급P95 악화1조건(둘째 seed·지속·긴 실행의9.0731ms)이 새 후보에서는0으로 줄었고, 새 확인24조건의 긴급P95는 각각 Band와 같았다. J는 두 후보가 모든 조건에서1e−8 이내로 같았다. 이 허용은 결과 동일성 설명이며 원정책/비악화 판정의1e−9 기준을 변경하지 않는다.

공동감소3조건은 **같은 하나의 도착 seed에 대한 세 비용 문맥**이며 독립3반복이 아니다. 모든 기한을 충족하면서 양 기준 대비 공동감소한 제한적 결과는 존재하지만 두 도착 seed에 걸친 일반 개선은 아니다. 열감소12조건 중 양 기준이 모두 전기한을 지킨 조건은6개다. 낮은 부하에서도 일부AP 증가가 남아 있다. 관측 가능한 부하 선택 규칙 없이 결과에서 좋은 seed/조건만 골라 운용 정책이라고 부르지 않는다.

현재 권고는 **첫 선택 검사를 연구 구현으로 보존하고 전체 채택은 보류**하는 것이다. 원 후보보다 서비스 비교가 나아졌지만 에너지/열 공동 성적은 거의 같아, 이 검사만으로 학습을 늘릴 근거가 되지 않는다. 큰 창 전수 선별·새 부하 예측·새 알고리즘을 추가로 연쇄하지 않았다.

## 검증과 제한

- 새 기능5검증 PASS: 미래 후속 냉각을 단건 이득으로 전용하지 않음·같은 시각 동시쌍 검사·첫 냉각만 검사·차단 시 미실행 예약 취소와 Band 반환·통과 시 선택 유지. 원엔진fixture2회/8요청과146환경의 요청/용량/완료경계 감사를 통과했다. 저장된 첫 선택 예측을 공유 검사에서 다시 판정한다.
- 진단24회와 이번146회를 합쳐 신규170환경·14,120요청 전량, 환경 실패0·누적6,466환경/641학습이다. 새학습/이번기기/ADB/NPU/계수 적합0이며 두 진단/평가 clock과 소비를 각각 계승했다. 기준96개 개발행은 재사용으로 환경0이다.
- PC 최대 판단시간은 Band0.301ms·원 공동85.745ms·새 검사91.755ms다. 증가한 실제 제어J와 폰의 판단시간은 측정하지 않았고 원 시뮬레이터의 추가 제어비용0 가정을 유지했다. 이 오버헤드를 포함한 실제 SLA/절감은 미판정이다.
- AP는 같은 동결 모형의 채널이며 표면온도/안전 한도가 아니다. 약0.02~0.04°C 차이를 모형 오차보다 확실한 실제 개선으로 주장하지 않는다. 두 seed와3실행 문맥은 정밀 신뢰구간의 근거가 아니다. 미래 실제 요청/실현 비용/선점·주파수·전력 제한 행동은 추가하지 않았다.
- 실행 전 `prepare/run`을 중복 시작해 원자 저장 임시파일의 Windows 사용중 오류1건이 났다. prepare는 중단됐고 run이 만든 단일 등록/입력/소스 해시를 확인한 후 정상 진행했다. 재등록·예산 초기화·원정책/판정 변경·환경 실패는 없다. 보고서의 재사용 원장 위치 누락도 원계보를 확인해 수정했고 실험을 다시 실행하지 않았다.

## 공유 결과 확인

```powershell
python -B -X utf8 -m tools.d1_rolling_prefix_check
```

이 명령은 GitHub 공유 파일로 설정/선정/완료량/누적 소비·첫 선택 판정을 확인하며 새 시뮬레이션/기기 실행0이다. 아래 prepare/run은 이번에 사용한 실행 명령 기록이며 로컬 원등록/원장 계보를 필요로 한다. 완료 폴더는 재실행하지 않고, 새 배치는 별도 계약과 남은 누적 예산으로 정한다. 원 큰 원장·모델·APK·키·개인 경로는 공유하지 않는다.

## 결과 전 고정한 계약

- 원 공동 계획의 창4·과업내EDD·CPU전용 최소여유 포함·평균 선별8·유휴credit0.25초·전체 현재 큐/3문맥 검사·원W/AP/초기화/기한을 유지한다. 계획 전체가 적격해도 **실제 첫 단건/동시쌍/냉각/자원 대기 이후 Band suffix**의 현재 요청 서비스·J·공통 최고AP가 원3문맥 모두 비악화여야 실행한다. 실패하면 아직 실행하지 않은 pending/hold/cooling만 취소하고 같은 시점 Band 선택을 반환한다.
- 새 도착을 알거나 전기한/실제 온도를 보장하는 필터가 아니다. 원 모형·기한·완료량·품질·5단계 점유·지원자원·기본/strict/experiment_ready=false를 유지한다. 미지원 AP 안전한도·표면온도·제어J는 null이다.
- 비교5역할: Band 요청 적용·Triton 고정 자원·원 공동 대기0·원 공동0.25초·첫 선택 검사0.25초. 개발24조건의 네 원정책96행은 hash와 입력 확인 후 환경0으로 재사용한다. 새 후보24환경과 합성4요청×2fixture를 먼저 수행한다.
- 개발24조건에서 양 기준 대비 서비스/J/AP 비악화와 low/sustained 주조건의 두 seed별 AP 감소가 있어야 적격이다. 확인 전에 선택/미선택을 동결한다. 새 확인815030101/102×4부하×3문맥24조건×5역할120환경을 고정 비교하고 확인 뒤 재선정/튜닝하지 않는다. 이전 소비 확인은 원인 설명이며 새 독립 확인으로 중복 집계하지 않는다.
- 기대146환경·이번160상한(실패 포함), 진단 후 누적6,320환경/641학습 계승·30분/마지막5분 저장이다. 한 후보·새학습/기기/ADB/NPU/계수적합0. 대표는 첫 새 확인 seed의 지속/평균으로 고정한다.
