## EDD 고정 문제와 학습·계산량

[기존6actor 진단](prior_diagnostic.csv)은 최종 잔차 점수 차이 상한1.138…1.587이 BASE 가산점의 최소2.197보다 작았음을 확인했다. BASE가 유효할 때 기존 가중치로 argmax를 뒤집을 수 없었다. 새 PPO는 이 지속적인 가산점을 제거했다. 확인 시간표가 EDD와 같은 조건은 PPO 각seed **0/48**, Double DQN은 각각3/48·12/48·0/48였다. 행동이 달라졌다고 성능 개선으로 판정하지 않는다.

이번 PPO와 DDQN은 같은 물리mask·상태·행동·종단 목적·64에피소드를 사용했지만 PPO의 Monte Carlo와 DDQN의1-step/replay, network head 및 탐색이 다르다. PPO informative 경험은5,997…6,275, DDQN7,957…9,016; optimizer step은PPO360…372/DDQN396…416이다. 같은 에피소드 수가 같은 경험량과 연산량을 뜻하지 않는다. 원32에피소드 C/E와는 가산점·목적/참조·자료·학습량도 달라 순수 알고리즘 변경 효과로 해석하지 않는다.

[실제 계산시간](training_compute_time.csv)의 환경·update·archive 포함 learner 벽시계는PPO 각626…641초, DDQN847…891초다(초기 process/network 준비 제외). 판단 비용은 원 PC 시뮬레이터의0증분 overhead 계약을 유지하고, host callback과 환경 벽시계를 별도로 기록했다. 확인48의 총환경 벽시계는Band8.24초·EDD8.27초·리스트733.33초·CP-SAT494.83초·RL각309.70…715.16초였다. 이 값은 병렬 PC 부하와 완전 예측 비용을 포함하며 **휴대폰 판단시간/J나 실기기 지연이 아니다.** 특히 후보 전체 예측과 solver 비용을 모바일 운영에서 무시할 수 있다고 주장하지 않는다.

## 모형 민감도와 남은 작업

[고정 일정720비용](coefficient_sensitivity.csv)은 첫 확인 seed의12조건×12정책을 원 모형과 이미 적합한 미채택 개발변형4로 후처리했다. 새 적합·재학습·변경계수 정책 재실행은0이다. 리스트 공동감소3조건의 Band 대비 방향은5설정 모두 유지됐다(J−2.862714…−0.018736/AP−0.135005…−0.059630°C). [민감도15행](joint_gain_sensitivity.csv). 불안정한 GPU 계수에 따른 큰 끝값을 실제 절감이나 통계 신뢰구간으로 쓰지 않는다.

별도 실측 확인의 J MAE3.913J/AP MAE0.260°C는 다른 부하·프로토콜의 오차다. 이를 보편 오차 한도나 임의 합격 margin으로 전용하지 않지만, 현재 작은 모형 이득을 물리 절감으로 확정할 근거도 부족하다. 표면온도와 휴대폰 제어 J는 미지원이며, 현재 APK에 numeric AP 지속 수신 경로도 없다.

추천은 **새 정책 미채택을 유지하면서, 리스트의 조건부 이득이 발생한 순서·자원·대기와 일반 지연 비용을 먼저 진단**하는 것이다. 같은 설정의 새 지속 trace에서 재현 여부를 확인할 다음 계약을 먼저 고정해야 한다. CP-SAT은 서비스/열 대조 후보로 보존하되 에너지 상충과 모바일 계산비용을 해결하기 전 주 방법으로 선정하지 않는다. RL은 희소 종단 credit·soft 제약·변동을 점검한 뒤 제한된 후속 학습을 검토하며 무제한 확장하지 않는다. 유망RL이 없어 WAIT/열 제거 추가 환경은0, 기기·NPU·ADB 실행0이다.

## 상태와 행동 및 목적

공통 상태109·후보68·32슬롯은 실제 도착한 큐, 공개된 lane 점유·phase·시각, 실측 프로파일, 과거 점유로 계산한 AP/h 추정치만 받는다. EDD 앞8요청의 단건 CPU/GPU 배정·허용된 분류GPU+탐지CPU 묶음·누적0.25초 이내 대기를 후보로 둔다. 미래 도착·실현 서비스벡터·실제 잔여시간·엔진 내부 열 상태는 받지 않는다. 빈 슬롯·미지원 조합·소유 중 lane은 물리 마스크로 차단한다.

PPO와 Double DQN의 공통 목적 버전은 `ENERGY_AP_BAND_TRITON_NONWORSE_V2`다. 종단 보상은 Band 전체120초 J−후보 J, 제약 비용은 Band/Triton 양쪽 대비 최고 AP·미완료·긴급 실패·일반 실패·긴급 P95의 양의 악화량이다. 비용 척도는 AP1°C, 실패1건, P95/1500ms이며 새로운 안전 온도 한도가 아니다. γ=1, 대기와 경과시간은 전체 비용에 포함된다. PPO는 Monte Carlo 반환, Double DQN은 같은 종단 벡터에 1-step bootstrap을 사용한다. 같은 에피소드 예산이 같은 transition·계산량을 뜻하지 않으므로 실제 수를 함께 보고한다.

PPO는 기존 네트워크·Adam·clip·entropy·epoch 설정을 유지하며 BASE logit 가산점만 새 네트워크에서 제거한다. 기존 C/E의 가중치는 그대로 보존한다. Double DQN은 같은 상태·후보 encoder에 행동별6채널 Q를 사용하고, 별도 target을32 gradient step마다 갱신한다. 최근32에피소드 replay와 ε0.30→0.10을 사전에 고정했다. 원 PPO와 비교할 때 목적·mask·가산점·학습량 변화가 함께 있다는 한계도 구분한다.

리스트는 세 문맥에서 현재 도착 큐의 기한 실패·긴급 P95·J/AP가 EDD 예측 후속 일정보다 악화되지 않는 후보 중 최고 AP, J 순으로 선택한다. 없으면 BASE다. 새 도착의 실제 SLA를 보장하는 필터가 아니다.

CP-SAT은 앞4요청의 비선점 lane 점유와 완료 경계를1ms 격자로 보수적으로 올림해 계획한다. 실제 허용된 CG_DC의 측정 에너지 중첩 비용을 포함하고, 예상 기한 실패 수→총 지각→에너지를 사전 순서로 최소화한다. ECT로 만든 실행 가능한 시작 힌트를 제공하지만 변수는 고정하지 않아 자원·순서·시작을 계속 탐색한다. 최대 deterministic time0.05·wall0.25초, worker1·seed0이다. 첫 행동만 실행하고 도착/공개 이벤트마다 다시 계획한다. 시작 지연은 공통 냉각 credit를 넘지 못한다.

**열은 CP-SAT 내부의 정확한 온도 최적화가 아니다.** 계산된 첫 행동을 원 세 문맥 열·에너지 예측 필터로 검사하며, 후보와 일치하지 않거나 UNKNOWN/거절이면 리스트로 돌아간다. 제한시간의 FEASIBLE을 최적해로 표시하지 않고, 정수 근사·fallback 빈도를 공개한다.

## 모형과 판정 경계

원 모형5682082a…와 원 초기 관측42f60312…를 유지한다. 지원은 A24 분류CPU/GPU·탐지CPU·CG_DC 최대2건이다. 응답은 긴급 OUTPUT_READY·일반 PERSISTED, lane 재사용은 전체5단계 이후다. 긴급1.5초·일반6초는 기존 engineering target이다. J0…120초·AP35…180초1초 격자는 정책마다 같다.

서비스 벡터의 mean/short/long은 기존에 선언한 전이 가정이다. 현재 모형이 일반적인 간섭·열에 의한 지연을 독립 검증했다고 확대하지 않는다. 모형 AP는 표면온도와 다르며 안전 온도 한도·기기 판단 J는 미지원이다. 현재 APK의 numeric AP 지속 수신도 미지원이다. 기기·ADB·NPU 실행0, 기본·strict·experiment_ready=false를 유지한다.

검증24조건에서 모든 조건의 Band/Triton 대비 완료량·기한 실패·긴급 P95·J/AP 비악화를 요구한다. low/sustained는 절대 전기한 충족도 요구한다. 적어도 한 조건에서 양쪽 대비 J와 AP가 함께 엄격히 감소해야 유망 후보로 인정한다. RL은3seed 모두 통과해야 한다. 후보 선택을 확인 자료 실행 전에 파일로 고정한다. 선택된 후보만 별도 확인48의 같은 기준으로 확정하며, 확인 후 승자를 바꾸지 않는다. 아무도 통과하지 못하면 새 정책 미채택으로 기록한다.
