# 세 역할 검토와 반영

이번 기록은 실제로 교환한 산업공학·RL·모바일 AI 역할의 검토와 구현 근거이다. 각 역할을 실재 사람 전문가 또는 외부 심사자의 검증으로 표시하지 않는다.

| 역할 | 지적 | 반영·검증 |
|---|---|---|
| 산업공학 | 원 후보 허용 검사의 모든 긴급 개별 응답 비악화는 최종 P95·기한 기준보다 강하다. 현재 자원 점유와 작업 호환성에 따른 실행·대기 대안을 막을 수 있다. | 기존 정책 보존 후 별도 ID/schema로 내부 검사만 바꿨다. 원 최종 KPI 판정은 불변이다. |
| RL | 과거 P95가 높으면 현재 긴급 응답이 늘어도 P95가 같을 수 있다. 이를 무제한 여유로 해석하면 안 된다. 관측 완료+현재 도착·소유 미응답을 같은 분모에 넣어야 한다. | 원 predictor의 같은 분모를 유지하고 긴급 miss·개별 요청 lateness·J·유한 drain과 요청별 0.25초 대기 한도를 유지했다. 기존 진행 중 PPO source/schema/Adam/RNG는 바꾸지 않았다. |
| 모바일 | 현재 큐의 조건부 P95는 실제 미래 도착까지 보장하지 않는다. GPU 분류+CPU 탐지만 병행 가능하고 실제 AVAILABLE 전 재사용은 금지된다. 고정 계획 실측은 온라인 스케줄러 실측과 다르다. | 동일 물리 mask·원 phase ABI·native 경계 감사를 유지했다. 이미 고정한 첫 네 기기 Band/Rule 재생과 대표 trace는 새 후보 결과로 바꾸지 않았다. |
| 통합 검토 | 원 개발 자료의 세 문맥 이벤트를 독립 성공 세 번으로 표시하면 안 된다. | seed826020101 sustained, 63.072586416초의 하나의 상태라는 범위를 고정했다. |

발견된 구체적 누락 후보는 처음 예상한 “분류를 GPU로 보내 CPU를 비우는 행동”이 아니었다. 실제 보존 원장에서는 CPU가 바쁠 때 분류를 즉시 GPU에 실행하는 대신 CPU의 실제 AVAILABLE까지 기다리는 `resource_wait`였다. 현재 전체 P95·기한 실패·J·AP가 세 문맥 모두 비악화인 이 후보가 개별 긴급 응답 증가 때문에 차단됐다. 구현과 보고서의 이름을 **P95 제약 실행·자원 대기 유연성**으로 바로잡았다.

순수 기능 검사에서는 현재·새 encoder의 상태 배열, 후보 배열, 물리 mask가 동일하고 예측 허용 mask만 바뀌는지 확인했다. 과거 고정 상태의 존재는 실제 native 개발 원장의 보존 snapshot으로 확인했다. 기능 검사와 조건부 예측 기회를 전체 요청 흐름의 성능 개선으로 승격하지 않는다.

산업공학과의 연결은 rolling horizon의 반복 재계획, 납기·완료 제약, 서로 다른 자원에서 실행 가능한 작업의 유연성, 보수적 작업 지연 허용이다. 이번 보완을 특정 기존 강건 최적화 알고리즘 전체의 재현 또는 전역 최적해로 부르지 않는다.
