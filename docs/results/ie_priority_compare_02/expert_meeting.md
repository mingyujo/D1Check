# 세 전문가 AI 토론과 응답 경계 보완

2026-10-10 사용자 요청으로 기존 모바일 `mobile_postmain`, 산업공학 `ie_postmain`, RL `rl_postmain` 세 에이전트를 다시 호출해 상호 질문·반론을 교환했다. AI의 역할 검토이며 실제 전문가의 인증이나 새로운 실측이 아니다.

|검토 관점|문제 제기|합의한 보완|
|---|---|---|
|모바일|응답2/3단계와 실제 lane 반환5단계가 다름. GPU가 빈 것만으로 CG_DC가 허용되지는 않음|CPU 소유 작업이 탐지이고 GPU가 실제 빈 경우만 허용. 다른 작업의 응답도 보호|
|산업공학|MST/ATC의 순위 변경이 실제 일정에 반영되지 않음. 후속 예측에서 모든 작업을 현재시각에 놓으면 암묵적인 backfill 발생|EDD head·동점·5phase ECT 유지, 다음 요청의 earliest를 앞선 선택의 start 이후로 진행|
|RL|좋은 선택이 없는 상태에서 학습부터 늘리면 의미가 약함. 희소한 경계 기회는 RL 일반의 가능성 판정이 아님|동일 후보의 강한 비학습 선택기부터 검증. 이번 새 학습0, 미래 학습은 별도 유한 예산·새 확인 필요|

첫 제안인 “탐지 head가 CPU를 기다릴 때 뒤 분류를 GPU로 backfill”은 원48조건에서 합법·도착·순위 조건을 동시에 만족하는 기회0으로 철회했다. 규칙이 발동하지 않는 배치를 숫자만 채우려고 실행하지 않았다.

두 번째 제안은 ECT가 전체 lane 종료를 최소화하면서 CPU를 기다리지만, GPU를 즉시 쓰는 편이 **응답은 빠른** 경우다. 개발의 해당 합법 상태604콜백 중 비악화 기회는1건이다. 개발 `822020102/burst/long_context`, C12의37.972985415초에서 GPU 예상 응답은0.562943ms 빠르고 lane 반환은1.175553ms 늦다. 기존 확인에서도1건을 발견했지만 이미 본 진단 자료이며 새 후보의 설정 선정·독립 확인에 사용하지 않았다.

## 구현한 단일 후보

정책 `IE_EDD_GPU_RESPONSE_NONWORSE_PC_V1`: 원 EDD head가 분류이고 최선5phase ECT가 점유된 CPU를 기다릴 때, CPU 소유 작업이 탐지·GPU 실제 빈 상태·GPU즉시 실행을 확인한다. GPU 예상 응답이 CPU 대기보다 늦지 않고, 현재 도착한 전체 큐의 strict EDD 후속 예측에서 **모든 요청의 응답이 늦지 않을 때만** GPU로 전환한다. 나머지 경우 원 EDD를 유지한다. 새 냉각 대기·기한·보상·계수·미래 입력은 추가하지 않는다.

이는 응답과 자원 반환 목적의 차이를 다루는 우리 제한적 보완이다. 전역 최적, 미래 도착의 서비스 보장, AP/J 개선 보장이 아니다. 예측 조건을 실제 기한·온도 보장으로 표현하지 않는다.

개발24·회귀4를 추가했다. GPU 보완 전환은 **1회**였고 일반 실패37건/긴급 실패0건/긴급 P95는 EDD와 같았다. 조건 평균 J는 약 **+0.000408J**, AP는 **+0.000679°C**로 소폭 악화했다. 원 서비스/J/AP 판정에서 미적격이며 새 채택은0이다. 매우 작은 모형 수치를 폰의 확실한 차이로 해석하지 않는다.

## 마지막 반론 반영과 기록

처음 실행한 후속 예측은 모든 `place`의 earliest를 현재시각으로 넣었다. 산업공학 검토자의 지적대로 앞선 예약 start 이후로 진행하도록 수정했다. 실행된 원소스 두 파일과 원등록을 `source_versions`·`response_registration.json`에 보존했다. 저장 판단을 최종 구현으로 재생해 실제 선택·허용 식이 같음을 검증하며, 최종 작은 native 회귀4를 남은 예산에서 수행한다. 개발 실행의 실제 허용 상태는 선택 분류1＋탐지5여서 이 수정에 따른 그 상태의 예측값은 같다.

또 원 결과의 `GPU_response_corrections`는 공통 dispatch reason을 세어1584로 잘못 기록됐다. 명시적인 `response_guard.allowed`와 실제 선택으로 세면1이다. 원압축결과/원소스는 보존하고 공개 CSV와 검증에는 수정된 수치를 사용한다. 이것은 선택·비용 변경이나 재학습이 아니다.

최초 재생 검사에서 저장 전이의 정수 ns와 콜백의 실수 ns 경계를 혼동했다. 엔진의 전이 반올림 규칙으로 복원하고 실패 기록/등록 버전은 로컬에 남겼다. 소비환경476 상태는 그대로이며 예산·시계를 새로 시작하지 않았다.

**결론:** 우선순위보다 응답/자원점유 경계와 합법 자원 배정을 구체화했지만, 이번 작은 보완도 서비스·열·에너지 우위는 확인되지 않았다. 기존 기준 유지가 타당하다. 다음 RL에는 실제로 반복 발생하는 유효 선택 기회와 비학습 대조를 넘을 근거가 먼저 필요하다. 기존64episode/8update로 RL의 실패·수렴을 단정하지 않는다.
