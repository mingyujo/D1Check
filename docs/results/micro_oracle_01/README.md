# 작은 요청열의 최적 일정과 개선 여지 확인

**24개 작은 조건의 선언된 유한 공간에서는 Band보다 서비스·J/AP가 함께 좋은 일정이 없었다.** 서비스/AP 조건의 최소 J와 J 조건의 최소 AP는 Band와 수치 표현 수준에서 같았고 원 엔진 재생24/24도 양쪽 기준 대비 비악화였다. 이 결과는4요청·100ms/3s 격자에 한정한다. 전체24/192요청, 연속시간, 온라인 정책이나 실제 휴대폰의 최적성을 뜻하지 않는다. 새 정책·학습·기기·NPU·기본 설정 변경 없이 PC 비교를 완료했다.

## 에너지 하한과 강건성

도착·기한·AP를 무시한 에너지 하한과 Band의 차이는0.0000000316…0.089195J였다. burst6조건은 ns 회계 반올림 보수폭 수준인약3.2e−8J이고, 나머지 조건의 낙관적 여유는약0.042…0.089J다. 후자는 서비스/AP조건 아래 달성되는 이득이 아니며 실제 선언 공간의 제약 최적값은 Band와 같았다. 이를 연속시간에서의 불가능 증명이나 모형 오차보다 큰 실제 절감으로 확대하지 않는다.

평균 문맥에서 고른8개 일정을 short/long에 고정 재생했다. 최소 J/AP의 두 목적이 같은 일정을 골라32역할 재생은16개 독립 문맥 조합을 두 번 다룬 것이며32개의 독립 반복이 아니다. 모든 요청과 기한은 지켰지만 Band 대비 기존 비악화 기준은20/32역할만 통과했고, 긴급 P95가 최대7.723371ms 늘었다. 짧아진 실제 처리시간에서도 고정된 평균 계획시각까지 기다려 재계획하는 Band보다 늦어질 수 있음을 보여준다.

비악화 실패12역할 중8역할의 AP차이는약3.4…3.6e−9°C에 불과하다. 원 수치 기준에서의 실패로 남기지만 의미 있는 물리 열 증가라고 주장하지 않는다. 다른4역할은 J약+0.000215J가 있었고 그중2역할에서 긴급 P95가 증가했다. 온도 예측오차가 서비스시간을 바꾸는 법칙은 미지원이다. 강건성은 기존 whole-phase 문맥 전이에 대한 한정된 재생이며 새로운 오차분포·열 스로틀 계수를 만들지 않았다.

## 이전 구현 이력과 이번 보완의 구분

프로젝트 전체에는 이미 [LLF와 두 MPC](../../../tools/d1_scheduler_alternatives.py), [ATC·CPU 병목 규칙](../../../tools/d1_industrial_scheduling.py)이 있었다. 이전 확인은 [대안 스케줄러 결과](../scheduler_alternatives_01/README.md)·[산업공학 비교](../industrial_scheduling_01/README.md)에 보존돼 있다. 최근 EDD/RL 비교 경로가 여유시간으로 직접 정렬하거나 명시적 CPU 보호를 하지 않는다는 점과, 저장소에 그런 시도가 전혀 없다는 주장은 다르다. 후자의 표현은 정정한다.

과거 LLF는 처리시간을 뺀 여유와 aging을 사용하고 자원은 예상 응답으로 선택했다. 이번 진단은 예상 자원 대기까지 포함한 응답 여유를 정렬하고 자원 ECT/lane 경계를 유지한다. 과거 CPU 병목 규칙은 mandatory CPU 지각·해소시점 등을 비교했고, 이번 규칙은 현재 CPU 전용 작업의 기한이 깨지는 특정 조건을 보호한다. 둘은 별도 ID이며 과거 결과를 새 성능이나 최초 구현으로 포장하지 않는다. 과거 작은 offline beam 일정도 있었지만 최적성/하한 증명을 하지 않았으므로 이번 유한 전수 인증과 구분한다.

## 질문과 정확한 비교 범위

기존에 소비한 학습 trace의 seed812000001·002와 low/queue/burst/sustained에서 **각 과업의 처음 두 요청**을 선택한다. 요청의 ID·순번·도착·입력 의미·긴급1.5초/일반6초 기한은 보존한다. 이4요청의 세 처리문맥을 평가해24조건을 만든다. 원래24/192요청 전체 성능이나 새 독립 holdout 평가로 표시하지 않는다.

오프라인 비교자는 요청별 CPU/GPU 선택과 시작 시각의 모든 조합을 확인한다. 시작 시각은 각 요청의 실제 도착+k×100ms(k0…30)에 그 요청의 **원 Band 실제 시작 시각**을 더한 유한 집합이다. Band 일정을 비교 공간에 포함하고, 결과를 본 뒤 격자·조건을 바꾸지 않는다. 과업별 실행 지원과 실제 lane 전체5단계 점유·호환성을 지킨다.

**정확성은 이 유한 시작시각 집합과 동결 모형 안에서의 전수 확인을 뜻한다.** 연속시간 전역 최적, 실제 휴대폰 최적, 온라인 정보만 쓰는 최적 정책이 아니다. 오프라인 비교자는 미래 도착과 해당 문맥의 실현 벡터를 알고 있다. 현재 RL의0.25초 냉각 credit를3초로 바꾸는 작업도 아니다. 확대된 대기 공간의 참고 성능이며 실제 엔진 재생으로 실행 경계를 다시 확인한다.

## 제약과 목적

- 모든 예정 요청 완료·동일 출력 품질, 실제 지원 조합만 허용한다. 한 lane의 중복 점유와 미지원 분류CPU+분류GPU 병행을 금지한다.
- 긴급/일반 기한 실패와 긴급 P95는 같은 조건의 Band·Triton 양쪽보다 악화되지 않아야 한다. 완료 응답 경계는 긴급 OUTPUT_READY·일반 PERSISTED, 자원 재사용은 전체5단계다.
- 모형 AP 최고값이 양쪽 기준보다 높지 않은 일정에서 J가 최소인 일정을 찾는다. J가 높지 않은 일정의 최소 AP도 별도로 찾는다. J와 AP가 둘 다 엄격히 낮은 일정의 존재 여부를 따로 인증한다.
- 일반 평균 완료시간도 높지 않아야 한다는 **추가 진단 조건**을 별도로 계산한다. 기존 채택 기준을 뒤늦게 바꾸지 않고, 단순 지연으로 얻은 이득을 드러낸다.
- J는 공통0…120초 전체 기기 모형값, AP는35…180초1초 격자다. 최고 표면온도·절대 안전 온도 한도·모바일 판단 J는 미지원이다.

전수 일정의 에너지와 AP는 원 선형 AP식의 닫힌형 펄스 해로 계산한다. 초기 관측·참조·메모리 상태를 그대로 사용하고, 각 실행구간과 CG_DC 중첩의 측정 계수 보정만 더한다. 원 `model.costs`와의 경로/J 일치 검증을 통과했다. 후보 수·용량/서비스/비용 통과 수·가지 제거 수를 보존하고 `방문+안전 제거=전체 공간`을 확인한다. 최소 일정은 원 엔진으로 재생해 실제 KPI를 다시 판단한다. 수치 표현의1ns 차이를 SLA 허용손실로 바꾸지 않는다.

별도로 도착·기한·AP 제약을 완화한 에너지 하한을 계산한다. 단독 점유량과 가능한 최대 CG_DC 겹침량으로 얻는 낙관적 하한이며, Band와의 차이가 작다면 이 모형의 에너지 개선 여지가 제한적이라는 근거다. 하한을 항상 달성 가능한 일정이라고 부르지 않는다. ns 반올림의 회계 오차도 보수적으로 포함한다.

새 진단 정책 두 개를 같은 미니 요청열에서만 비교한다. 기존 EDD/기존 RL은 변경하지 않는다.
