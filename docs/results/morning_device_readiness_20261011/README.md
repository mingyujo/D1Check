# 오전 A24 추가 비교 준비와 보류

새 대표 흐름에서 Band·공동 리스트·비용 리스트의 96개 요청 배정과 실행 시각이 모두 같아, 같은 계획을 다시 기기에서 실행할 정보 이득이 없다. 추가 실측은 시작하지 않았다. 원래 사전 고정한 대표 흐름을 유리한 다른 흐름으로 바꾸지 않았다.

이 기록은 2026-10-11 오전의 읽기 전용 준비 상태이다. 기존 야간 ABBA 네 세션은 완료된 별도 작업으로 보존한다. 새 RL 후보가 다른 동결 계획을 만든 경우에도 아래 게이트를 다시 확인하고 별도 실행 계약을 등록해야 한다.

| 확인 항목 | 실제 결과 |
|---|---|
| A24 연결·identity | SM-A245N, 기존 기기 fingerprint 일치 |
| 관측 시점 | 09:27:45~09:27:48 KST의 별도 읽기 전용 조회 |
| 배터리·충전 | 66%, AC·USB·무선 충전 없음 |
| AP / BAT / HAL SKIN | 25.5 / 26.5 / 27.6°C |
| thermal status | 0 |
| 앱 owner | 조회 당시 modelprobe 프로세스 없음 |
| 추가 설치·추론·물리 세션·claim | 각각 0 |
| 추가 ADB | 8회: 최초 수동 연결 조회 1 + 장부 기록 7 |

ADB 8회는 이 오전 준비 작업의 명령 수이다. 기존 야간의 수집기 1,748회 또는 모바일 담당 전체 1,766회와 합쳐 같은 장부로 표시하지 않는다. 기기 전체나 모든 담당자의 총 명령 수를 뜻하지 않는다. 원시 배터리·시리얼·host 경로는 비공유 `output/morning_mobile_20261011_v1`에 보존했다. 공유 파일에는 요약과 SHA만 넣었다.

## 초기 온도 근거

실제 동결 모형 입력에서 개발 17세션의 부하 시작 전 AP 표본 최소·최대는 **25.9~34.7°C**, 각 세션의 마지막 시작 전 anchor는 **25.9~32.5°C**였다. 이는 관측 자료의 범위이며 그 사이 모든 초기 상태에서 정확도가 검증됐다는 뜻이 아니다. 모형은 `strict_support=false`, `accuracy_pass=null`, `experiment_ready=false`이고 냉각에 따른 처리속도 회복을 반영하지 않는다.

현재 읽기 전용 AP 25.5°C는 개발 관측 최저보다 0.4°C 낮다. 기존 독립 hybrid 확인의 공통 시작 AP 30.2/30.4°C 및 야간 ABBA 29.3/29.3/29.5/29.6°C와도 다른 상태이다. 이 값만으로 지원 범위 내 정책효과 비교를 선언할 수 없다. 실제 실행을 준비하더라도 자연스러운 런타임 준비 뒤의 공통 시작 관측과 인과적인 AP 이력으로 판정해야 하며, 목표 온도로 가열하거나 게이트를 낮추지 않는다. 범위 밖 자료는 별도 외삽 진단으로만 표시하거나 비교를 보류한다. AP 일치도 내부 열 상태·이전 부하·백그라운드 작업의 일치를 보장하지 않는다.

## 재개 가능한 조건

추가 기기 비교는 다음을 모두 만족할 때만 별도 작업으로 수행한다.

1. 결과 전 고정된 같은 입력·도착·기한·seed에서 의미 있는 서로 다른 동결 계획이 존재한다. 지금의 Band·JointList·CostList 대표는 이 조건을 만족하지 않는다.
2. 기존 opt-in APK의 96건 ABI를 그대로 사용한다: 공통 원점 +35초부터 350ms 교대 도착, 긴급 분류 48건·일반 탐지 48건, 기한 1.5/6초. 분류 CPU/GPU·탐지 CPU, 최대 두 건의 검증된 CG_DC 병행만 허용한다. 지원하지 않는 trace로 바꾸거나 CPU 분류와 GPU 분류를 동시에 실행하지 않는다.
3. 기존 APK·서명·payload·정책·모형의 SHA, owner 부재, 배터리·충전·열·관측 이력과 저장 공간을 새 claim 직전에 확인한다. APK 설치는 추가 0회이다. 기존 네 세션 계획은 재소비하지 않는다.
4. 부모 담당자의 무손실 NTFS 압축 후 보고 공간은 4,320,350,208바이트였다. 4GiB 게이트보다 약 25MB만 많아, 그 보고를 다음 claim의 현재 공간으로 전용하지 않는다. 시작 직전의 게이트와 마지막 저장 시간을 확보해야 한다.
5. 새 승인 범위는 최대 두 물리 세션·208추론·20분·마지막 3분 저장이며 아직 소비하지 않았다. 실행기·새 계획·owner·시계는 시작하지 않았다. 남은 회의 시간에 완결할 수 없으면 새 실행을 시작하지 않는다.

## 이번 실측으로 답할 수 없는 것

기존 APK는 동결된 PC dispatch 계획을 실행한다. Band·리스트·RL의 온라인 판단, 후보 생성, 예측 계산, actor forward를 기기에서 수행하지 않으므로 그 지연·제어 에너지는 측정하지 못한다. 고정 재생기의 짧은 sort 시간으로 이를 대신하지 않는다. 설치 없는 이번 준비에서 온라인 제어 비용이나 표면 온도 센서를 추가하지 않았다.

기존 야간 자료는 384건의 실제 추론·품질·응답·AVAILABLE·용량 보존을 확인했다. 반면 Rule−Band 에너지는 순서 반전 두 쌍에서 +3.7556/−4.7567J로 부호가 달랐다. 같은 Rule 두 세션의 J 차이도 약 7.2646J였다. 모형의 공통 120초 J 절대오차 평균 5.2189J는 대응 정책 차이의 통계적 허용 오차가 아니다. 오류가 서로 상쇄될 수 있지만 현재 자료가 그 상쇄나 미세 절감의 판별력을 입증하지 않는다.

J는 원시 전류의 mA 해석을 전제로 한 기기 전체 120초 적분이며 자원별 rail 측정은 아니다. AP는 센서 채널이고 HAL SKIN도 이름 그대로의 채널이므로 최고 표면 온도로 승격하지 않는다. 실제 AP 표본은 목표 35~180초의 양 끝을 완전히 확보하지 못했으며, 누락 경계는 채우지 않는다. 이러한 한계는 새 설치나 비교 조건 변경으로 조용히 해소된 것으로 처리하지 않는다.

다음 실측의 우선순위는 동일 계획의 반복보다 전류 단위·전체 J의 독립 확인, 배경 전력·충전·부하 전 이력의 기록, 실제 온라인 후보/예측/actor 비용의 계측이다. 새 알고리즘의 실기기 절감을 먼저 보장하지 않는다.
