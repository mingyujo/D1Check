**현재 후보를 채택하거나 RL 본학습으로 넘기지 않는다.** pilot의 완료·기한·AP/J 집계는 현재 저장 자료와 일치한다. 그러나 수치 보완의 이동 범위, 같은 내부 기준정책과의 비교, 실제 선택 가능한 행동의 다양성을 보완해야 다음 단계를 판단할 수 있다. 이번 검토의 환경/학습/기기 추가는0이며 누적71을 유지한다.

## 중요도순 발견 사항

### 1. 수치 보완의 이동량이 수치 오차 범위를 벗어날 수 있다 — 수정 필요

`tools/d1_reserved_thermal_pilot_repair.py`의 `StrictPlacement.place`는 **겹친 길이**가1ns 이하인지만 확인한 뒤 시작을 충돌 작업의 끝으로 이동한다. 이동량 자체는 제한하지 않는다. 엔진을 호출하지 않은 직접 함수 반례:

- 새 작업: 시작35.0, 종료35.621736894854166초.
- 이미 계획된 CPU 작업: 시작35.62173689452082, 종료36.621736894854166초.
- 겹침0.333344019ns지만 보완 후 새 작업 시작은36.621736894854166초로, **1.621736894854166초** 이동한다.

입력은 forecaster가 받는 미래 예약 구간이다. 이것이 실제48조건에서 발생했다고 단정하지 않는다. 현재 원본에는 보정 전후 이동량이 없어 그 발생 여부를 확정할 수 없다. 원래 실패를 재현한 앞쪽 경계의 미세 겹침은 수정됐지만, 수정 전체를 동등한 수치 처리라고 인증하기에는 검증이 부족하다. 원48행은 보존하며 서로 다른 실행 소스4+44행이라는 표시도 유지한다.

### 2. 신규 규칙의 내부 EFT와 비교군 SHARED_EFT가 다르다 — 대조 보완 필요

신규 규칙의 기준/실패 복귀는 `d1_empirical_request_policy.Controller.__call__`의 `EFT_REFERENCE` 동작이다. 바쁜 CPU가 곧 비면 GPU 즉시 실행보다 CPU 대기를 고를 수 있다. 비교군 `SHARED_EFT`와 동일하지 않다. 대표 seed610810001/queue/mean의 분류 요청3은 SHARED_EFT에서35.613263315초 GPU 실행, 신규에서는CPU 대기 후35.621736895초 실행이다. 이때 신규는 열 최적화 선택이 아니라 예약 탈락 후 내부EFT로 복귀했다.

**같은 입력의 EFT_REFERENCE48행은 기존 완료 자료에 이미 있다.** `external_rules_01/results.csv`와 그 SHA를 고정한 Triton 계약을 확인해 읽었다. 새 실행 없이 수행한 사후 진단이며 원480행 비교를 바꾸지 않았다.

| 비교 | 확인 결과 |
|---|---|
| 내부EFT 전량·일반 기한 실패 |3,168완료·53실패로 신규와 동일|
| 신규−내부EFT의 긴급P95/기한 준수 건수 |48조건 모두 동일|

| 주평가24조건의 신규−내부EFT 평균 |AP−0.002364481°C, J+0.003087053|
| 주평가24조건의 내부EFT 대비 공동 감소 |2조건; 독립 기기 개선 근거 아님|

따라서 강한Triton 대비 주24공동개선24를 새 예약 설계의 효과로 귀속할 수 없다. 기존 내부EFT와의 차이는 훨씬 작다. 강한 외부 기준 대비 추가 일반 기한 실패17건도 현재 자료에서는 신규·내부EFT 모두에 나타난다. 예약 기능만이 실패를 만들었다고 해석하지 않는다.

### 3. 적격 계획 수와 실제 행동 다양성이 다르다 — 현재 RL 근거 부족

전체 원본12,623 scoring callback을 확인했다. 적격 후보가 있는5,930번에서 **첫 요청ID·backend 조합이 둘 이상인 callback은0**이다. 첫 제안의 대기값까지 포함하면4,266번에 둘 이상이지만, 같은 바쁜 lane을 기다리는 계획들이 실제로 같은 다음 행동일 수 있다. 모든 후보의 실제 첫 시작/반환 행동을 저장하지 않아 유효한 WAIT 선택지 수는 아직 확정할 수 없다.

같은 snapshot의 기준계획이 적격인5,928번 중 AP 감소·J 비증가 후보가 있는 경우162, J 감소·AP 비증가 후보가 있는 경우0이다. 탐색 상한64에 도달한 callback도0이었다. 현 결과의 병목을 단순히 탐색 예산 부족이나 학습 횟수 부족으로 해석하지 않는다. 지연 선택이 후속 상태를 바꾸는 RL 가능성까지 부정하는 것은 아니지만, 현재 자료만으로6,144에피소드 본학습을 정당화하지 않는다.

### 4. 외부 목표는 여전히 미충족 — 판정 유지

주평가24조건에서 강한Triton 대비 평균AP−0.119788°C/J−0.770236이지만, Band 대비AP−0.048470°C/J+0.154012, SHARED_EFT 대비AP−0.059351°C/J+0.088176이다. 전체 일반 실패53 vs강한기준36도 유지한다. Band/EFT 대비 단1개의 열 감소·J동일 사례는AP 약0.000062776°C 차이다. 작은 모형 차이를 실기기 우월성으로 확대하지 않는다.

대표 queue의 J 증가를 점유상태별로 분해하면 신규−SHARED_EFT는 분류CPU +0.289672J, 탐지CPU +0.651962J, 허용병행 −0.811894J, 합계약+0.129741J다. GPU 배정 감소 자체가 에너지 감소를 뜻하지 않는다. 이 분해는 동일 모형의 회계이며 인과적 절감 실측이 아니다.

## 다음 Sol 작업: 수치 범위 수정·대조 검증만

새 보상/학습/seed/물리계수 탐색을 추가하지 않는다. 원 pilot·검토·등록·기본 정책 파일은 보존한다. 이번 보완은 `stage3_numeric_audit_v1`라는 별도 실행 등록으로 같은 캠페인 장부에 연결한다. 아직 존재하지 않는 실행 명령을 준비 완료라고 표시하지 않는다.

1. **수치 보완 이동량을 제한한다.** 최초 미보정 proposal 시작과 최종 시작의 누적 차이가1ns 이내일 때만 보정한다. 그보다 크게 옮겨야 하거나 지원되지 않는 점유가 남으면 해당 retained 후보를 부적격으로 기록한다. 다른 후보/원 복귀 경로로 계속하며 에피소드를 미완료로 조용히 버리지 않는다. 초기 cap·signed J·WAIT·원 기한·판정 EPS·계수는 유지한다. 실제 lane을 예측으로 해제하지 않는다.
2. 앞쪽 끝 경계, 미래 예약 시작 경계의 이번1.62초 반례, 여러 충돌에 따른 누적 이동, 기존0.25초 의도적 간격, 지원 병행/같은 lane, 후보 탈락 후 fallback 보존을 직접 검증한다. 순수 계획 함수 검증과 실제 엔진 실행을 구분해 차감한다.
3. 실행 전 원본/보완 코드·테스트·같은48입력·검토·runtime binding을 별도로 고정한다. 새 비교용 variant는 `RESERVED_THERMAL_REQUEST_V1_NUMERIC_R2`로 식별한다. 원18소스와 첫 수치adapter를 고쳐 기존 허가/receipt를 무효화하지 않는다. 등록/검증을 우회하는 monkeypatch 실행으로 진행하지 않는다.
4. 후보별 보정 전후 시작·이동량·거절 원인과 실제 제안 행동을 저장한다. 첫 작업이 지금 실행 가능한지, 아니라면 실제 반환할 WAIT 시각이 무엇인지를 이용해 행동을 중복 제거한다. 요청/배정만 같은 후보와 실제 행동도 같은 후보를 구분한다. 진단 필드 추가가 선택을 바꾸지 않는지 확인한다.
5. **동일48조건을 수정본 한 버전으로 평가한다.** 최초48행을 덮어쓰지 않는다. 기존10정책480행 + 이미 완료된 내부EFT48행 + 수정본48행 =576논리행으로 비교하고, 내부EFT는 정확한 출처·입력·설정·소스가 일치할 때만 재사용한다. 기존48조건에 맞춘 개발/회귀 보완이며 새 holdout이 아니다. 최종192조건 시험은 아직 시작하지 않는다.
6. 서비스·비용·실패·계산 비용과 원/수정본 차이를 모두 보고한다. Band·SHARED_EFT·강한Triton·내부EFT를 각각 비교한다. 학습 없는 내부EFT 대비 차이와 외부 기준 대비 차이를 분리한다. 수치 반례의 영향 및 실제 행동 선택지가 확인되면 Astra 단계3 재검토로 인계한다.

**다음 Sol 범위는 최대64실제 환경 시작**이다. 수정본48조건과 나머지 최대16fixture/실패/복구를 모두 포함한다. 기존 단계2 잔여441·전체 잔여19,929에서 차감하며 별도 새 예산으로 초기화하지 않는다. 최대 소비 시 누적135, 단계2 잔여377/전체19,865이다. 학습/기기0, 추가 정책 탐색0이다. 벽시계 상한60분·마지막5분 저장 예약을 실행 시작 전에 등록한다. 상한 내 완료 불가 시 부분 상태와 원인을 저장하고 자동으로 예산을 늘리지 않는다. 학습 세부 계약은 계속 미동결이다.

이 보완의 기계적 수정/검증/지정 배치 범위는 이번 판정으로 구체화했다. 동일 승인을 반복해서 묻지 않는다. 새 설계식이나 서비스 판정 변경이 필요하면 임의로 수정하지 말고 구체 차이와 근거를 남긴다.
