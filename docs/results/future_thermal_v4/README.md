# 관측 이력으로 만든 미래 열부하 비교와 예측 경량화

기존 후보는 이미 도착한 요청만 예측해 다음 작업의 열과 겹치는 경우를 놓쳤고, PC 판단 비용도 컸다. 이번에는 **기존 판단의 수학적 경량화**와 **관측 이력에 따른 다음 요청 가정**을 분리해 비교한다. 실제 미래 요청을 읽거나 실측 모형을 교체하지 않는다.

## 완료 결과와 판단

**계산 경량화는 검증됐고, 미래 가정 정책의 열 개선은 확인되지 않았다.** PC 예측 엔진의 경량화는 사용 가능한 보완으로 보존하되 앱 기본·Band 연구 기준을 교체하지 않는다. 미래 가정의 개발 합격과 새 확인 미합격을 그대로 기록한다.

P95·최고 AP는 조건별 값의 평균이다. 기한 실패21건은 과부하에 남아 있으며 전량 완료를 전기한 성공으로 표현하지 않는다. EDD/Triton까지 포함한7역할의 모든 결과는 [전체 CSV](final_results.csv)에 보존한다.

기존 작업량 정책과 경량화는 사전 보존8조건＋새 확인24조건에서 **전체 요청 원장32/32 동일**했다. 새 확인에서 판단시간 합계는256.407→62.440초, **동일 판단의 PC 비용4.11배 감소**다. 별도 같은 프로세스/같은4요청 입력을20회 번갈아 계산한 순수 예측 비교는 중앙값4.751→3.249ms(1.46배), 수치 차이 최대3.56e−15였다. 입력 크기·PC 부하·복사하는 이력 길이에 따라 속도 차이가 달라진다. 이전 날짜의 보존8조건 host 시간만으로 속도를 주장하지 않는다.

미래 후보의 더 작은4초대 판단시간에는 실제 선택을Band/대기2개로 제한하고 대기 허용이 없으면 예측을 생략하는 효과가 함께 들어간다. 이를 같은 전체 후보의 경량화4.11배와 합산하거나 알고리즘 자체의 우위로 해석하지 않는다. 같은 후보/예산의 RL 알고리즘 비교도 아니다.

최악 가정은 개발24에서 기준 비악화를 유지했으나 열 이득seed0으로 미선택했다. 새 확인에서도 추가 대기0·Band 원장24/24 동일했다. 선언한 가정 안에서 보수적으로 대기를 막은 결과이며 전역 최적·일반 강건성의 증명은 아니다.

관측 빈도는 개발24/24양기준 비악화와 두 개발seed 열감소로 **확인 전 선택**됐다. 하지만 새 확인에서는 열감소0/24, 낮은 부하 두seed 모두 AP가 약0.0030~0.0038°C 증가했다. 일반 평균은 낮은 부하에서 각각83.333/69.444ms 지연했고 J·긴급 P95는 같았다. 실제 추가 대기는33회, Band와 원장동일18/24였다. 확률처럼 사용한 최근 과업 빈도와 구간 양끝 가정이 이 확인에서 열 감축을 충분히 예측하지 못했다. 확인 뒤 가중치/도착 가정/합격 여유를 튜닝하지 않았다.

## 근거와 적용 한계

- 다음 도착은 실제 trace가 아니라 관측 이력의 가정이다. 가상 분류/탐지는 예측기 내부에만 존재하며 실제 fixture6요청/예정 도착/전체 완료량에 섞이지 않았다. 알려진 긴급 P95와 가상 긴급별 응답을 분리했다. [fixture 검증](fixture_verification.json)·[원장 보존](preservation.json)·[판단/가정 규모](decision_diagnostics.csv).
- 원 선형 AP식의 현재 추정 AP/h·과거 최고·미래 grid와5단계 점유/J를 유지했고 미래계수/지원/SLA를 새로 만들지 않았다. 수작업8새검증＋기존 열분산/작업량 관련14검증, 원엔진225감사·선정 독립 재계산·화면158행/5그림을 확인했다. [검증 버전](verification.json).
- AP는 실측 기반 모형 채널이며 최고 표면온도가 아니다. 작은0.003°C 차이를 기기 열 효과나 모형 오차보다 확실한 개선으로 주장하지 않는다. 두 도착seed×3비용문맥은6독립 반복이 아니고 실측 모형의 새 독립 확인도 아니다. 열 오차→처리속도/주파수 회복 결합·실제 제어J·안전 한도/초과시간은 미지원/null이다.
- 경량화 최대callback도 이번 PC에서163.591ms로 실제 폰 비용 검증을 대체하지 않는다. 원 시뮬레이터의 제어 오버헤드0 가정을 변경하지 않았으므로 같은 긴급 P95는 실제 폰에서 동일하다는 뜻이 아니다. 제어 계산의 실제 에너지를 이번 J에 임의로 더하지 않는다.
- 확인 정책의 에너지/열 공동감소0이다. 기존 Maskable PPO·Double DQN·체크포인트는 보존했고 새 학습0이다. 예측 속도 개선만으로 RL 보상/수렴/성능 개선을 주장하지 않는다.

## 결과 전 고정 계약

작업 ID `IE-FUTURE-THERMAL-04`. 원 모델/초기 preload/계수/품질·지원·완료/5단계 lane 해제·전체 요청을 보존한다. 현재 다른 AP 구조 후보는 Arrival 전이가 실패했으므로 사용하지 않는다. 기존 결과·체크포인트·기본/strict/experiment_ready=false를 유지한다.

경량화는 예측 속에 복사하던 Band 열 이력을 제거하고 자원/서비스 추정 EMA만 같은 식으로 갱신한다. 원 선형 AP식을 벡터화한 구간 pulse 합으로 같은1초 grid를 계산한다. 현재 추정 AP/h와 과거 최고값은 유지하며 J는 같은 점유 구간/120초로 계산한다. 기존 작업량 허용 정책과 전체 후보는 그대로 유지한 경량화 정책으로 행동 동일성과 속도를 검증한다.

미래 가정은 현재까지 관측한 최근8개 도착 간격의 최소/최대에서 다음 시각을 만들고, 다음 과업이 분류 또는 탐지인 경우를 각각 비교한다. 최소3관측·동시도착/이미 지난 예측시각은 대기 후보를 제거한다. 최대5가정(무도착＋두시각×두과업)×원3실행시간 문맥이다. 이것은 실제 다음 도착의 범위나 확률 보장이 아니다.

- **최악 가정 후보**: 모든 동일 가정의 알려진 긴급/일반 기한·P95·J·최고 AP가 기준보다 악화하지 않는 대기만 남기고 최악 미래 AP 차이가 감소해야 한다.
- **관측 빈도 후보**: 같은 서비스/J 검사를 모든 가정에서 유지하지만 열 점수는 최근8개 과업 빈도에 과업당1개 가상 count를 더한 비중, 구간 양끝에는 같은 비중을 준다. 이 비중은 경험적 설계이며 교정된 확률이 아니다. 실제 도착큐/무도착 AP 비악화도 요구한다. 일부 가정의 AP 상충을 허용하므로 실제 미래 열 비악화를 보장하지 않는다.
- 예측 속 가상 요청에는 기존 분류1.5초/탐지6초 계약만 적용한다. 실제 큐·엔진 예정 요청·완료량에는 추가하지 않는다. 알려진 긴급 P95는 실제 과거＋현재 요청만으로 계산하고 가상 긴급 응답은 따로 각각 비교한다. 새 가상 요청으로 분모를 늘려 서비스 성적을 좋게 만들지 않는다.
- 두 미래 후보의 실제 행동은 원 Band 즉시 배정 또는 작업량/기한 허용 장치를 통과한 일반 요청의 누적0.25초 대기다. 이후 도착/phase 이벤트에서 재판단한다. 자원 후보 폭을 줄인 효과와 계산 경량화 효과를 합쳐 동일 알고리즘 속도 개선이라고 부르지 않는다.

## 실행과 선정

- 먼저 기존813030101/102의4부하/평균8조건을 경량화 정책으로 재실행해 원 전체 원장이 같음을 확인한다. 별도6요청 fixture에서는 실제 미래를 보지 않고 가상 예측을 만들었는지, 실제 원장에 가상 ID가 없음을 검증한다.
- 개발은 이미 소비한813010101/102×4부하×3문맥24조건이다. 기준4정책96행은 hash 확인 후 환경0으로 재사용하고 미래 후보2개만48환경 실행한다. 별도 새 확인814020101/102×4부하×3문맥24조건×7정책168환경을 실행한다.
- 개발24조건에서 Band/Triton 양쪽 대비 전체 완료·기한 실패·긴급 P95·J/AP 비악화와 두 개발 seed 각각 low/sustained 열 감소가 있어야 선택한다. 최악 AP 차이→평균 J→동률 최악 가정 우선으로 확인 전에 고정한다. 확인 후 재선정·가중치/온도 문턱/SLA 튜닝0이다.
- 원24/192요청 전체·도착·입력·품질·원3문맥 실현 비용·초기 상태·자원·120초 기기 J·AP35…180초1초grid를 동일하게 비교한다. 일반 평균·미완료/실패·실제 점유/병행·PC 판단시간을 보고한다. 상대 서비스 비악화와 절대 전기한 충족을 분리한다.
- 신규 환경 상한256/정상 예상225=보존8＋fixture1＋개발48＋확인168. 학습0·기기/ADB/NPU0, 기존5,804환경/641학습을 계승한다. 등록 후1시간·마지막5분 저장, 실패도 차감하며 원 clock/등록/소비를 초기화하지 않는다.

## 재현

python -B -X utf8 -m unittest tools.test_d1_fast_future_thermal

진행 중 실행 경로와 이전 등록은 보존하며 별도 결과 폴더에 기록한다. 모델·키·APK·대용량 원 실행은 공유하지 않는다.
