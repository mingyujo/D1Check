# 관측한 작업량으로 대기를 제한하는 열 분산

이번에 발전시킨 방법은 **EDD·응답 여유시간으로 후보를 구성하고, 관측한 혼잡이 낮을 때만 일반 요청을 짧게 기다리는 방식**이다. 새 확인24조건에서 Band 대비 완료량·기한 실패·긴급 P95·J를 유지했지만, 열 효과가 seed별로 달라 **최종 채택은 보류**했다. 산업공학 요소는 실제 판단에 들어갔으며 후보의 실패와 남은 개선 지점도 결과로 남긴다.

## 모형과 제어 비용의 한계

AP는 표면온도가 아닌 같은 실측 기반 모형 채널이다. 원계수와 이미 적합된 미채택 개발변형4개의 **고정 일정** 민감도를 전 조건/3정책/5모형=360비용·240차이로 추가 판독했다. 새 적합/환경/스케줄러 재실행0, 확인 재튜닝·기한/열 허용폭 변경0이다. 원 모형 재계산은 원 결과와 최대5.69e−14차이로 일치했다.

낮은 부하 첫 seed의 AP 차이는 변형에 따라-0.019325…+0.002533°C로 부호가 바뀐다. 둘째 seed는-0.017210…-0.003443°C로5모형 모두 감소 방향이지만, 이것을 실제 기기 절감·확률 구간·독립 확인으로 해석하지 않는다. [고정 계약](sensitivity_contract.json)·[전체 비용](coefficient_sensitivity.csv)·[모형별 차이](coefficient_sensitivity_pairs.csv). 이미 미채택한 변형을 기본 모형에 적용하지 않았다.

다른 확인 프로토콜의 AP MAE0.260°C에 비해 이번0.0025~0.0051°C 차이는 작다. 그 MAE를 이번 조건의 보편 오차한도나 합격 여유로 전용하지 않는다. 현재 모형에 열 오차→처리시간/주파수 회복 결합은 없으며 숫자 AP의 앱 자율 관측·실제 표면온도 검증도 미완료다.

PC 판단시간 합계는 새 후보88.872s vs Band0.169s(확인24조건), 새 후보의 최대callback161.896ms였다. 이 처리시간·폰에서의 에너지는 시뮬레이터 비용에 포함되지 않는다. 제어비용까지 포함한 실배포 효과·SLA는 미판정이며 실제 제어J/온도 안전 한도/초과시간은 null을 유지한다. 작은 AP 감소를 이 오버헤드보다 확실한 실제 이득으로 주장하지 않는다.

## 발전한 부분과 다음 작업

- 산업공학 요소는 EDD 후보4, 응답 여유가 작은 CPU 전용 요청, 호환성·작업량/가용창 검사, 현재 도착 요청의 절대 기한 가능, 첫 행동 후 재계획이다. 단순히 정책 이름에 산업공학을 붙인 비교가 아니다. 이번 확인에서 순서/자원보다 대기 허용 여부가 실제 차이를 만들었다.
- 발전한 것은 **고부하에서 대기하지 않고 강한 기준을 유지하는 구조**다. 다만 개발 합격→새 확인 미합격이며, 동일 모형에서 두 기준을 전 조건 이겼다고 주장하지 않는다. Band 연구 기준/앱 기본/strict/experiment_ready=false를 유지한다.
- 후속 우선순위는 새 대규모 RL보다 **관측 도착 이력으로 만드는 작은 미래 도착 가정과 열 이력 예측**이다. 실제 미래를 넣지 않고 클래스/도착 변동 가정을 미리 고정한 뒤 새 자료에서 검증해야 한다. 빠른 분석식·캐시로 판단 비용도 줄이고, 그 비용이 검증되기 전 기기 효과를 판정하지 않는다. 이번에 추가 후보/환경/실측을 자동 연쇄하지 않았다.
- RL은 현재 native Maskable PPO/Double DQN·체크포인트를 보존했다. 새 학습0회다. 후속 RL에는 관측 도착 간격·현재 CPU 작업량/기한 여유·Band EMA·잔열 추정·남은 credit이 필요하며, 바뀐 상태/행동/열 우선 목적은 별도 schema로 고정해야 한다. 미래 도착/실현 비용을 입력하거나 기존 actor의 이름만 바꿔 성능을 비교하지 않는다.
- 실제 후속 환경168/실패0·성공11,088요청 전량, 확인9,504/9,504. 개발 기준120행은 기존 완료 결과를 재사용해 환경0이다. 등록부터8분57.6초·순수6추가 검증, 두 라운드506환경/33,270전량(합성fixture6포함)·누적5,804환경/641학습, 새 RL/기기/ADB/NPU0이다.
- [전체 입력](inputs.json)·[선택 동결](selection.json)·[확인 CSV](final_results.csv)·[허용 장치 제거 비교](wait_ablation.csv)·[대기/판단 기록](decision_diagnostics.csv)·[오프라인 화면](index.html)·[검증](verification.json)·그림5개를 보존한다. 선행 보고서/그림5개까지 총10개이며 원 자료와 사용자 변경을 유지했다.

## 수정 근거와 결과 전 계약

작업 ID `IE-THERMAL-LOAD-GATE-01`. [선행 V3 개발](../thermal_slack_v3/README.md)에서0.25초 대기는 낮은 부하6조건의 J·긴급 P95 유지/AP 감소를 보였으나, 큐·몰림에서 일반 기한 실패가 늘고 지속 부하에서는 J 감소/AP 증가로 상충했다. 1초 대기는 개발 적격0이다. 기존 V3 실행의 소스·설정·원 결과는 바꾸지 않고 완료시킨다. 다음 수정은 **개발 결과만**으로 정한1개이며, 확인 자료는 V3의 확인 seed까지 재사용하지 않고 새로 고정한다.

추가하는 것은 대기 허용 장치 하나다. 기존 Band fallback, EDD상위4+CPU 전용 최소 응답여유 후보,0.25초 누적 credit,3문맥 원계수/물리 점유/첫 행동 후 재계획은 그대로다.

1. 현재까지 도착을 관측한 요청이3건 이상 있어야 한다. 최근8개 도착 간격의 최소값에서 마지막 도착 후 경과시간을 빼서 다음 도착까지의 보수적인 **예상 여유창**을 만든다. 실제 다음 도착을 아는 값이 아니다. 같은 시각 도착은 간격0으로 처리한다.
2. 대기 중 CPU 전용 요청의 **3문맥 중 가장 긴5단계 점유시간 합**과 남은 냉각 credit이 그 창 안에 들어갈 때만 일반 요청의 추가 대기를 후보로 남긴다. backlog가 많거나 도착이 잦으면 원 Band로 처리한다. workload family/실제 미래 도착은 판단 입력에 넣지 않는다.
3. 대기 후보와 local Band의 현재 도착 요청 예측은 세 문맥 모두에서 **절대 기한·120초 완료 가능**해야 한다. 이미 예측 기한을 놓친 작업을 더 늦춰 AP만 줄이지 않는다. 그 뒤 원 서비스/J/AP 비교·미래 AP 개선 필터를 적용한다.

이 장치는 생산관리의 **가용시간 대비 잔여 작업량·자원 호환성·납기 우선·제약 만족 후 비용 선택**을 현재 앱의 CPU/GPU 요청에 적용한 것이다. 원 도착·기한·완료 요구를 바꾸지 않으며 가설적인 미래 요청을 실제 trace에 추가하지 않는다. 관측 간격은 미래 간격의 보장이 아니므로 온라인 판단의 실제 서비스 보장이나 강건 최적해로 부르지 않는다.

| 고정 자원 기준 | Triton 고정 자원 |

- 개발은 기존813010101/102×4부하×3문맥24조건을 **튜닝 자료로 재사용**한다. 완료된5기준의120행은 source/receipt hash를 확인하고 재실행0, 새 후보24환경만 실행한다.
- 확인 seed813030101/102×4부하×3문맥=24조건×6정책144환경이다. 각24/192요청·전체 예정 도착·실현 비용·deadline·초기 상태·CPU/GPU·120초 J·같은AP35…180초1초grid를 공통으로 유지한다. V3의 이미 실행 중 확인 seed와 분리한다.
- 개발24조건의 Band/Triton 양쪽 서비스/J/AP 비악화와 두 개발 seed 각각 주 low/sustained 열감소가 있어야 선택한다. 선택을 새 확인 전에 고정하며 새 확인 후 다시 고르지 않는다. AP 우선/J 비악화와 엄격한 J/AP 공동감소·절대 전기한 충족을 각각 보고한다. 일반 평균 지연도 표시한다.
- 추가 환경 최대192/정상 예상168, 학습0,30분·저장5분 예약. 선행 V3 실제338회를 끝낸 누적5,636/641을 계승한다. 새 실행은 별도 ID/경로로 저장하고 실패도 차감한다. 두 라운드의 정상 합계506환경은 전체20,000 상한에 차감하며 기존 종료 clock/실패를 초기화하지 않는다.
- 새 임계값 튜닝·보상 가중치·도착 유형 분류학습·기기/NPU/ADB/계수 적합0이다. 원모형/기본/strict/experiment_ready=false·사용자/다른worktree를 보존한다. 실제 표면온도/기기 절감·미측정 제어 J/열 한도를 가정으로 채우지 않는다.
- 대표는 새 확인 첫 seed의 낮은 부하/평균으로 고정한다. 확인은2독립 도착 seed와 그3비용 문맥의 작은 PC 평가이며 실측 모형 독립 검증·정밀 CI는 아니다.
