# 시뮬레이터 활용·정책 판단 관점의 1차 독립 AI 검토

> **현재 추천은 하단의 2차·3차 교차토론 정정이다.** 1차 독립 의견은 판단 변화의 증거로 보존했다. bounded-decay 우선 추천을 철회했고 **고정 δ 삭제 ablation → δ=0 제약 네 상태 재추정** 순서를 권고한다. 3차의 최근20초 초기화 대조도 장기/정책차 악화로 정식 후보 추천을 철회했다. δ 삭제와 초기화 교체는 진단이며, 남긴 정식 학습 family는 조건부 δ=0/p4 한 개다. 관측 갱신은 별도 입력 조건의 후속 연구다.

## 결론

**우선 수정은 전력 보정의 시간 구조다. 단, 그것만으로 일반 도착 일정의 AP 오차까지 해결됐다고 할 수 없다.** 권고 후보는 최대 두 구조로 제한한다. 첫째, 현재 상수 전력 offset을 적분이 유한한 transient로 바꾸고 이미 확인한 AP head를 보존하는 open-loop 후보. 둘째, 도착 조건의 AP·배경전력 변화에는 각 head의 사전 가용 관측만 사용하는 별도 관측 갱신 후보다. 첫 후보는 현재 macro에서 두 출력 개선을 유지할 수 있는 가장 작은 수정, 둘째는 기존 Arrival의 AP/전력 오차까지 겨냥한 확장이다. 어느 쪽도 현 근거만으로 성공을 확정하지 않는다.

scope 차단은 잘못된 사용을 막는 인터페이스 조건이다. 목표인 두 오차 감소는 실제 예측과 같은 시간창의 오차표로 따로 입증해야 한다. 기존 LOAD_SLOW 확인을 다시 하거나 더 긴 C0를 먼저 재수집하는 것은 이번 첫 행동으로 추천하지 않는다. 전류·AP·lane의 기존 시계열에 필요한 다음 검사가 이미 가능하다.

## 핵심 원인과 실제 양출력 개선 범위

1. **확정된 수학적 실패:** 부하가 끝나 상태 추가W가 0이어도 `idle_bias_w`가 계속 적용된다. LOAD의 약 2009.324초 유휴에 +48.5243J가 추가되어 −10.9984J를 +37.5259J로 바꿨다. 이는 관측 오차/OS 원인 인증과 별개인 코드의 누적 구조다.
2. **확인되는 시간 변화:** C0는 상태 부하가 없는데 원모형 대비 관측 평균전력 차이가 등록600초 +0.021913W, 덮인 회복 +0.012059W로 달랐다. LOAD 회복의 차이는 +0.003988W다. LOAD 등록창 +0.025251W는 부하 상태 오차도 포함하므로 이를 순수 배경전력으로 취급하면 안 된다. `δ=+0.0241496W`를 전체 시간에 유지하는 가정은 양 회복 모두에 과하다.
3. **AP는 별도 오류:** LOAD_SLOW의 하나의 느린 입력은 원동결 상태 전력 proxy의 비율을 물려받고 S(35)=0으로 시작한다. 이전 이력/전환이 다른 Arrival에서는 13/29 AP MAE 악화가 남는다. τ1920 미식별은 물리 인과 주장에 장애이지만, 같은 유한창의 예측을 검증하는 것 자체를 금지하지는 않는다. 이미 새 LOAD의 회복 방향을 확인했으므로 τ만 식별하려고 다시 긴 실측을 반복할 필요는 없다.
4. **원자료 분해상 상쇄:** LOAD의 `[35,635]` 600초 J 절대오차는 15.151→10.763J, AP MAE는 0.5437→0.1862°C로 같은 창에서 둘 다 감소했다. 그러나 실제 작업이 있었던 `[35,545.186]` J 절대오차는 11.807→11.938J로 조금 악화했다. 600초 평균 개선은 모든 요청/시간 구간의 개선이 아니다.

## 구현 후보 1 — 유한적분 전력 transient + 보존한 AP head (우선)

현재 상수 bias 열을 다음 한 구조로 대체한다. 시계 35초는 기존 부하 진입 기준이며 결과에서 고른 종료시각이 아니다.

```text
P_E(t) = P_pre + a * exp(-(t-35)/tau_E) + Σ p_state * I_state(t)  [t >= 35]
E_E(t) = P_pre*t + a*tau_E*(1-exp(-max(0,t-35)/tau_E)) + exposure(t)·p
a: signed, p_state >= 0, tau_E > 0
E(lo,hi) = E_E(hi)-E_E(lo)
AP: 기존 고정 LOAD_SLOW, 기존 proxy/계수 그대로
```

**제안·가설:** 원래의 기준전력차가 장시간 내내 유지되지 않고 소멸하는 저차원 근사를 시험한다. transient 추가J는 `a*tau_E`로 유한하므로 상수 bias의 무제한 누적을 구조적으로 제거한다. 실제 background가 영구히 0이 된다거나 τ_E가 하드웨어 시간상수라는 주장은 아니다. C0도 있으므로 부하 종료에만 보정을 끄는 구현은 피한다. 고정600초까지만 보정을 남기는 사후 절단도 피한다.

구현 순서:

1. 현재 저장된 **개발4**의 5초 적분과 실제 상태 노출로 시간열의 변화를 먼저 확인한다. 새 fit 전에 transient와 네 상태 열의 rank/조건수, A/B 순서의 confounding, 유휴잔차의 부호/기울기·train 범위를 기록한다. 새 긴 C0/LOAD와 과거29는 후보 선택 자료로 사용하지 않는다.
2. 기존 `energy_fit`와 `prediction`의 옆에 별도 version의 한 head만 만든다. τ_E의 후보 범위/선택 규칙은 개발 관측 길이와 pre 기록 근거로 사전에 고정한다. AP의 τ1920을 전력 τ_E로 복사하지 않는다. a와 네 p를 새 basis에서 다시 추정해야 하며, 상수 bias 때의 p를 그대로 끼우면 상태 비용에 흡수됐던 오차를 중복 보정할 수 있다.
3. 개발 세션 제외평가 후 동결한다. 기존35는 전부 평가하되 macro/Arrival/history·같은 창과 별도 창을 나눈다. 기존4 이후 tail을 train에 넣는다면 이는 새 추정 범위로 미리 등록한다. 이미 본 긴2는 사후 외삽 검사로 남긴다.
4. AP는 바꾸지 않아 새 LOAD의 확인을 보존한다. 이 조합으로 성공할 수 있는 첫 대상은 **macro의 같은600초 및 덮인 회복에서 J개선 + 기존 AP개선/동률을 함께 유지**하는 것이다. old29의 AP13 악화는 해결되지 않으므로 전체 Arrival 모형 채택 조건을 충족했다고 주장하지 않는다.

실패 가능성도 분명하다. 개발4가 약815초까지인 상태에서 긴 tail τ_E를 식별하지 못하거나, 모든 세션의 background가 같은 transient가 아니면 이 구조는 실패할 수 있다. Jacobian/rank가 충분해도 미래 오차한도는 자동 성립하지 않는다. train만으로 시간형태를 결정할 수 없으면 τ 상한을 반복 확대하거나 확인2로 역추정하지 않고 후보를 보류한다.

## 구현 후보 2 — 사전 가용 관측으로 각 head를 따로 갱신 (조건부 차선)

도착 조건의 AP 평균오차에는 이미 관측 갱신의 구체적 근거가 있다. 원래 rolling AP는 같은10초창 확인0.258→0.156°C, 지속0.383→0.209°C를 보였다. 그러나 확인 최대는 1.077→1.380°C로 악화했고, 전력 잔차를 전량 지속시키면 개별10초 J가 악화했다. MEMORY30도 지속 J 평균이 악화했고 개발 gate를 실패했다. 따라서 기존 rolling/30초 식을 그대로 결합하는 것은 해결책으로 인정하지 않는다.

**제안·가설:** 전력은 일반 잔차가 아니라 **관측된 유휴의 baseline 편차**를 별도 추정하고, AP는 현재 출력잔차만 별도 갱신한다.

```text
E observer: 이전까지 완전히 덮인 안정 유휴 창에서
            observed_W - P_pre 를 저차원 baseline 편차로 갱신
            mixed/전환창의 상태 비용 잔차를 background로 흡수하지 않음
            부하 중에는 직전 유효 baseline을 유지하며 age/미관측을 명시
AP observer: 최신 가용 AP - 해당 시각의 원 AP 예측을 출력잔차로 갱신
             전력 observer의 값을 AP 열입력으로 대입하지 않음
future cost: 발행 당시의 observer 상태와 A 조건/별도 B 예측 일정만 사용
```

기존30초 과거창과10초 미래창을 출발 계약으로 쓸 수 있으나 그 길이의 성공을 가정하지 않는다. head별 갱신 강도는 많아도 한 scalar씩 개발 자료로 선택하고, 관측이 없는 전환을 결과를 보고 골라 차단하지 않는다. stable-idle 조건은 **발행 이전의 lane 기록**으로 판정한다. 실제 미래 상태 분류는 평가 진단으로만 쓴다. 관측이 stale/결측이면 원 head나 unavailable로 사전에 정한 방식으로 처리하고 상태를 기록한다.

검증은 먼저 기존20의 가용시각이 있는 `rolling_forecast_01/inputs.json.gz`, 기존 macro4와 긴2의 원 표본으로 한다. 전력 개별10초 MAE·등록 전체J·J곡선 오차를 같이 검사하고, AP는 평균/최대/전환창/단순 persistence 대조를 포함한다. AP 값유지보다 못하면 동역학 모델의 추가효과를 주장하지 않는다. 전체80초 순오차의 상쇄만 좋아진 후보는 탈락이다.

**이 후보가 해결하는 목표는 관측 갱신 이후의 단기 시간별 오차다.** 부하전 정보만으로120/600초 전체를 예측하는 후보1과 별도 estimand다. long idle의 낮아진 실제전력을 가용 관측으로 반영할 수 있다는 장점은 있지만, 무관측 장기 예측까지 개선했다고 쓸 수 없다. 현재 설치 APK에 numeric AP를 정책 consumer로 전달하는 경로가 검증되지 않았으므로 먼저 offline causal replay로 평가한다. producer의 기록 proxy를 consumer 실제 수신시각으로 승격하지 않는다.

## 두 head와 모형 인터페이스

공유할 것은 task/backend 상태, 실제 dispatch~lane 해제, clock origin, 초기 입력의 cutoff와 관측 availability다. **전력W와 AP℃의 계수·잔차 상태·선택 gate는 분리한다.** 여러 모델/스레드/정밀도/기기의 비용을 같은 상태로 뭉개지 않는다.

권고 인터페이스는 `cost_heads.predict(initial, schedule, queries, layer, observations_prefix=None)` 같은 명시적 경계다. 결과에는 head별 model ID/hash, prediction layer, 입력 cutoff, 실제/예측 일정, horizon/coverage, target window, AP/J 지원 및 unavailable 이유를 남긴다. AP가 scope 밖이라도 E가 지원될 수 있고 그 반대도 있으므로 bundle 하나의 allowed=true로 묶지 않는다. `both_improved`는 평가 결과이며 예측 시점의 허용 플래그가 아니다.

LOAD_SLOW의 원전력 proxy를 새 p_state로 교체하는 것은 AP head 자체의 새 후보다. API 정리라고 처리하면 앞선 동결 확인을 조용히 다른 식으로 바꾼다. 물리열 결합을 하려면 새 구조·추정·독립평가가 필요하고 이번 최대2 후보 범위에 자동 추가하지 않는다. 온도를 전력으로 역산하거나 AP를 처리시간 감속계수로 연결하지 않는다.

## A/B와 정책 판단: 공백이 실제 선택을 바꾸는가

A는 실제 일정이 주어진 비용 예측이다. B는 예정 도착→서비스 추정→예측 lane→비용이다. 동일 head에서 `B_prediction - A_prediction`은 스케줄 전이가 비용에 더한 차이를 나타내고, `A_prediction - observation`은 비용/초기화 잔차다. 이 산술 분해는 인과 원인 인증이 아니다. 후보1/2의 각 버전에서 두 층위를 별도 표로 저장하고 기존 ledger/서비스 모델을 먼저 동결해야 한다.

정책 비교의 오차는 `e_delta=(Jhat_PAR-Jhat_CPU)-(J_PAR-J_CPU)=e_PAR-e_CPU`다. 공통 오차가 소거될 수도, 서로 다른 부호가 합쳐져 커질 수도 있다. 평균 개별 MAE만 낮추면 충분하지 않다. 실제 저장된 지속4쌍 A의 FROZEN에서는 **2/4 에너지 차이 부호가 반대**다:

| 쌍 | 관측 PAR−CPU | A 예측 PAR−CPU | 판단 영향 |
|---|---:|---:|---|
| sustained0/1 | −5.304J | +3.963J | 관측은 PAR가 낮지만 모형은 CPU가 낮다고 선택 |
| sustained5/4 | +3.393J | −10.587J | 관측은 CPU가 낮지만 모형은 PAR가 낮다고 선택 |

JOINT 재추정은 최근14 개별 J MAE4.319→4.273J를 보였지만 이4쌍의 차이 MAE는6.322→8.730J로 악화했다. 이 자료는 다른 날/순서/초기이력의 기술적 짝이므로 보편 인과절감은 아니다. 그래도 **현재 오차 공백이 순위를 실제로 뒤집는 질문**임을 보여준다.

따라서 비용으로 정책을 선택하려면 같은 입력·전체 도착 분모·같은 horizon·기기/모델/준비조건을 맞춘 CPU/PAR 짝을 보고 J 차이 및 AP 최고/경로/면적 차이의 잔차와 부호를 검사해야 한다. 사후 관측 최대오차를 미래 universal bound로 쓰지 않는다. 서비스 guard의 P95/전체 도착 성공률·기한 검사를 비용 판단보다 먼저 수행한다. 작은 정책 이득이 기존 짝 오차/제어비용보다 작으면 `policy_winner=null`이 올바른 결과이지 모형 전체 실패나 기존 자료 무용의 결론은 아니다.

## 기존 자료로 가능한 검증과 최소 추가 실측

**지금은 새 실측 없이 두 후보의 구현 가능성을 걸러낼 수 있다.** 기존 macro4, prior Arrival3+확인6, history12, sustained8, long2의 역할을 유지하고 중복 입력을 제거한다. power/AP clock bracket·lane 해제·원 hash 계약을 재사용한다. 데이터 캐시에 필요한 시계 필드가 없으면 원 manifest/journal에서 복원하며 오차가 작아진 사례만 가져오지 않는다.

추가 실측이 필요한 시점은 후보를 동결한 뒤에도 다음 두 질문 중 하나가 정책 사용에 남을 때다.

1. 같은 등록 arrival를 CPU/PAR가 실제 실행할 때 A 비용과 B 일정의 새 독립 전이 오차가 정책차보다 큰가?
2. observer를 사용하려면 numeric AP/전력의 **consumer 수신시각·가용성 및 실제 제어비용** 때문에 순위가 바뀌는가?

그때는 동일 준비/4resident/입력/계측에서 CPU–PAR–PAR–CPU 한 block(4실행)이 두 정책 각2회와 역순을 포함하는 최소 비교 설계 예시다. 한 실행에서 pre/post 전력·AP, 요청 전체 서비스/lane, 관측 consumer 전달·scheduler 구간을 함께 기록하면 모형/일정/제어비용 질문을 통합할 수 있다. 실행시간/호출예산은 현재 고정하지 않는다. 짧은 요청열과 등록 tail로 충분한지 후보의 사전 예측 분리가 결정해야 한다. 기존 완료 long C0/LOAD를 무조건 재실행하지 않는다. 4실행으로 신뢰구간/분포/τ/아주 작은 이득이 자동 인증되지는 않으며 식별 불가면 추가 반복을 자동 승인하지 않는다. 현재 이 내용은 실행 계획/승인이 아니다.

## 다른 두 관점에 제기할 반론 3개

1. **열모형 관점에:** τ1920이나 물리원인을 먼저 완전히 식별해야 두 출력 오차 개선에 착수할 수 있다는 주장은 과하다. 새 LOAD의 유한창 확인은 이미 있다. 반대로 전력계수를 AP proxy에 대입하면 식별이 개선된다는 주장도 확인식의 교체다. 실제 정책 horizon에서 필요한 오차와 물리 식별의 목적을 구분해야 한다.
2. **전력·계측 관점에:** constant bias를 decay시키면 전체J가 좋아질 수 있으나 5/10초 오차와 부하 구간 악화가 남을 수 있다. 센서 단위/센서 내부 갱신주기만 고치면 정책 차이를 판별할 수 있다는 주장은 background/이력/상태/제어 비용의 차등오차를 빠뜨린다. 단위 개선과 짝 차이 개선을 실제 데이터로 각각 확인해야 한다.
3. **통합 해결책 관점에:** rolling AP 평균 개선과 MEMORY30 에너지 평균 개선을 서로 다른 창/자료에서 가져와 두 출력 개선으로 묶으면 안 된다. 같은 발행시각·같은 대상창·전체 세션 및 전환 최악·persistence 대조·A/B·짝 차이를 통과해야 한다. 특히 관측 입력이 가능한 PC 재생을 현재 APK의 온라인 기능으로 주장할 수 없다.

## 2차 교차토론 — 추천 수정·직접 반론·합의와 미합의

### 추천 수정

**1차 bounded-decay를 최우선 후보에서 철회한다.** energy 검토자는 이미 `E_PRE_TRANSIENT`가 전력 예측에 실패했고 anchor/τ의 새 정보가 없다고 반론했다. identification 검토자는 δ의 LOSO 부호 변동과 비단조 잔차를 지적했다. 유한적분은 무제한 누적을 없애는 수식 성질일 뿐 이번 데이터에서 단조감쇠가 맞는다는 근거가 아니다. 새 τ를 찾으면 해결될 것이라는 추정으로 먼저 적합하지 않는다.

**1차 observer도 현재 offline full-horizon 후보에서 제외한다.** 기존 `causal_background_pc_v1`를 추가 확인했다. 혼합 상태에서 관측전력−상태예측−pre-W 잔차 r을 AP에 γ로 입력했고, γ LOSO0.01950–0.19914의 약10.2배 변동, 개발 AP MAE0.45832→0.47809°C, 확인30초 J MAE3.91198→4.16008J 악화로 미채택됐다. idle-only observer는 task 비용 오류를 background r에 흡수하지 않는다는 구조적 차이가 있지만, 성공 근거는 없다. 관측 갱신 이후10초 예측은 부하전 입력만으로 전체창을 예측하는 문제와 다르다. 향후 목적을 바꿔 따로 시험할 수 있다는 판단만 남긴다.

현재 추천은 아래 두 개다. **구현·새 fit을 이번에 실행했다는 의미가 아니다.**

## 3차 root 반론 검토 — 최근20초 초기화의 정보 조건과 full-horizon 실패

### 판정과 반론 후 수정

root의 **P_pre50 불안정은 δ=0/p4 재추정에도 남는다**는 지적은 타당하다. 상태 추가전력을 다시 추정해도 이후 유휴의 background 변화는 설명할 수 없다. 원50초 초기화를 그대로 쓰는 제약재fit을 background 문제 해결로 표현해선 안 된다.

다만 **최근20초가 더 좋은 초기값이라고 정식 후보로 추천하는 것은 거부한다.** `P_recent=mean_W[10,30]`를35초 이후 상수로 쓰는 식은 `E_PRE_TRANSIENT`의 지수감쇠와 다르므로 별도 진단할 이유는 있다. 그 차이만으로 최신값의 장기 외삽이 타당해지지는 않는다. 직접 산술에서 120초의 성공과 긴 회복의 명백한 악화가 동시에 나타났다.

두 AI에게 직접 질의하며 처음에는 정식P50/P20의 통제된 재fit 대조를 가능성으로 제시했다. energy 검토자의 **회복에서는 p4노출=0이어서 재fit으로 P20 오류를 고칠 수 없다**는 반론과 identification 검토자의 전체창·짝 차이 반례를 받아들여 **P20 정식재fit 허용 초안을 철회**했다. 정식 후보 한도는 최대2이지 반드시2개를 채워야 한다는 요구가 아니다. 지금은 δ 삭제와 P20 교체를 각각 component/initialization 진단으로 보존하고, 필요시 개발4만의 δ=0/p4-P50 제약재fit 한 family를 조건부로 남긴다. 이 family의 background 한계도 미해결이다.

### 구분해야 할 세 수식

```text
P50: ∫[-20,30] observed_W / 50
P20: ∫[10,30] observed_W / 20

기준 fixed δ삭제: E50(t)=P50*t + exposure(t)·p4
초기화 진단:     E20(t)=E50(t)+(P20-P50)*max(0,t-35)
```

기준0..35초 회계는 공통 P50으로 유지하고35초 이후만 바꾼다. `[lo,hi]` 변화량은 `(P20-P50)*[max(0,hi-35)-max(0,lo-35)]`다. P20를 전체0..t에 적용하면 `35*(P20-P50)`의 과거 구간 수정이 추가되어 개선을 섞으므로 이번 진단에서 하지 않는다. P20를 부하 이후 감쇠시키거나 확인 결과로 window를 더 짧게 고르는 별도 가정도 추가하지 않는다.

이 값은 whole-device W의 초기화 대조이지 새 AP 계수가 아니다. AP LOAD_SLOW의 원 proxy/초기화는 불변이다. p4-P50을 그대로 P20에 옮긴 수치는 fit0 구조 대조이며 baseline-P20에서 새로 학습한 p4의 성과가 아니다.

### A/B와 미래 정보의 허용 경계

- P20는35초 발행 이전의 완전히 resident-idle인 관측에서 얻어야 한다. 10..30초 midpoint coverage만으로 충분하지 않으며, endpoint 보간의 오른쪽 표본까지 sensor read/event 공개가35초 이전이어야 한다. 두원센서의 clock origin·단위·plugged·state 조건도 유지한다. energy AI는 개발4+긴2 원journal에서 idle/readiness≤35를 직접 확인했다고 전달했고, identification AI는 cache 오른쪽 midpoint 최대30.8935초를 확인했다. cache만의 midpoints를 consumer 실제 수신시각 인증으로 승격하지 않는다.
- A에서는 실제 미래lane 일정이 비용 조건이고, B에서는 원 forecast lane이 조건이다. P20는 양쪽에서 같은35초 이전 초기정보로 사용하므로 이후 AP/W 관측을 넣는 누설이 아니다. B의 미래 실제일정을 넣어선 안 된다. 서로 다른 초기화 입력으로 A/B를 비교하면 비용head와 일정오차가 혼합되므로 같은 버전의 head/초기화를 사용한다.
- E20−E50의 초기화 이동은 같은 세션의 같은horizon에서 A/B에 동일하다. 따라서 B−A의 비용차 분해를 곧바로 개선하지 않는다. task 서비스시간/dispatch 정책은 바꾸지 않는다.
- 0..35초는35초 발행 시점에 이미 지난 구간이다. 기존 whole0..120값은 초기관측구간을 포함하는 회계/재생 지표이고, t=0부터 아무 관측 없이 발행한 순수120초 전망으로 부르지 않는다. 공통 prefix를 보존한 전체120 비교와 prospective35..120 비교를 둘다 명시한다. 실제측정 prefix로 대체하고 후보만 이득을 얻는 비교는 하지 않는다.
