## 결과 전 고정 설계

작업 ID `IE-THERMAL-SLACK-03`. 원 Band 요청 적용을 fallback으로 둔다. 후보는 EDD 상위4요청과 최소 응답 여유시간의 CPU 전용 요청1건, 가능한 CPU/GPU 단건 배정·검증된 분류GPU+탐지CPU 묶음이다. 산업공학 규칙은 실제 후보 구성과 판단에 사용하지만, 특정 생산관리 알고리즘 전체를 그대로 재현한 것이나 새로운 산업공학 이론은 아니다. [기존 산업공학 구현](../industrial_scheduling_01/README.md)과 [원 외부 규칙 비교](../ie_candidates_v2/README.md)를 보존한다.

응답 여유시간은 `도착+상대기한−예상응답완료시각`이다. 여기에는 현재 점유와 응답 단계의 예상 처리시간이 들어간다. CPU 전용 요청을 후보에 남기고 분류를 GPU로 보내는 허용 병행을 비교하므로 자원 유연성도 반영한다. 추론 출력·저장 응답·5단계 lane 재사용을 바꾸지 않고 선점·주파수·NPU 행동은 추가하지 않는다.

예측은 **이미 도착한 전체 큐**와 현재 공개 lane/과거 이력만 사용한다. 원3문맥(평균/짧음/김)을 가정한 미래 궤적을 각각 계산하고, 해당 첫 행동 뒤 Band suffix로 남은 현재 요청을 처리한다. 가정한 EMA 갱신은 복제된 predictor에서만 적용한다. 실제 controller에 미래 도착·실현 문맥·실제 잔여시간은 전달하지 않는다. 알 수 없는 관측 잔여 구간은 비용0이 아니라 원 Band fallback이다.

실행 가능한 후보 중 세 예측 모두에서 현재 도착 요청의 긴급/일반 기한 실패·긴급 P95·남은 J·공통 전체 AP가 local Band보다 악화하지 않는 후보를 남긴다. 그중 **미래 최고 AP의 최악 차이**가 엄격히 줄어드는 첫 행동을 선택하고 동률이면 작은 J, 그래도 같으면 고정 후보 순서다. 이미 확정된 과거 최고값은 전역 AP 비교에 포함하되 앞으로의 열 차이를 가리는 선택 점수로 사용하지 않는다. 이후 실제 도착/phase 이벤트마다 다시 판단한다. 예측 필터는 실제 미래 서비스 보장이 아니다.

추가 유휴 대기는 **양 자원이 비고 긴급 요청이 없을 때 일반 요청에만** 허용한다. 대기 한도는 실제 dispatch 사이의 누적 credit0.25초/1초 두 버전으로 고정한다. 대기·시간 진행·새 도착만으로 credit을 채우지 않는다. 새 긴급 도착은 대기를 재판단하게 한다. 같은 자원·순서 후보에서 대기를 제거한 ablation도 비교한다. 기존 PPO의0.25초 행동 공간과 새1초 버전은 별도 ID다.

## 평가 계약과 예산

기존 연구의 주 관심인 열 감축을 검사하되 **서비스·전체 완료량·J 비악화에서 AP 감소**를 새 버전의 후보 선정 기준으로 명시한다. 과거 J/AP 엄격한 공동감소 기준을 소급 변경하지 않으며 이번에도 공동감소를 따로 보고한다. AP는 검증된 같은 모형 채널로만 계산하며 표면온도·안전 임계값을 새로 만들지 않는다.

- 개발 seed813010101/102, 확인813020101/102 각각2seed×4부하(낮음/큐/몰림/지속)×3문맥=24조건. 기본24요청, 지속192요청이며 **전체 예정 요청을 유지**한다. 원 deadline·입력·초기 측정 preload·자원·실현 비용·120초 J와35…180초 AP1초 grid를 같게 한다. 새 기기/새 온도 시작값/계수 적합0이다.
- 튜닝 기회는 미리 정한0.25/1초 두 대기 범위뿐이다. 새 가중치/온도 문턱/기한 여유율 탐색0. 개발24조건에서 Band/Triton **모두** 대비 서비스/J/AP 비악화이고, 저부하·지속 주 조건에서 두 seed 각각 열 감소가 있어야 적격이다. 최악 AP 차이→평균 J→짧은 대기로 선택을 고정한 뒤 확인을 시작한다. 확인은7역할 전부 보존하되 확인 결과로 다시 고르지 않는다.
- 확인은 조건별 긴급 P95/위반·일반 기한 내 완료/평균·실패/미완료·J·동일 AP 최고/경로·실제 병행/점유·PC 판단시간을 보고한다. 기준이 과부하에서 실패한 경우 상대 비악화와 전기한 충족을 분리한다. 일반 평균 지연을 함께 표시하고 앱 판단의 실제 J/한도 초과시간은 근거 없으면 null이다.
- 새 환경 최대384(정상 예상338=개발168+확인168+fixture2), 학습0, 등록부터1시간·저장5분 예약. 이전5,298환경/641학습을 계승한다. 전수 수학 예측은 환경 호출과 구분하며 실제 환경은 시작 전 journal에 차감한다. 실패도 보존·차감한다. 사용자 변경·다른worktree·모형/기본/strict/experiment_ready=false·기기/ADB/NPU0 유지.
- 대표는 첫 확인 seed의 지속/평균으로 고정한다. 실제 도착이 있는 전체 실행과 앞선 조건부15요청 결과를 합산하지 않는다. 확인 seed는 이 후보의 개발과 분리되지만 실측 모델의 독립 확인은 아니다. 2seed/3문맥을6독립 반복이나 정밀 CI로 표시하지 않는다.

## RL 연결 경계

현재 native Maskable PPO/Double DQN과 종료 archive는 그대로 보존한다. 이번은 새 학습0으로 기본 선택이 개선 가능한지부터 확인한다. 새 후보가 확인에서도 서비스/J를 지키며 AP를 줄인 경우에만 같은 후보·mask·목적·예산의3seed RL을 후속으로 검토한다. Band fallback/EMA/미래 AP 점수/1초 credit은 과거 EDD 특성·행동 의미와 다르므로 이전 actor에 이름만 바꿔 끼우지 않는다. 후속 RL의 상태·행동 schema와 보상/제약은 별도 버전으로 고정해야 한다.
