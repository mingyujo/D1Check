## 이번에 끝낸 것

- 기존 개발 3세션으로 동결한 `separated-power-model-v1`과 확인 6세션을 모두 재사용했다. 마지막 CPU 세션을 이상치로 제외하지 않았다. 최근 배경 개발4의 gamma=0/미채택 후보로 계수를 바꾸지 않았다.
- CPU→PAR→SER→SER→PAR→CPU 순서와 각 정책의 두 독립 실행을 유지했다. 이미 결과를 본 자료에 대한 사후 분석이며 지금 새 독립 검증을 얻은 것은 아니다.
- 이전 비교표의 4개 차이를 재현하고 `예측 차이−관측 차이=각 세션 오차의 차이`를 검사했다.
- 같은 96요청·350ms 도착·기한 입력과 각 세션의 부하 전 초기 입력을 CPU/PAR/SER에 공통 적용했다. 6 초기조건×3 정책=18개의 제한된 PC 예측만 수행했다. 전체 정책 배치·튜닝·재적합은 하지 않았다.
- 기존 정책 선택 차단 코드를 그대로 사용했다. 수치 예측은 허용하지만 `energy-ap-policy-selection` 호출은 거부한다. 사후 최대오차를 미래 허용폭으로 만들지 않는다.

## 같은 초기 입력의 모형 차이

각 초기조건에서 정책−CPU를 계산했다. 미래 AP·전류·실제 완료시각은 예측 입력에서 제외했다. A24의 등록된 두 모델·resident 구성과 정책별 개발 처리시간을 사용한다. 에너지 상태는 분류 CPU, 탐지 CPU, 분류 GPU, 분류 GPU＋탐지 CPU 및 resident 유휴다. 이 확인6의 시작 AP는 30.2~30.9°C이며 원래 strict 시작 범위 확대를 뜻하지 않는다. 임의 상태나 열에 따른 처리시간 변화는 새로 만들지 않았다.

|정책−CPU|0~120초 에너지|35~180초 최고 AP|긴급 P95|전체 기한 예측|
|---|---:|---:|---:|---:|
|PAR|−1.712761J|+0.793111~+0.815737°C|−463.646ms|96/96|
|SER|+2.481829J|+0.193587~+0.223154°C|+141.144ms|62/96|

에너지 차이가 초기조건 6개에서 같은 것은 모형의 같은 resident 전력 항이 차분에서 소거되기 때문이다. 실제 기기의 배경 전력이 같거나 온도가 전력과 무관하다는 실증이 아니다. 같은 관측 초기 입력도 숨은 열 이력까지 같다는 뜻은 아니다. PAR의 예측은 응답 개선·에너지 감소·최고 AP 증가라는 상충을 보여 주지만, 이를 최종 정책 선택 근거로 승격하지 않는다.

**예측 시간 경계:** 초기 입력은 기존 계약의 부하 전 AP와 전력 −20~30초 평균이다. 부하 시작은 common 35초다. 0~120초 비용은 같은 입력으로 계산한 공통창 회계이며, 0초 이전에 만들어진 무관측 예측이 아니다. 35초 이후 미래 관측은 사용하지 않는다. AP 반사실 비교는 35~180초 1초 격자이고 실제 관측과의 새 오차 점수는 아니다.

## 오차가 정책 차이를 얼마나 가리는가

|실제 비교 block|정책−CPU 관측 J|예측 J|차이의 오차 J|관측 최고 AP 차이|최고 AP 차이의 오차|
|---|---:|---:|---:|---:|---:|
|0 PAR|+1.657|+1.061|−0.596|+0.300°C|+0.737°C|
|0 SER|−0.134|−2.735|−2.601|−0.100°C|+0.649°C|
|1 PAR|−42.939|−12.179|+30.760|−2.400°C|+2.420°C|
|1 SER|−41.254|+0.247|+41.501|−3.500°C|+2.955°C|

이 표는 초기·이전 이력·배경이 다른 세션의 산술 차이다. block1의 CPU가 부하 종료 뒤 크게 가열됐다는 기존 [사후 유휴 분석](../post_idle_pc_v1/README.md)을 재사용했다. 그 원인이나 무작위 배경 분포를 새로 확정하지 않는다. 초기 AP 차이는 block0 0/+0.1°C, block1 −0.4/−0.4°C로 CSV에 보존했다.

확인 6개 에너지 예측 오차는 +4.354/+3.758/+1.753/+6.004/−4.737/−35.497J다. AP MAE는 0.271/0.436/0.311/0.151/0.227/0.927°C, 마지막 CPU 최대절대오차 4.213°C다. 이 수치를 모든 미래 조건의 오차 한도로 사용하지 않는다.

정책별 과거 에너지 잔차 2개와 CPU 잔차 2개를 빠짐없이 교차 대입한 **유한 산술 민감도**도 저장했다. `조정 차이=동일 초기조건의 예측 차이−(정책 잔차−CPU 잔차)`다.

- PAR: −40.968~+7.378J로 부호가 뒤집힐 수 있다.
- SER: −39.019~+5.083J로 부호가 뒤집힐 수 있다.

이 범위는 신뢰구간·미래 오차 한도·발생 확률이 아니다. 잔차의 교환 가능성도 입증하지 않았으며 독립 관측 4개가 추가된 것이 아니다. 이미 본 잔차가 작은 정책 차이를 덮을 수 있음을 보여 주는 산술 예시다. AP는 초기조건과 쿼리 시각이 달라 이 방식의 범위를 만들지 않았다. 대신 위 실제 최고 AP 차이의 오차와 동일 초기조건의 모형 차이를 별도로 보고한다.

AP 실제 점수창은 각 세션 35.206~37.784초에 처음 관측되어 177.361~179.824초에 끝난다. 정확한 세션별 시작·끝은 [sessions.csv](evaluation/sessions.csv)에 있다. 최고값은 그 창의 관측 최고값이며 모든 사이 시각의 물리 최고값이 아니다. 서로 다른 창과 초기조건의 최고값 차이를 통제된 열 효과로 해석하지 않는다.
