# CPU–PAR 비교의 판별 가능성 — 2026-10-04 PC 판정

**현재 96요청 입력의 1.713J 절감 예측을 입증하기 위해 같은 실측을 확대 반복하는 것은 권고하지 않는다.** 필요한 실제 반복 수는 `null`이다. “몇 번만 더 하면 완료”라는 근거가 없으며, 그렇다고 정책 효과가 없거나 모든 조건에서 계측이 불가능하다는 결론도 아니다.

## 고정한 비교 질문

입력은 이미 등록·실행한 **A24 혼합96(분류48/탐지48), 350ms 예정 도착, CPU vs PAR** 한 가지다. 두 정책 모두 이전 두 실행에서 전체 기한96/96을 충족했고 PAR에서 약13초 실제 병행이 있었다. SER은 전체 기한61/96이므로 이번의 “전체 요청 기한을 지키는 선택” 비교에서 제외했다. SER 결과·실패는 삭제하지 않았다.

새 입력을 여러 개 생성하거나 예측 절감량이 가장 큰 trace를 고르지 않았다. 기존의 동일 초기 입력 18예측을 그대로 읽었으며 새 시뮬레이션·후보 적합도 0이다. 1.712761J는 이 동결식의 점 예측 차이이며 **실용적으로 의미 있는 최소 절감량은 아니다.** 현재 연구 요구에서 최소 J 이득과 허용 AP 증가가 아직 수치로 정해지지 않았다. 이를 임의의 1%·5%로 대신하지 않는다.

질문은 ①이 조건의 실제 전체 기기 J 차이를 구분할 수 있는가, ②동결 모형이 그 차이와 AP 상충을 설명하는가다. 직접 정책 효과 확인과 개별 세션의 경로 예측 정확도는 별도 결과다. 모형의 예측오차 표준편차를 직접 정책 효과의 변동으로 바꾸어 계산하지 않았다.

## 자료가 말해 주는 것과 말해 주지 않는 것

CPU→PAR→SER→SER→PAR→CPU 중 기존 대응 block 두 개를 그대로 사용했다. 이 순서는 이미 역순을 포함한다. “다음에는 순서만 교차하면 해결된다”는 권고를 하지 않는다.

- 실제 PAR−CPU 120초 차이: **+1.656725, −42.939088J**.
- 두 차이의 기술적 표본 표준편차: **31.534002J**, 자유도는 단 1이다.
- 이 표준편차에는 초기조건·이전 부하·시간에 따른 배경 차이가 섞여 있다. 독립·동일분포·정상성·무작위 배정·안정된 미래 분산은 입증되지 않았다. 따라서 실제 검정력, 신뢰할 모집단 분산, 필요한 반복 수는 계산 완료로 표시할 수 없다.
- 큰 차이를 만든 마지막 CPU를 제거하거나 센서 표본·요청96개·잔차 교차조합을 독립 반복으로 사용하지 않았다. 최근 배경 개발4는 APK/관측 프로토콜과 자료 역할이 달라 이번 두 비교에 합쳐 표본 수를 늘리지 않았다.

## 반복 수 민감도: 실측 권고 횟수가 아님

NIST의 알려진 분산 정규 설계식 `n≈((z(1−α/2)+z(power))σ/δ)²`를 **가정의 민감도**로만 적용했다. 독립 대응차이, 안정되고 알려진 σ, 편향 없음이 필요하다. 실제 σ를 추정해야 하는 소표본에서는 이 식으로 충분한 반복 수를 보장할 수 없다. [NIST 표본 수 조건](https://www.itl.nist.gov/div898/handbook/prc/section2/prc222.htm), [대응차이의 분석](https://www.itl.nist.gov/div898/handbook/prc/section3/prc311.htm).

양측 α=0.05·검정력0.8은 **계산 예시의 위험 설정**이며 이미 본 결과의 정확도 PASS 기준이나 실행 계약이 아니다. δ=1.712761J를 넣었다.

|가정한 비교 쌍|기기 세션 수|σ=31.534J라 가정할 때 검출 차이|1.713J를 겨냥할 때 필요한 σ|고정 관측만|
|---:|---:|---:|---:|---:|
|4|8|44.173J|1.223J 이하|28분|
|8|16|31.235J|1.729J 이하|56분|
|16|32|22.086J|2.445J 이하|112분|
|32|64|15.617J|3.458J 이하|224분|

관측 SD31.534J를 미래의 알려진 σ로 그대로 놓으면 **2,661쌍**이 나온다. 이 수치는 실제 필요 횟수·하한도 아니며 권고하지 않는다. 두 관측으로 미래 변동을 확정할 수 없다는 문제를 숫자만 정밀하게 써서 숨기지 않는다. 표의 시간은 기존 코드 `fixed_observation_seconds=n*210`에 따른 세션당 고정 관측만이며 설치·gate·준비·회수·cleanup·충전/휴식 공백·실패를 포함하지 않는다. 새 실행 예산이 아니다.

예를 들어 8쌍 규모를 생각하려면 차분 SD가 약1.729J 이하라는 근거가 필요하다. 이는 지금의 기술적 SD보다 약18배 작다. 초기 AP를 맞추거나 순서를 교차하면 그 수준으로 줄어든다는 근거는 없다. [절반·1/4·1/10 변동 가정](evaluation/hypothetical_reductions.csv)은 달성한 개선이 아니라 필요한 조건의 민감도다.

**반복으로 없어지지 않는 항도 있다.** 1.713J는 120초 평균 차분 전력 **14.273mW**에 해당한다. 이 정도 정책 간 체계적 편향이면 점 예측 이득과 같아진다. 이것은 센서의 실측 분해능이나 인증된 정확도가 아니다. 조건 차이·계측 편향이 반복마다 남는다면 표본 수를 늘려도 제거되지 않는다. [가상의 편향 민감도](evaluation/hypothetical_bias.csv)는 편향 한도가 목표 차이 이상이면 유한 반복 수를 반환하지 않는다. 실제 편향 한도 역시 현재 `null`이다.

## AP와 응답은 별도로 판독한다

- 같은 초기 입력의 AP 최고값 차이 예측은 PAR−CPU **+0.793~+0.816°C**다. 관측 최고값 차이는 +0.3/−2.4°C로 방향이 달랐다. 세션별 AP 조회 시각·창 끝·초기 상태가 다르고 내부 갱신 시각도 보장되지 않아, 이 두 최고값 차이로 열 검정의 반복 수를 산정하지 않았다.
- AP 평균오차를 모든 미래 최고값의 허용폭으로 삼지 않는다. 시작 온도를 뺀 경로는 보조 설명이고 절대 최고 AP를 대체하지 않는다. 센서0.1°C 표시 간격은 독립 열 효과를 0.1°C까지 구분한다는 증거가 아니다.
- 응답은 기존에 관측한 PAR 긴급P95 약456~469ms 개선과 전체 기한96/96을 사용한다. 이 서비스 결과만으로 에너지·열 최적화 목표가 완료된 것은 아니다.
- 에너지 절감이 있더라도 열 증가를 얼마까지 허용하는지 정하지 않은 상태에서 하나의 종합 점수·정책 승자를 만들지 않는다. 모형은 상충을 나타낼 수 있지만 사용자의 효용을 임의로 정하지 않는다.
