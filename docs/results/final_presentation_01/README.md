## 최종 주장의 범위

**A24의 등록된 혼합 AI 요청에서 실측 기반 일정·에너지·AP 시뮬레이터를 구현하고 새 온라인 실행과 대조했다. 병행의 긴급 응답 개선은 관측했으며, 작은 에너지·열 차이에 따른 정책 우열은 미판정이다.**

원래 목표인 응답 요구를 지키는 에너지·열 최적화 연구를 유지한다. 구현·예측 평가 완료와 일관된 절감 정책 입증을 구분한다. 보편적인 최적 정책·배터리 사용시간 연장·열 안전 보장은 이번 성과에 포함하지 않는다. `experiment_ready=false`, `strict_supported=false`, `accuracy_pass=null`, `policy_winner=null`을 유지한다.

### 슬라이드 3에 넣을 방법

- A24 EfficientNet-Lite0 분류와 EfficientDet-Lite0 탐지. CPU 우선과 분류 GPU＋탐지 CPU 병행 정책, resident runtime4·warmup8/세션.
- 비교 순서 CPU/PAR, PAR/CPU, PAR/CPU, CPU/PAR. 8세션 본 요청 총1,536개. 도착은 이전 완료와 독립이고 기기에 인위적인 감속을 넣지 않았다.
- 분리 개발3에서 동결한 모형을 사용했다. 초기조건은 저장된 부하 전 AP와 −20~30초 평균 기기 전력이다. 이후 실제 전류·AP·미래 완료시각은 B의 예측 입력에 사용하지 않았다.
- 기기 전체 에너지 J, 지정 AP 센서 온도. 전류 raw=mA 해석은 조건부이며 절대 에너지 정확도는 인증하지 않았다. AP는 BAT·표면온도와 다르다.
- 독립 확인은 계수 적합에 사용하지 않은 세션이라는 뜻이다. 연속 실행의 열 이력이 통계적으로 독립이라는 뜻은 아니다.

## 시연 순서와 정확한 문장

1. [통합 화면](../simulator_workbench_01/index.html)을 로컬 브라우저로 열고 등록192요청을 선택한다. “이 화면은 저장된 실측과 예측을 보여 줍니다. 현재 휴대폰을 측정하는 화면은 아닙니다.”
2. [전체 결과](../online_policy_study_01/overnight_sustained_run01/index.html)에서 8세션·192/192를 보여 준다. 그림1로 응답 개선을 설명하고 그림2로 에너지·열 우열 미판정을 설명한다.
3. 첫 CPU/PAR의 경로를 연다. “A는 실제 lane 일정을 입력으로 썼고, B는 예정 도착에서 일정을 생성했습니다.”
4. 아래 두 명령으로 같은 초기조건의 B 계산을 재현한다. “이 값은 동결 모형의 계산이며 실제 정책 절감량이 아닙니다.”

저장소 루트에서 Python·NumPy·Matplotlib 환경을 사용한다. 두 출력 디렉터리는 새 경로여야 한다. 이미 존재하면 기존 결과를 보존하고 새 이름을 사용한다.

```powershell
python -B -m tools.d1_sustained_readout predict --bundle docs/results/online_policy_study_01/overnight_sustained_run01 --index 0 --policy CPU_URGENT_ONLINE_V1 --output output/presentation_cpu
python -B -m tools.d1_sustained_readout predict --bundle docs/results/online_policy_study_01/overnight_sustained_run01 --index 0 --policy B2_PARALLEL_ONLINE_V1 --output output/presentation_par
```

기존 검증된 계산값 CPU185.389926J/PAR183.299134J, 차이−2.090792J다. 같은 초기조건 모형의 PAR 최고AP 증가는+0.728~+0.748°C이며 실제 관측 최고AP 차이−0.4~+0.4°C와 다르다. 이번 자료 묶음을 만들면서 예측을 다시 실행하지 않았다. 준비되지 않은 환경에서는 저장된 결과로 동일한 설명을 할 수 있다. HTML은 GitHub 파일 화면이 아닌 로컬 브라우저에서 연다.

## 질문에 대한 답변

- **에너지·열 모형을 만들었나?** 등록된 조건에서 두 출력을 계산하고 새 실행과 오차를 대조했다. 범용 물리 모형이나 작은 정책 차이를 보장하는 모형은 아니다.
- **병행이 배터리를 아끼나?** 최신4쌍의 에너지 차이는−5.304~+11.682J로 방향이 바뀌었다. 사용시간 연장·일관된 절감은 입증하지 않았다.
- **발열이 늘었다는 결과인가?** 실제 최고AP 차이는−0.4~+0.4°C다. 약+0.73°C는 같은 초기조건의 모형 예측이다.
- **최적화를 완성했나?** 구현·예측 평가·정책 비교는 완료했다. 에너지·열 최적 정책의 우월성은 미입증이며 이를 최종 한계로 명시한다.
- **추가 실측이 필요한가?** 이 제한된 결론의 제출에는 필요하지 않다. 더 강한 절감 주장에는 실용적 효과 크기와 오차·편향을 구분할 설계가 먼저 필요하다.
- **S26도 같은 결과인가?** 아니다. [S26 인계](../../team/S26_HANDOFF_20261003.md)의 기기별 모델·실행 증거로 별도 작성해야 한다.

```powershell
python -B docs/results/final_presentation_01/build_figures.py
```

기존 CSV만 읽어 같은 디렉터리의 파생 그림·표를 갱신한다. 과거 원본·모형·원 결과는 쓰지 않는다. PNG는16:9, SVG도 제공하며 벡터 글자는 폰트 이식 문제를 줄이기 위해 경로로 저장한다. SVG는 편집 가능한 네이티브 PPT 차트가 아니므로 담당자가 차트를 편집하려면 원 CSV와 표를 사용한다. 한국어 글꼴 맑은 고딕/Noto Sans CJK KR/나눔고딕 중 하나가 필요하다.

[검증 기록](verification.json)은 source SHA, 생성 코드·출력 hash와 검증 시각을 보존한다. 원 CSV의4쌍 차이를8세션에서 다시 대조하고, 모든192/192·중복 없는8행·strict/accuracy 상태·동결 모형 SHA 불변을 검사했다. PC 그림 검증은 새 실기기 검증이 아니다.
