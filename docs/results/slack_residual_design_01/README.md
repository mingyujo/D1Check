# 기한 여유를 쓰는 보정 RL — 재설계 완료

2026-10-08 · SLACK-RESIDUAL-DESIGN-01

**새 방향은 SHARED_EFT를 기본으로 두고, 실제 기한 안에서 배정·허용 병행·짧은 대기를 보정하는 RL이다.** 현재 완료된 것은 설계와 기존 기록의 원인 분석이다. 새 정책 구현·성능 배치·학습은 시작하지 않았다.

## 왜 바꾸는가

기존 규칙의 추가 예약은 실제 기한보다 ‘처음 EFT가 예측한 완료시각’을 앞세웠다. 12,672요청 중12,403개가 이른 예약을 받았고, 선언된 기한과의 차이는 평균2.986초였다. 예약 검사만으로 탈락한 후보가579,528개였다.

예약 라벨을 제외하면 6,776 callback에 추가 즉시 배정이 나타난다. **실제 기한을 지킬 수 있는 대안6,776개라는 뜻은 아니다.** 기록에 모든 후보의 guard 응답이 없으므로 새 prototype에서 재검증해야 한다. 늦춰도 되는 여유를 이미 입증했다고 해석하지 않는다.

## 바뀌는 핵심

| 기존 | 새 설계 |
|---|---|
| 최초 EFT 예상 완료시각까지 유지 |원래 긴급1.5초·일반6초 기한으로 재검사|
| 내부 EFT_REFERENCE로 복귀 |정확한 SHARED_EFT로 복귀, Band는 별도 비교|
| 적격 계획들의 첫 요청/backend가 같음 |단건과 분류GPU+탐지CPU 2건 배정 묶음, 제한 대기|
| 반복 callback의 signed J 예산 검사 |모형 점유시간을 관측하고 전체 에피소드 J 악화를 별도 제약으로 학습|
| 후보/WAIT 이름의 차이 |실제 같은시각 배정 집합과 점유 prefix 차이를 검사|

**기한·전체 완료·긴급 P95 비악화·에너지 비악화 기준은 유지한다.** 물리 계수·모형 지원·기본 정책·strict·experiment_ready=false도 유지한다. 추가 예약을 제거하는 새 정책을 만들며 원 R2 결과를 고치지 않는다.

## RL이 맡는 일

기본 정책을 따를지, 기한 안에서 다른 CPU/GPU 배정이나 허용 병행을 사용할지, 짧게 기다릴지 선택한다. 모델 예측에서 에너지를 줄이는 병행과 열 최고값을 높이는 병행을 구분할 수 있도록 상태별 점유시간·현재 모형 온도·이미 관측한 최고값·원 기한 여유를 입력한다.

후보 요청은 최대8개, 행동은32slot, 관측107개·후보별특징61개로 설계했다. Actor는 후보 공통 encoder를 쓰고 critic은 열 보상과5제약을 다룬다. 관측한 응답/P95도 입력하며, 에너지·서비스 제약은 SHARED_EFT와 Band 각각에 대해 유지한다. 새 학습은 옛85관측/17행동 PPO의 연장이 아니다.

2건 묶음은 engine을 바꾸지 않고 같은시각의 연속 단건 callback으로 실행한다. 실제 lane 반환 전에 재사용하지 않는다. 이미 실행 중인 작업의 과거를 짧은 처리문맥으로 다시 해석하지 않고, 관측 overrun이면 기본 판단으로 복귀한다.

## 학습을 시작하는 조건

1. 의미·lane·묶음·aging·미래정보 금지 검증을 통과한다.
2. 실제로 다른 실행을 만드는 복수 행동이 있다.
3. 개발자료의 전체 실행에서 기한·완료·긴급 P95·J를 악화하지 않는 열 개선 신호가 있다.
4. 계산 비용과 소스·입력·예산·시간·체크포인트 계약을 고정한다.

그 전에는 학습0이다. 기존 작은 공동 이득 일정은 긴급P95가671–790ms 늘고 미래입력을 사용했으므로 이번 기준의 성공 teacher로 사용하지 않는다. PPO의 벌점/승수가 있다는 이유로 정책을 적격으로 채택하지 않는다.

제안 예산은 기존 잔여17,759환경에서 최대13,912환경이다. 본학습3seed×2,032=6,096과 학습fixture48을 합쳐 전체학습6,144 상한을 유지한다. 세 learner의 공통case별 SHARED_EFT와 Band 참조를 완전한 binding으로 cache하는 것이 예산의 전제이며, cache 불일치 때 자동 재계산하지 않는다. 숫자는 조건부 후속 배분이며 이번 실행 허가가 아니다. training 벽시계는 prototype 계산비용 확인 전null이다.
