## 재사용한 근거와 새 가정

- 원 동결본: [separated-power-model-v1](../online_policy_study_01/overnight_sustained_run01/model.json), SHA `5682082a936b7c83efeee747ceeb64fd0c64f0bef8765bbf1b90b807db872db2`. 개발3의 상태별 추가W·AP 식/계수·준비 이력 초기화를 변경하지 않았다. 새 적합0.
- 상태: resident idle, 분류CPU, 분류GPU, 탐지CPU, 분류GPU+탐지CPU. 탐지GPU·두 분류 동시 실행 등 비용이 없는 상태는 제외했다. CPU 공유 lane·GPU lane의 소유권은 dispatch→lane_available다. output_ready 또는 worker_release에서 조기 재사용하지 않는다.
- **새 처리시간 가정:** 개발 정책별 같은 task/backend/priority의 5단계 평균 벡터를 문맥별 동일 가중 평균한다. 분류CPU는CPU개발1, 분류GPU는병행/직렬개발2, 탐지CPU는개발3 문맥을 사용한다. 같은 프로필을 모든 기준선/후보에 적용한다. 정책마다 자기 측정 시간을 붙여 이득을 만들지 않는다. 문맥 불변성·새 일정의 간섭·온도에 따른 처리시간은 미검증이다.
- 민감도: 각 cell의 전체5단계 벡터 중 합이 짧은/긴 실제 개발 문맥 벡터를 각각 simulated realization으로 사용한다. 단계별 최솟값을 조합하지 않는다. **정책이 보는 추정값은 계속 평균**이다. 이것은 기존 문맥 차이에 대한 민감도이며 확률분포·신뢰구간·미래 최악 한도는 아니다. 3배열도 원시 요청별 변동을 모두 포괄하지 않는다.
- 초기조건은 이미 본192요청의 initial index0에서 부하 전 AP 이력/평균W만 사용했다. 확인 후 AP·전류·실제 미래 완료는 입력에서 제외했다. 기존 확인 자료를 통한 초기조건 선택과 이번 정책 설계는 사후 연구이며 새로운 독립 확인으로 부르지 않는다.
- 기존 low/queue/burst 24입력의 도착 간격·모델·등급을 유지하고 공통 시작에35초를 더했다. 원192/400ms도 함께 사용했다. 과거 seed201을 유지했지만 이번엔 결정론적 개발 평균이어서 seed가 독립 반복을 만들지 않는다. 기존 CAL03 간섭계수1.5를 여기에 이식하지 않았다.
- 전력·열 계수는 실측 유래, 처리시간의 자유 배정 전이는 가정이다. AP는 과거 모델 상태를 이어 계산하며 새 실제 AP 피드백은 없다. 초기 AP=주변온도 가정, S26 계수, 임의 스로틀·전력 상수는 추가하지 않았다.

## 같은 실행기 안의 다섯 정책

모두 같은 도착·입력·3cell·기한(긴급1.5초/일반6초)·EDF/4초 aging·비선점·resident·worker 소유권을 쓴다. 따라서 아래 이름은 과거 Android B2/B3 정책의 정확한 재현 ID가 아니라 **공통 조건으로 연결한 새 PC 기준선 ID**다.

|ID|의사결정|
|---|---|
|CPU_REFERENCE|전부CPU, 전체 직렬|
|SPLIT_SERIAL_REFERENCE|분류GPU/탐지CPU 고정, 전체 직렬|
|SPLIT_REFERENCE|같은 고정배정, 지원된 병행 허용|
|EFT_REFERENCE|현재 도착한 head 요청의 가장 빠른 예상 응답 경로 선택|
|ENERGY_AP_REQUEST_V1|현재 도착한 큐를 대상으로 배정·즉시/250ms 유예 비교; 도착 후 자발적 유예2초 이내|

후보는 현재 실행 요청의 경과시간과 고정 평균으로 남은 점유를 추정한다. 미도착 요청이나 엔진의 실제 잔여시간은 받지 않는다. 후속 도착을 미리 읽지 않는 대신, 새 도착·실행 단계·lane 해제·예약 재검토 시점에 다시 판단한다. 초과 실행으로 잔여시간이 불명확하면0으로 바꾸지 않고 실제 이벤트를 기다린다.

각 행동은 현재 도착한 큐를 끝내는 작은 예측 일정을 만든다(나머지는EFT). 알려진 미응답 요청의 기한을 만족하고 **같은 큐 EFT의 예측 최고AP보다 높지 않은 행동** 중 공통120초 잔여J 최소를 선택한다. 동률은 낮은AP→빠른 시작→CPU다. 적격 행동이 없으면EFT를 쓰고 fallback/기한 위반을 기록한다. 이미 발생한 위반은 전체 결과에 남는다. 이 상대 열 조건은 제안 규칙이며 안전상한·전역 무악화·미래 요청의 기한 보장이 아니다.

정책 계산·추가 기록 비용은 PC에서0으로 가정했다. 측정된 전처리·출력·저장·worker release 단계는 유지했다. 실제 Android 정책 비용·실시간 numeric AP 전달 경로는 검증하지 않았으며 이번에 배포하지 않는다.

## 다른 입력과 민감도: 후보를 채택하지 않은 이유

|입력|EFT→후보 기한 준수|후보−EFT J|후보−EFT 최고AP °C|판독|
|---|---:|---:|---|
|low24|24→24|−0.043|+0.020|긴급P95 156→1356ms. 거의 같은 에너지에 응답 손해|
|queue24|20→20|−0.086|+0.048|둘 다 전체 기한 미충족. 고정병행은22/24|
|burst24|23→21|+0.043|−0.023|서비스가 악화하며J도 증가. 고정병행23/24|
|sustained192|192→192|−1.364|−0.187|평균 모형 내 상충 개선 가능성, 응답 손해|

국소AP 조건을 지켰는데 전체 최고AP가 올라간 low/queue 결과도 보존했다. 국소 비교의 이후 실제 도착·재판단 일정이 달라지므로 전역 무악화가 보장되지 않는다. 이는 코드를 다시 맞춰 없애지 않은 후보의 설계 한계다.

긴 개발 문맥 벡터를 실현값으로 사용한 sustained 민감도에서는 **후보191/192, EFT·고정병행192/192**였다. 후보J 개선은−1.238~−1.537J, 최고AP−0.154~−0.198°C로 남지만 기한 안정성을 확보한 정책이라고 할 수 없다. 과거8세션의J오차를 이 새 후보의 보편오차한도로 적용하지 않으며, 그보다 작은 차이를 바로 실측 절감으로 읽지 않는다.

현재 전력식 `E=P_preload*T+Σincrement[state]*occupancy[state]`에서는 같은창·같은 상태 점유시간의 순서만 바꿔J가 줄지 않는다. 후보의J 차이는 주로 자원 선택과 겹침 시간의 변화다. 시작 유예 자체의 절전 기능이나 온도→처리시간 효과를 발명하지 않았다. 최고AP 저하는 늦은 냉각·응답 지연과 함께 판독해야 한다.

**종료 판정:** 요청별 정책 비교 경로 구현·제한 탐색 완료. 후보1개를 구현했고 결과 후 재튜닝·두 번째 후보 검색은0이다. 강한 고정 기준선을 넘어섰다고 채택하지 않는다. `policy_winner/accuracy_pass=null`, 기존 strict/선택guard/experiment_ready=false 불변이다. 동일 B2 반복 실측이나 새 계측 계획을 만들지 않았다.

**다음 PC 작업 하나:** 이번에 저장한 후보의 대기 결정에서, 작은J/AP 이득 때문에 소모한 요청별 기한 여유와 긴 문맥191/192 위반의 연결을 분해한다. 그 근거로 대기 허용 규칙을 고칠지/배정만 유지할지 결정하며, 같은 전체 배치나 추가 실측부터 반복하지 않는다. 이 작업 없이 현 후보의 실기기 절감을 검증하려는 실행은 권고하지 않는다.

## 검증·재현·보존

신규15+기존 이벤트15+기존 열탐색10+기존 판독4 = **44테스트 통과**. 실제 엔진 진입, 미래도착 변경에 대한 결정 prefix 불변, private lane 차단, lane 해제, AP 기존식/온라인 누적 일치, 유예2초 상한, 처리시간 문맥 변동, 미완료 냉각null, J적분/상태 순서 불변, 기존 strict 차단을 확인했다. PC 통과는 기기 안정성/간섭 식별이 아니다.

첫 CLI는 `-m` 실행의 클래스 identity 검사 결함으로 첫 계산 전 중단했다. 명시적 프로토콜 인터페이스 검사로 수정했다. 첫 완료60계산에서는 미완료split의 이후AP 표시 결함을 발견했고, 후보/입력/추정법은 그대로 둔 채 판독만 수정해60개를 재생했다. `evaluation`(진입 중단), `evaluation_v2`(수정 전 판독), `evaluation_v3`(최종,23.446초)를 로컬에 보존하며 Git 공유는v3만 한다. 이PC 재실행은 기기 재시도가 아니다. 과거1200개 전체 배치를 반복하지 않았다.
