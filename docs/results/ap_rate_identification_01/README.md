# AP 냉각률·부하 반응을 기존 자료로 어디까지 구분했는가

2026-10-02 · [그림·요약](index.html) · [적합 전 고정한 분석 계약](contract.json) · [검증](verification.json) · [전체 수치](final/scores.csv)

**냉각률과 부하 크기를 조정하는 것만으로 남은 열 반응을 해결하지 못했다.** 구조 하나를 기존 개발 1세션에만 적합했다. 부하 반응을 0.720002배로 줄이면 평균오차는 일부 개선되지만 부하가 있는 7세션 모두 최고온도 절대오차가 커진다. 새 진단 후보는 채택하지 않는다. 기존 준비 이력 후보의 두 독립 확인 결과와 제한 시뮬레이터는 그대로 유효하며, 일반 동적 AP·열 피드백의 지원을 확대하지 않는다.

새 기기 명령·실측·APK·실행 계획·claim은 모두 0이다. 기존 동결본·원본·소비 계획·기본 엔진·strict·experiment_ready=false는 보존했다.

## 무엇을 실제로 계산했나

이미 본 개발/확인/전이 7세션과 무부하 C·부하 L 대조를 재사용했다. 이번 부하 자료는 모두 짧은 CG_DC 24요청 사례다. `cgdc_transfer`는 9월의 긴 1,073요청 진단과 다른, [24요청 전이 자료](../energy_ap_cgdc_transfer_01/run01/data/summary.json)다. 자료 출처·해시는 [입력 번들](final/inputs.json)의 source_sha256에 있다.

- 적합: 기존 `idle_development` 1세션만 사용.
- 적합 제외 평가: 기존 확인·전이·한 묶음·두 반묶음·최근 +35/+65초의 6세션. **모두 결과를 본 뒤 선택한 이번 구조에는 사후 평가**다. 최근 두 세션이 변경 없는 이전 후보의 독립 확인이라는 사실은 유지한다.
- 무부하 C: 본 작업 0이지만 runtime/warmup 준비는 수행했던 resident 대조다. baseline 이후부터 공통 원점 +35초 전의 AP만 초기화에 사용하고 이후 표본으로 평가한다. 가상 작업을 만들지 않는다.
- 부하 L: 필요한 부하 전 55초가 없으므로 후보 점수는 계산하지 않는다. 관측 경로·고정 구간 변화는 삭제하지 않고 함께 남겼다.

기존 식의 β와 공통 배율 k만 대상으로 삼았다.

```text
u = 기존 상태 AP 기울기 − resident_idle 기울기
dT/dt = β(E − T) + k·u + H
dH/dt = −H / 30
```

τ=30초·γ=0·상태별 상대 기울기·실제 lane 일정은 고정한다. 매 β에서 부하 전 AP만으로 E/H를 같은 절차로 초기화한다. E는 주변 온도가 아니고 H는 측정된 내부 열이 아니다. 그 뒤 관측 AP·전류는 예측 입력에 넣지 않는다. β는 기존 값의 0.2–5배를 로그 간격 61점으로 고정했고 각 점의 k≥0은 개발 AP 최소제곱으로 계산했다. 결과를 보고 범위를 확대하거나 다른 구조를 추가하지 않았다.

최적 β는 **0.045932520308001434/s**, 기존 값과 같은 격자점이다. k=**0.7200023282045722**, 개발 RMSE=0.258923°C. 이것은 기존 β가 모든 조건에서 맞다는 증명이 아니다. 최저 RMSE+0.05°C의 기술적 민감도 범위는 β=0.035126–0.063374/s, k=0.499776–0.962386이다. **신뢰구간·생리적 범위·합격 기준이 아니다.** 두 계수의 개발 수치 Jacobian은 rank2/정규화 조건수1.668이지만 물리적 유일성·새 조건의 정확도를 보장하지 않는다.

## 결과: 평균 개선으로 최고온도 악화를 숨기지 않는다

비교 대상은 최초의 절대 AP식이 아니라 이미 고정된 **준비 이력 후보 τ30/γ0**다. 모든 점수는 각 세션의 첫 부하 이후 AP 표본부터 마지막 유효 표본까지의 같은 창이다. 공통 120초 전체 점수가 아니며 창·분모는 CSV의 first_s/last_s/samples로 고정했다. 최고온도 오차도 이 표본 창의 최고값 차이이고 연속 시간의 진짜 최고 인증이 아니다.

| 개발: 적합 | 0.182549→0.162043 | −0.191308→−0.506260 |
| 기존 유휴 확인 | 0.256938→0.231813 | −0.072827→−0.273359 |

개발 외 부하 6세션 중 5개 MAE는 감소하지만 +65초는 MAE·최대·최고가 모두 악화한다. 부하 7개 전부 최고 절대오차가 증가한다. **평균오차의 개선만으로 부하 크기를 낮추는 수정을 채택하지 않았다.** 파일은 `ap-rate-gain-diagnostic-v1`의 미채택 사후 결과로만 보존한다. 같은 자료에 추가 후보를 맞춰 성공 결과를 찾지 않았다.

## 무부하와 이력에서 좁혀진 것

[고정 구간 변화](final/observed_windows.csv)에서 C는 90–115초와 120–145초에 각각 +0.1°C 상승했고 150–175초에는 −0.1°C였다. 본 작업 없이도 일부 작은 상승이 있다. 부하 세션의 150–175초 상승과 **같은 시점·같은 원인이라고 주장하지 않는다.** APK·초기 이력·측정 시점이 다르고 C→L 한 순서뿐이므로 대조를 빼서 부하의 인과 효과로 쓰지 않는다. AP가 0.1°C 단위로 보고된 작은 변화는 센서 양자화·갱신의 한계와 함께 읽어야 한다.

C에서는 u=0이므로 k에 대한 정보는 정확히 0이고 k=null이다. 준비 이력 후보의 C 오차는 MAE0.346076°C로 모두 양수다. 부하 배율 수정으로 이 오차를 없앨 수 없다. 그렇다고 원인을 주변 온도 변화·센서 지연·잔열 중 하나로 특정할 수도 없다. 기존 +35/+65초 관측은 등록 부하의 시점 차이를 제공하지만, 같은 새 APK의 무부하 대조를 포함한 짝지어진 자료는 아니다.

두 감쇠율을 모두 자유롭게 만들면 무부하 해 `T=E+A·exp(−βt)+B·exp(−t/τ)`에서 두 지수항의 이름을 바꿔도 같은 AP가 된다. 테스트로 이 대칭을 확인했다. 이는 **두 자유 감쇠율의 물리적 명명에 관한 한계**이며 τ를 고정한 이번 β의 수치 추정이 불가능하다는 뜻은 아니다. AP 하나만 보고 두 계수를 서로 다른 실제 내부 열 부품에 대응시킬 수 없다.

세 부하 상태(CG, DC, CG_DC)의 단위 반응 열은 수치 rank3이나 정규화 조건수는 세션별 4.76–455.14로 차이가 크다. 짧은 병행·단독 점유와 센서 갱신 때문에 기여가 불균형하다. rank 충족만으로 각각의 반응 계수를 정밀 식별했다고 하지 않았고 상태별 재적합도 하지 않았다. [시간 경로](final/observed_paths.csv)는 공통 원점과 마지막 lane 해제 이후 시간을 모두 남겼으며 관측 최고점에 맞춰 시간을 이동하지 않았다.

## 종료 판정과 필요한 최소 해결 조건

이번 PC 작업의 종료 조건은 **기존 β 고정이 단순 오류인지 점검하고, 공통 부하 크기 조정 하나의 재사용 가능성과 무부하의 식별 한계를 수치로 판정하는 것**이다. 완료했다. 코드상 시간 정렬·기존 계수 손상 등의 새 결함은 발견하지 않았다. 계수 두 개의 조정만으로 후기·최고 반응을 해결했다는 주장은 기각했다.

현재 사용 가능한 범위는 기존 일정/응답 시뮬레이션, 정확히 연결되는 CPU/B2 실측 비용 대조, 실제 lane 일정과 충분한 부하 전 AP를 입력으로 쓰는 **기존 준비 이력 후보의 제한된 조건부 평가**다. 기존 독립 확인 MAE0.178596/0.189876°C는 유지되지만 모든 일정의 보편 오차한도·정책 순위에 쓰지 않는다. 원래 전력식의 오차와 온도→처리시간 연결도 이번 계산으로 해결되지 않는다.

제한된 프로젝트 결과를 완성하는 데 새 실측은 필수가 아니다. **후기·최고 AP까지 예측하는 열 정책으로 확대하려면 다음 공백을 해결해야 한다.**

| 남은 질문 | 기존 자료의 부족 | 최소 해결 조건 | 완료 판독 |
|---|---|---|---|
| 준비 후 배경 변화인가, 등록 부하에 따라 이동하는 반응인가 | 새 APK +35/+65에는 무부하 짝이 없고 기존 C/L은 초기 이력·순서가 다름 | 같은 APK/resident/runtime/warmup/관측으로 무부하와 부하 시점 대조. 기존 +35/+65는 사후 제약으로 재사용하되 새 동등 조건이라고 합치지 않음 | 공통 원점과 실제 부하/lane 종료 상대 시간 둘 다에서 방향·형태·최고 시점을 비교. 구분 안 되면 미식별 종료 |
| 수정 반응이 다른 실행에도 예측력을 가지는가 | 이번 한 개발 적합의 이득과 악화가 공존 | 위 자료로 구조·추정 절차를 정한 경우 별도 실행은 개발에 쓰지 않고 동결 후 확인에 남김 | 절대/변화 AP·MAE·최대·최고·구간 잔차를 모두 보고. 사후 임계값·실패 후 자동 재적합 금지 |

기존 기록의 AP 간격은 대략 2–3초이고 짧은 병행은 그와 비슷하거나 짧다. 실제 read bracket·lane 경계·준비 전후 기록이 필요하다. 후기 질문은 현재 확보된 공통 원점 150–175초까지의 구간을 포함해야 한다. 이는 **필요한 관측 범위**이며 충분한 세션 길이·반복 수·예산을 확정한 실행 계획은 아니다. 주변 온도는 실제 관측할 때만 사용한다. 순서 변동을 구분할 통제와 계수 개발/확인의 독립성이 필요하며 한 C/L 쌍으로 통계적 안정성을 보장하지 않는다.

**다음 행동 하나:** 열 정책 범위로 확장할 경우 위의 ‘무부하 배경 대 부하 시점 반응’ 대조를 한 묶음으로 고정한다. 같은 B2 실측 단순 반복, 또 다른 전체 감사, 새 후보 무제한 탐색은 하지 않는다. 이번에는 실행기·예산·승인·소비 기록을 만들지 않았다.

## 재현과 검증

저장소 루트에서 Python·NumPy·Matplotlib로 실행한다. 작은 공유 파생 입력만 필요하며 ADB/SDK/원본 모델 바이너리는 사용하지 않는다. 출력 경로는 새 경로여야 한다.

```powershell
python -X utf8 -B -m tools.d1_ap_rate_identification --output output/ap_rate_identification_check
python -X utf8 -B -m unittest tools.test_d1_ap_rate_identification -v
python -X utf8 -B docs/results/ap_rate_identification_01/verify.py
```

원본 해시까지 다시 확인할 때만 마지막 명령에 `--archive <D1Check_Arrival_Extension 경로>`를 추가한다. 외부 원본이 없는 환경의 기본 검증은 공유 파일만 검사하며 원본 확인으로 표시하지 않는다.

관련 테스트 8건: 합성 계수 복원·선형 반응·미래 AP 누설 방지·확인 자료 적합 차단·무부하 미식별·감쇠항 교환·초기화 시간 경계·결측/미지원 차단을 확인했다. 실제 CLI로 모든 공유 수치를 만들고 기존 7세션 점수·동결 해시·CSV/그림 수치를 대조했다. PC 통과는 물리 식별·새 독립 확인·기기 안정성 증명이 아니다. 상세 명령/시점/HEAD/파일 해시는 verification.json에 있다.
