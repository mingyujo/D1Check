# 산업공학 ECT·SPT·EDD의 동일 조건 검증

**세 단순 규칙을 가져오는 것만으로 현재 목표를 해결하지 못했다.** SPT/EDD + ECT는 주96조건의 전량·실제 기한·긴급P95를 유지했지만, 공용 SHARED_EFT보다 평균 AP를 0.065317°C 낮추는 대신 J를 0.080970 늘렸다. Band 적용 대비 주96조건 공동감소는 0이다. FIFO + ECT는 긴급 지연이 커졌다. 기본 정책·원 모형·strict·`experiment_ready=false`는 그대로다.

## 무엇을 검증했나

- `IE-DISPATCH-PC-01`, 고정 정책3개. FIFO/SPT/EDD가 작업 순서를 정하고 동일 ECT가 자원을 선택한다. ECT는 **5단계 전체 lane 반환 시각**을 최소화하며 SHARED_EFT의 응답 완료 최소화와 구별한다.
- SPT 처리시간은 지원 자원 중 최소 mean 전체 점유시간. EDD는 도착+실제 응답 기한순이다. 동점·공개 phase 재판단·예상 overrun 대기는 결과 전에 고정했다. 추가 aging/긴급 가중치/기한 보호·냉각 wait·drop·튜닝은 0회다.
- 원 ECT/SPT/EDD의 핵심 원리를 적용한 **제한적 B**다. 이종 자원 처리시간 축약·허용 병행·응답/기계 완료 차이를 대응표에 명시했다. 제조현장 시스템 전체, 정확 HEFT, StarPU를 실행한 비교가 아니다.
- 완료된 최신192조건: trace seed610880001..610880016 × low/queue/burst/sustained × mean/short/long. 입력/시작 상태·기한·5단계 비용·전체120초·최대2건·허용 병행·seed201은 동일하다. 이미 본 자료의 진단 비교이며 새 독립 시험이 아니다.
- 3새정책576환경 + 6완료정책1,152행 재사용 = **9정책1,728행/114,048논리 요청**. 재사용은 SHARED_EFT, 내부 EFT_REFERENCE, Band whole-request, Triton 제한해제, 우리 ENERGY_AP, ARRIVED_QUEUE. 진행 중/미완료 학습 결과 사용0.
- 함수13검증(규칙8/판정5)과 엔진 fixture6·기존2EFT 재현을 완료했다. 기존2정책 첫 조건의 **전체 요청 원장과 주요지표가 정확히 동일**했다. 실제 새환경584/38,100예정 요청·실행 실패0. 모든 새 정책 원장/기한/점유/인과경계/ECT순서와 J독립 적분을 확인했다.

## 주요 결과

다음 차이는 **후보−기준, 조건별 차이의 평균**이다. 주평가는 결과 전 고정된 low+sustained96조건이다.

| 주96조건, SHARED_EFT 대비 | 긴급P95 차이 | 일반 평균 차이 | J 차이 | 최고 AP 차이 | 서비스 비악화 | 전기한+J/AP 공동감소 |
|---|---:|---:|---:|---:|---:|---:|
| 선착순 + ECT | +556.754ms | +7.863ms | −0.045339J | −0.029670°C | 48/96 | 0/96 |
| 짧은 작업 우선 + ECT | 0ms | +63.739ms | +0.080970J | −0.065317°C | 96/96 | 4/96 |
| 기한 우선 + ECT | 0ms | +63.739ms | +0.080970J | −0.065317°C | 96/96 | 4/96 |

SPT/EDD의 **실제 전체 요청 원장은192/192조건에서 동일**했다. 이는 일반적인 두 알고리즘의 동치가 아니다. 이번 두 작업·고정 처리시간/기한·도착 구성에서는 선택이 같았다. 같은 효과를 독립 후보 두 개의 성공으로 합산하지 않는다.

- SPT/EDD − Band 적용: 주96 평균 J **+0.169820**, AP **−0.053022°C**, 긴급P95 0ms, 일반평균 +63.764ms. 전기한+공동감소 **0/96**.
- 과부하를 포함한 전체192에서 SPT/EDD는 긴급 실패0이나 일반 실패 **292**, SHARED_EFT204/Band193. FIFO는 긴급560·일반207이다. 모두12,672/12,672요청을 완료했지만 완료와 기한 성공은 다르다.
- 전체192 Band 대비 SPT/EDD의 상대적 공동감소 **1/192**는 queue/long/seed610880005다. 후보와 Band 모두 일반 기한 위반이 남았다. 전체 기한을 충족한 공동감소는 **0/192**다. `joint_gain`(상대 서비스 비악화)와 `joint_gain_all_deadlines`(추가 전기한)을 CSV에 별도로 남겼다.
- low48은 모든 단순 규칙/SHARED/Band가 비용·서비스 동률. sustained48의 평균 분류GPU 배정 수는 SHARED65.479/Band59.646/SPT·EDD50.188이다. 자원 선택·대기/순서 차이가 실제 점유와 병행 시간을 바꿨다. CPU 분류를 늘려 AP를 낮춘 변화가 여기서는 J 증가와 연결됐다. 전체 에너지·열의 인과적 기기 효과를 뜻하지 않는다.

기존 우리 열·에너지 두 규칙도 같은 입력의 비교표에 포함했다. ENERGY_AP는 긴급703/일반517, ARRIVED_QUEUE는 긴급338/일반410실패였다. 이들도 현재 목표를 입증한 채택 정책이 아니다. “우리 정책이 항상 우수하다”는 결론을 내리지 않는다.

## 근거의 범위와 남은 일

모형은 기존 A24 기반 `5682082a…` 그대로다. 시간의 mean/short/long 전이는 공통 가정이며 새 실측이 아니다. J는공통0..120초 whole device, 최고AP는35..180초1초격자다. **AP를 최고 표면 온도라고 쓰지 않는다.** 표면 온도/안전 온도 한도·초과시간/미지원 자원의 비용은 계산 불가다. 조용히0이나 S26 계수를 넣지 않았다.

PC callback시간은 결과에 남기되 휴대폰 시간·J로 환산하지 않는다. 차등 제어비용0은 기존 모형 가정이다. 이미 확인된 이력 예측 잔차와 다른 조건의 작은 계산 차이를 보편 오차한도/확실한 실제 절감으로 해석하지 않는다. 이번 결과는 **같은 모형에서 위 대응 규칙을 적용했을 때의 상충**을 보여준다.

전체 본문 접근403은 접근 제한이고 원 규칙의 개념 확인 실패와 구분한다. 공식 출판사 검색 색인의 규칙 설명까지 확인했다. 원 동점/세부 실행기/현장 채택 정도는 확인되지 않아 자체 적용 설정으로 표시했다. 규칙 조건이 없는 외부 제품 이름을 붙이지 않았다.

이 비교는 RL 재설계의 구현이나 gate 통과가 아니다. 새 prototype/학습/실측 자동시작0. 단순 규칙을 새 핵심 기여로 주장하기보다, **기한과 전량을 유지하면서 공용 EFT/Band 대비 열·에너지를 개선하는 추가 판단**에 연구 기여를 두어야 한다.

## 검증·오류·예산

- 결과 전 contract/input 참조/소스/대응표 고정, 소규모 fixture 후 첫6행 smoke를 포함해 전체 범위를 완료했다. 최대600신규환경/60분·마지막5분 저장, 실제584. 본학습/기기/ADB/설치0.
- 기존환경2241+이번584=**2825/20000**, 잔여**17175**. 기존 실패3/단계2 129/학습0/6144와 종료 clock을 보존한다. 후속 RL 제안13912가 그대로 승인·등록되었다는 뜻이 아니며 새 소비를 반영해 등록해야 한다(산술 잔여3263).
- 문서 탐색의 cp949 stdout 오류는 UTF-8로 재조회했다. 브라우저 검사 직접 파일 호출의 import 오류는 `-m` 진입으로, 체크 기록 함수 이름 오류는 checker의 `s.p.digest`로 고쳤다. 새 환경/정책 원본/판정 기준 변경은 없다.
- 초안은 상대 공동감소와 전기한 성공을 구별하는 열을 보완했다. 원 상대 수치를 삭제하지 않았다. 시각 확인 뒤 점 색상과 전체기한 미충족 표시를 맞췄다. 원 산출물/초안은 로컬에 보존했다.
- 오프라인 Chrome:5그림/1743표행·Band검색196행·검색복구 통과. 별도 소유 headless profile만 실행·종료했다. 사용자 HTML/PDF/VSCode·다른 worktree·다른 AP 작업/미커밋 변경은 보존했다.
