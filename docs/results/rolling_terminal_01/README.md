# 같은 종료 시각의 AP·잔열 조건을 가진 롤링 호라이즌

작업 ID `IE-ROLLING-TERMINAL-03`. 현재 첫 선택 검사에 **종단상태 제약**을 더하면 실제 유용한 선택이 남는지 개발 자료부터 점검한다. [생산스케줄링 종단제약 연구](https://www.sciencedirect.com/science/article/pii/S0377221721001223)의 계획 이후 상태를 고려하는 개념을 열 상태에 대응한 것이다. 원 논문의 재고/수요 알고리즘이나 실제 스마트폰 제어 전체를 재현한 비교가 아니다.

## 결과와 판정

**종단 AP 조건은 구현·검증했지만, 실제 개발24조건에서 새 정책은 Band와 실행 원장·KPI가 모두 같아 추가 이득이 없었다.** 사전 중단 기준에 따라 새 확인·학습을 진행하지 않고 미채택으로 종료했다. 개발 자료의 결과이며 독립 확인이나 롤링 호라이즌/RL 일반의 실패를 뜻하지 않는다.

|---|---:|---:|---:|

P95/최고AP는 조건별 값의 평균이다. 일반 기한 실패24건은 남아 있어 완료량과 기한 내 완료를 구분한다. Triton 고정 자원까지 포함한4역할96행 중 기준72행은 원 입력·코드·모형 해시와 일치한 개발 결과를 재사용했다. 외부 Band/Triton 전체를 실행한 비교가 아니라 저장소의 출처 기반 요청 배정 재현 규칙이다.

새 후보와 Band의24원장은 **합성 비용 원본명 `source_request_id`만 제외**하고 요청·배정·응답·저장·lane반환·상태 전체가 같았다. 조건별 J/AP/P95/일반 평균 차이는 모두 정확히0이었다. [원장 해시 대조](ledger_equality.csv). 원장은 같아도 정책 판단 코드/판단 횟수와 PC 계산 비용은 같다는 뜻이 아니다.

## 원 경로의 기회가 실제 정책의 기회는 아니었다

원 후보를 강제 재생한 개발24조건에서655개의 첫 선택 예측값을 복원했다. 기존 첫 선택 검사 통과633개 중 종단조건 통과338개·첫 prefix의 예측 이득291개였지만 **두 조건을 함께 만족한 것은2개**였다. 냉각269개는 종단조건을 모두 통과하지 못했다. 통과 대부분은 이미 Band와 같은 첫 선택/예측이어서 개선으로 세지 않았다.

유용2개는 첫 seed·지속·107.145383586초의 같은 요청에 대한 평균/짧은 실행 문맥 CPU 대기였다. 최악 예상 남은 J가 각각 약0.000697/0.001128J 낮고 종단 AP가 낮았지만, 같은 도착 seed·시점에 속한 가정 기반 기회이며 독립2반복이 아니다. [두 예측 사례](useful_probe_examples.json).

작은 실제 정책 파일럿에서는 처음부터 종단 조건으로 냉각을 차단하면서 경로가 바뀌었다. 종단검사540회 중377회를 차단했고 Band와 모든 결과가 같아졌다. 따라서 기존 원장 위에서 계산한 두 예측 이득을 새 정책의 성능으로 전용하지 않는다. **검사가 더 보수적으로 바뀌었다는 사실만으로 열·에너지 개선을 얻지는 못했다.**

## 모형·수식의 적용 범위

원식은 `dT/dt=−beta·(T−R)+k·u+h`, `dh/dt=(g·u−h)/30`이다. **g=0은 폰에 잔열이나 열 관성이 없다는 뜻이 아니다.** 이 동결식에서 새 부하가 추가 상태h를 구동하지 않는다는 뜻이며 T 자체의1차 열 관성은 유지된다. 초기 h는 음수일 수도 있어 물리적인 잔열양으로 그대로 해석하지 않는다. 이번 같은H의 h 차이 최대1.735e−18은 수치 반올림 수준이고 독립적인 선택 정보가 없었다.

공통H 이후 같은 열 입력을 줄 때는 `delta_h(d)=delta_h(0)·exp(−d/30)`, `delta_T(d)=delta_T(0)·exp(−beta·d)+delta_h(0)·convolution(beta,30,d)`이다. convolution은 양수이므로 시작의 두 차이가 비양수이면 이후 차이도 비양수다. **같은 미래 열 입력·같은 모형·해당 종단 상태가 실제로 성립한다는 조건**의 수식이다. 실제 새 요청·자원 선택·재계획·모형 오차가 달라질 수 있어 미래 기한이나 실제 온도의 보장은 아니다.

종단 제약은 현재 도착 요청을 예측상 모두 처리한 두 일정의 공통H에서 연속시간 AP를 비교하는 추가 가설이다. 평가의 원120초 J와35…180초1초 AP grid·응답/5단계 lane 경계·서비스/품질/지원·계수는 바꾸지 않았다. AP는 표면온도가 아니며 안전 한도/실제 제어J/한도 초과시간은 미지원/null이다. 새 g·기기 값·임의 온도 한계·가중치를 만들지 않았다.

## 결과 전 고정한 계약

- 실제 원 모형은 `beta=0.045932520308001434`, `k=1.075703577508385`, **`g=0`**이다. 현재 식의 h는 작업 부하가 새 잔열을 누적하는 항이 아니며 독립적인 부하 정보가 없다. 새 g/시간상수/기기 계수를 만들지 않는다. 초기 preload·원 AP/J·지원·응답/5단계 lane 경계를 유지한다.
- 원 첫 선택 검사 후보의 개발24조건만 강제행동 재생한다. 원장/전이/판단을 정확히 복원하고, 모든 기존 첫 선택 예측값을 다시 확인한 뒤 새 종단 조건을 계산한다. 강제행동은 사후 진단이며 새 온라인 정책 성능이나 독립 확인이 아니다. 미래 실제 도착·실현 비용은 예측 입력이 아니다.
- 각 시점에서 실제 첫 prefix+Band suffix와 현재 큐의 Band 예측을 원3문맥으로 비교한다. 문맥별 두 일정의 lane 종료 중 늦은 시각을 공통H로 정한다. 이미 도착한 요청을 전부 처리한 상태에서 같은H의 T/h를 비교한다. H>120초는 부적격이며 개별 종료 시각끼리 비교하거나 미래 비용을0으로 채우지 않는다.
- 원 서비스/J/최고AP 첫 선택 검사를 유지하고, 공통H의 AP와 h가 모두 Band보다 악화하지 않는 조건을 추가한다. AP 안전 한도/표면온도 한계를 새로 정하지 않는다. h는 모형으로 추정한 상태이며 원식의 `g=0`에서는 두 일정의 같은H 값이 동률이다.
- **유용한 선택**은 원 첫 선택 검사 통과·종단 조건3문맥 통과·첫 prefix의 최악 미래AP 또는 J 차이의 엄격 감소가 동시에 있어야 한다. Band와 같은 예측/첫 선택을 종단 조건 통과만으로 개선이라고 세지 않는다. 유용한 선택0이면 새정책pilot/새확인/학습을 수행하지 않고 종료한다. 있으면 한 후보의 작은 별도 개발/새확인 계약을 먼저 등록한다.
- 이전6,466환경/641학습 계승·기대24/이번32환경 상한(실패 포함), 등록30분/마지막5분 저장이다. 원결과/모형/기본/strict/experiment_ready=false·사용자 변경/다른 작업·worktree를 보존한다. 새학습/이번기기/ADB/NPU/계수적합0이다.
- 대표는 첫 개발 seed의 지속/평균이며, 추가 반례는 기존 첫 선택 검사를 통과했지만 종단 조건이 실패한 최초 시점으로 고정한다. 결과를 본 뒤 조건/허용폭/모형을 조정하지 않는다.
