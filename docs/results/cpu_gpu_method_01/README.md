## 현재 RL과 수정한 후보

현재 C는 EDD 정렬의 앞8요청에서 요청·CPU/GPU·분류GPU+탐지CPU 묶음·짧은 대기를 **직접 선택하는 native masked PPO**다. EDD+ECT는 기본 제안/fallback과 후보 뒤의 예측 후속규칙에도 쓰인다. 현재 알고리즘에 행동 마스크가 이미 있어 별도 Maskable PPO 라이브러리를 중복 추가하지 않았다. 상태109·후보68·32slot·6critic이며 실제 미래도착/잔여비용을 받지 않는다.

| 역할 | 실행한 후보와 유지/수정 |
|---|---|
| A 기존 시스템 | Band의 공개HEFT/FIFO대표·idle worker·yield·EMA 흐름, Triton rate-off 고정instance 요청 대응을 원 adapter 그대로 실행. 임의 FIFO 대체0 |
| B 산업공학 기본 | EDD 절대응답기한 순서, 실제lane점유/호환성+mean전체5단계 완료ECT. 원 adapter 보존 |
| C 현재 RL | 기존 AP 우선·J/서비스/P95 제약과 예측 SLA mask. 기존소스는 보존하고기본복귀의입력형식 오류만 `CurrentController`로 보완 |
| D 에너지/열 규칙 | 세문맥 기한·AP비악화가 예상되는 후보에서J최소. 무가중치·튜닝0·없으면정확한BASE |
| E 보완 RL | 같은PPO/109·68 network/optimizer에서 **물리실행 mask**와 별도 `ENERGY_AP_NONWORSE_V1` 목적. γ1의전체J차이 보상과AP/완료/서비스/P95제약 |
| 강한 자체 기준 | 완료된 `SHARED_EFT`의 실제 공용예상응답·aging 동작 |

C와 E의 차이는 mask/목적 패키지다. **PPO 알고리즘 우열 비교가 아니다.** 새 HEFT/GNN/RecurrentPPO/SAC/ALNS/NSGA-II/DoubleDQN은 필요 근거가 없어추가하지않았다. 기존85관측/17행동PPO checkpoint는이구조와호환되지않아새109/68에로드하지않았다. 착수시C구조의학습checkpoint는없었으며이번에3seed를새로실행했다.

C/E의 AP와30초h는 공개된과거점유와고정초기관측에서계산한 **모형 추정치**다. 엔진의실제내부열상태/미래비용이아니다. 현APK의numeric AP지속수신은미지원이므로PC연구입력과앱자체운영가능성을구분한다. 이초기화/추정계약없이현재policy를폰에배포할수있다고쓰지않는다.

## 공통 학습과 평가 규모

결과전입력·정책·선정기준을등록했다. 훈련은공통32case(8trace seed×4부하,사전순환3문맥),C/E각학습seed11·23·37×32episode=**192본학습/각4update**다. 모든seed를보고하며좋은seed나checkpoint를최종자료로선별하지않았다. 따로검증12조건/확인24조건(2trace seed×4부하×3문맥)을고정했다. 모든조건에같은요청·입력의미·기한·시작관측·지원자원·실현seed201을적용했다. 낮은부하·대기열·몰림·지속부하를포함한다.

- 검증12×11역할=132행, 확인24×11=264행. 확인17,424/17,424논리요청 완료; 정책마다1,584/1,584이다.
- 실제환경717=학습192+학습/재개fixture32+참조96+검증132+확인264+실패1. 학습실제시작225=192+32+실패1이며기존전체6,144상한에포함한다.
- 누적2,916+717=**3,633/20,000환경**, 잔여16,367. 이번실제기기/ADB/측정/설치/NPU0. 원자료와과거계획을새이름으로초기화하지않았다.
- C/E각8episode연속과4episode저장/재개를비교해최종weights·Adam계산·승수·RNG동등성을확인했다. fixtureweights는본학습초기값으로쓰지않았고매learner를공통설정으로새로초기화했다.

32episode는안정성과기능을보는작은파일럿이며수렴판정이아니다. C본학습informative transition은seed별2,434..2,470, E는2,770..2,825다. 동일episode예산이어도mask/행동 때문에경험량이달라지므로이를함께표시했다. 탐색·보상튜닝0,NN/optimizer수치는기존설계대로다.

원모형5682082a·초기관측42f60312,응답기한긴급1.5초/일반6초·공통J0..120초/AP35..180초1초격자를유지했다. 이기한은프로젝트의고정engineering target이며실사용SLA가아니다. 지원은분류CPU/GPU·탐지CPU·CG_DC 최대2건뿐이다. 입력/정밀도/출력품질의정책별변경0이다.

**확인자료에서 C/E각seed의 실제시간표는 EDD+ECT와24/24동일**했다. 동일원장확인은요청/행동/dispatch·phase·응답·lane반환·status를대조했으며source_request_id 표기차이는물리시간표와구분했다. reward/loss가달랐다는이유로policy가개선됐다고쓰지않는다. 초기BASE prior0.9와짧은학습이최종argmax에미친정도는후속진단대상이며원인을확정하지않는다.

주12(low/sustained)에서도모든C/E는전량/기한·긴급P95를지켰지만Band보다J가평균 **+0.182674J**, AP는 **−0.050222°C**였다. AP가낮아도energy비악화가아니므로채택하지않는다. D는주12에서일반실패26·긴급P95482.746ms, Band225.117ms여서낮은J가서비스희생을상쇄하지못한다.

Band는검증12에서유일하게모든조건의공용EFT/Band대비서비스·J/AP비악화조건을유지했다. 확인결과를보기전에이를선택했고,확인24에서도24/24비악화를유지했다. 주12에서공용EFT와긴급P95/기한/전량은같고J−0.083874/AP−0.012063°C,전체24에서는J−0.041937/AP−0.006032°C다. Triton대비주12 J−0.952425/AP−0.072150°C/P95−68.937352ms다.

따라서이번방법론의선정은 **실측프로파일의예상지연과자원점유를이용하는설명가능한동적배정,그중검토한Band HEFT whole-request 적용규칙**이다. 자체새정책의우월성이나상용Band제품직접실행을주장하지않는다. 기존앱기본/strict/experiment_ready=false는자동으로바꾸지않았다. 보고서에서이를강한기준선의채택결과로표시하며산업공학기본EDD의고유성과과장하지않는다.

과부하queue/burst에서는선정기준에도일반기한실패18이남는다. “모든부하에서전체기한보장”은미달성이다. 이연구의확인결과는기존기준대비추가악화없음과주부하의절대기한충족으로한정한다. `selected_new_policy=null`은새로만든정책개선이없다는뜻이며확인된기존규칙선정과구분한다.

## 비용·변동·오차 경계

판단은0증분overhead를가정한기존PC모형으로비교했다. 별도로PCwall/hostcallback을기록했다. 확인24총벽시계는Band4.27초,EDD3.93초,D284.69초,C각203.06..205.81초,E각141.56..164.56초였다. 학습32episode벽시계 C각272.56..278.55초/E각223.76..227.61초다. 병렬CPU부하·로그/특징처리차이가있어이를폰제어소비나순수PPO알고리즘속도우위로환산하지않는다. Shared는원구현에callbacktimer가없어host판단시간null이고환경wall만기록한다.

원모형+이미측정자료에서적합한미채택개발변형4를고정일정에후처리했다. [660비용](coefficient_sensitivity.csv) · [근거·범위](sensitivity_contract.json). 첫확인seed의주6조건Band−공용EFT는설정집합전체J/AP비증가방향을유지했다(동률포함). EDD/C/E−공용EFT는ΔJ범위−5.037857..+0.150896J로부호가바뀐다. 이것은재학습/새보정/변경계수에서policy재실행한결과가아니고,기존개발묶음stress probe이다. 불안정한GPU전력계수가만드는큰끝값을실제절감으로쓰지않는다.

최근별도확인J MAE3.913J/AP MAE0.260°C와초기이력/유휴/회복오차에비하면선정기준의모형차이는작다. 다른부하의오차를보편한도나임의합격margin으로전용하지않으며휴대폰에서분별가능한절감을확정하지않는다. 두확인trace seed와3상관처리문맥·3학습seed로는좁은물리적신뢰구간을만들근거가부족해차이와범위를보고한다.

## 미완료와 구체적인 다음 작업

1. **RL구성제거/대규모학습은보류:** C/E가검증에서3seed모두유망조건을실패했다. WAIT/열정보제거만확대해미채택후보를성공으로만들지않는다. 원알고리즘/예산을유지한추가학습량실험이필요하면같은6실행을128episode까지최종Adam/RNG에서연장하는새계약(추가576본episode)을고정하고새검증trace로판정한다. 현재실행은하지않았다.
2. **실기기효과확인:** 선정Band와Shared의동일지원작업·입력·도착·초기AP조건·공통120초기기J/AP·실행순서AB/BA를짝지어반복하고판단비용도측정해야한다. 실행수를실측변동에맞춰산정해별도승인한다. GPU단독계수식별·부하후배경변동·초기AP계약의한계도분리한다. 이번새측정0이다.
3. **앱이식전조건:** numericAP host의존초기화,공개thermal signal과모형추정의입력계약,모바일solver시간/J를확인해야한다. 표면온도지표가필수이면같은표면채널계측/보정이별도로필요하다. NPU지원확장은이번후속계획에넣지않는다.

프로젝트목표인기한·긴급응답·열/에너지감축은유지한다. 이번확정은검토후보/조건내방법선정이며전역최적이나기기별무재학습전이가아니다.
