## 2. 당장 다시 측정하지 말고 공유/PC 보완할 것

1. **10/2 밤 자료:** N1300, M1, M2/M2r 각 run의 sanitized manifest/validation/receipt, per-segment model·accelerator·APK/input 해시, 센서시계/구간경계, 전류raw·전압·AP/BAT/PA/SKIN·thermal_status·충전 여부, 실제 inference span/전환/cleanup. 기존 out_1002 요약은 이미 읽었으므로 똑같은 요약을 다시 만드는 요청이 아니다. 원시 전체 대신 재현 가능한 최소 export와 원본 파일 checksum/inventory를 제공해도 된다. 팀원 PC 원본은 보존한다.
2. **자원 증거:** 연쇄의 runtime별/PID별/segment별 accelerator 교체 증거와 시간 보존 미설명50~99ms 구간을 기존 로그로 먼저 판독한다. 런 전체의 첫 모델만 보고 NPU/GPU를 판정하는 경로를 보완해야 하며 이를 기기 재측정 사유로 바로 바꾸지 않는다.
3. **에너지:** C2의 단위 판별 통과와 내부 일관성 FAIL을 구분해 원 전류·전압·charge counter·시간창/단위 근거를 제공한다. exported `raw_unverified`를 임의 J PASS로 바꾸지 않는다. 기존 데이터의 정렬/단위/적분 문제면 PC에서 해결하고, 측정 신호가 실제 누락된 때만 새 수집을 결정한다. A24의 raw=mA나 전력/열 상수를 S26에 복사하지 않는다.
4. **최신 코드/자료 매핑:** 보고서에 과거 로컬 `sim/...` 경로가 남아 있다. GitHub의 실제 `s26/results/out_1002`·`s26/tools` 경로와 실행 당시 commit/판정기 hash를 연결한다. 소스/작은 CSV/JSON은 Git, APK·모델/AOT·키·대형raw·기기 고유식별은 공개 Git에 추가하지 않는다.

## 3. S26에서 남은 실측 — 우선순위와 완료 조건

아래는 목적별 요청이다. **전 항목 일괄 실행 지시가 아니며 기존 데이터가 해당 조건을 충족하면 재사용한다.** 준비/냉각/회수/기기 보호까지 포함한 최종 호출·시간 예산은 S26 실행 코드·gate로 확정해야 한다. A24의1300초/32호출 예산을 승계하지 않는다.

|우선순위·목적|필요한 실제 확인|재사용/최소 범위·완료 조건|
|---|---|---|
|**우선: 두 작업으로 연구 범위 연결**|EfficientNet 분류와 EfficientDet 탐지의 대표 이미지 품질, 실제 사용할 CPU/GPU(및 선택한 NPU) 경로의 종단간 시간|C2 NPU20런·AOT/raw smoke 반복 대신 누락된 대표 입력/decoded 품질과 CPU 기준 출력 비교. 정답/판정/모델/입력/전후처리를 결과 전에 고정. 탐지는 NPU run + CPU decode/NMS·저장 경계 구분. 이미 통과한 동일 조건은 재사용. 품질 부적격 backend는 후보에서 제외하고 다른 경로가 통과한 것으로 대체하지 않음|
|**그 다음: 사용 정책의 기기별 비용**|같은 resident/엔진/입력에서 단독·실제 사용할 병행·전환·부하 전후 유휴의 일정/J/AP|A24 CPU_URGENT 대 PAR96에 대응하는 범위라면 우선 classification_CPU, detection_CPU, classification_GPU 및 CG_DC가 필요. detection_GPU·NPU병행·3건병행을 표 채우기용으로 추가하지 않음. S26에서 실제 지원·품질을 통과한 배정만 허용. 과거 MobileNet 단일 반복/연쇄는 이 공백을 채우지 않음|

기기 환경·OS 열 보호는 유지한다. 시작온도는 실행 환경 gate와 모형 적용 범위로 나누고, A24 32.5–34.0°C를 S26 시작 제한으로 옮기지 않는다. 센서 값/단위/신선도, AP와 SKIN의 의미, 비충전·화면·메모리·열 상태를 S26 계약대로 기록한다. 수치가 안정됐다는 이유만으로 숨은 열 상태가 같다고 하지 않는다.

### MobileNet 열 정책 범위를 계속 사용할 때만 필요한 보충

두 모델 과제와 별도 축이다. 아래 항목은 최신 담당자 보고서의 미실행 목록을 연구 질문에 연결한 **권고**이며 새 동결 계획이 아니다.

- **NPU 장시간:** 600~1300초 미래 예측/스로틀을 주장할 경우, 같은 APK·프로토콜에서 N1300 독립1런이 최소 확인 후보다. 0~600초 범위는 기존 M2r H1/H2도 먼저 재사용한다. 부하1300초는 전체 소요 상한이 아니며 냉각/회수 별도다. 개발에 사용한1300초1런을 독립 확인이라 하지 않는다. 낮은 시작값을 이유로 임의 가열하지 않는다.
- **GPU 회복/유예:** 현재처럼 d10 회복을 쓸 경우 M1 동일 경계의 독립1런(60+1200+300=1560초 관측)이 재현성 최소 후보. 정책이 완전 유휴d0 대기를 쓰면 d10을 d0으로 간주할 수 없어 별도의 고정 대기→짧은 probe 경로가 필요하다. 두 가지를 모두 무조건 실행하지 말고 실제 정책의 대기 동작 하나를 먼저 고른다. 20초는10초bin 상한으로 유지한다.
- **뜨거울 때 CPU로 전환하는 정책을 쓸 때:** 미실행 M2 CPU 피해자 대조. 기존 GPU30초→CPU60초와 GPU600초→CPU60초 chain을 ABBA로 사용할 경우4런의 고정 구간 합은 **1500초**(2×90+2×660); 준비·전환·냉각·회수 제외. CPU 피해 지연/초기화·J/열 이력을 확인한다. 그 정책을 제외하면 필수가 아니다.
- **EfficientNet×CPU20런:** 기존 밤 계획에서 SOC 때문에 미실행한 사실을 보존한다. 모델별 자원 비교를 위한 CPU 기준은 필요하지만20런 전체 반복 수는 그 계획의 목적/분모다. 현재 두 작업 도착 과제의 필수 반복 수로 자동 복사하지 않는다. CPU/GPU/NPU의 같은 모델·입력·품질·runtime 경계를 먼저 맞춘다.

N1300+M1+M2 CPU를 묶으면 계산상 고정 구간만4360초(72분40초)다. **추천된 일괄 실행 예산이 아니며 전체 완료시간·배터리 충분성 보장이 아니다.** 지난 밤 실제5.24시간·SOC88→31은 예산을 다시 잡아야 함을 보여주며, 무리한 밤샘/자동 재시도/기준 완화를 요구하지 않는다.

## 4. 완료와 보류의 기준

- 이미 확보: S26 MobileNet 단일자원·스로틀/전환/회복 pilot 근거, EfficientNet NPU 합성입력20런. 같은 표를 다시 채울 필요 없음.
- 자료 적격성: 전체 호출/구간/시계/센서/품질·위임·환경/cleanup 분모와 결측을 먼저 판정.
- 예측 확인: 개발에 쓰지 않은 실행에서, 사전 고정 모형의 같은 시간창 오차 산출. 미지원 상태는 null. 보고값이 작다고 허용폭을 사후 설정하지 않음.
- 정책 판단: 지연·성공률·J·열 차이가 해당 조건의 예측 오차/변동성에 비해 구분되는지 별도 판정. 개별 계수 식별이나 모형 수치 반환만으로 정책 우월성 완료 아님.
- 하지 않을 것: S26 계수를 A24에 전용, MobileNet 결과를 EfficientDet에 전용, SOC/사용시간 절감 주장, 임의3건 병행, 열 보호 해제, 품질 gate 완화, 미채택 A24 gamma의 S26 채택, 과거 종료 계획 재개.

**팀원에게 지금 요청하는 행동:** 기존10/2 밤의 재현 export·C2 에너지 근거·두 모델 대표 입력 품질/요청 경계의 보유 여부를 먼저 회신하고, 없는 항목 중 위 우선순위에 맞는 다음 수집 범위를 정한다. 같은 장시간 실험을 바로 반복하지 않는다. 이미 더 최신 결과가 있다면 그 commit/경로로 이 목록을 갱신한다.

## 전달용 메시지

영훈아, GitHub `s26-measure`의10/2~3 밤 결과(cea8eae)까지 확인했어. EfficientNet NPU20런, NPU1300초, GPU↔NPU 양방향 결합, GPU 회복까지 이미 한 걸 반영했으니 이걸 다시 처음부터 측정할 필요는 없어.

우리 A24는 최근 개발4의 전력 초기화 오류를 고쳐120초 J 평균절대오차8.363→3.260J로 줄였고 AP MAE는0.184°C였어. 배경 보정gamma는 개선이 안 돼 미채택했고, 작은 정책 차이를 확정할 수 있는지는 기존 독립 확인자료로 이어서 볼 예정이야. 기본 모형을 바꾸거나 실측을 더 시작한 건 아니야.

S26에서 우선 필요한 건 **기존10/2 raw의 재현 가능한 export와 C2 에너지 내부 일관성FAIL 근거**, 그리고 **EfficientNet/EfficientDet의 대표 입력 품질·요청 단위 종단간 경계**야. NPU raw 출력 성공/합성32입력 통과와 실제 탐지 품질을 나눠야 하고, 두 작업 정책에는 실제 사용할 배정의 단독/병행·전후 유휴·같은창 J/AP 기록이 필요해. 이미 가진 자료는 먼저 재사용하자.

추가 장시간 실측은 목적이 있을 때만: NPU600~1300초 범위 확인이면 N1300 독립1런, d10 회복을 정책에 쓸 거면 M1 독립1런, 뜨거울 때 CPU로 넘길 정책이면 미실행 M2 CPU 피해자ABBA가 후보야. 전부 필수로 묶어 돌리자는 뜻은 아니고, 완전유휴 회복을 주장할 거면 d10 자료만으로 대체할 수 없어. EfficientNet×CPU20런도 당시 미실행 항목으로 남기되 우리 과제에 필요한 분모를 먼저 맞추자.

진행상황·정확한 근거·남은 항목은 이 문서에 정리했어. 새 실행 전에 보유 자료/가능한 경로를 알려주면 중복 측정 없이 남은 범위만 고정하자. APK·모델·키·원시logcat 전체는 공개 GitHub에 올리지 말고 작은 요약·판정·checksum과 공유 가능한 export만 부탁해.
