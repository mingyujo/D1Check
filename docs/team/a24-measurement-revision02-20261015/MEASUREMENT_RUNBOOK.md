# A24 실측 진행 원장·재개 안내

이 파일은 대화 압축·새 세션·이동 후에도 먼저 읽을 **현재 실측 안내 문서**다. 매 실측 시작·유의미한 단계 완료·중지 때 갱신한다. 문서만 믿고 실행하지 말고 실제 Git·실행 프로세스·등록 원장·원물과 대조한다. 과거 PLAN의 “실행0/미구현” 문장은 당시 이력이며 현재 상태는 이 파일과 `PACKAGE_STATUS.json`을 따른다.

갱신: 2026-10-15. **묶음04 CPU/GPU 측정·회수·출력 검산 완료,12:55:25 KST 실행 종료. 새 실측은 시작하지 않는다.** 결과·문서의 PC 검증을 마쳤고, 이 안내와 공유 결과를 함께 Git에 보존한다.

## 1. 재개할 때 반드시 확인할 순서

1. `docs/PROJECT_STATUS.md` → 이 파일 → `PACKAGE_STATUS.json`을 읽는다. 실제 브랜치·HEAD·변경사항·worktree를 대조한다.
2. 아래 현재 묶음의 `job.json`, `USER_WINDOW.json`, `SOURCE_SHA256.json`, 실행 로그와 원장의 `START/COMPLETE/PRESTART_REJECT`를 확인한다. 살아 있는 실행을 중복 시작하지 않는다.
3. 사용자 최신 중지·이동·종료 시각을 확인한다. 종료된 시간창, 완료·실패 ID, 과거 자동감독을 재실행하지 않는다.
4. 마지막 완료 단계부터 원물 검증·분석을 이어간다. 다음 측정은 승인 범위·남은 예산·새 ID·사전 고정 조건이 모두 있을 때만 시작한다.
5. 진행 결과·실제 소비·미완료·다음 행동을 이 파일과 STATUS에 기록하고 Git에 저장한다. 결과가 없는 항목을 완료로 표시하지 않는다.

공유 브랜치: `codex/a24-laptop-prep-20261014`. 원 사용 작업공간과 데스크톱·S26 작업은 별도이며 변경하지 않는다.

## 2. 현재 승인과 중단 경계

- 최신 지시: GPU부터 수행하고 충분한 냉각을 기다린 뒤 CPU를 진행한다. **2026-10-15 13:20 KST까지 종료**한다. 임시 13:10 지시는 13:20 지시로 대체됐다.

- SOC 10% 이상, 동일 등록 A24, 비충전, 같은 화면·통신·입력을 사용한다. 단절 시 동일 기기의 재연결을 최대 20분 기다리되 종료 시각을 넘기지 않는다. 실행 명령을 무작정 재전송하지 않는다.
- 새 앱 시작에는 21분, 본측정 START에는 5분의 남은 시간 여유를 요구한다. 기존 앱 안전 조건과 비선점·실제 자원 반환을 유지한다.

- 데스크톱 학습·시뮬레이션, EP813 및 복구 불가능한 미저장 EP814, 기존 체크포인트, S26/NPU, 사용자 미커밋 파일은 건드리지 않는다.

## 6. 고정하는 의미·자료·버전

- 모델: 승인 EfficientNet-Lite0 분류 / EfficientDet-Lite0 탐지, 기존 labels·anchors·한 승인 PNG·전처리 tensor 그대로. 한 이미지 반복으로 전체 정확도를 주장하지 않는다.
- 분류 모델 SHA: `6c7ab0a6e5dcbf38a8c33b960996a55a3b4300b36a018c4545801de3a3c8bde0`.
- 탐지 모델 SHA: `40338edf5ec70d43e318b0a716a84d4564cd1802759a7a07170c7e43796dbf58`.
- APK SHA: `6fbe5c0812e3d123259be5004d37c6a4d6e9a2b750df2ac4ae5460b01f0bfd8b`. 같은 APK를 재사용한다.
- 기존161소스 목록 SHA: `7edc7240cf3109a26e3a548cab84106b95c0115595e24d1e64b1ce9326d450ee`. 기존 소스·본 controller·APK는 변경하지 않는다.
- C 기한2.2초/D5초. 첫 도착35초,서비스0~120초,AP35~180초,로그210초. 서비스 종료 후에는 시작된 요청만 실제 반환까지 비선점 drain한다.
- C 응답은 output-ready,D는 fsync→rename→readback 완료다. worker release/실제 AVAILABLE과 응답 완료를 혼동하지 않는다.
- 전체 예정 요청을 분모로 완료·기한 내·실패·거절·미완료를 보고하고 완료 표본 P95를 함께 낸다. 미완료·실패를 지워 이득을 만들지 않는다.
- HAL AP는 읽기값이다. cache age/독립 갱신·실제 표면온도는 미검증이다. 전류 API와 charge counter 단위 불일치로 검증 에너지 **J=null**. 임의1000배 보정·온도→J 변환은 하지 않는다.
- 요청 수와 센서 읽기 수는 독립 반복 수가 아니다. 이번 대응1쌍은 신뢰구간/제품 열·배터리 절감을 확정할 근거가 아니다. 원모형 자동 재보정·과거 확인자료의 독립성 재명명 금지,`experiment_ready=false` 유지.
