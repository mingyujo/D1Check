# 미실행 1건과 실패 5건의 후속 실행

2026-10-16 사용자의 “미실행된거 마저 진행해봐”, “실패한것도 진행해”에 따른 유한 실행이다. 과거 완료 보고서는 당시 스냅샷으로 보존한다.

- 원 독립 확인: 미사용 ordinal17, L64 병행 64요청을 기존 ID와 기준온도 27.1℃로 이어간다. 기존 실패 두 건을 성공으로 교체하지 않는다.
- 실패 보완: 아래 다섯 사례에 새 ID를 하나씩 부여하고, 고정 순서로 각 1회·총 480요청을 등록한다. 기존 105회 예약을 보존하고 새 5회만 추가해 계산상 상한은 110회다. 이는 무제한 재시도 승인이 아니다.
- 실제 실행은 같은 A24·설치된 기존 APK·기존 모델/입력·179개 동결 소스를 유지한다. 새 adapter만 별도로 추가한다. PC 사전 검증 4개 및 실제 authorization 조립 5개가 통과했다. 이는 기기 성공을 뜻하지 않는다.

| 순서 | 기존 실패 | 같은 요청·설정으로 보완하는 내용 |
|---:|---|---|
| 1 | C9 ORDER | 혼합 128건, EDD 순서·직렬 |
| 2 | C10 BASE | 저부하 64건, FIFO·직렬 |
| 3 | R2 PAIR | 혼합 128건, 분류 GPU·탐지 CPU 병행 |
| 4 | R3 ORDER | 혼합 128건, EDD 순서·직렬 |
| 5 | SUP12 ON | 분류 GPU 32건·Perfetto ON, 이미 검증한 공식 설정 경로 적용 |

보완 5건은 관측 후 진단 반복이며 독립 확인 40에 합치지 않는다. C9/R2는 이전 SUP12에서도, ON은 TRACE2에서도 이미 새 ID 성공 자료가 있다. 이번에는 최종 원장의 다섯 실패를 모두 같은 방식으로 대응시켜 재확인하되, 중복된 재현 근거임을 공개한다. ON 단독 반복을 계측 오버헤드 비교로 사용하지 않는다.

각 보완은 준비 후 처음 통과하는 안정 60초를 자신의 기준으로 정한다. 기존 MAIN 허용폭 ±0.5℃·기울기 0.1℃/분·최대 표본 간격 10초·대기 상한 600초는 유지한다. 서로 다른 시작온도 반복으로 열 우열을 주장하지 않는다. 응답·자원 반환·저장 경계와 요청 분모도 보존한다.

배터리 10% 이상·비충전·같은 기기 재연결 최대 20분을 유지한다. 현재 기술적 시간창은 기기 12:40, 저장 12:45 KST다. 실제 접속 불가·안전 조건·모호한 APP 전송을 기준 완화나 같은 ID 재전송으로 해결하지 않는다. 오류가 나면 원장과 원자료를 보존하고, 실제 종료를 확인한 뒤 미사용 범위만 이어간다.

에너지 J는 미판정, AP는 HAL 채널이며 물리 표면온도 검증이 아니다. `experiment_ready=false`를 유지한다. 데스크톱 학습·다른 worktree·S26/NPU는 변경하지 않는다.

PC 재현:

```powershell
python -B -m unittest discover -s tools -p test_d1_a24_failed5.py -v
python -B tools/d1_a24_failed5_runner.py inspect output/A24FAILED5/job.json
```

`inspect`는 기기를 실행하지 않는다. `execute`는 실제 측정이며 이미 사용된 폴더·ID에는 다시 실행하지 않는다. 진행 상황은 [고정 현황](../LIVE_PROGRESS.md), 결과는 별도 후속 보고서에 연결한다.
