# REV02 설계 초안 — 현재는 실행하지 않음

## 1. 목적과 범위

정책 간 완료량·기한·응답과 AP 읽기값을 비교할 때 초기 상태 차이를 줄인다. 특정 절대 온도에 도달하기 어려워 실측을 계속 거절하는 문제를 피하되, 정책마다 유리한 출발 온도를 고르는 방식은 허용하지 않는다.

이 문서는 새 독립 확인의 **제안**이다. 실측 실행 권한0, experiment_ready=false, 실행 동결 미완료다. 기존 PLAN/실행 ID/실패를 고치거나 새 결과로 재분류하지 않는다.

## 2. 비교 묶음과 기준 선택

한 비교 묶음은 새 개정 ID × 반복 번호 × 부하 종류다.

| 부하 | 같은 초기 기준으로 비교할 군 | 요청 |
| --- | --- | --- |
| L64 | BASE, PAIR_G | 같은 C32/D32 도착 기록 |
| C252 | CPU, GPU | 같은 분류252건 도착 기록 |
| M128 | BASE, ORDER, PAIR_G, WAIT200 | 같은 C96/D32 도착 기록 |

부하가 다른 묶음끼리 같은 온도나 같은 KPI 수준을 강제하지 않는다. 분석도 부하별 대응 차이로 나눈다. 각 묶음은 다음 알고리즘을 첫 본 요청보다 먼저 적용한다.

1. 기존과 동일한 네 runtime 상주·각2회 워밍업 뒤 ready 시각을 기록한다. 추가 가열·냉각 작업이나 준비용 추론을 만들지 않는다.
2. ready 뒤 AP의 읽기 시각 괄호와 값을 보존한다. 관측 이력이60초를 덮도록 하며, 읽기 간격 jitter 때문에 필요한 경계 직전 한 점은 포함한다. 미래 표본은 사용하지 않는다.
3. 처음으로 이력60초·최대 gap10초·관측 선형 기울기 절댓값0.1℃/분 이하를 만족하고, 그 이력의 모든 값이 해당 중앙값±0.5℃ 안인 창을 선택한다. 최대 대기는 기존과 같은600초다.
4. 그 **첫 유효 창의 중앙값**을 해당 묶음의 Tref로 한다. 계약 SHA·준비 SHA·표본 SHA·선택 시각·기준값을 본 요청 전에 별도 기준 파일로 봉인한다. 응답·AP 결과·에너지·정책 성적을 보고 창을 다시 고르지 않는다.
5. 첫 군과 이후 모든 군은 같은 Tref±0.5℃ 및 기울기/이력/gap 조건을 적용한다. 각 군이 자기 기준을 새로 계산하지 않는다.
6. 기준을 맞추지 못하면 사유와 전체 예정 요청을 보존하고 해당 묶음을 불완전으로 표시한다. 자동 재기준·실패 슬롯 재실행·좋은 묶음으로 대체·반복 추가를 하지 않는다.

0.5℃·0.1℃/분은 기존의 잠정 비교 통제값을 유지한 것이다. 센서 정확도, 안전 한계, 내부 열 평형이나 실제 표면 온도의 허용 오차로 검증된 값이 아니다. HAL cache age와 독립 갱신 시각도 미확인이다. 첫 유효 창을 찾았다는 것이 내부 잔열이나 DVFS까지 같다는 보장은 아니다.

## 3. 유지하는 실행 의미

기존 모델·한 승인 PNG·labels/anchors/tensor SHA·정밀도/스레드/전후처리·기한·입력 recipe를 유지한다. C는2.2초/D는5초, 첫 도착35초, 서비스0~120초, AP35~180초, logging210초다. M128 묶음 간격은2.032194초다.

분류CPU/GPU와 탐지CPU 요청만 사용한다. DG는 기존 공통 상주/워밍업일 뿐 본 요청 후보가 아니다. 최대2건 CG_DC 병행, 비선점, 실제 worker 반환 뒤 AVAILABLE, C output-ready와 D durable persistence의 구분을 유지한다. FIFO/EDD 동점 및 WAIT200의 최대16회·명목3.2초와 실제 overshoot 기록도 바꾸지 않는다. 새 스케줄러·RL·물리 계수·NPU를 추가하지 않는다.

SOC10% 이상·비충전·같은 기기/화면/밝기/통신·기존 앱 안전 조건·같은 기기 연결복구 최대20분을 유지한다. 위치·주변 상태·초기 AP 경로·배터리·준비 종료와 이전 부하/휴지 시간을 기록한다. 관측 불가능한 상태를 같다고 선언하지 않는다. 사용자 재연결 후 화면 timeout은 기존18000000ms와 달리2147483647ms로 관측됐다. 우리가 설정을 바꾸지는 않았으며, 향후 실행 계약에는 당시 실제 설정을 명시해야 한다.

## 4. 규모와 순서 제안

기존64 상한의 시도28·미시도36을 보존한다. **새로 승인된 실측은0**이며 예산 이관도0이다. 향후 별도 실행 지시가 있을 때 검토할 구성은4반복 × (L64 2군 + C252 2군 + M128 4군) =32세션·4,576예정 요청이다. 이 경우에도 미배분4슬롯을 자동 추가 실험에 쓰지 않는다. 기존 실패·중지 슬롯의 대체로 표시하지 않는다.

입력·실행 순서 seed와 새 session/request UUID는 아직 발급하지 않았다. 향후 등록 시 기존 DEV/CONFIRM과 분리하고, 같은 부하·반복 안에서는 동일한 요청 bank를 사용한다. 기존 결과를 새 확인의 반복으로 합치지 않는다.

L64/C252는 AB와 BA를 각2회 배치하는 안이다. M128의 네 순서안은 다음과 같다. 각 정책은 각 위치에 한 번씩, 각 인접 순서쌍은 전체에서 한 번씩 나온다. 실제 반복 배정·부하 묶음 순서는 결과를 보기 전에 등록한다.

| 순서안 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- |
| 1 | BASE | ORDER | WAIT200 | PAIR_G |
| 2 | ORDER | PAIR_G | BASE | WAIT200 |
| 3 | PAIR_G | WAIT200 | ORDER | BASE |
| 4 | WAIT200 | BASE | PAIR_G | ORDER |

순서 균형도 긴 잔열·SOC·장소 변동을 제거하지 못한다. 기록된 초기 상태와 부하별 결과를 함께 해석한다.

## 5. 분석 계약 제안

다섯 비교 L64 PAIR_G−BASE, C252 GPU−CPU, M128 ORDER/PAIR_G/WAIT200−BASE를 유지한다. 각 비교의 독립 반복은 최대4이지 요청 수나 센서 읽기 수가 아니다. 작은 표본의 미보정 대응 Student-t95% 구간을 탐색적으로 보고하며 n<2는 구간null, 누락은 대체하지 않는다. 추가 반복을 성적에 따라 붙이지 않는다.

전체 예정 도착을 분모로 완료·실패·사전거절·중지·기한초과·미완료를 표시한다. 완료 표본의 nearest-rank P95와 전체 분모의 서비스 성적을 함께 보고한다. 동일 전량 완료·서비스 비악화 조건을 먼저 확인한 뒤 비용 차이를 해석한다.

AP 경로·평균·관측 최고값과 실제 각 세션의 시작 읽기값을 보고한다. 시작 대비 변화량은 보조 설명값이며 열량이나 에너지로 변환하지 않는다. 서로 다른 초기 묶음의 AP 절댓값을 단순 합쳐 정책 우위로 해석하지 않는다. L64의 실제 병행0인 경우는 음성 대조로 남긴다.

에너지 J=null, 표면 온도 미검증, 새 수치 forecaster 없음/모형 정확도 PASS 없음은 유지한다. 기존 모형을 새 실측으로 자동 재보정하거나 기존 확인을 독립 검증으로 재사용하지 않는다. 대표 그림은 성적과 무관한 첫 완전한 M128 BASE/PAIR_G 묶음이다.

## 6. 아직 필요한 PC 작업과 실행 금지 경계

현재 구현은 기준 선택을 검산하는 **순수 PC 함수**뿐이다. 실제 host의 준비→묶음 기준 봉인→승인 SHA 결합, 새 plan/registry/입력 identity, 중지·부분 복구, 개정 분석 adapter와 원 파서 호환 검사가 필요하다. 기존 APK의 재사용 가능 여부도 아직 판정하지 않았다. 기존 run_one은 고정 Tref 계약을 요구하므로 새 계약 JSON을 넘기는 것만으로 동작하지 않는다.

명시적인 향후 실측 지시 전에는 연결·설치·워밍업·추론·계측·START/claim·세션 소비를 시작하지 않는다. 기존 job/autowatcher를 재가동하지 않는다. 이번 작업에서는 원래 진행 중이던 앱의 종료 확인·읽기전용 회수만 하고, 새 개정 실측은0이다.

방법론 근거: [NIST Randomized block designs](https://www.itl.nist.gov/div898/handbook/pri/section3/pri332.htm). 이 문서는 해당 원칙을 현재 부하별 정책 비교에 적용한 제안이며, 통계 가정 충족이나 정책 개선의 증거 자체가 아니다.
