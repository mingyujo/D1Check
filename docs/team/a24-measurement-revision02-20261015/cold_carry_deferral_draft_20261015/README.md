# 장시간 냉각 대기 해소 — 실행 순서 개정 초안

**이후 사용자 명시 선택으로 [C8에서 채택](../confirm_m128_order_amended_20261015/README.md)했다.** 여기의 실행 불가 초안·PC 증거는 원본으로 유지하며 실제 실행은 C8의 승인·시간창·계약·원장을 따른다.

**PC 구현·검증 완료 / 순서 변경에 대한 사용자 선택 전 / 실행 권한0.** 원래의 고정 실행 순서를 바꾸는 제안이며 현재 실험의 판정·온도 조건을 완화하지 않는다. C6/C7은 앱 전 대기에서 종료됐고 현재 controller/APP는 실행 중이 아니다.

## 제안할 실행 범위

| 항목 | 기존 고정 순서 | 제안 |
| --- | --- | --- |
| 다음 L64 PAIR_G, 원 ordinal17 | 앞 BASE의27.1℃에 도달할 때까지 대기 | 원ID·기준·미실행 상태를 보존해 전체 실행 순서의 맨 뒤로 이동 |
| 다음 새 M128 묶음, 원 ordinal18~21 | L64 PAIR_G 뒤 | **WAIT200 → BASE → PAIR_G → ORDER**, 최대4회 먼저 대상 |

| 나머지 원계획 | 총40조건·5,720요청 | 원40ID·입력·기한·정책·요청·분모 전부 보존 |

따라서 새 순서는 **원0~16 → 원18~39 → 원17**이다. 실제 이번 창에 등록할 대상은 첫 미실행18~21 최대4개뿐이다. 원40을 줄이거나, 미실행17을 완료·실패로 바꾸거나, 기존 BASE의 기준을 덮어쓰지 않는다. 새로운 상태에서 실패·미완료·미시작을 그대로 남긴다. M128 네 조건을 이번 남은 시간 안에 전부 마친다고 보장하지 않는다. 공통 준비 뒤 기준이 정해지고 각 군의 냉각·MAIN조건도 충족해야 한다.

이 선택은 **원래의 고정 실행 순서 계약 변경**이므로 사용자 선택을 받은 뒤에만 새 시간창을 결합한다. 기존17조건을 보고 정책·기준을 유리하게 고르는 변경은 아니며, 미시작 상태의 오래된 냉각 기준이 뒤 조건 전체를 막는 운영 문제를 분리한다. 실제 채택 시 원계약과 다른 순서·이유·시각을 별도 개정으로 기록해야 한다. 미시작17의 지연이 시간·환경 혼입을 없애지는 않는다.
