# C10 통신 실패 보존 후 C11 미실행13 계속

C10은 정상5조건·본요청1072건을 회수한 뒤, 원27 L64 BASE의 APP 전달 중 연결 오류로 02:24:26 KST 종료했다. 원래 host outcome은 `FAILED_PRESERVED`이며 변경하지 않았다. 같은 ID의 APP/START를 재전송하거나 예산을 환급하지 않는다.

연결 복구 후 같은 등록폰에서 두 차례 분리 관찰했다. 앱 프로세스·해당 결과 디렉터리·본측정 시작 승인 파일이 없었고, 원 host 로그에도 시작 승인 업로드가 없었다. 따라서 **MAIN0·예정64건 미실시**로 보존하고 미실행 다음 ID로 진행한다. 워밍업 실제 횟수는 증거가 없어 null로 남긴다. 존재하지 않는 journal 닫힘을 만든 것이 아니다. [원 실패와 읽기 관찰 증거](C10_NO_MAIN_FAILURE_PROOF.json).

새 읽기 전용 검증기는 이 정확한 오류·APP 예산 소비·START/claim 부재·두 번의 동일폰/빈프로세스/출력없음/승인없음·실제 host 로그를 모두 요구한다. 프로세스/출력/승인/기존MAIN/짧은 관찰 간격이 있으면 차단하는 PC3검사를 통과했다. 별도 coordinator 사본에는 이 기록 확인과 해당 검증기 SHA 고정만 추가했으며 원4ce2df05 coordinator와 원179/APK/MAIN/서비스/기준/완료/반환 코드는 보존한다.

실제C11은02:33:08 KST 시작, `output/A24R02C11/job.json` / Documents `A24R02C11` / global `A24R02C11_GLOBAL`이다. 시작전 미실행13·1720예정요청, 원68/81소비·기존확인25정상/2시작전실패, 기존MAIN3808건이다. 13개 승인 결합과 새 시간창 결합을 PC검증하고 같은폰/APK/SOC/비충전/화면/미사용경로/빈프로세스를 읽기 확인했다. 옛L6427.1℃와 원순서는 유지하며 기존 실패64를 성공으로 대체하지 않는다.

후속 큐는 `output/A24FOLLOW17/queue.json`이다. 구 `A24FOLLOW16`은 불명확 전달에서 멈춘 증거를 보존하며 재시작하지 않았다. 새 큐가 C11 종료·닫힘/owner해제 후 미사용 개정ORDER1→보완12를 직렬 실행한다. 큐의 구문자열 C10은 과거 명칭이며 실제 대상은 config의 C11 경로다. 추가 오류는 실제 상태를 진단하고 미사용 ID/별도 새 계획으로 처리한다. 단절은 같은 기기 최대20분 대기, 실제 작업자 기술상한은 기기12:40/저장12:45 KST다.
