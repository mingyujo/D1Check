# DEV8 연속 실행 v2 — 준비 전 냉각 판단 수정

2026-10-15 14:28:50 KST에 첫 GPU 회수 후, CPU 앱을 시작하기 전에 호스트 대기만 중지했다. CPU의 앱 시작·워밍업·START·세션 소비는 0이다. 기존 GPU는 252/252건 기한 내 완료·출력 252건 PASS이며 재실행하지 않는다. 원물과 177개 실행 소스는 변경하지 않는다.

## 원인과 변경 경계

기존 준비 전 냉각에도 `Tref±0.5℃`를 적용해 AP가 25.7~25.8℃로 내려가면 26.35℃ 기준의 하한 25.85℃보다 낮다는 이유로 계속 대기했다. 이 조건은 워밍업 후 본측정의 시작 상태를 맞추는 조건과 역할이 다르다.

별도 연속 실행기는 **준비 전**에만 60초 안정성·관측 간격·기울기 검사를 유지하면서 `AP≤같은 Tref`인 더 차가운 폰의 준비를 허용한다. 임의 가열이나 새 온도 기준을 사용하지 않는다. 기존 준비 전 조건과 달라진 점을 사전 계약에 기록하고 기존 대기 기록도 보존한다.

**본측정 START 조건은 변경하지 않는다.** 동일 APK·입력·공통 8회 워밍업 뒤 원래 컨트롤러가 같은 기준의 ±0.5℃·60초·기울기 0.1℃/분·최대 600초를 다시 검사한다. 기준을 충족하지 않으면 MAIN을 시작하지 않는다. 응답·실제 worker 반환·요청량·기한·병행·WAIT·AP 관측창·품질 판정은 그대로다.

원래 177개 소스는 바이트 그대로 두고 별도 실행기·순수 회귀검사 2파일을 추가한 179파일 명세를 사용한다. 첫 GPU의 실제 호스트 소스는 177, 나머지 7군은 검증 후 179로 기록한다. 새 소스의 8군 실기기 통과라고 소급 표시하지 않는다. 확인용 동결 전에 이 차이의 검증 범위를 명시해야 한다.

## 승인·예산·재개 범위

- 사용자가 총상한 **81회 = 기존 33시도 + 이번 DEV 최대 8 + 새 독립 확인 40**을 명시적으로 승인했다. 실패·중단도 보존하며 확인40을 축소하지 않는다.
- 이번 DEV는 이미 완료한 GPU 1회를 포함해 최대 8시도다. 연속 실행은 **아직 앱을 시작하지 않은 7개 ID만** 수행한다. 완료·실패·START가 있는 ID는 재시도하지 않는다.
- 원래 시간창을 연장하지 않는다. 기기명령 16:33:25, 저장 포함 전체 16:38:25 KST 종료다. 새 앱은 21분, START는 5분의 여유를 요구한다.
- 새 독립 확인은 이 실행기에서 시작하지 않는다. 기능검증 결과·소스 차이·분석 계약·예측 또는 예측 없음·원장·40회 계획을 먼저 동결해야 한다.
