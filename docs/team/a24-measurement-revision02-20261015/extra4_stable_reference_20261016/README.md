# 새 안정 기준의 혼합4조건 — 원확인40과 별도

사용자 선택 **“85회로 확대: 새 기준으로 혼합 4조건 모두 재측정해 공정하게 비교”**를 반영한다. 총상한85 = 원계획81 + 별도개정4다. 원계획81/확인40의 파일·ID·예산은 소급 수정하지 않는다. 현재까지 원계획62소비(확인21시도·정상20), 원미시도19와 개정4를 합쳐23회가 남는다.

현재 방문에서 이전28.4℃를 통과하지 못한 ORDER는 본요청0/예정128미완료·준비APP1로 보존했다. [C9 종료·원물·원장](../../../results/a24_measurement_share_20261016/confirmation_visit_09/README.md). 새4조건은 같은ID의 자동재실행이 아니라 **별도 계획·새ID·새공통초기기준의 개정 비교**다.

기존 suite는40/8개 등록만 검증하므로 개정4개용 별도 등록 validator와 coordinator를 추가했다. 새 controller는 기존 `d1_a24_revision02_suite_control.py`와 **등록 import·자기파일 경로·설명문만 다르며**, 온도판정·실행·응답·반환·실패보존·회수 함수를 모두 동일하게 유지한다. `lifecycle_identity()`와 관련 검사에서 코드/AST를 대조한다. 원179파일·APK는 변경하지 않는다. 새source manifest는 원179와 새4개PC호스트파일을 함께 고정하며, 이전 실제기기 기능증거와 신규PC검증을 구분한다.

실제job `output/A24R02R1/job.json`, 원물 `Documents/A24R02R1`, 전역추가4예약 `Documents/A24R02R1_GLOBAL`이다. 최초 실행 전에 원본40 실행기 owner 부재·동일기기·APK·SOC/비충전·화면을 확인한다. 코드·문서 작성은 실측 완료가 아니다.
