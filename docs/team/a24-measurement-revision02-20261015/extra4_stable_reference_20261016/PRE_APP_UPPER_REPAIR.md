# 준비 전 예비 조건 보완 — 본측정 판정 유지

첫WAIT는27.6℃ 기준을 본요청 전에 고정하고128건 전량 회수했다. 다음BASE는 **앱0/예약0/MAIN0**의 예비 냉각 중 AP27.6~27.9℃ 부근에서 멈췄다. 기존 준비 조건은 최근60초 전체가 `AP ≤ Tref`여야 했으므로, 예를 들어27.9℃로 안정된 상태를 막는다. 반면 원본 MAIN 판정은 같은 안정 이력에서27.6±0.5℃를 허용한다.

이 차이를 실제 원본 판정 함수로 검산했다. 새 예비 조건은 **안정 이력이 있고 AP ≤ Tref+0.5℃일 때 앱 준비만 허용**한다. 워밍업 후에는 원래 MAIN 함수가27.6±0.5℃·60초·기울기0.1℃/분·공백10초·최대600초·SOC/비충전을 다시 검사한다. 예비 조건을 통과한 것이 MAIN 허용은 아니다. 28.2℃·급변·이력 부족·공백은 계속 거부한다. 준비 전 대기도 무한 대기 대신 최대600초로 제한하고, 도달하지 못하면APP0으로 보존한다.

R1은2026-10-16 01:20:34 KST에 협조 중지했다. **완료WAIT1·128건/추가소비1만 유지**하며 BASE·PAIR·ORDER는 같은 미실행ID로 이어간다. R2는 R1 전역예약 원장을 그대로 공유해 전체추가APP를4회로 제한하고, 첫WAIT의 원reference SHA `6dfb7c202f9fc2bf1e7cf04be26277952a277a5cbf184177a06526307dc6c08d`를 원바이트로 이월한다. 재기준·완료한ID 재실행·예산환급·추가예산은0이다.

새 호스트는 `tools/d1_a24_extra4_continue.py`이며 원179+등록호스트4를 보존한 채 계속실행기/검증2파일만 더한185파일 SHA 목록을 사용한다. 실행·응답·저장·자원반환·본측정 온도판정 함수는 바꾸지 않았다. 초기 WAIT와 나머지3의 **준비 전 호스트 버전 차이**를 보고하고, 같은 참조 허용폭이 내부 열 상태의 완전한 동일함을 보장한다고 주장하지 않는다. 정책별 시작AP와 전체구간을 함께 보고하며 작은 열 차이를 확정 절감으로 해석하지 않는다.

실제job `output/A24R02R2/job.json`, 원물 `Documents/A24R02R2`, 전역예약은 기존 `Documents/A24R02R1_GLOBAL`이다. R1과 이전 자동계속은 종료됐으며 원19는 아직 시작하지 않았다. R2 남은3 종료·회수/소유 프로세스 부재 후에만 원19 C10을 시작한다.
