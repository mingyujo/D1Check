# 현재 안정 온도 사용 — 사용자 지시와 예산 선택

사용자 지시: **“아까혼합묶음 얼마 안해서 안정온도면 그냥 이걸 기준으로 잡고 해”**. 안정 상태에서 새 공통 기준을 정하는 개정 방향은 승인된 것으로 기록한다. 과거28.4℃ 기준·원자료를 덮어쓰거나 서로 다른 초기 조건을 같은 조건으로 합치지 않는다.

현재 C9 첫 ORDER는 앱 준비1회가 이미 시작되었으나00:49:57 KST 점검에서 MAIN START/claim은0이다. 원 실행기는 처음 고정된28.4℃를 메모리에서 사용하는 중이고, 600초의 준비 후 판정을 중간에 다른 기준으로 변조하지 않는다. 다음 APP 차단 플래그를 기록했으며, 현재 앱의 기존 판정·원물 회수·정상 종료 경계를 보존한다. 이 APP는 본요청0이어도 예산1회를 소비한다. 현재 전체62/81소비·정상 독립 확인20/40이고, 원미시도19회가 남는다.

| 구체적 선택 | 처리 | 총 예산 필요 | 비교 가능한 범위 |
|---|---|---:|---|
| 새 공통 안정 기준으로 혼합4조건 재측정 | 원혼합3조건과 현재준비 시도 보존, 동일 입력/seed·128요청의 BASE/PAIR/WAIT/ORDER에 각각 새 ID를 부여. 첫 준비 후 원 안정60초 알고리즘으로 기준을 결과 전에 고정하고 나머지3조건이 공유 | 기존81 + 새4 = **85** | 새4조건 사이의 시작 조건을 맞춘 비교. 과거3조건과 별도 개정 묶음 |
| ORDER만 새 안정 기준으로 별도 실행 | 현재 준비 시도는 보존, 새 ID의 ORDER128요청1회 추가 | 기존81 + 새1 = **82** | 새 ORDER와 과거3조건은 초기 기준이 달라 엄격한 동일 조건 비교 불가 |
| 기존81 유지 | 현재 준비 시도 종료 후 원미시도19회만 진행. 새 부하 묶음의 기준은 원래대로 첫 안정 준비에서 선택 | **81** | 이번 혼합 묶음의 미완성/시작 조건 문제를 그대로 보고 |

85/82는 기존81회 상한을 초과하므로 사용자의 추가 선택 전 실행하지 않는다. 81유지 경로의 독립적인 원물 보존·PC 준비는 계속한다. 새 기준의 허용폭·60초 이력·기울기·공백·600초 판정, 원요청·기한·실행/저장 경계·모델·품질·APK·계수는 바꾸지 않는다. 새 기준4조건을 진행하더라도 실제 J/표면온도 검증 또는 열 절감의 성공을 전제하지 않는다.
