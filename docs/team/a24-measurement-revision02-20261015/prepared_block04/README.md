# 준비 후 기준 봉인·CPU 실행 전 수동 냉각 — 묶음04

사용자는 충분히 식힌 뒤 이어 수행하고 현재 값 기준으로 GPU부터 재개하되 늦게 끝나도 된다고 지시했다. 준비 전 수동 대기 값27.6℃를 쓴 묶음03은 GPU공통 준비 뒤 AP28.2~29.5℃·마지막28.5℃로본요청0 사전거절이었다. CPU는 미시도다. 이 기록과 원26.1℃ 묶음을 보존하고 합산하지 않는다.

**이번은 첫 GPU의 공통 준비를 마친 뒤 최초 안정60초 이력 중앙값을 본요청 전에 봉인한다.** 원래 준비 후 기준 방식으로 돌아가되, CPU는 새 앱을 켜기 전에 그 고정 기준까지 수동 냉각을 기다린다. 미리 정한 알고리즘이므로 실제 기준 숫자는 준비 뒤에만 생긴다. GPU 성적을 보고 수치를 고르지 않는다.

CPU 앱 실행 전: 새 추론 없이 AP를5초 간격으로 읽어60초 이력·10초gap·기울기0.1℃/분·기준±0.5℃를 확인하며 마지막값은 기준 이하를 요구한다. 통과 뒤에만 CPU 앱을 켜 공통 준비를 수행하고, 준비 후에도 기존60초 gate를 다시 통과해야 본요청을 시작한다. 준비앱의10분 한도를 전체 냉각 시간으로 사용하지 않는다. CPU가 자기 기준을 새로 잡지는 않는다.

모델/승인 이미지/252요청씩의 도착·기한/4runtime상주·각2회 워밍업/시간창/결과·lane경계/APK는 그대로다. 앱 설치/모델 교체/주파수·전력 설정 변경/추가 가열은 하지 않는다. 원161개 소스와 본 controller는 그대로이며 wrapper만 앱 밖 냉각 단계로 확장했다.

GPU→CPU 최대2시도,원64 중 이전31시도 보존·미사용33에서2배정(둘 다시도 시31잔여). 묶음03 미시도 CPU는 실제 시도로 세지 않는다. 작업 상한13:20 KST,앱 시작21분·START5분 여유가 필요하다. 냉각이 늦어도 승인된 남은 시간 밖으로 새 실행을 시작하지 않는다.

개발 절차 보완이며 최종 독립 확인이 아니다. 같은 AP가 내부 잔열/주변·부하까지 같다는 뜻은 아니고,단일 승인 이미지 반복이다. J계산불가/표면온도미검증/수치모형정확도미검증/experiment_ready=false를 유지한다. 앱 밖 대기와 준비 시간은 실제 wall time으로 별도 기록하며 이를 무료 에너지 절감으로 해석하지 않는다.
