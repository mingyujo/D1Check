# 공동 롤링 호라이즌의 세 관점 재검토와 실행 첫 행동 선택기

작업 `ROLLING-EXPERT-REVIEW-04`, 2026-10-10. 사용자 “세 전문가가 회의해서 이걸 더 발전시켜보자” 지시로 기존 모바일·산업공학·RL AI 세 에이전트를 다시 호출했다. 원 공동 계획/첫 선택 검사/종단 검사/실패 진단을 읽고 직접 질문·반론을 두 라운드 교환했다. **결론은 실행 첫 행동을 직접 선정하는 별도 원형 선택기다. 정의 구현·검사까지 완료했으며 온라인 정책 연결과 성능 개선은 아직 미확정이다.**

## 현재 구현과 반복하지 않을 보완

기존 공동 롤링은 현재 도착 요청창4, 과업 내 EDD, CPU 전용 탐지의 최소 여유 포함, 최대72계획 중 평균 선별8을 사용한다. 각 계획의 현재 전체 큐＋Band 후속을 원3문맥으로 예측하고 기한 실패·긴급P95·J·AP 비악화 조건을 적용한다. 첫 단건/가능한 병행 쌍/유한대기만 실행하고 새 사건에서 재계획한다.

이미 적용한 보완은 원후보의 첫 행동 검사, 선별 손실 진단, 공통 종료 시각의 종단 AP 검사다. 개발 큰창24의 선별 손실0은 전상태의 무손실 증명이 아니지만 선별 범위부터 넓힐 근거는 약하다. 종단 조건은 실제 개발24에서 Band와 일정/KPI가 모두 같아 추가 이득0이었다. 같은 종단 조건·추가 학습·임계값 조정을 새 해법처럼 반복하지 않는다.

현재 확인 결과는 [공동 계획](results/rolling_joint_01/README.md)의15조건 AP 감소/서비스·J 유지와 지속 악화, [첫 선택 검사](results/rolling_prefix_01/README.md)의24조건 긴급P95 Band 동일/12조건 AP 감소/3조건 공동감소다. 공동3은 하나의 도착 seed의3문맥이고, 다른 seed의 AP 증가·일반 평균 완료 지연 및 양 기준 서비스 손실 때문에 전범위 미채택이다.

## 선택기 정의와 핵심 식

원 shortlist8을 확대하지 않는다. 각 후보를 실제 반환할 행동으로 변환하고 같은 실행 행동은 한 번만 평가한다. 단건과 병행 쌍은 실제 요청/backend의 순서를 보존한다. 냉각 대기는 timer/hold signature, 자원 대기는 도착·어느 lane AVAILABLE 사건까지의 hold로 구분하며 **대상 미래 요청 배정은 약속하지 않는다.** 응답 완료/worker release로 실제 lane이 반환됐다고 처리하지 않는다.

동일 공개 상태 (s), 동일 과거 최고 (P_s), 같은 계수/문맥 (c)에서 실제 행동 (a)＋Band 후속 예측을 비교한다.

\[
G_c(a)=\max(P_s,\,P_{\mathrm{future},c}(a)),\quad
\Delta A(a)=\max_c(G_c(a)-G_c(B)),\quad
\Delta J(a)=\max_c(J_c(a)-J_c(B)).
\]

원 서비스/J/AP 비악화 예측을 통과하고 `ΔA < −EPS` 또는 `ΔJ < −EPS`인 실제 prefix만 원형의 개선 후보다. `EPS=1e−9`는 기존 예측 수치 회계값이며 새로운 물리 허용폭/SLA가 아니다. 최종 성능 판정은 기존 원단위KPI·epsilon0을 유지한다. 순위는 최악 전체 최고 AP 차이→최악J 차이→기존 후보 순번이다. 미래 AP만 낮아진 경우는 별도 진단이며 이득 선정에 쓰지 않는다. 이 선정 의미는 원 미래 AP 기준과 다른 **별도 draft 버전**이며 원정책을 소급 수정하지 않는다.

같은 실행prefix/상태의 예측이 다르면 가장 유리한 값을 고르지 않고 모호성으로 제외한다. 기준 Band의 실제 행동을 해결하지 못하면 비교 미확정으로 돌아간다. Band 별칭이나 같은 실제 행동은 새로운 기회로 세지 않는다. 예측 불가/누락/비유한 값도 임의0으로 채우지 않는다.

## 원형 구현과 마지막 반례 수정

- `tools/d1_rolling_prefix_selection.py`: 원형의 행동 변환·동치·3문맥 비악화/전체KPI 선택 순수 함수. 시뮬레이터·학습·기기 import가 없고 기존 controller에 연결하지 않았다.
- 첫12검사를 전문가가 읽고 추가 반례를 찾았다. 기준 `global31/future30.5`이면 공동 과거최고가31인데 후보 `global30.8/future30.5`를 같은 상태 개선으로 허용할 수 없었다. **공통 `past_peak_c`와 `state_key`를 필수로 받고 `global=max(past,future)`를 검사**하도록 수정했다.
- Band 별칭을 개선으로 선택하는 경우, 같은backend 병행, 없는/만료된 냉각timer, 자원대기의 잘못된timer, 서로 다른상태의 예측도 차단했다. 순수16검사 PASS. 산업공학 최종 읽기에서 추가 필수 오류는 발견되지 않았다.
- 의미 문자열은 실제 WAIT 예측기의 정합 증명이 아니다. 기존 `plan[:1]`의 강제 미래 배정 투영은 새 선택 근거로 거절한다. 취소·재계획 의미에 맞는 WAIT projector와 same-state provider는 아직 구현하지 않았다.

이 검사는 정의 반례의 수정과 입력/선택 정합 근거다. Band보다 좋은 실제 대안이 존재하거나 새 온라인 정책 성능이 좋아졌다는 증거가 아니다.

## 남은 검증과 유한 후속 제안

저장 진단에는 모든 shortlist의 **전체 계획** 예측은 있지만 모든 대안 **실행 prefix**의 예측과 완전한 공개 상태가 없다. 기존1등이 차단됐을 때 더 좋은 다른prefix가 있었는지는 **미확정**이다. 단순히 전체 계획 예측을 대안prefix 성과로 옮기지 않는다.

다음 진단은 별도 등록 후 개발mean의2seed×4부하, 최대8상태로 제한하는 제안이다. 각 그룹에서 최초 guard 차단 상태, 없으면 최초 비Band 선정 상태를 구조 규칙으로 고른다. 없거나 공개 상태/실제대기 의미를 복원할 수 없으면 unknown으로 종료한다. 전이의 ns 정수화와 공개phase·dispatch·lane반환·관측응답·credit/hold·모형 추정T/h·Band EMA를 복원하되 미래 도착/실현 잔여비용을 입력하지 않는다.

원8prefix×3문맥＋Band3＝최대27예측/상태, 총216예측이다. 원shortlist 복원에 평균72계획/상태가 필요하면576추가·최대792예측을 별도 고정한다. 이는 사후 조건부 모형 진단이며 native 환경/학습/기기0이고 독립 성능 확인이 아니다. 기회0/복원불가이면 자동 전체24상태 확대나 RL 학습을 하지 않는다. **이 후속 제안은 아직 실행 등록·실행하지 않았다.**

기회가 확인된 뒤에만 같은 입력/후보 기회의 비학습 대조와 새 독립 확인을 설계한다. 새로운 학습은 반복되는 유효 선택 기회, 대조 대비 추가효과 근거, 별도 유한 학습 예산이 필요하다. 기존64episode/8update나128/16update 결과를 RL 일반의 실패/수렴으로 해석하지 않는다.

## 산업공학 근거·범위

롤링 호라이즌 휴리스틱의 시간창 분해는 [Singer의 생산 스케줄링 연구](https://www.sciencedirect.com/science/article/abs/pii/S0305054899000982), 상세 단기 일정과 후속 생산능력 계획의 반복 연결은 [Li–Ierapetritou 연구](https://www.sciencedirect.com/science/article/pii/S000925091000477X)에 사용된다. 예측 계획과 실제 구현 일정의 차이는 [Maravelias 연구실의 온라인 스케줄링 설명](https://maravelias.princeton.edu/research/chemical-production-scheduling/online-scheduling)과 [종단 재고 제약 연구](https://www.sciencedirect.com/science/article/pii/S0377221721001223)의 문제의식에도 있다. 논문 공개 초록/저자 자료를 확인했으며 접근되지 않는 본문을 읽었다고 주장하지 않는다.

우리 문제는 앱 요청의 비선점 이종자원 배정·납기·호환성·실행시점 계획이다. 제조 DAG/재고/수요예측·논문의 최적성/성능을 전용하지 않는다. 고정5phase에는 냉각→서비스 회복이 없고 AP는 표면온도가 아니다. 첫 행동의 국소 비악화는 미래 도착/전체episode/물리적 온도를 보장하지 않는다. 일반 완료 지연·판단부담·미완료를 최종 평가에 계속 보고한다.
