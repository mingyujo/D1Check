# S26 시뮬레이션 계획 — 기존 엔진 재사용과 혼합 요청 모형 검증

## 1. 목표와 기존 연구 범위

GitHub에 있는 S26 `d1sim`을 보존·재사용하되, 최신 S26 분류·탐지 혼합 요청의 **정확한 모델·엔진·CPU thread·resident 집합·요청 경계에 맞는 프로필과 adapter**를 별도로 구성한다. 먼저 응답·전체 도착 성공률·AP/SKIN·기기 전체 에너지의 예측 가능 범위를 검증하고, 그 범위에서 정책 후보를 탐색한다. 모형의 정확도와 실기기 정책 효과를 별도 판정한다.

A24 계수를 S26에 옮기거나 두 기기의 회귀 자료를 합치지 않는다. 기존 MobileNet/CPU4와 최신 EfficientNet/EfficientDet/CPU1도 같은 측정 계약으로 간주하지 않는다. MobileNet의 과거 열 구조·모형 오차·holdout은 해당 버전의 근거로 보존한다.

기존 `S26-THERMAL-SCOPE-02`의 제출 범위와 기본/RL/strict/`experiment_ready=false`는 유지한다. 최신 혼합 자료를 활용하는 이번 모형 연구가 과거 두 모델 재현·품질·정책 효과·에너지 적격성의 완료를 뜻하지 않는다. 측정된 조합만 최대 두 건 병행하며, 세 backend가 있다는 이유로 세 건을 동시에 실행하지 않는다.

## 2. GitHub에 있는 기존 시뮬레이터와 우리 모형의 차이

비교 기준은 S26 원격 `s26-measure`의 고정 HEAD와 현재 A24 v3 thermal-only hybrid다. S26의 주 정책 평가 경로와 최신 혼합 실측 경로를 구분한다.

| 항목 | 현재 A24 모형 | GitHub S26 기존 d1sim |
|---|---|---|
| 주 작업 | EfficientNet 분류＋EfficientDet 탐지, 실제 요청 단위 | 주요 `policy_eval_v2`는 EffNet 단일 분류의 FG 1회/BG 128회 chunk; 최근 분류＋탐지 혼합 실측은 별도 request-runner 자료 |
| 자원 | CPU/GPU, 검증된 분류GPU＋탐지CPU 병행 | CPU4/GPU/NPU 프로필. 주 FG/BG 평가 경로는 GPU 또는 NPU 한 자원에서 한 작업씩 실행 |
| 완료·점유 경계 | 전후 처리·output·persist·worker release·lane available의 실제 벡터 | 추론율·chunk·switch 비용 중심의 해당 S26 계약. 그대로 mixed 7경계와 같다고 할 수 없음 |
| 열과 처리속도 | AP 비용 예측을 보정하지만 온도→서비스 시간 피드백 없음 | AP/SKIN 열 상태·부하 이력·controller·감속이 처리율과 전력에 연결됨 |
| 에너지 | 사전 전력＋원 상태별 증분전력, 이번 energy 개선 실패 보존 | 상태/controller 기반 전력 프로필과 센서·잔량계 분석. 일부 단위/내부 일관성·전이 한계 있음 |
| 핵심 강점 | 두 모델 요청·큐·병행·완료 경계가 구체적 | 장시간 가열·냉각·GPU/NPU 전환·감속 모델이 더 풍부함 |
| 주의점 | 장시간 열 감속·작은 정책 에너지 차는 미검증 | 모형이 복잡해도 새 mixed CPU1 계약에 대한 정확도·품질을 자동 보증하지 않음 |

따라서 두 모형 중 하나가 보편적으로 더 정확하다고 판단하지 않는다. AP와 SKIN, 단일 추론과 chunk, 서로 다른 시간창·정밀도·기기는 같은 오차 표로 합치지 않는다.

코드 근거: [S26 엔진](https://github.com/mingyujo/D1Check/tree/0a0749890fba2452c5907433c6bea476a2da7e24/d1sim), [주 정책 sim](https://github.com/mingyujo/D1Check/blob/0a0749890fba2452c5907433c6bea476a2da7e24/d1sim/policy_eval_v2/sim.py), [V22 모형](https://github.com/mingyujo/D1Check/blob/0a0749890fba2452c5907433c6bea476a2da7e24/d1sim/throttle_v22.py), [A24 예측 API](../tools/d1_simulation_model_v3_prediction.py), [A24 최종 판독](results/simulation_model_v3_expert_01/README.md). 원 README의 v0 설명만으로 이후 v2/v22/v3 전체의 검증 상태를 판정하지 않는다.

## 3. 자료와 사용할 역할

| 자료 | 고정 원격 HEAD | 이번 계획의 역할 |
|---|---|---|
| `s26-measure` | `0a0749890fba2452c5907433c6bea476a2da7e24` | 기존 엔진·열/감속 구조·에너지 판정기·버전별 모형 오차 비교 |
| `s26-mixreq` | `21cba44faa5fff1fb9703b590aa536a6207f8de5` | R3/R4C/R4S의 새 mixed 계약·요청 경계·전력·온도 |
| `s26-quality20` | `5857152ad8244c41975843ded77dd33024f38f2d` | exact 입력·backend·출력 품질과 별도 APK 귀속 확인 |

R3와 R4C는 각각 **16세션×192요청**이다. R4S는 16예정 슬롯·18실제 시도(유효14/실패4)와 별도 준비/중지2 기록이다. 유효 정책 짝은 A4/N2로 불균형이다. R4S 공유 묶음의 파일 수107,032는 원장과 일치하지만 모든 파일 내용·SHA를 재검증한 결과는 아니다. 큰 GitHub tree 조회가 잘린 경우 누락 파일이라고 판단하지 않고 하위 트리를 조회한다.

이미 원 결과를 본 자료이므로 새 모형의 후행 개발·회고 검증에 사용한다. R4C의 원래 확인 역할은 보존하되, 지금 새로 맞춘 모형의 미열람 독립 확인이라고 부르지 않는다. R4S는 장시간 전이와 실패·배출 한계의 stress 자료다. 미래 새 독립 확인은 모형·입력·분석을 동결한 뒤 별도 등록한다.

품질20은 별도 quality-runner APK에 귀속한다. CPU 참조 일치, GPU 실제 정밀도 미확인, NPU FP16 합격선 미등록에 따른 품질 PASS 보류를 보존한다. 실제 backend 실행 증거와 출력 품질 합격은 다르다. 미검증 경로는 **관측 재생·오차 연구**로 기술하고, 품질 승인된 새 정책 후보 mask에는 넣지 않는다. 새 candidate 등록 전 request-runner의 exact 계약과 품질 증거를 연결해야 한다.

## 4. 전처리·적격성 감사부터 고정

1. **원장과 provenance:** 세션/시도/pair/block/day·모델/입력/라벨·APK·source·runtime·정밀도·thread·resident 집합을 표로 묶는다. 공통 ancestor에서 중복 공유된 자료는 hash/session ID로 한 번만 세고, 다른 프로토콜은 별도 strata로 남긴다.
2. **시각:** 요청·전력은 기기 단조시계, HAL은 `device_boottime_s`에 연결한다. `pc_ms`로 latency를 계산하지 않는다. HAL에는 전후 bracket이 없으므로 갱신 지연은 미식별로 표시하고 ±한 실제 관측 간격의 정렬 민감도를 공개한다. 이것은 CI가 아니다.
3. **센서:** 정기 적분에는 `kind=power_sample`만 쓴다. 대표 R4C의239 power_sample와204 admission 센서 중복 기록을 합쳐443표본으로 적분하지 않는다. 동일 전류값은 실제 갱신·정체일 수 있어 임의 삭제하지 않는다. current/charge valid·부호·단위·전압·충전·갭·snapshot 폭·CC 눈금·몰림을 점검한다. 기록되지 않은 절전 상태를 false로 채우지 않는다.
4. **적분·구간:** S26 manifest의 baseline30/common120/cooling60과 실제 anchors를 먼저 연결한다. A24 사전창 −20..30초를 복사하지 않는다. 정해진 창의 경계 절단·선형 적분을 쓰되 외삽·긴 공백 연결·누락0 대체는 금지한다. 기존 S26 energy judge의 창 안 첫/끝 표본 계약은 따로 재현한다.
5. **완료·실패:** urgent 완료는 output, normal은 원 persist 계약, lane 점유는 lane_available까지다. 요청의 일곱 경계와 host 호출 시작/반환도 검증한다. 실패4의 관측 prefix·미완료·예정 요청은 보존하고, 없는 후반 J/온도를 채우지 않는다. full120/full720 coverage와 부분 관측을 구분한다.
6. **상태 식별:** 관측된 단독/병행 노출·수치 rank·condition·반복을 검사한다. 짧은 요청을900ms 전력 표본 하나와 직접 대응시키지 않는다. joint 전력을 단독 전력의 합으로 만들지 않는다. 생성만 된 detection_GPU나 세 건 동시 실행을 지원으로 채우지 않는다.

## 5. 최소 모형 — 복잡도는 단계별로 제한

| 출력 | 먼저 재현할 기준 | 이번 우선 후보·보류 |
|---|---|---|
| 서비스 | S0: S26 exact task/backend/context의 고정 phase 벡터와 세션 블록 재생 | S1: 누적 실행/점유 한 변수의 제한된 감속. 온도→service S2는 시간·열 교락 분리 전 보류 |
| AP/SKIN | T0: 사전 최종 온도 유지, 적합0 | T1: 예측 점유 기반의 양의1pole 응답·사전 anchor. 2RC/복잡 ML/자유 ambient＋hidden H 동시 추정은 보류 |
| 에너지 | 기존 S26 J 계산·판정 계약을 재현하고 sensor-target 기준 확보 | E0: S26 사전 전력＋식별 가능한 상태별 고정 증분. prelate·τ 보정 E1은 즉시 등록하지 않음 |

E0의 구조는 `E_hat(0,T)=P_pre·T＋Σp_state·예측 점유초`다. S26 전류의 μA 계약·계측 가정을 보존하고 A24 mA 해석과 합치지 않는다. 예측 전력→열 연결은 전력 적격성이 필요하지만, 점유→온도 경험 T1은 별도로 검증할 수 있다.

E1은 S26 개발자료에서 사전 특징이 이후 유휴 잔차를 pair/day 제외로 예측하고, 시간상수의 S26 근거를 확보했을 때만 별도 등록한다. A24에서 실패한 τ30/prelate를 복사하지 않는다. E_int/E_cc 비율이 맞도록 단위나 gain을 사후 조정하지 않는다. 근거가 없으면 E0의 한계로 종료한다.

T1/S1의 계수·τ·규제 목록은 **원자료 적격성·식별성 감사 뒤, 적합 결과를 보기 전에** 별도 실행 계약으로 고정한다. 짧은 창만으로 느린 시간상수를 식별했다고 가정하지 않는다. 상태별 노출이 공선적이면 항을 줄이거나 미지원으로 남긴다. 현재 제안은 S0/S1·T0/T1·E0의 유한 family이며, 실패 뒤 구조를 계속 늘리는 탐색을 포함하지 않는다.

## 6. 평가 — 절대 오차와 정책 차이를 함께

**A:** 실제 일정에 조건부인 서비스/비용 진단. **B:** 예정 요청＋사전 관측→예측 큐·서비스·점유→온도·에너지. B에 실제 미래 온도·전력·duty·완료 시각을 넣지 않는다. 알려진 과거 관측과 미래 평가 정답의 경계를 API로 분리한다.

| 지표 | 보고할 내용 |
|---|---|
| 서비스 | phase/host 호출 오차, 완료 응답 P50/P95, 전체 도착 기준 완료·기한 성공·실패/거절/만료/미완료, backlog/drain |
| 온도 | AP/SKIN 각각 MAE·최대오차·peak·부하/냉각 잔차·초기값/정렬 민감도. SKIN peak38.1°C 유효 집중과 실패의더높은값을별도감사 |
| 에너지 | full120와full720 각각 부호/절대/상대J오차, 부분 관측coverage, E_int와E_cc 내부 일관성·눈금 민감도·정책 짝차 부호 |
| 정책 판별 | 같은 전체 요청·기한·관측창의 예측−실측 짝차 오차, CPU/PAR/PAR-NPU의 관측 가능한 순위·동률·뒤집힘 |

요청 행 random split을 금지한다. pair의 두 정책, 같은 run의 부하/회복, 연속 블록과 날짜를 함께 묶고, 동일 raw를 여러 export에서 중복 사용하지 않는다. 개발 범위 안의 pair/day 제외와 short→long/resident4→5/프로토콜 전이는 따로 판독한다. N 유효짝2를 A4와 합쳐 표본수를 늘리지 않는다. 많은 요청·가상 seed는 독립 기기 세션이 아니다.

허용 오차는 용도별로 적합 전에 등록할 값이다. 현재0.2°C 또는1%를 S26의 보편 합격선으로 쓰지 않는다. 우선 기준선 대비 개선·정책별 악화·최악 세션을 모두 공개하고, 목표 정책 효과를 구분할 만큼 **짝차 오차와 불확실성**이 작은지 판정한다. 예측 차이의 방향이 불확실성에 민감하면 후보 순위는 미판정이다.

## 7. 실행 순서와 종료·추가 측정 조건

| P3 | 동결 후 R4C·R4S의 사후 전이·정책차 판독 | 이미본자료임을표시, 새blind 주장0. 지원 범위와 새 실측 질문 특정 |
| P4 | 필요할 때 별도 새 독립 확인 등록 | 모형·APK·품질·입력·조건·예산 동결 뒤만 실행. 현재 기기 실행 승인·예약0 |

PC 작업시간·fit 횟수의 실행 상한도 P0 뒤 P1/P2 계약에서 고정한다. 현재 계획을 무제한 적합·RL 학습의 승인으로 해석하지 않는다. 식별 실패, coverage 부족, 품질/시각 미해결이면 해당 출력 또는 경로를 보류하고 성능을 가상으로 채우지 않는다.

추가 측정의 발동은 ① 특정 state 노출 부족, ② 초기 열 이력·τ 미식별, ③ 시간과 열을 분리한 감속/회복 확인 필요, ④ 품질/새 조합 필요, ⑤ 동결 후 독립성 확보 필요일 때다. 이미있는 원본을 먼저 회수하고, 단순히 성적이 나쁘다는 이유로 같은 실험을 재시도하지 않는다.

독립 확인의 최소안은 **한 질문·한 부하조건의 기준/대안 ABBA4세션**이다. 각 정책2회라 반복성 확인용 최소안이며 통계적 정책 우월성 인증 표본수가 아니다. 장시간 전이 질문은 별도 지속조건 ABBA4 제안으로 분리하고, NPU는 해당 품질 gate를 먼저 충족해야 한다. 가열/유휴 순서교차 실험은 S2 열→service 질문의 별도 설계다. 기기·추론·설치·총시간·마지막 저장 한도와 실패/대체 규칙은 실제 등록 때 확정한다.

S26 energy_1008의 C1/C2 전류적분/잔량계 내부 일관성 약4% 차이와 정책 차의 부호 역전은 원래 판정과 함께 보존한다. 조건부 동등성 적격을 절대 J 교정으로 바꾸지 않는다. 작은 절감 방향이나 절대 정확도가 필요하면 독립 참조 계측을 검토하며, 외부 계측 없이 진행하면 sensor-target 예측 범위로 한정한다.

## 8. 이번 계획의 완료와 근거

완료 대상은 기존 시뮬레이터 존재/코드 범위 확인, A24와의 차이, 3역할 2차 반박 기록, 자료·전처리·모형·검증·측정발동 계획이다. 모형 개발 완료·정책 효과·GPU/NPU 품질 전체 PASS는 현재 완료 대상이 아니다. 원격 브랜치를 merge/push하거나 기존 정책·모형·실측을 변경하지 않는다.
