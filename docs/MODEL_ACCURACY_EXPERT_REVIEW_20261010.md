# 에너지·AP 오차 감소: 세 관점 토론과 해결 순서

**기존 자료에서 줄일 수 있는 오차 성분을 찾았다. 그러나 전체 시뮬레이터를 바꿀 만큼 일반적인 해법은 아직 확인되지 않았다.** 가장 작은 다음 후보는 `유휴 상수 보정 δ=0 + 상태별 추가 전력 4개 재추정`이다. AP는 이미 동결한 LOAD_SLOW를 분리해 유지한다. 최근 유휴 전력을 긴 미래 전체에 전용하는 대안은 실제 반례로 기각했다. 새 실측은 후보 동결 뒤 필요한 질문에만 조건부로 남긴다.

## 실제 토론과 제안 변경

사용자 요청으로 세 검토 AI를 만들었다. 사람 전문가의 검증이나 자격 인증은 아니다.

| 관점 | 담당 질문 | 검토 기록 |
|---|---|---|
| 에너지·열 모형 | 어떤 수식 항이 오차를 만들며 무엇이 식별되는가 | [모형 검토](results/model_accuracy_expert_review_01/reviews/energy_thermal_review.md) |
| 실험 식별·독립 확인 | 초기 정보·개발/확인·순서·센서 경계를 지키는가 | [식별 검토](results/model_accuracy_expert_review_01/reviews/identification_validation_review.md) |
| 시뮬레이션·정책 | 조건부 비용과 종단간 예측, 정책 차이까지 지원하는가 | [정책 검토](results/model_accuracy_expert_review_01/reviews/simulation_policy_review.md) |

독립 검토 → 서로 직접 질의·반론 → 주 검토자의 초기 전력 문제 제기에 대한 재토론의 3차를 수행했다. 처음 제안된 온라인 관측기와 최근20초 기준 재추정은 반례 후 우선 후보에서 제외됐다. 다수 의견을 성공 증거로 대신하지 않았으며, 최종 기준전력 해법·필요 반복 수에는 확정 합의가 없다.

새 단위·적분·시간 정렬 결함을 원모형에서 발견하지 않았다. 이번 새 진단의 초안만 정책 짝의 실행 순서를 정책 방향으로 오인했다. 정책 ID로 CPU/PAR 방향을 고정하고 기존 관측 차이와 일치하는지 검사하도록 수정했다. [초안 보존·수정 사유](results/model_accuracy_expert_review_01/diagnostics_01/diagnostic_correction.json), 최종 수치는 `diagnostics_02`다. 기존 원자료나 과거 모형 결함으로 소급하지 않는다.

## 1. 확인된 문제: 긴 시간으로 전용한 기준전력

직전 [에너지 후보](ENERGY_AP_JOINT_FOLLOWUP_PC_20261010.md)는 `P50·시간 + δ·35초 이후 시간 + 상태 추가전력·실제 점유시간`이다. `P50`은 부하 전 `[-20,30]`초의 전체 기기 평균 전력이다.

- δ=+0.0241496W는 실제 배경·온도·주변의 인과 계수가 아니라 개발4의 유효 잔차 보정값이다. 세션 제외 추정값도 +0.0283/+0.0167/−0.0035/+0.0550W로 안정적이지 않다.
- LOAD 작업 후 유휴 2009.324초에 δ가 48.5243J를 계속 더해 원 오차 −10.9984J를 +37.5259J로 바꾼 것은 수학적으로 확인됐다. 실제 기기에서 배경이 변한 원인은 미확정이다.
- 준비 유휴도 정상 평형이라고 할 수 없다. 개발4의 초기20초→최근20초 평균 전력 변화는 +0.133/+0.068/+0.008/−0.227W이며, 마지막 유휴 전력과 P50 차이의 부호도 갈린다. 임의 감쇠시간·종료시각을 맞춰 긴 잔차를 없애지 않는다.

**0.05W의 미래 기준전력 오차가 2000초 지속하면 100J가 된다.** 상태 계수만 정밀해져도 작업이 없는 구간의 이 오차는 해결되지 않는다. 그렇다고 모든 과거 예측이나 정책 비교가 불가능하다는 결론도 아니다. 같은 초기조건·같은 창의 반사실적 정책 비교에서는 공통 기준항이 소거될 수 있으나, 서로 다른 실측 세션의 환경 차이는 소거되지 않는다.

## 2. 기존 자료로 수행한 성분 분해

새 물리 계수 추정은 0회다. 직전 후보의 p4를 고정하고 δ 항만 제거한 **성분 제거 진단**이며, δ=0으로 다시 학습한 모형의 결과가 아니다. AP는 고정 LOAD_SLOW를 사용했다.

| LOAD_A_LONG / 정확한 구간 | 원 에너지 오차 | 기존 δ 후보 | δ 제거 진단 | 원 AP MAE → 고정 AP |
|---|---:|---:|---:|---:|
| 등록600초 `[35,635]` | −15.151J | +10.763J | −3.726J | 0.544→0.186°C |
| 작업 존재 `[35,545.1858]` | −11.807J | +11.938J | −0.383J | 0.529→0.172°C |
| 덮인 회복 `[635,2554.5103]` | −7.655J | +38.700J | −7.655J | 0.404→0.169°C |

**두 출력의 공통 관측 구간 `[37.417396683,2554.510266266]`에서도** 관측2639.3775J, 원식2616.3173J, δ 제거2627.4431J다. 부호 있는 차이는 −23.0602→−11.9345J, 같은 구간 원표본 AP MAE는0.43731→0.17296°C다. AP922표본의 마지막은2552.2474초이며 센서 끝의 온도를 만들어 채우지 않는다. [같은 창 원수치](results/model_accuracy_expert_review_01/diagnostics_02/LOAD_A_LONG_matched_window.json).

개발4의 세션 제외 참고120초 평균 절대J는12.697→7.251J, 이미 본 과거29는5.522→5.087J다. **과거11세션 악화와 무부하 C0 미개선이 남는다.** C0의 같은 보정은 상태 노출이0이므로 원식과 동일하다. 전체 회복 끝 표본 누락은 기존처럼 전체J=null, 덮인 prefix만 계산한다. 120초·600초·긴 prefix의 평균을 합쳐 보편적인 시뮬레이션 오차로 표현하지 않는다.

AP 개선도 느린 항 하나만의 성과가 아니다. LOAD600초 MAE는 원0.5437 / 고정 빠른 항만0.4453 / 빠른 항+느린 항0.1862°C다. 빠른4계수 변경과 느린 부하 이력 항의 역할을 분리했다. 느린 τ1920초는 격자 상한에서 선택된 값으로 유일한 물리 시간상수 식별이 아니다. AP의 원 전력 proxy에 새 에너지 계수를 넣지 않는다. 과거29 AP 악화13건도 보존한다.

## 3. 기각한 대안과 정책 차이

최근 유휴 `P20=평균[10,30]`은35초 이전에 사용할 수 있었다. 그래서 앞0..35초 회계를 보존하고 이후만 P50 대신 쓰는 별도 초기화 진단을 수행했다. 기존 감쇠 후보와 식은 다르지만 **새로 측정된 최근값을 긴 미래에 상수로 쓰는 가정**은 여전히 필요하다.

- 개발4의120초 평균 절대J는3.248J로 좋아 보였다.
- 긴 LOAD의120초 차이는 −0.0077J였지만,600초 +23.926J / 덮인 회복 +80.810J / 등록+회복 prefix +104.736J로 악화했다.
- 과거29 평균 절대J도6.560J로 악화했다. 무부하 회복에서는 상태 노출이0이므로 p4 재추정으로 이 실패를 고칠 수 없다.

이 반론으로 정책 검토 AI의 P20 정식 재추정 제안과 주 검토자의 영구 초기값 교체안을 철회했다. C0에는P20/LOAD에는P50을 결과에 맞춰 골라 쓰지 않는다. 단일 감쇠·더 긴 τ 탐색·기존 실패 관측기의 이름 변경도 현재 추천에서 제외했다.

기존 지속 CPU 긴급우선/PAR 4짝의 관측 `PAR−CPU` 방향을 보존한 결과:

| 비교 | 차이 예측의 평균 절대오차 | 에너지 차이 부호 오판 |
|---|---:|---:|
| 원식 | 6.322J | 2/4 |
| δ 제거 고정 p4 | 6.213J | 2/4 |
| 최근20초 영구 초기화 | 9.952J | 2/4 |

공통 δ는 같은120초 짝에서 소거된다. 이를 삭제한 전체J 개선만으로 정책 순위가 해결되지 않는다. 위 짝은 이미 본 별도 세션 비교로, 순수한 인과 정책 효과나 모든 조건의 오차 한도가 아니다. [방향·전체 짝표](results/model_accuracy_expert_review_01/diagnostics_02/paired_difference_diagnostics.csv).

## 4. 가장 작은 후속 해결 절차

**다음 PC 작업 하나는 δ=0 제약 p4 후보의 개발4 세션 제외 평가다.** 추천은 조건부이며 이번에 수행한0fit 성분 분해와 구분한다. [구체적 계획](results/model_accuracy_expert_review_01/consensus_plan.json).

1. 상태 노출에 대응하는 개발 잔차를 확인한 뒤 후보1개만 구현한다. 원50초 기준·동일5초 개발 적분·동일 세션 가중 최소제곱·p4 비음수 제약을 유지하고 δ만0으로 고정한다. 개발4의4제외추정+최종1=최대5fit, AP fit0이다. 상태행렬 rank4가 안 나오면 미식별로 끝낸다.
2. 평가29+긴2는 추정에 쓰지 않는다. 모두 이미 열람한 사후 평가이며 기본/RL/strict와 별도다. 같은 창의 부하/유휴/회복·5/10초 잔차·누적J·AP 경로·최악 조건·짝 차이를 모두 보고한다. 무부하 C0가 개선되지 않는 구조적 한계를 숨기지 않는다.
3. 실제 일정 조건부 A를 먼저 평가한다. 저장된 B 예정 일정이 있는 자료에는 동일 비용식을 적용해 A/B를 별도 표로 둔다. 미래 실측 전력/AP를 넣거나 새 정책·RL 배치를 실행하지 않는다. 관측 pre를 사용한120초 전체 회계는0초에 발행한 순수 미래 예측이 아니다.
4. 평균만 좋아지고 긴 회복/조건별/정책 차이가 나빠지면 제한 개선·미채택으로 종료한다. 수치 오차만 보고 정확도PASS 기준을 만들지 않는다. 성공할 때까지 후보·창·계수를 바꾸는 경로는 없다.

기존 LOAD_SLOW가 지원하는 등록 macro의 AP 진단은 계속 사용할 수 있다. 상태 전력의 제한 개선과 일반 도착·정책 비용·열→처리시간 검증은 다른 완료 항목이다. 전체 기준전력 예측 문제는 아직 열려 있다.

## 5. 추가 실측은 목적별 조건부 계획

**지금 동일 B2나 긴 C0를 다시 측정하는 것이 우선은 아니다.** PC 후보와 정보 시점·판독 창을 동결한 뒤 아래 질문이 남을 때만 진행한다. 이번에는 새 기기 실행기·APK·collection_plan·소비 claim을 만들지 않았다.

| 질문 | 최소 구성과 역할 | 종료 기준 / 해결하지 못하는 것 |
|---|---|---|
| 동결한 두 출력 후보가 새로운 등록 macro에서도 맞는가 | 기존 C0_LONG+LOAD_A_LONG 2조건의 새 확인 block1개. 사전 pre-W/AP와 실제 lane·J/AP·환경을 함께 기록 | 두 출력 같은 창 오차·가열/냉각·결측·악화를 보고 완료. 확인 자료 재추정0. 독립 반복 변동성/날짜·순서의 인과 분리 아님 |
| 정책 차이가 오차에 묻히는가 | 같은 arrival의 CPU/PAR 짝과 순서 통제. ABBA4는 설계 예시이며 확정 표본 수가 아님 | 관측 정책 차이와 예측 차이·서비스 분모·방향을 비교. 정책 직접4회가 동적 모형 전체 검증은 아님 |
| pre와 이전 이력만으로 장기 배경을 구분할 수 있는가 | 첫2조건을 자동 반복하지 않는다. 기록 가능한 사전 이력·조건화·양순서 독립 block의 역할을 먼저 정의 | 새 개발 자료 필요 여부와 식별항을 결정. 현재 필요반복수·총시간·허용오차는 근거 부족으로 미확정 |

**변경 없는 기존2프로필의 코드상 참고 상한**은 runtime8 / warmup16 / 적격성8 / 본부하≤1200 / 총추론≤1224, staging2·14파일, 설치본pull·APKpush·설치 각≤1(동일본 생략), 고정관측5280초(88분), 총예약9050초(2시간30분50초), ADB≤16752다. 재시도·대체·추가0. 세션당 baseline120+공통600+회복1920초, 예약3880초이며 전체는설치600+2×3880+세션간90+분석600초다. 이는 현재 소스의 참고 산술이지 새 계획의 실행 승인·해시·완주 예상이 아니다.

새 순서·조건화·반복·정책4회에 이 예산을 복사하지 않는다. 별도 새ID/미소비 계획과 동결 hash·현재 기기/설치본/환경 gate, 중단·회수 예약이 있어야 실행 가능하다. 숫자 AP와 thermal status를 대체하지 않으며 환경·배터리 기준의 임의 완화/설정 변경·가열·재연결은 제안하지 않는다. 주변 온도를 새로 안다고 가정하지 않는다. 이번 실측 필요성은 **독립 확인에는 필요, 현재 후보의 제한 개선 판정에는 기존 자료로 먼저 가능, 장기 배경의 원인 식별에는 아직 설계 조건 부족**으로 구분한다.
