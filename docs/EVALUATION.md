# 평가 기준과 해석 범위

## 공통 평가 방법

한 기기 안에서는 같은 요청 입력·납기·모형·관측창을 각 정책에 적용합니다. 분류는 긴급 요청(0.8초), 탐지는 일반 요청(2초)으로 다룹니다. 정시율의 분모는 전체 도착 요청입니다. 응답 시점과 자원 반환 시점은 구분하며, 시작한 추론은 중단하지 않는 비선점 모형입니다.

- 정시율 = 기한 안에 응답한 요청 수 / 전체 도착 요청 수.
- 응답시간 = 응답 시각 − 계획 도착 시각. P95는 입력별 nearest-rank P95를 구한 뒤 평균하며, 합쳐 계산한 P95와 구분합니다.
- 소비는 관측 구간의 모형 전력을 적분합니다. A24는 J*, S26은 API-J이며 실제 배터리 소비 검증값이 아닙니다.
- 평균 AP 온도는 요청 공급 시작 이후 관측 종료까지의 시간 평균입니다. 피부 온도나 부품 접합 온도를 뜻하지 않습니다.
- 미응답·미완료를 별도로 보존합니다. 정시 처리 실패를 분모에서 빼지 않습니다.

주 조건은 공급 시작 35초, 공급 길이 N/도착률, 공급 끝+45초 배정 종료, +60초 검열 진단, +90초 관측 종료의 규칙을 공유합니다. 개별 입력의 정확한 시점은 해당 입력 JSON과 원시 결과에 있습니다.

## 기기별로 다른 부분

| 항목 | A24 | S26 |
|---|---|---|
| 분류 경로 | CPU·GPU | CPU·GPU·NPU |
| 탐지 경로 | CPU·GPU 전이 가정 포함 | CPU |
| 주 입력 | 512건·8건 묶음·명목 25% | 1,024건·16건 묶음·명목 85% |
| 기준선 배정 | 가능한 CPU/GPU 중 예측 응답에 따른 동적 배정 | 분류 GPU→NPU→CPU 우선, 탐지 CPU |
| 100% 참고 정책 | TRAIN 안전여유를 보완한 교사규칙 | BC 기반 전체 배정 정책+서비스 보완 |

명목 부하는 입력 생성의 기준값이며 실측 CPU 사용률이 아닙니다. 두 기기는 처리 프로필과 지원 경로가 달라 같은 명목 부하라도 같은 난도가 아닙니다. 공통 지표로 각 기기 안에서 기준선 대비 변화를 비교하며, A24와 S26을 동일 난도의 직접 대결로 해석하지 않습니다.

## 측정·가정·개발 검증 구분

측정 자료에는 처리·자원 점유 시점, 전력 대리지표, AP 센서 온도 등이 있습니다. 요청 도착·납기·중요도, 가상 자원 용량, 일부 미측정 경로·병행 간섭과 모형 계수는 연구 입력 또는 가정입니다. CPU 추론 슬롯 3개와 일부 GPU/NPU 병행 조합은 실기기에서 확인한 동시 처리 능력으로 주장하지 않습니다.

후속 온도 모형의 A24 약 0.11℃·S26 약 0.42℃ 평균 오차는 같은 측정 pool의 그룹 분리 개발 평가입니다. 이후의 오차 보완을 주 정책 실험에 소급 적용하거나, 정책 실행의 독립 실기기 검증으로 간주하지 않습니다. 평균 오차만으로 최대 오차·장시간 반응·정책 간 우열의 정확성을 보장할 수도 없습니다. 원시 파일의 물리 검증 실패/미확인 표시는 유지했습니다.

현재 결과는 실측 자료에서 구성한 모형 안의 조건부 비교입니다. 정책의 휴대폰 탑재 성능, 모바일에서의 예측·NN·제어 계산비용, 실기기 순절감은 검증하지 않았습니다. S26 체크포인트의 앞선 교사 초기화·PPO 계보와 현재 BC/서비스 보완 단계도 구분하며, 전체 개선을 BC 하나의 독립 효과로 귀속하지 않습니다.

## 입력 민감도 자료

A24의 규모·구성비 분석과 S26의 부하·도착 패턴 확장 자료를 좋은 조건과 악화 조건 모두 포함해 공개합니다. 이는 저장된 입력 범위의 민감도 분석입니다. 전력·열 계수 변화에 대한 민감도 분석이나 새로운 독립 실측은 아닙니다. S26 확장 비교의 기준선은 EDF이므로, 같은 범위의 FIFO 우위까지 주장하지 않습니다.
