# A24 저온 resident 유휴 AP 반응 — 최소 개발·확인 PC 계획

**판정:** 기존 B2 한 세션을 반복하면 저온 오차의 재현성은 확인할 수 있어도 부하 *전에 관측한 유휴 반응*으로 부하 *이후를 예측*할 수 있는지 식별하지 못한다. 같은 서명 APK의 기록 release gate를 이용해 **부하 전 resident 유휴 → 짧은 CG_DC 묶음 → 부하 후 resident 유휴**를 개발 1세션에서 관측하고, **두 묶음으로 순서를 달리한 확인 1세션**에 사전 고정식을 적용하는 계획을 PC에서 구현·Check했다. 상태 `PC_READY_DEVICE_UNVERIFIED_NOT_APPROVED`: 현재 기기·설치본·안전 gate·실기기 완주는 미확인이고 실행 승인·claim·출력은 없다. 동결 모형·기존 사후 후보·strict 범위·`experiment_ready=false`는 불변이다.

새 **별도 진단 후보** `ap-preload-idle-reference-diagnostic-v1`은
`dT/dt = β(E−T) + (a_state−a_idle)`이다. 동결 β·기울기 차이를 고정하고, 각 세션의 부하 전 AP 표본 `(t_i,T_i)`만으로 `T_i = E+(T_0−E)exp(−β(t_i−t_0))`의 `E`를 최소제곱 추정한다. `T_0`는 첫 표본이지 주변온도나 평형이 아니다. 새 전역 적합계수는 **0개**이며 `E`는 그 세션에서 실제 관측한 초기 조건이다. 개발 세션의 적격성과 구조·원본 동결 해시를 확인 시작 전에 기록한다. 이미 본 B2 오차를 보고 선택한 구조이므로 개발·기존 B2·과거 DC 확인을 독립 사전 검증으로 부르지 않는다. 확인 세션에서는 자기 **부하 전** AP로 `E`를 산출할 뿐, 부하 후 AP나 결과로 β/기울기를 재보정하지 않는다.

기존 동결의 공통 유휴 평형34.380°C는 개발 반복 부하·화면·resident·주변/잔열 조건이 섞인 상태 회귀 결과이지 기기의 물리 상수가 아니다. B2에는 시작값29.9°C가 실제로 투입됐으나 동결 평형으로 올라가는 항이 방향을 만들었다. 주변온도를 계측하지 않았으므로 주변 변화, 준비 후 잔열, 내부 숨은 상태, 앱/host 계측 프로토콜 효과의 **상대 기여는 계속 미확정**이다. 유휴 AP가 평탄해 보이는 표본만으로 내부 열 상태 같음을 인증하지 않는다. 센서 시계/적분 결함 재감사는 수행하지 않았다.

## 구간 길이·기기 gate·자료 역할

동결 β의 시정수는 **21.77초**다. 기존 B2의 부하 전 AP 약2.5–2.8초 표본 간격에서 32초/13표본은 사전 고정한 55초·15표본 요건에 못 미친다. 새 release+35초는 기존 baseline30초와 공통창 초반 유휴 약35초를 합쳐 **예정상 약65초**의 부하 전 유휴를 만든다. 같은 관측 주기라면 AP 약24–27표본이 예상되지만 실제 센서 내부 갱신 주기·표본 수를 보장하지 않는다. 개발 첫 묶음의 마지막 PC release는 46.329초(+실제 lane 점유), 확인 두 번째는 71.329초(+실제 lane 점유)다. 완주 시 예정상 공통창 내 후행 유휴는 각각 약74/49초에 앱 cooling60초가 더해진다. 실제 완료 시각이 지연되면 이를 줄여 적격성을 다시 판정한다. AP 첫/끝·중간 표본의 결측은 0으로 채우지 않는다.

시작 직전 **신선한** HAL numeric AP가 **32.5°C 미만**일 때만 이 *저온 연구 층*의 본 요청을 한 번 시작한다. 이 값은 별도 안전 하한이 아니며 기존 BAT≤35°C·배터리≥20%·비충전·thermal0·화면·메모리·GPU 품질·기기/서명 gate를 완화하지 않는다. 낮은 값을 맞추려고 가열·추가 warmup·무기한 대기하지 않는다. 확인 세션의 시작 AP가 높아지면 그 계획은 멈추고 독립 저온 확인은 미완료로 남긴다. 두 실행의 순서·준비 이력·배터리·화면·센서 표본·실제 lane·host 조회를 각 세션별로 보존한다. 90초 세션 간 대기는 자연 상태 관측 예약이지 동일 내부 열 상태 보장이 아니다.

AP와 전류/전압은 함께 기록하되 이 짧은 묶음으로 병행 **기기 전체 W를 별도 적합하지 않는다**. 개별 요청 전력·온도에 따른 처리시간 감속·BAT/피부 온도·SOC·열 안전성은 범위 밖이다. 같은 APK/센서/host 조회를 재사용하지만 *release 시각·대기·열 이력*은 B2 원본과 달라 동결 W/AP의 동일 조건 확인으로 합치지 않는다.

## 분석 및 종료 규칙

- 자료 적격성: plan/manifest/APK/동결 SHA, 24개 예정 요청 전부의 결과·실제 lane 해제, 120초 전력/AP coverage, 부하 전 AP span·gap·표본, post-load/냉각 AP 표본≥20·gap≤10초, thermal0, 충전·화면·cleanup을 각각 검사한다. 결측·지원 밖이면 전체 경로 오차 `null`이다.
- 개발 완료 시 고정 구조·분석 코드·원 동결 SHA·개발 `validated.json` SHA·부하 전 `E`/적합 잔차를 별도 `ap_model_freeze.json`에 기록한다. 부하 전 `E`의 수치 식별과 **부하 후 예측 정확도는 다른 판정**이다. 개발 불적격·실패면 확인 미시도, 확인 실패 후 개발 재맞춤·추가 세션은 없다.
- 확인에는 실제 lane 일정과 관측 시작 AP·부하 전 AP를 조건부 입력으로 쓰고, 그 뒤 AP는 비교 대상으로만 쓴다. 가열/냉각 **방향**, 절대/시작 대비 AP 경로 MAE·최대오차·최고값 오차, 부하/유휴별 부호 잔차를 출력한다. 개발과 확인을 세션 표본 수로 세며 센서 표본을 독립 반복으로 취급하지 않는다. 기존 동결식과 별도 사후 후보의 결과는 구별한다. 허용오차/정책 차이 판정 근거가 없어 `accuracy_pass`와 `policy_selection_pass`는 `null`이다.
- 확인에서 방향·형태가 어긋나면 이 1상태 후보를 미채택으로 남기고 숨은 열 이력/환경 기록의 추가 식별 필요성을 특정한다. 맞더라도 A24 동일 resident·저온 시작·이번 짧은 CG_DC/유휴 순서의 **조건부 진단**만 가능하다. 다른 온도, B2 온라인 정책, 전체 상태 전환, 정책 우월성, strict 지원 확대는 자동 판정하지 않는다. 한 개발+한 확인으로 세션 간 변동성·정책 선택 충분성도 입증하지 못한다.
