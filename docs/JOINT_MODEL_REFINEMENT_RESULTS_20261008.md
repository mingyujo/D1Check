## 왜 계수 재추정만으로 해결되지 않았는가

고정 유휴 기준을 유지한 후보는 작업 종료 후 잔차를 바꾸지 않는다. 원모형의 부하 후 절대오차 평균은 과거확인6에서6.661J, 새확인6에서2.921J, 지속8에서0.600J이며 후보도 같다. 상태 전력 계수 수정으로 미관측 배경 소비의 시간 변화를 설명할 수는 없다. 과거 확인의 부하 후 온도/소비 상승 원인도 시스템·환경·잔열 중 하나로 확정하지 않는다.

새 개발6의 분류GPU 단독 점유 합은 **1.018초**, 기존 개발3은25.002초다. 새 개발6만으로 추정한 분류GPU 추가전력은2.918W이며 전체9는0.477W다. 수치 rank4라도 짧은 노출·센서bin 혼합·배경 잔차에 민감하다. 이 차이가 실제 GPU 물리전력 변화라는 근거는 없다.

현재4개 개발 적합값을 그대로 이용한 명목 CPU/PAR 차이 민감도에서 지속4쌍 중2쌍은 예측ΔJ 부호가 바뀐다. 예를 들어 CPU sustained3/PAR sustained2는−2.041..+7.735J다. [계수 안정성](results/joint_model_refinement_01/run/coefficient_stability.csv)·[24개 민감도행](results/joint_model_refinement_01/run/policy_model_sensitivity.csv). 이 범위는 개발 묶음 변경 민감도이며 확률구간·보편오차한도·통제 정책효과가 아니다.

## 종료·지원 범위·남은 정보

결론은 **특정 조건에서만 개선**이다. 이번 공동 적합 후보는 미채택으로 종료한다. 결과 후 구조/계수/격자/합격선 탐색·추가 실측·새 계획은0이다. 기존 원모형 SHA `5682082a936b7c83efeee747ceeb64fd0c64f0bef8765bbf1b90b807db872db2`, 기본 시뮬레이터·RL·strict·experiment_ready=false를 유지한다. A24의 열→처리시간, S26/NPU, SOC/사용시간, 절대전류 정확도는 이번 출력의 검증 범위가 아니다.

앞으로 실제 오차 감소를 확인하려면 다음 정보를 구분해야 한다. **동일 프로토콜에서 분류GPU 단독 노출이 충분한 자료로 단독/병행 계수를 구분하는 것**, 그리고 **비슷한 부하전 관측에서도 달라지는 부하후 유휴 소비/AP를 기록해 배경 변동과 정책 차이를 구분하는 것**이다. 기존 고정 상태 자료는 resident/프로토콜/초기조건이 달라 동일계수 적합으로 바로 추가하지 않는다. 단순 B2 반복이나 새로운 센서 표본 수 증가가 위 식별을 보장하지 않는다.

현재 자료로 특정된 공백이지만 추가 실측 횟수·정밀도·예산은 미확정이며 이번에는 실행기를 만들지 않았다. 필요한 관측은 같은 모델/입력/resident의 pre/load/post AP·전류/전압·실제lane경계·준비이력·기존 환경 기록이다. 센서내부 온도/주변온도/시스템 전력을 만들어 넣지 않는다. 새 계수를 만들면 자료 역할을 개발로 표시하고 별도 미사용 실행에서 확인해야 한다. 종료 조건은 식별 가능한 계수의 안정성·전체창/구간/방향·정책 차이 오차의 산출이며 임의 1J/0.1°C PASS를 만들지 않는다.

다음 PC 행동 하나는 **저장 정책 비교에 개발 묶음 민감도 범위를 병기해, 작은 평균 이득과 계수 변경에도 유지되는 방향을 구분하는 선택적 판독을 연결**하는 것이다. 현재 진행 중인 EDD/RL 작업을 수정하거나 모형을 교체하는 승인은 이 결과에 포함되지 않는다.
