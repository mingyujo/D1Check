## 결론 먼저

1. **이식은 가능하다 [실행].** A24 의 정책 입력 모듈과 PPO 학습기를 한 줄도 고치지 않고 S26 엔진에 연결했다.
   - 학습 안 된 RL 이 S26 한 에피소드(M128, 128건)를 끝까지 제어했다. 128/128 정시, 결정 360회, 1.1 s.
   - 16 에피소드 학습 루프도 돌았다. PPO 업데이트 2회, Adam 72 step, 신경망 변경 확인, 25 s.
   - S26 엔진 물리·계수 파일은 수정하지 않았다.
2. **필요한 수정은 "새 파일 2개 + 연결 규칙 4개"뿐이다** (§3). 엔진 수정은 없다.
3. **다만 이식만으로 "우월"이 나온다는 근거는 없다 [문서].**
   - S26 은 이미 한 번 같은 RL 계열을 학습했다. 이전 엔진에서 4계열 × 3 seed × 64 에피소드를 돌렸고 결과는 ATC 대비 ΔJ −0.02 J, ΔAP −0.0014 ℃였다. 에너지 10 %·AP 0.5 ℃ 공동목표는 0/6,060행이다.
   - A24 의 RL 도 EDD·ATC 보다 정시가 적었다.
   - 원인은 선택지가 좁은 데 있다. 과거 S26 결정 15,360회 중 9,810회는 후보가 1건이었다. 이번 시제품에서도 360회 중 239회는 합법 행동이 1개뿐이었다.

## 1. A24 "롤링+ATC+RL" 의 정체 [코드]

| 구성 | A24 내용 | 위치 |
|---|---|---|
| 롤링 | 도착·반납·센서 갱신마다 대기열을 다시 보고 1건씩 결정. 비선점 | `src/interactive_kernel.py` (`simulate_protocol`, `frozen_policy`) |

| RL | 후보 × 자원(슬롯×3) + WAIT 50/200/1000 ms + RESOURCE_WAIT 중 하나를 고른다. 계열 `JOINT_ATC_RL` (ATC 사전확률 없음, ATC 순위는 입력 특징으로만) | 같은 파일 · `lab_backend.py` `RLPolicy` (84행) |
| 신경망 | 집합 인코더. 요청 24×24 · 자원 3×12 · 전역 24 → 행동 80×16. actor + critic(비용 5개) | `reference/rolling/learner.py` `Net` |
| 학습 | 마스크 PPO. 8 에피소드마다 업데이트, 3 epoch, clip 0.2. 비용 5개 = [작업 J/100, 열면적/1000, 긴급 미달, 일반 미달, 미완료]. 열 가중 0.5, 서비스 α 0.95, 미달 비용은 듀얼 변수로 조정 | `learner.py` `Learner.update` · `tools/…train_v2.py` 78행 |
| 선정 | 64 에피소드 중 EP16/32/64 를 DEV 로만 고른다. 순서는 미완료 → 서비스 부족 → J → AP. EVAL 로 다시 고르지 않는다 | `train_v2.py` `score` · 86행 |

## 2. S26 에 맞는지 — 핵심 근거

| 쟁점 | 근거 | 판정 |
|---|---|---|
| 정책 입력 모듈이 S26 자원 규칙을 아는가 | A24 의 이전 모듈 `reference/rolling/policy_bridge.py` 29행 `"max2 only D_CPU + C_GPU/NPU"`, 66행 `_routes` (분류 CPU/GPU/NPU · 탐지 CPU), 141행 `_physical`. S26 엔진 `legal()` 의 두 조합과 **같다** [코드] | 그대로 사용 가능 |
| 엔진에 정책을 끼울 자리가 있는가 | S26 `s26_simulator_v2.cjs` 18행 `choose()` 를 하위 클래스가 덮어쓴다. 우리 규칙도 같은 방식이다. 기본 루프는 이것만 호출한다 [코드] | 엔진 수정 불필요 |
| RL 에 줄 명목 추정이 있는가 | S26 `rolling_action_v2.cjs` `publicNominals`·`estimate` 가 자원별 점유·응답·에너지 대리값·열 대리값을 준다. 에너지 대리값은 0.14~0.68 로 양수이고, 입력 모듈의 `≥ 0` 조건을 통과한다 [실행] | 그대로 매핑 |
| 언어가 다른데 (S26 = Node, RL = PyTorch) | 엔진 `choose()` 에서 표준입출력으로 Python 학습기에 물어본다 [실행: Linux 에서 성공]. 신경망을 JS 로 옮길 필요는 없다 | 가능. **Windows 에서 다시 확인 필요** |
| 계산 시간 | S26 1회 0.3 s (우리 규칙) / RL 연결 1.1 s · 학습 1.6 s/에피소드 [실행] | A24 의 64 에피소드보다 훨씬 많이 학습할 수 있다 |
| 학습용 입력 | S26 봉인 요청표는 21 슬롯(M128·SMOOTH128 두 모양 × 초기 문맥)이고, 잠재 표본 stream 은 무한 [코드] | 가능. 다만 **요청표 모양이 2개뿐이라 과적합 위험이 있다** |

## 4. 하지 않은 것 · 확인 필요

- 시제품 결과(학습 안 된 RL, 16 에피소드)를 성능 근거로 쓰지 않는다. 등록 실험이 아니다.
- Windows PC 에서 Node 쪽 `fs.readSync(0)` 블로킹 입력이 되는지 확인해야 한다. 안 되면 WSL 이나 클라우드에서 돌린다.
- 이전 S26 RARL 체크포인트는 "입력·물리·행동 형식이 달라 이식 완료라 하지 않는다" [문서 `POLICIES.md`]. 새로 학습해야 한다.
- 조민규 예산 원장(S26 SIM 잔여 12)과 등록 절차는 건드리지 않았다. 이식 실험을 하려면 새 등록이 필요하고, 조민규와 합의가 필요하다.

## 5. 이길 가능성에 대한 정직한 판단

- 순서(ATC)로는 차이가 나기 어렵다. 같은 배정기의 FIFO·EDF 와 궤적이 48/48 동일했고, 선택 시점 1,551회가 모두 동점이었다 [문서].
- RL 이 차이를 낼 수 있는 곳은 **자원 선택(GPU↔NPU)과 WAIT** 다. 하지만 S26 대리값에서 GPU 는 에너지가 낮고 NPU 는 열이 낮다. 그래서 에너지와 열을 동시에 개선하기보다 둘 사이를 맞바꿀 가능성이 크다 [1017 탐색: w 를 바꿔도 맞바꿈만 나옴].
- 과거 S26 RARL 의 결과(ATC 대비 사실상 0)가 가장 직접적인 반대 근거다.
- 그래서 이식의 가치는 "두 기기에 같은 규칙을 적용했다"는 일관성에 있다. 우위를 보이려면 선택지가 넓어지는 부하 조건(경쟁·과부하)과 함께 봐야 한다 (`프롬프트_시뮬설정탐색_1017.md` 의 A 축).
