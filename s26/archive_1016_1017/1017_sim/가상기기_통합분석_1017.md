# 가상 기기 실험 통합 분석 (2026-10-17 21시, Cowork 클라우드)

대상은 10/17 에 세 세션이 돌린 S26 가상 기기 실험 4개(E1 ~ E4)다. 비교 기준으로 실측 모형 실험 2개(E0, E5)를 함께 놓았다.

모든 수치는 원자료(jsonl)를 같은 잣대로 **다시 계산**한 값이다 (`unify.py` → `UNIFIED.csv`).
- 최강 비교군: 그 설정에서 전체 정시율이 가장 높은 비교군.
- 과부하 쌍: 비교군 최고 정시율이 99 % 미만인 쌍.
- 표기: 모두 [시뮬 예측]. ΔJ · ΔAP 는 "우리 − 최강 비교군" 이다.

## 1. 각 시뮬레이터에 수치를 어떻게 넣었나

공통 사항:
- 엔진 = 조민규 `s26_simulator` (브랜치 `codex/s26-simulator-handoff-20261016`).
- 납기는 긴급(분류) 0.8 s · 일반(탐지) 2 s 로 모든 실험에서 같다.
- 전력·AP 온도 모형 (`packet.power` · `packet.AP`) 은 모든 실험에서 손대지 않았다.
- 바꾼 것은 세 종류뿐이다: ① 처리시간 회귀의 온도 계수 ② 병행 허용 규칙 ③ 부하(요청표).

- 적용 방식: 실행 중에 메모리 안의 packet 값만 바꿨다. 파일은 그대로다.
- 엔진 물리와 우리 규칙의 명목 추정이 같은 값을 읽는다.

### 1-2. 병행 허용 규칙 (`legal()`)

| 실험 | 실측 계약 | 바꾼 것 |
|---|---|---|
| E1 · E2 · E3 | 분류(GPU 또는 NPU) + 탐지 CPU, 최대 2건 | 없음 |
| E3x 탐색의 P · PT 기기 | 〃 | 분류 GPU + 분류 NPU 동시 허용 (`clsPair`) |
| E4 B 켬 | 〃 | 분류 GPU + 분류 NPU 동시 허용 (최대 2건 유지) |

- GPU+NPU 동시 실행의 처리시간 겹침은 엔진의 기존 OVERLAP 계수를 그대로 썼다.
  - GPU +0.149, NPU +0.111. 이 값은 분류+탐지 쌍에서만 측정됐다.
- GPU+NPU 동시 실행의 전력·온도는 측정이 없는 외삽이다.

### 1-4. 정책 (우리 규칙 · RL · 비교군)
- **우리 규칙** = `ROLLING_ATC_ROUTE_V2`: 도착 요청 납기 손해 검사 → ATC 순서 → 경로는 에너지·열 대리값. E0~E3 은 WAIT 끔, E4 는 WAIT 켬.
- **E2 RL** = 잔차 선형 RL.
  - 우리 규칙 후보 위에 특징 15개(그중 1개 = "규칙이 고른 후보")의 선형 점수를 매긴다.
  - 학습: self-critical 정책 경사, 보상 = 정시 건수 − 0.02 × J, 25 s 4부하 × k ∈ {2, 4, 8}, 500 에피소드.
  - 선정: 개발 점수로 ep350 을 골랐다 (θ 는 `RL_SELECTED.json`).
- **E5 RL** = A24 PPO(`JOINT_ATC_RL`) 무수정 이식, 3 seed × 512 에피소드, DEV 선정.
- **비교군**:
  - FIFO/EDF + 빈 자원 채우기: NPU 고정(`*_BF_CN`), 빈 가속기 NPU→GPU(`*_BF_ANY`), 같은 배정기(`FIFO_FREE`·`EDF_FREE`)
  - FIFO 병행 NPU/GPU (strict head)
- **A24 시뮬레이터**: 가상 기기를 적용하지 않았다. 부하만 바꿨고(분류 25 % · 참조 부하 1.6 / 2.0), 확인 결과는 RL > 모든 비교군 12/16 으로 미확인이었다 (`1017_우리규칙_우위조건_탐색`).

### 읽는 법
- **서비스 (정시율)**: 모든 실험에서 우리 규칙(또는 RL)이 최강 비교군보다 과부하 정시율이 높았다. 이긴 쌍은 100 % 다.
- **RL 이 규칙을 넘은 것은 E2 하나다** (k = 2 · 4 확인 쌍 100 %, k = 8 은 93 %). 실측 모형(k = 1)에서는 모두 동률이었고, A24 PPO 이식(E5)은 규칙보다 낮았다.
- **NPU 쏠림이 풀리는 경우**는 셋이다.
  - 분류가 많은 부하 (E4 실측 계수 · E3)
  - NPU 가 열에 약한 기기 (E3)
  - GPU+NPU 동시 실행 기기 (E3x · E4)
- **에너지·열을 줄인 결과는 하나도 없다.** 차이가 0 이거나 나빠졌다. 자원을 나눠 쓰는 결과일수록 J 와 최고 AP 가 올라간다.
  - E3: 최고 AP +2 ~ +7 ℃
  - E4 동시 켬: 평균 AP +0.4 ℃
- **가드 (긴급 정시)**: E3 와 E4 의 동시 끔 기기는 과부하가 커서 우리 규칙도 긴급을 다 지키지 못했다 (50 ~ 78 %). 다만 비교군보다는 높다.

## 3. 우리 결론을 가장 잘 보여주는 결과 (요청대로 실측 근거·조민규 설계는 고려하지 않음)

우리 결론의 구성: "**롤링+ATC+RL** 규칙이 **기한(가드)을 지키면서** 비교군보다 **우월**하고, **열·에너지 부담**을 줄이며, **자원을 한쪽에 몰지 않는다**."

평가 항목 (각 0 ~ 2점):
- **목표 규칙**: RL 이 규칙·비교군을 다 넘으면 2, 규칙만 이기면 1
- **우위 크기**: 과부하 쌍 100 % 승리이고 +10 %p 이상이면 2, +5 %p 이상이면 1
- **가드**: 긴급 정시 우리 100 % 면 2, 90 % 이상이면 1
- **열·에너지**: 줄었으면 2, 차이 없음이면 1, 나빠졌으면 0
- **자원 분산**: NPU ≤ 80 % 면 2, ≤ 90 % 면 1
- **확인 표본**: 등록 확인이면 2, 개발만이면 0

### 판정
- **단일 결과로는 E2 k = 4 가 가장 잘 보여준다.** 우리가 내세우는 "롤링+ATC+RL" 이 규칙과 비교군을 확인 쌍 84/84 에서 모두 넘은 유일한 결과다. 긴급 100 % 를 지켰고 에너지·열 손해가 없다.
  - 정시율: RL 94.6 % > 규칙 88.9 % > FIFO+채우기 82.4 %
  - "RL → 규칙 → 비교군" 의 계단이 한 표에 나온다.
  - 약점: 분류를 100 % NPU 로 보낸다 (쏠림). 열·에너지를 *줄이지는* 못한다.
- **쏠림 문제까지 덮으려면 E4 (실측 계수 그대로)를 짝으로 붙이는 것이 가장 좋다.** 계수를 하나도 바꾸지 않았는데 분류가 많은 과부하에서 GPU 49 % · NPU 51 % 로 나눠 쓰며 +15 ~ 19 %p 이겼고, 에너지·열 차이는 0 이다. 약점은 RL 이 아니라 규칙이라는 점과 긴급 78 % (비교군 65 %) 다.
- **E3 (NPU 열 취약)** 은 쏠림 해소와 우위 크기는 가장 극적이다 (+26 %p · NPU 29 %). 하지만 결론의 다른 축을 거스른다. 최고 AP 가 +4 ~ +7 ℃ 오르고, 긴급이 50 ~ 63 % 로 무너지고, a = 1 ~ 2 (10 ℃ 당 2.7 ~ 7.4배) 라는 가정이 극단적이다. 대표로 쓰기 어렵다.
- **결론과 맞지 않는 빈칸**: "열·에너지 부담을 줄인다" 를 보여주는 결과는 하나도 없다. 모든 우위는 서비스(정시율)에서 나왔다. 발표 결론을 "가드를 지키며 정시율을 올린다 + 열·에너지는 늘리지 않는다" 로 좁히면 E2 + E4 조합이 결론과 거의 완전히 맞는다.

### 추천 발표 문장
"스로틀이 강한 기기(가상)에서 롤링+ATC+RL 은 규칙보다 +5.7 %p, FIFO+채우기보다 +11.8 %p 정시율이 높았다 (확인 84/84, 긴급 100 %, 에너지·온도 차이 없음). 분류 요청이 몰리는 경우에는 GPU 와 NPU 를 반씩 나눠 쓰면서도 같은 우위가 유지됐다."

(실측 근거·조민규 설계를 넣으면 순위가 바뀐다. 실측 모형만 쓴 것은 E0 · E4 실측 계수 · E5 다. 이 평가는 요청대로 그것을 빼고 했다.)
