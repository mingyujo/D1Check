# 과부하 영역 확인 사전 등록 v1 (2026-10-17, 확인 실행 전 고정)
탐색(개발)에서 본 영역을 새 표본으로 한 번만 확인한다. 물리 계수·납기 계약 무변경. 바꾼 것 = 요청 수·간격·혼합(부하 조건)과 비교군 추가.

## S26 (우리 = 롤링+ATC, WAIT 끔 — RL 은 이 엔진에서 규칙을 넘지 못해 제외)
- 영역: 탐지 비중 높은 과부하 = 묶음당 분류5·탐지3, 간격 0.537 / 0.65 s, 길이 25 / 50 / 75 s, 몰림·분산 (12 부하)
- 확인 표본: stream 260017300~303 × 맥락 3 (R1-4 · R2-3 · R3-1 M128 초기이력) = 부하당 12쌍
- 비교군: FIFO 병행 NPU · EDF 병행 NPU · FIFO 빈자원채우기 NPU · EDF 빈자원채우기 NPU · FIFO 빈자원채우기 GPU
- 판정: 우리 정시 건수 > 비교군 중 최고 정시 건수 인 쌍 ≥ 80 % → "과부하 서비스 우위 확인". J·AP 는 |평균 ΔAP| > 0.18 ℃ 일 때만 "차이", 아니면 "오차 안".

## A24 (우리 = 롤링+ATC+RL EP32)
- 영역: 분류 25 % · 참조 부하 1.6 / 2.0 · 96 / 192건 · steady / burst (8 조건)
- 확인 표본: 요청표 seed 20261030 · 20261031 (개발 격자는 20261029) = 16 조건
- 비교군: EDD · ATC · FIFO 자유 · FIFO 고정 직렬 · 모바일 규칙
- 판정: RL 정시 > max(EDD, ATC, 모바일, FIFO 자유) 인 조건 ≥ 80 % → "과부하 서비스 우위 확인"; RL > EDD 만 ≥ 80 % 이면 "EDD 대비 우위". J·AP 는 0.354 ℃ 기준.
