# 사전 등록 — 가상 기기: NPU 쏠림 없이 우리 규칙이 이기는 기기 조건 (2026-10-17 18시, Cowork 클라우드)

**지위: 가상 기기 시나리오. S26 실측 모형의 예측이 아니다.** 결과는 "어떤 기기 조건이면 우리 규칙이 자원을 나눠 쓰며 이기는가"를 보이는 조건 지도다. S26 결론을 바꾸지 않는다. 발표 문장에는 늘 "가상 기기"를 붙인다.

미리 본 것:
- 회귀 4회: 엔진 사본 + 스위치 끔 = 원본과 비트 동일.
- 스모크 4회: 스위치 켬 (R3-1 · R3-4 문맥) — 우리 규칙이 GPU 를 섞는 것과 7C1D 부하 정시가 크게 바뀌는 것을 봤다.
- 앞선 결과: 우리 규칙은 S26 실측 모형에서 분류를 100 % NPU 로 보낸다. 과부하 서비스 우위는 같은 배정기의 FIFO·EDF 대비로 확인됐다.

## 1. 가상 기기 스위치 (2개, 엔진 사본에만 적용 · 원본 무수정)
- **A. NPU 열 감속** `AP:classification_NPU` 계수 (10 ℃ 당 log 처리시간):
  - {실측 −0.0007 (≈ 감속 없음)}
  - {0.15 — 우리 S26 폰 실측 NPU 장시간 감속 근사: 600 s 가열 ×1.21 · AP +13 ℃}
  - {0.30 — 그 2배}
  - 엔진 물리와 정책의 명목 모형이 같은 값을 읽는다.
- **B. 분류 가속기 동시 실행**: 분류 GPU + 분류 NPU 를 동시에 한 쌍으로 허용한다 {끔 = 실측 계약 · 켬}.
  - 세 개 동시는 허용하지 않는다 (최대 2 owner 유지).
  - 동시 실행 시 감속은 엔진의 기존 OVERLAP 계수를 그대로 쓴다. 이 계수는 분류+탐지 쌍에서만 측정됐으므로 GPU+NPU 쌍에는 외삽이다.
  - 전력·온도 모형도 이 조합은 측정이 없다 (외삽).
- 가상 기기 6개 = A 3 × B 2. **6개 모두 보고한다.** 나머지 계수·납기 (0.8 s / 2 s)·분모는 무변경이다.

## 2. 정책 · 부하 · 표본
- 정책 5개:
  - RULE = 우리 롤링+ATC (WAIT 켬)
  - FIFO_FREE · EDF_FREE = 같은 배정기·같은 정보 (가상 쌍도 같이 씀)
  - FIFO_PAIR_CN · FIFO_PAIR_CG = 고정 자원 strict
- RL 은 제외한다. A24 입력 모듈의 쌍 계약에 GPU+NPU 가 없어서다.
- 부하 13개:
  - R21 슬롯 자체 요청표 1개
  - 생성 12개 = 25 s × 묶음 {분류7·탐지1, 분류6·탐지2, 분류5·탐지3} × 간격 {0.4, 0.537} s × {몰림, 분산}
- 문맥 R3-0~6 (EVAL 문맥), stream 3000. 기기마다 91 쌍. 정책 설정을 고르는 단계가 없으므로 DEV 분할은 없다.

## 3. 판정 (기기마다)
- **과부하 쌍**: 4개 비교군 중 최고 정시율이 99 % 미만인 쌍. 결과를 보기 전에 이 기준을 정해, 앞선 실험에서 용량 안 쌍이 섞인 문제를 막는다.
- **쏠림 없음 (S)**: 생성 부하 전체에서 RULE 의 분류 중 NPU 비율 ≤ 90 % 이고 GPU 비율 ≥ 10 %.
- **H1 (서비스 우위)**: 과부하 쌍에서 RULE − 최고 비교군 정시율이 +0.5 %p 이상인 쌍이 ≥ 80 % 이고 평균 차 > +0.5 %p. 과부하 쌍이 10개 미만이면 "판정 불가".
- **유의미 (등록 결론)**: S 와 H1 이 둘 다 통과.
- **열·에너지 (기술만)**: 과부하 쌍에서 RULE − FIFO_FREE 의 ΔJ · Δ평균 AP · Δ최고 AP 의 평균과 부호 비율. "있음"이라고 부르려면 |Δ평균 AP| > 0.18 ℃ 이고 같은 부호 ≥ 80 %.
- 보존 검사: 실행마다 정시 + 지연 + 미완료 = 계획.

## 4. 미리 쓰는 결론 문장
- 유의미: "가상 기기 (NPU 열 감속 x · 분류 가속기 동시 실행 y) 에서 우리 규칙은 분류를 GPU/NPU 에 나눠 쓰면서 (NPU z %) 같은 정보의 FIFO·EDF 보다 과부하 정시율이 높았다 (쌍 w %)."
- S 실패: "이 가상 기기에서도 우리 규칙은 한 자원에 쏠렸다."
- H1 실패: "자원은 나눠 썼지만 서비스 우위는 등록 기준을 넘지 못했다."
