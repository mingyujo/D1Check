# 사전 등록 — S26 롤링+ATC+RL (A24 PPO 이식) 실험 (2026-10-17, Cowork 클라우드)

이 문서는 학습·DEV·EVAL 실행 **전**에 고정한다. SHA-256 은 원장(`LEDGER.md`)에 적는다. 고친 판은 `_v2` 로 새로 만든다.
미리 본 것: (1) TRAIN 문맥(R1-*)에서 스모크 5회 (학습 안 된 RL, 시간 측정·결정성 확인), (2) 규칙 6회 시간 측정 (DEV 문맥 R2-3 · 과부하 2부하). 앞선 세션의 탐색 결과(`claude/1017_우리규칙_우위조건_탐색.md`: 탐지 비중 높은 과부하에서 우리 규칙 서비스 우위)를 알고 설계했다 — 부하 축 선택은 결과를 본 뒤의 선택이다.

## 1. 무엇을 · 무엇과
- **RL** = A24 `JOINT_ATC_RL` 그대로: A24 `reference/rolling/policy_bridge.py` (분류 CPU/GPU/NPU · 탐지 CPU · 병행 = 탐지 CPU + 분류 GPU/NPU — S26 계약과 같음) + `reference/rolling/learner.py` (PPO, Settings 기본값, 8 에피소드마다 갱신). 두 파일 무수정. α 0.95 · 열 가중 0.5 (A24 값).
- **비교군**: `FIFO_FREE` · `EDF_FREE` (조민규 fair_resource_v1, 같은 배정기·빈 자원 채우기) · `FIFO_PAIR_CN` · `FIFO_PAIR_CG` (strict head 참고) · **우리 규칙** `RULE` (ROLLING_ATC_ROUTE_V2, WAIT 켬) · `RULE_NOWAIT`.
- **대조군**: 학습 전 RL (EP0, argmax). 학습이 기여했는지 본다.
- 엔진·물리 계수·납기 (긴급 0.8 s · 일반 2 s)·분모 무변경. 엔진은 `choose()` 하위 클래스로만 연결 (`rl_server.cjs`).

## 2. 부하 · 분할
- 부하 9개 (학습·DEV·EVAL 공통 모양): R21 봉인 요청표 1 (**그 슬롯 자체의 128건**, M128 또는 SMOOTH128) + 생성 과부하 8 = 지속 25 s × 간격 {0.537, 0.65} s × 묶음 {분류6·탐지2, 분류5·탐지3} × {몰림, 분산}. 생성 부하는 35 s 부터 묶음 반복 (M128 구조 확장) — **R21 측정 범위 밖 외삽**.
- 보류 부하 (EVAL 에만, 학습·DEV 에 없음): 지속 50 s · 간격 0.6 s · 분류5·탐지3 · {몰림, 분산} = 2개.
- 문맥 (초기 열 이력): TRAIN = R1-0~6 · DEV = R2-0~6 · EVAL = R3-0~6. 잠재 표본 stream: TRAIN 1,000,000 + 10,000·seed + e · DEV 2000 · EVAL 3000, 3001.
- 크기: DEV = 7 문맥 × 9 부하 (R21 1 + 생성 8) × 1 stream = 63 / 체크포인트. EVAL 주 = 7 × 9 × 2 = 126 쌍 / 정책 · EVAL 보류 = 7 × 2 × 2 = 28 쌍.

## 3. 학습 · 선정 (DEV 만)
- seed 3개 (46101 · 46103 · 46107 — 과거 S26 RARL 과 같은 값) × 512 에피소드. 에피소드 = TRAIN (부하·문맥) 균등 무작위 (seed 고정 RNG).
- 비용 = A24 train_v2 배치 [J/100, (AP − 시작 AP)⁺ 면적/1000, 긴급 미달 비율, 일반 미달 비율, 미완료 비율], 마지막 결정에 한 번. J 가 censored(null) 면 0 으로 두고 미완료 항이 벌점을 진다.
- S26 연결 규칙: 실행 중 작업이 있으면 WAIT 금지 · WAIT 누적 ≤ 2 s · 대기열 > 512 면 도착 순 앞 512 건만 입력 (A24 계약 상한, 잘림 횟수 기록) · 전력·작업 단계는 공개 상태에 없어 0 (A24 모듈이 "모름" 기록).
- 체크포인트 EP0 · 64 · 128 · 256 · 512. seed 별로 DEV 점수 (A24 `score`: 미완료 합 → 우선순위별 서비스 부족 max(0, 0.95 − 정시율) 평균 → 평균 J → 평균 AP, 사전식) 최소를 고른다. EVAL 을 보고 다시 고르지 않는다.

## 4. 판정 (EVAL, 한 번)
- 쌍 = 같은 문맥·부하·stream. 주 지표 = **전체 정시율** (정시 / 계획).
- **H1 (RL vs 최강 비교군)**: 쌍마다 비교군 = max 정시율 {FIFO_FREE, EDF_FREE, FIFO_PAIR_CN, FIFO_PAIR_CG}. 생성 과부하 쌍 (112) 에서 RL − 비교군 ≥ +0.5 %p 인 쌍이 ≥ 80 % 이고 평균 차 > +0.5 %p → seed 통과. **3 seed 중 2 이상 통과 → "RL 우위 확인 (과부하 서비스)"**. 아니면 "미확인".
- **H2 (RL vs 우리 규칙 RULE·RULE_NOWAIT 중 높은 쪽)**: 같은 기준 → "RL 추가 기여 확인" / 쌍의 ≥ 80 % 가 |차| < 0.5 %p → "동등" / 그 외 "미확인 (혼재 또는 열세)".
- **H3 (R21 용량 안, 14 쌍)**: 가드 = RL 128/128 정시 전부. 가드 통과 시 RL − FIFO_FREE 평균 AP 차 |·| > 0.18 ℃ 이고 같은 부호 ≥ 80 % → 열 차이 "있음", 아니면 "모형 오차 안". J 는 부호 비율만 기술.
- **보류 부하 (28 쌍)**: H1 · H2 와 같은 기준으로 따로 판정 · 보고 (주 판정에 섞지 않음).
- 대조군: DEV 에서 선정 체크포인트가 EP0 보다 점수가 낮지 않으면 "학습 기여 없음" 으로 적는다.
- 과적합 격차: DEV 와 EVAL 의 (RL − 최강 비교군) 평균 차를 나란히 적는다.
- 보존 검사: 실행마다 정시 + 지연 + 미완료 = 계획 (엔진 서버가 검사, 실패 시 중단) · RL 행동은 마스크 안 (A24 Controller 가 검사) · 불법 경로는 엔진이 예외.

## 5. 미리 쓰는 결론 문장
- H1 확인: "탐지 비중이 높은 과부하 (시뮬 외삽) 에서 롤링+ATC+RL 은 같은 정보의 FIFO·EDF 보다 정시율이 높았다 (seed k/3, 쌍 x %)."
- H1 미확인: "S26 시뮬레이터에서 A24 와 같은 RL 은 강한 비교군 대비 서비스 우위를 등록 기준으로 보이지 못했다."
- H2 동등/미확인: "RL 을 더해도 롤링+ATC 규칙 대비 추가 이득은 확인되지 않았다."
- 열·에너지는 H3 결과 문장만 쓴다. 과부하에서 J·AP 차이는 기술만 한다 (R21 대비 J 약 4배 과대 예측 · AP 정책 간 오차 0.18 ℃).
