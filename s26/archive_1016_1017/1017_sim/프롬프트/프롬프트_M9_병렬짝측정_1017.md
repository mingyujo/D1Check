## 6. 3단계 — 사전 등록 (`d1sim/docs/M9_병렬짝_사전등록_v1.md` · 첫 폰 세션 전 커밋 · push · SHA 원장)

담을 것 (이 문단을 거의 그대로):

1. **비교 단위** = 같은 블록의 짝 arm vs 그 SERIAL 대조 (A vs A0 · B vs B0 · C vs C0). 반복 = 블록 (n ≤ 2) · 블록별 값 둘 다 공개 · 유의성 주장 없음.
2. **주결과 1 (처리시간 겹침 비용)** — 경로별 (짝의 두 경로 각각): 짝 arm 의 `overlap_fraction ≥ 0.5` 요청 추론 시간 중앙값 ÷ 대조 arm 같은 경로 추론 시간 중앙값 = 겹침 배율 `m`. log m 을 시뮬 외삽값과 비교: 분류 GPU 0.149 · 분류 NPU 0.111 (packet `OVERLAP:` 계수, 분류+탐지 짝에서만 측정) · 분류 CPU 0 (자료 없음).
   - |log m − 외삽| ≤ 0.05 (두 블록 다) → "외삽 계수 범위 안"
   - log m − 외삽 > 0.05 (두 블록 다) → "외삽이 겹침 비용을 과소 — 가상 기기 E4 우위 재계산 필요"
   - log m − 외삽 < −0.05 (두 블록 다) → "외삽이 겹침 비용을 과대"
   - 두 블록이 갈리면 → "블록 간 갈림 — 판정 안 함"
3. **주결과 2 (처리량)**: 마지막 요청 lane_available 시각 · 전량 완료 · 정시율 (짝 vs 대조).
4. **주결과 3 (에너지 · 열, 같은 경로 구성에서 동시 실행 효과)**: J0~180 (R21 v2 단위 가설 · 세션 r 범위 안일 때만) · AP35~180 시간 평균 · AP 관측 peak · AP180 − AP0. 짝 − 대조 Δ 를 블록별로. 문구 = "방향 (k/2) — 크기 단정 안 함".
5. **시뮬 재현 (6단계)**: 측정 세션 12개를 시뮬로 다시 돌린 예측 vs 실측 — 정시율 · 마지막 완료 시각 · J0~180 · AP35~180 평균. AP 는 세션별 |오차| 와 **짝−대조 Δ 의 오차**를 R21 기준 0.18 ℃ 와 나란히 · J 는 방향 일치 수만. 판정 문구 = "재현 오차 안 (0.18 ℃) / 밖".
6. **전력 짝 가정 명시**: 시뮬 전력 모형의 짝 곱항은 CC_DC · CG_DC · CN_DC 뿐 → 새 짝은 **곱항 0 = 가산 가정** (재적합 불가 · 조민규 정규화 자료 필요). 결과 문장에 늘 붙인다.
7. **무효 · 재시도**: R21 동결 `exclusion_rules` 그대로. 무효 세션은 대체 1회 (같은 블록 끝) · 그래도 무효면 그 쌍 n 감소.
8. **주장 경계**: 3개 동시 · CPU 내부 병렬 · CPU 다중 스레드 · 탐지가 낀 새 짝 = 미검증.
