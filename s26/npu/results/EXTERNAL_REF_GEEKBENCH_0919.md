## 우리 프로젝트에 주는 것

1. **경로 B 실행 가능성 확인** — 같은 펌웨어, 같은 구조(TFLite Interpreter + ENN 델리게이트). G0 의 "LiteRT 심볼 FAIL" 은 경로 A 얘기이고 B 와는 무관함이 실증됨.
2. **NPU 의 준비시간(전환비용)이 자릿수부터 다르다** — 온디바이스 컴파일 0.2~31 s (모델·정밀도 의존, 20 s·31 s 가 반복 등장 = 컴파일러 타임아웃/재시도 의심). CPU 31 ms·GPU 273 ms 와 비교하면 **NPU 는 "준비된 모델만 즉시, 아니면 수십 초"** 인 자원. 시뮬레이터 `switch_cost_s.idle->NPU` 는 캐시 유무로 두 값이 필요.
3. **FP32 는 NPU 자원이 아니다** — SP 가 HP 의 16~20배 느림. 우리 NPU 측정은 FP16(또는 INT8) 만 의미 있고, "FP32 NPU" 셀은 프로파일에서 `unsupported` 로 마스킹.
4. **INT8 분류 정확도 붕괴(0.014)** — MobileNet 류 uint8 양자화 모델이 ENN 에서 깨질 수 있다는 실측. KS-D 를 NPU 축으로 확장할 때 **정확도 게이트를 먼저** 두고, 깨지면 FP16 vs INT8 비교 자체를 "미지원" 으로 기록한다. (CPU/GPU 의 KS-D1 과는 별개)
5. 참고 규모: 이미지 분류 FP16 배치 70 기준 0.18 ms/img. 단일 이미지 지연은 이보다 훨씬 클 것(배치 이득 제거, 우리 측정으로 확인).
