S26 롤링+ATC+BC 서비스 개선 후보 - 기존 공식 최종 유지 / 비채택

사용자 지시: 기존 정책은 그대로 두고, 롤링+ATC+BC의 열·에너지 감소를 최대한 유지하면서 긴급 납기 실패와 미완료를 줄인다.

이 폴더의 고정 후보는 BC_RESOURCE_EDF_NORMAL이다. 기존 BC 가중치·32특징·최대27행동의 원 물리 mask를 유지하고, 신경망 뒤에 별도의 자원·진행 보호를 결합했다. CPU 추론슬롯은 CPU만 지원하는 탐지에 예약하고, 분류는 NPU를 우선 사용하며 현재 보이는 NPU 단독 순차 예측이 납기를 넘을 때 GPU를 허용한다. 긴급 선두의 명목 위험을 보호하고 일반 CPU 요청의 순서는 EDF로 고정한다. 일반 순서에는 BC가 개입하지 않는다. 이는 순수 BC 또는 새 학습 성과가 아닌 보호 규칙을 포함한 시스템 후보다.

원 공식 최종은 롤링+ATC+공개 교사학습 초기화+PPO881087, 납기 강제 보호 없음이다. FINAL_POLICY.json, FINAL_POLICY_KO.md, 기존 V4 보고서·원 결과·기준정책·체크포인트·원자료·실패·optimizer/RNG·A24는 변경하지 않는다. 사용자가 채택을 결정하기 전에는 이번 후보를 공식 최종으로 사용하지 않는다.

읽는 순서:
1. STATUS.json: 현재 실행/검산/완료 상태와 남은 작업
2. FINAL_REVIEW_KO.html / CONFIRMATION_ASSESSMENT.json: 개발과 새 확인을 구분한 최종 판독; REPORT_KO.html은 기본 전체표
3. IMPROVEMENT_SUMMARY.json: 같은 내용의 기계 판독 수치
4. PROTOCOL.json / OPERATION.json: 목적·고정 규칙·입력·상한·소스 SHA
5. SELECTION_FROZEN.json: 별도 새8을 실행하기 전에 고정한 선택과 목표 충족 여부
6. ANALYSIS.json / RESULTS.csv: 독립 검산·대응 비교·개별 입력 수치·한계
7. PRESERVATION.json / FILES.json: 기존 파일과 새 고유 실행의 보존·무결성

이전 비교는 형제 폴더 bc_service_repair_20261020에 별도148회로 보존한다. 대기만 막으면 에너지가 늘고, 일반 요청이 이미 늦었을 때 보호하는 첫 자원 후보는 전체 정시율 손실이 생겼다. 이 개발32 결과를 본 뒤 일반 EDF 보완 한 가지를 별도60회로 등록했다. 새 파라미터 탐색이나 가중치 갱신은 없었다. 두 등록 합계208회이며, 앞선 conclusion_*의512회와 역사적 SIM512 500/12 잔여는 별도 계보다. 완료된 기존 방법 재실행·대체seed·예산 환급·예약/자동화 조회·재개는 없다.

이번60회는 개발32에 새 후보만32회, 원 최종4에 새 후보만4회, 다시 별도 생성한 새8에 BC/새 후보/EDF 24회다. 개발32와 원4만으로 후보를 고정한 뒤 새8을 실행한다. 이전148의 확인8과 이번 확인8은 다른 난수 이름공간이며 결과를 합쳐 하나의 새 독립 확인 실험이라고 하지 않는다. 모든 실패와 불리한 사례를 보존하고 누락·미완료를 에너지 성과로 인정하지 않는다.

전력·열 정확도 gate FAIL과 기존 명목 캐시의 정확한 동등성 주장 FAIL은 유지한다. CPU3의 추가 코어·전력·열·간섭 및 모바일 NN/예측/보호 비용은 미측정이다. API-J/AP는 조건부 모형 수치로 실제 S26 절감·납기 보장·대기 상한 인증이 아니다. 명목85%와105% 스트레스는 분리해 읽어야 한다.

감사/보고 코드의 누락 비교 방지·실패 표시와 보고서 들여쓰기 보완은 실행/정책/입력 변경과 구분해 기록했다. 기존 소스·OP 스냅샷은 보존했고, 이번60회는 그 보완이 끝난 뒤 최초로 시작했다. 정책 규칙·파라미터·입력·상한은 해당 보완에서 바꾸지 않았다.

이 후보와 출력 경로를 그대로 재실행하지 않는다. evaluate.py는 소비한 namespace를 거부한다. 추가 변형·학습·실측을 하려면 목적과 별도 등록·입력/출력 경로가 필요하다. 이번 비교가 끝나면 자동으로 더 탐색하거나 기존 최종을 바꾸지 않는다.
