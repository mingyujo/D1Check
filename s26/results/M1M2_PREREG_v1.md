## 2. M1 — 스로틀 회복

**연쇄** (`m1_recovery_gpu_v1.json`, per_segment, GPU 모델 1개를 이어 씀 → 구간 사이 모델 교체 없음, 전환 창 = warmup + D1Check run 재확인 [D `NpuChain.kt:297`]):

| 구간 | 가속기 · duty · 길이 | 역할 |
|---|---|---|
| 0 `cold_ref_d10` | GPU d10 · 60 s | 식은 상태 기준 (같은 duty 비교용) |
| 1 `heat_d100` | GPU d100 · **1200 s** | 출발 상태 만들기 |
| 2 `probe_d10` | GPU d10 · 300 s | 회복 탐침 |

**출발 상태 = ② 온도 평탄 출발 (1200 s 고정)** — 초안의 선택과 이유:
- C1a [P]: 지연은 ~420 s 부터 평탄(시작점 [E]), **SKIN 은 420 s 38.3 → 1188 s 39.3 ℃ 로 계속 올랐고** 그 뒤 1300 s 까지 39.0 으로 내려왔다. 즉 1200 s 는 "지연도 온도도 더 안 움직이는" 가장 이른 관측 지점이다 [E, 1런]
- ① 지연 평탄 출발(~420~600 s)은 짧지만 **온도가 아직 오르는 중**이라, 탐침에서 보이는 회복이 "식는 중"인지 "덜 데워진 것"인지 섞인다. 회복을 느린 열 노드가 정한다면(시뮬 v0 형태 M-A2, τ_s 293 s [D 작업결과_0927_시뮬v0 §2]) 출발 온도가 회복 시간을 바꾼다
- 연쇄 모드는 "상태가 되면 넘어가기" 가 아니라 **고정 길이** 라서, 반복 가능한 출발 상태는 고정 길이로만 만들 수 있다
- 대가: 1200 s 는 ① 보다 ~10~13분·~3 %p 더 든다 [E]. 예산이 모자라면 ① (600 s, `heat_d100` 만 600 으로 바꾼 새 파일) 로 내리고 **"출발 상태 변경"** 으로 적는다 (동결 전 결정)

**판정 (먼저 숫자로)**:
- `ref_d10` = 구간 0 의 추론 전수 지연 중앙값
- 회복 시각 = 구간 2 시작 기준 첫 10 s 칸 k 로서 **칸 k 와 뒤 3칸(40 s)의 중앙값이 모두 ≤ `ref_d10` × 1.10** (GPU 진입 문턱 +10 % 와 대칭). 결과 = 10k s
- 구간 2 안에 없으면 **"270 s 안에 미회복"** (오른쪽 중도절단). 부분 회복 곡선(칸별 중앙/`ref_d10`)은 항상 적는다
- **계단형 / 점진형** (정책 타이머·히스테리시스 vs 온도 추종): 탐침 첫 칸에서 회복 칸까지 줄어든 지연 중 **≥ 50 % 가 한 칸 사이에서** 줄었으면 "계단형", 아니면 "점진형". 같은 칸 구간의 SKIN·AP 궤적을 나란히 적는다 (계단인데 온도는 매끄러우면 타이머 쪽 [E], 지연이 온도를 따라가면 온도 추종 [E])
- 구간 1 에서 C1a 와의 재현성도 적는다: 진입 시각(1-1 규칙), 540~600 s·1000~1200 s 60 s 중앙 배율 — §3 엔진 대조의 **보조 자료** (구간 0 의 60 s d10 이 앞에 있어 식은 출발이 아니다)

**M1 반대 해석** (ground-truth 2):
1. "회복" 이 온도가 아니라 **시간(정책 타이머)** 으로 온다 → 계단/점진 규칙 + 온도 궤적 (위)
2. 탐침 d10 도 부하다 — 측정하는 것은 "10 % 부하 아래의 회복" 이지 idle 회복이 아니다 → 결과 문장에 조건을 박는다
3. d10 은 1 s 가동마다 GPU 클럭이 다시 올라오는 구간이 있을 수 있다 → 같은 d10 인 `ref_d10` 과만 비교 (d100 기준과 비교하지 않는다)
4. 1200 s 가열 중 SOC 하락(C1a 86 → 81 %, 1300 s)이 전력 한도를 바꾼다 → 구간별 SOC 기록, 2런째가 있으면 SOC 가 다른 두 런 비교
5. 실내 온도 변화 → 세션 시작·끝 기록 (칸 내 기록 없음은 한계로 적는다)

## 3. 엔진 대조 기준 — CompiledModel GPU vs Interpreter GPU (결과 보기 전 고정)

주 자료: **M2 가열 팔의 GPU d100 600 s 구간** (게이트 통과 후 식은 상태에서 시작 — C1-probe 와 같은 출발) × 2런. 보조: M1 구간 1.
Interpreter 기준 [P]: C1-probe r1 · r2 (600 s) · C1a (1300 s) — 진입 60 · 60 · 70 s, 540~600 s 60 s 중앙 배율 ×2.084 · ×1.972 · ×2.017 (7.379/3.6582), 540~600 s 전력 배율 ×0.394 · ×0.413 · ×0.379 (C1a 60 s 표 540~600 s 2.44 W ÷ 처음 30 s P0 6.435 W [P C1a_결과 §3·§4]; C1a 평형창 1000~1300 s 는 ×0.394).

"같은 모양" = 아래 셋을 **모두** 만족 (각 런별, 2런 중 2런):
1. 진입 시각(1-1, +10 %) ∈ **[40, 90] s** (Interpreter 60~70 s ± 20 s)
2. 540~600 s 60 s 중앙 / 자기 처음 30 s 중앙 ∈ **[1.77, 2.29]** (Interpreter 1.972~2.084 ± 10 %)
3. 540~600 s 평균 전력 / 처음 30 s 평균 전력 ∈ **[0.28, 0.51]** (Interpreter 0.379~0.413 ± 0.10; 전력은 단위 가정·절대 정확도 미인증 — 비율로만)

- 모두 만족 → "같은 모양" → 스로틀 모형(v0 는 Interpreter 로 피팅)을 CompiledModel GPU 에 **절대 지연 척도만 바꿔** 쓴다
- 하나라도 불만족 → "다른 모양" → CompiledModel GPU 곡선을 따로 적는다 (v1 에서 따로 피팅)
- 절대 지연은 비교하지 않는다 — 엔진이 다르다 (NPU 엔진 대조 +21.4 % [D CLAUDE.md]; 같은 프로토콜 7.2× 중 ~17 % 가 프로토콜 몫 [D 프롬프트])
- CPU: 연쇄의 CPU 구간(CompiledModel)과 0927→28 밤 CPU4 (Interpreter XNNPACK 4스레드) 는 스레드 설정부터 다르다 (CompiledModel CPU 는 `CpuOptions` 를 안 준다 — 스레드 수 `미확인`) → **CPU 엔진 대조는 하지 않는다** (M2 CPU 피해자는 대조 팔 차이로만 읽는다)

## 4. M2 — 자원 간 결합 (피해자 NPU 우선)

**연쇄** (모두 per_segment — 두 팔 모두 GPU→NPU 전환이 같은 방식으로 한 번 일어난다):

| 팔 | 파일 | 구간 0 | 구간 1 (피해자) | 합계 |
|---|---|---|---|---|
| 가열 (H) | `m2_heated_gpu_to_npu_v1.json` | GPU d100 **600 s** | NPU d100 60 s | 660 s |
| 대조 (C) | `m2_control_gpu_to_npu_v1.json` | GPU d100 **30 s** (진입 60~70 s 전 [P]) | NPU d100 60 s | 90 s |

- 가열 600 s 의 근거: C1a 는 ~420 s 부터 지연 평탄 [E 시작점], 600 s 끝값은 평형값의 −5.6~−0.2 % [P]. 1200 s 까지 늘려도 지연은 거의 같다 — 대신 SKIN 이 ~0.8 ℃ 더 오른다 [P C1a 600 s 38.5 → 1188 s 39.3]. **피해자에 전해지는 것이 온도라면 600 s 는 결합을 약하게 본다** — 반대 해석 6 으로 적는다
- 순서 = **C1 → H1 → H2 → C2** (ABBA, SOC·실내 온도의 선형 표류를 두 팔에 고르게). 각 팔 2회
- 슬롯마다 시작 게이트(HAL SKIN ≤ 32 · AP ≤ 32 · BAT ≤ 30 ℃, `s26_start_gate.py`)는 **슬롯 시작 때만** — 구간 사이에는 없다

**판정 (먼저 숫자로)** — 피해자 지표 `v` = 구간 1 의 추론 전수 지연 중앙값:
- 대조 폭 `s_C` = |v(C1) − v(C2)| / mean(v(C1), v(C2))
- **결합 있음**: min(v(H1), v(H2)) / max(v(C1), v(C2)) − 1 ≥ **max(+3 %, 2 × s_C)**
- **결합 없음**: max(v(H1), v(H2)) / min(v(C1), v(C2)) − 1 ≤ **s_C** (가열이 대조 폭 안)
- 그 밖 = **판정 보류** (3·4회째를 다음 밤에)
- +3 % 하한의 근거: 같은 모델(MobileNet AOT) 식은 NPU d100 60 s 의 처음 30 s 잡음 RMS 0.232 %, 10 s 칸 최대 ×1.004 [P 사전등록 1-1] — 칸 흔들림의 ~7배로 잡았다. (다른 모델 참고: EfficientNet C2 d100 칸 0.987~1.012, 런 간 CV ≤ 0.30 % [P C2_결과 §2])
- 보조 (판정에 안 씀): 피해자 첫 10 s 칸 / 나머지 칸, 피해자 시작 시각의 SKIN·AP·BAT·SOC, 전환 창 길이(GPU→NPU 전환비용 — 두 팔 × 2)
- **참고값만** (결합 효과로 읽지 않는다): NPU MobileNet d100 0.7427 ms (9/25 formal 5런 중앙) [D 작업결과_0928_밤측정.md §5] · CPU CompiledModel d100 4.407 ms (0927 C5 5런 중앙) [D 작업결과_0927_밤측정.md:76]. 도구·프로토콜이 달라 피해자 값과 직접 빼지 않는다

**CPU 피해자** (예산이 남으면, 같은 ABBA — `m2_heated_gpu_to_cpu_v1.json` / `m2_control_gpu_to_cpu_v1.json`):
- CPU 는 스스로 60 s 안에 +13~23 % 느려진다 [P 1-1, Interpreter] → **주 지표 = 구간 1 의 처음 20 s 중앙값** (CPU +10 % 진입 30 s 전), 60 s 전체 중앙은 보조. 판정식은 NPU 와 같다 (+3 % 하한 대신 **+5 %**). **이 +5 % 는 1-1 의 3×RMS 규칙(→ CPU 진입 +15 %)이 아니다** — 1-1 의 CPU '잡음' RMS 4.9 % 는 무작위가 아니라 부하 초반의 단조 상승이고 [P 1-1], 그 상승은 두 팔에 공통이라 팔 간 차이에서 빠진다 [E]. 하한은 CPU4 처음 30 s 기준값의 런 간 차이 3.9 % (r1 4.631 vs r2 4.459 ms [P 스로틀곡선_0928 §1]) 보다 크게 잡은 값이다 [E]
- CompiledModel CPU 가 60 s 안에 스스로 느려지는지는 `미확인` (이 초안 작성 중 C5 런 안의 10 s 칸 추이를 확인하지 않았다) — 대조 팔이 그 몫을 잡는다

**M2 반대 해석** (ground-truth 1·2 — 지연이 늘었을 때 "열 결합" 말고):
1. **전환 직후 초기화·warmup** → 전환 창은 구간 밖 (보존 검사로 확인) + 두 팔의 첫 10 s 칸 비교
2. **가속기 전환 자체** (GPU 드라이버·메모리 해제가 NPU 를 늦춤) → 대조 팔이 같은 전환을 한다. 전환은 같고 열만 다르다
3. **배터리 SOC·전압 하락** (가열 600 s 동안 ~3~4 %p [E]) → ABBA + 피해자 시작 SOC 기록. H 와 C 의 피해자 시작 SOC 차이가 5 %p 를 넘으면 표시
4. **실내 온도 변화** → ABBA + 세션 시작·끝 기록
5. **열이 아니라 전력 예산(SoC 공유 전력 한도)을 통한 결합** → 이 설계로는 열과 구분 못 한다. 결론 문장은 "자원 간 결합(열 또는 공유 전력 한도)" 으로 쓰고 기제를 주장하지 않는다
6. **가열 600 s 가 결합을 약하게 본다** (SKIN 이 1200 s 까지 오른다) → "결합 없음" 이 나오면 이 한계를 같이 쓰고, M1 의 1200 s 가열 뒤 탐침 전에 NPU 구간을 넣는 변형을 다음 밤 후보로
7. **대조 팔 30 s 도 조금 데운다** → 그만큼 결합을 작게 본다 (보수적 방향)

## 5. 반대 방향(NPU·CPU 가 발열원, GPU 가 피해자)이 필요한가 — **필요 (첫 밤, NPU 발열원 1쌍)**

> [2026-09-28 12:3x 정정 — 독립 검증 지적] 첫 판은 "v0 류 정책은 작업을 GPU→NPU 로 옮긴다" 를 근거로 반대 방향을 미뤘다. **방향이 거꾸로였다**: v0 는 NPU 가 조여지면 BG 를 **'식은' GPU 로 옮긴다** [D `SIM_V0_결과_0927.md:42` "v0 가 '식은' GPU 로 BG 를 옮김" · `:60` · `작업결과_0927_시뮬v0.md:43·49`]. 첫 판 문장은 이 정정 블록으로 대신한다 (초안이라 원문을 지웠고, 이 줄이 그 기록이다).

- 0927→28 밤 [P]: CPU4 는 30 s 에 진입, 240 s 부터 ×1.39~1.45·~3.1~3.5 W 로 평탄. NPU 는 165 s 에 문턱 바로 아래(150 s 칸 ×1.0997), 끝 60 s 전력 ×0.90, 끝 SKIN 38.2 · AP 42.1 ℃ (GPU d100 진입 온도대)
