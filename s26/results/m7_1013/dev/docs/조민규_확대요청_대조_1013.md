## 3. 요청 3 — burst (완화 · 추가 0 기본)

- 그의 첫 후보 "분류 50 / 탐지 50 · 총 100건 · 4 초마다 10건 동시 도착" vs 우리 **B** (M6 등록 §3-2): 버스트 k = 0 … 9 · 안 j = 0 … 9 · 예정 도착 35,000 + 4,000 k + **50 j** ms · j 짝 = 분류 · 홀 = 탐지 · 기한 1.5 / 6 s · 같은 이미지 · 모델. **차이 = 버스트 안 50 ms 간격 (0 ms 아님)**. 요청 JSON (ordinal · task · priority · offset · deadline) 투영 SHA `9fc5ef9f…` 를 보낸다 → 그가 PC 요청열 JSON 을 보내 대조.

- 실패 · 작은 차이 결과 전부 전달 = 기본 (무효 폴더 보존).

4. M6-A/B 12 세션을 `cycle = m6` 로 묶음에 넣는 것 (기본: 넣음 · 행만).

## 8. 카톡 회신 초안 (발송 전 · 첨부 = `sim\M7_확대반복_사전등록_v1.md` · 이 파일)

민규야, 10/13 확대 요청 전부 진행할게 (57세션 + 장시간 12). 같은 M6 APK `6a4da1ac…` 그대로 쓰고, 개발 → 네 동결 SHA → 확인 순서도 그대로. 등록 v1 같이 보낸다 (SHA 는 첫 측정 전에 커밋하고 알려 줄게). 되는 것 · 완화한 것 · 안 되는 것만 먼저:

**1. 초기열·냉각 15** — 된다. A = 직전 앱 실행 끝 뒤 20분 이상 유휴 (시작 전 120초 AP·SKIN 기울기 0.1 ℃/min 이하면 "안정", 최대 대기 20분 넘으면 "안정 미달" 표시하고 진행). B = L-C (CPU 직렬 100건) 끝 → 90초 → K780. C = L-N (분류 NPU ∥ 탐지 CPU 병행 — 기존 경로에 있어서 GPU 대체 안 해도 돼) 끝 → 90초 → K780. 준비 부하 마지막 AVAILABLE (P 세션 common_boundary) 과 K 시작 (K 세션 progress 첫 줄) 은 따로 남아. 완화 하나: "준비 부하 시작부터 끊김 없이" 는 호스트 HAL (AP/SKIN/BAT + dumpsys battery, 약 2.3초) 을 P 시작 120초 전부터 K 끝까지 연속으로 기록해서 맞추고, 앱 전력 샘플은 P 끝 (cooling 60초) ~ K 준비 사이 약 90초가 비어 (앱을 안 고치는 대가 — null + 이유로 남김). 세트 순서는 라틴 방진 (ABC / BCA / CAB, 확인 ACB / BAC).

**2. L/B × C/G/N × 3+2 = 30** — 된다. 새 개발 3블록 (정책 자리 균형: C→G→N / G→N→C / N→C→G, 밤·낮·밤), 네 동결 뒤 확인 2블록. M6-A/B 12세션은 cycle=m6 로 세션 표에 같이 둘게 (쓸지는 네가). 정책 ID 대응표 (C=`CPU_URGENT_ONLINE_V1`, G=`B2_PARALLEL_ONLINE_V1`, N=`S26_NPU_PARALLEL_V1`, 탐지는 셋 다 CPU) 등록에 넣었어. 충전은 블록 밖 · 분리 시각 → 첫 실행 간격 자동 기록. 완화 하나: 마지막 AVAILABLE 뒤 180초 — 온도는 호스트 HAL 을 원점+300초까지 돌려서 맞추고, 앱 전력은 cooling 60초까지 (마지막 AVAILABLE 뒤 약 105초) 야. 전력까지 180초가 꼭 필요하면 cooling 상수를 바꾼 새 APK 가 필요한데 그러면 "같은 APK" 가 깨져서 기본은 안 하고, 네가 원하면 2 확인 끝난 뒤 별도 등록으로 할게.

**3. burst** — 네 첫 후보 (100건 · 4초마다 10건) 는 우리 B 와 거의 같아: B = 4초마다 10건, 버스트 안 50 ms 간격 (0 ms 동시 아님), 분류/탐지 번갈아, 기한 1.5/6초, 같은 이미지. 균등 대응은 L (같은 100건·기한, 400 ms 간격). 요청 JSON 투영 SHA 는 B `9fc5ef9f…` · L `ad29e819…` — 네 PC 요청열 JSON 보내 주면 대조할게. 현 APK 는 유도식 고정이라 0 ms 동시는 그대로 재생 못 해 (비슷하게 돌리지 않을게). 50 ms 를 받아 주면 3 은 2 의 B 칸 (개발 3 · 확인 2) 으로 대신하고 추가 세션 0. 0 ms 가 꼭 필요하면 검증부만 바꾼 새 APK 로 2 뒤에 12세션.

**4. 지속 600초 12** — 조건부로 된다. 같은 APK 에 남아 있는 R4 지속 행 (`S26-MIXREQ-03`: 3,000건 · 200 ms · 창 720초) 그대로 쓰고 (확인 뒤 알려 줄게), 준비는 그 행의 블록 (A/N, R4 와 같음 — 블록 M 아님, 표시), 냉각 600초는 호스트 HAL 로. 유효 규칙은 R4 v3 그대로 (drain 미완료 무효 · 재시도 1회). 1~3 개발 끝난 뒤 기기 시간 되면 개발 6 먼저.

**안 되는 것**: 실내 온도 실제값 (온도계 없음 → 전부 미기록) · 외부 전력계 (없음). Q20 은 같은 APK·엔진 diff 0 이라 Q1/Q3 참조로.
