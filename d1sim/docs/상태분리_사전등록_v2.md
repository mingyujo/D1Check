## 1. 세션 꼴 (request-runner · 기존 APK `591cae72…` · 기존 정책 3개 · 새 계획 매니페스트만)

## 2. 계산 (측정 뒤 · `d1sim/a24fmt_v1/compute.py` 의 같은 정의 — 상태 · 5 s 창 · P_pre · µA)

1. 적합 = 개발 6 세션 (+ R3 16 은 넣지 않음 — 이번 꼴과 섞지 않는다).
2. **식별 기준 (결과 전 고정 · v1 의 조건수 기준 결함을 고친 것)**: 상태마다 (a) 노출 ≥ 50 % 인 5 s 창 ≥ 6개 (b) VIF ≤ 10 (c) NNLS 증분 0 ≤ p ≤ 5 W · θ 가 상한 (5 ℃/s) 에 붙지 않음. 셋 다 → 그 상태 "식별", 아니면 "미식별" (값 대신 `null`).
3. **확인 (블록 3 · 4, 정책당 2 세션)**: 개발 계수로 실측 점유를 넣어 (조건 A) J (0 ~ 120 s) · AP 경로 예측 → 상대 J 오차 · AP MAE 를 기술. 기준: J |상대오차| ≤ 10 % 그리고 AP MAE ≤ 1.0 ℃ 인 세션 ≥ 4/6 그리고 정책마다 ≥ 1/2 → "상태 분리 값 확인 (같은 꼴 · 2 블록)", 아니면 "확인 안 됨". 다른 이름 쓰지 않는다.
4. R4C (이미 본 자료) 에 개발 계수를 적용한 회고 오차를 같이 기술 (판정 아님).
