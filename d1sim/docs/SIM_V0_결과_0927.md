## 5. 반대 해석부터 (ground-truth 1·2)

결론마다 가장 강한 반대 해석과 데이터가 그것을 배제하는지:

1. **"v0 가 V7 에서 이긴 건 v0 가 좋아서가 아니라 기준선이 해로운 반응을 해서다."** → **배제 못 함, 오히려 지지됨.** V7 은 NPU 가 조여지지 않는데(스로틀 0) status 모형은 SKIN ≥ 40 에 반응한다. npumgr 는 언로드(재로드 0.111 s)와 BG 보류로 스스로 처리량을 깎았다 (S1 처리량 1085.6 vs 1211.8). v0 의 V7 결과는 V1 의 npumgr 와 같다 (S1 p95 0.090 · BG 1.000 · 처리량 1211.8) — 즉 "열 반응을 하지 않는 우선순위 정책"이 이겼다. 게다가 **NPU 가 조여지지 않는데 SKIN 이 43.5 ℃ 까지 오르는 조합 자체가 GPU 실측(SKIN ~38.4 에서 제어)과 어긋난다** [E]
2. **"v0 가 V4·V5·V6 에서 FG p95 를 낮춘 건 BG 를 덜 돌려서다."** → **데이터가 지지.** 같은 셀 BG 완료율 0.44~0.61 vs 0.83, NPU 가동 335 s vs 600 s, 처리량 −26~−47 %. 사전 등록 가드가 정확히 이 해를 걸렀다
3. **"스로틀이 안 걸리는 조건이라 차이가 없는 것이다."** → V1·V3 (S1·S2) 에서 **맞다** — 스로틀 시간 0, v0 = npumgr. 이 셀들은 열에 대해 아무 말도 못 한다
4. **"무작위 탐색 대조군도 같은 만큼 이긴다/진다."** → **맞다.** 무작위 최선과 손 최선이 전 셀에서 같은 방향·비슷한 크기 (§3). 규칙 설계의 기여 없음
5. **"v0 는 시뮬레이터 자신의 모형을 완벽히 안다 — 실기기에선 더 나쁠 것."** → 배제 못 함. v0 의 `predict` 는 시뮬레이터와 같은 모형을 쓴다 (예측 오차 0). 이번 결과는 v0 에 **유리한 쪽으로 편향**됐는데도 가드 안의 해가 없다
6. **"FG p95 는 열이 아니라 비선점 BG 조각 길이가 정한다."** → 대체로 맞다 [E]. npumgr FG p95 0.090 (스로틀 없음) ≈ NPU 128 추론 조각 0.095 s. 조각을 쪼개거나 선점하는 정책이면 열과 무관하게 p95 가 준다 — 이번 v0 설계 공간 밖. 조각 128 은 [E] 가정값
7. **"S0 대조에서 열이 결과를 바꿨다면 모형 버그."** → S0 은 모든 정책·변형에서 스로틀 시간 0, 최고 SKIN ≤ 30.64 ℃, 테스트 `test_s0_heat_does_not_change_results` 로 열 on/off 결과 동일 확인 [P-시뮬]. 버그 징후 없음

## 7. 민감도 스윕 — "미작동" 목록 (대응표 "죽은 파라미터")

소수점까지 같음 = 그 기제가 한 번도 작동하지 않음 [P-시뮬, `report_v0.md` 스윕 표]:
- 교차 전환비용: fixed-NPU·npumgr 전 셀 (자원 전환이 없음). v0 S1 V4 도 같음 (NPU 만 씀)
- 결합(독립/공유): fixed·npumgr·shortest 전 셀 (V2 = V4, V1 = V3 — 단 `first_throttle_s` 만 다름, §3 정의)
- 회복(same/slow): fixed·npumgr **S1** (V4 = V5). S2 에선 작동 (npumgr 기한 위반 0.622 → 0.629, 스트림 사이 짧은 휴지에 회복이 걸림)
- status 모형 hal40: NPU 스로틀 변형(V6 = V4) 전 정책
- **작동한 것**: T_th · τ (모든 NPU 스로틀 셀), NPU 스로틀 유무, v0 에 대해 결합·회복·교차 전환
