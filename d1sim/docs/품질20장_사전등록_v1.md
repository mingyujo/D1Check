## 3. 지표 · 판정 (이미지별 표가 먼저 — 평균으로 불일치를 가리지 않는다)

**필수 (모든 backend · 하나라도 실패 = 그 backend "실패" 보존)**: 출력 전부 finite · shape `[1, 1000]` · dtype float32 · 라벨 순서 = 참조 (0 기반).

**이미지별로 기록** (backend 마다 20행): top-1 일치 (참조와) · top-5 **순서까지 같음** 여부 · top-5 **집합 겹침** |∩|/5 (순서 무시 — 둘을 구분) · cosine · 최대 |차| · 평균 |차| · FP32 허용식 `|cand − ref| ≤ 1e-4 + 1e-3·|ref|` 위반 수 (1000 중) · 2회 반복 비트 동일 여부.

**집계** (이미지별 표 아래): top-1 일치 n/20 · top-5 순서 같음 n/20 · 집합 겹침 평균·최소 · cosine 최소·중앙 · 최대 |차| 의 최댓값 · 위반 수 0 인 이미지 n/20.

**판정 (backend 마다)**

| backend | 판정 |
|---|---|
| CPU | 20장 모두 필수 통과 + FP32 허용식 위반 0 → **"참조와 일치 (FP32 기존 경로 기준)"** · 하나라도 위반 → "불일치" (이미지 목록) — 원인 판정은 따로 |
| GPU | 실제 정밀도가 FP32 로 확인되면 CPU 와 같은 기준 · `미확인` 이면 **지표만 · PASS 보류** |
| NPU | **FP32 허용식을 적용하지 않는다** (FP16 경로에 자동 적용 금지 [D]). 근거 있는 FP16 합격선이 이 등록에 없으므로 → **지표만 보고 · 품질 PASS 보류**. 필수 항목 실패는 "실패" 로 보존 |

- FP16 합격선을 쓰고 싶으면 **결과 전에** `_v2` 로 근거와 함께 등록한다 (조민규 동의 포함). 결과를 본 뒤 만들지 않는다.
- 결과 문장 틀: "대표 입력 20장에서 [backend] 출력은 조민규 CPU 참조와 top-1 n/20 · top-5 순서 n/20 · cosine 최소 ○ 로 일치했다 (참조 일치 — 정답 정확도 아님 · NPU 품질 PASS 보류: FP16 합격선 미등록)."

## 4. 반대 해석 (결과 전)

- 참조 출력은 조민규 PC 의 CPU 경로 (그의 엔진 판) — 우리 CPU CompiledModel 과 엔진이 다르면 CPU 위반이 엔진 차이일 수 있다 (그래서 CPU 먼저)
- Softmax 출력은 작은 확률 값이 많아 절대 차가 작게 보인다 → cosine · top-k 와 같이 읽는다
- 20장 · 5 클래스 × 4 — top-1 일치는 변별력이 제한적이다
