- FIFO = ready 요청을 (예정 도착 → ordinal → id) 로 정렬한 **head 하나만** · head 의 lane 이 busy 면 null (추월 없음). EDD = (절대기한 → 예정 도착 → ordinal → id) · strict head 같음.
- SERIAL = running (dispatch ~ lane_available) 1건이라도 있으면 dispatch 0 (lane 이 달라도). PAIR = running ∪ {후보} ⊆ 허용 조합 · |running| < 2 · 같은 lane 1.
- 비선점 · lane 점유 = 실제 시각 (dispatch_ns ~ lane_available_ns) · AVAILABLE = lane_available (응답 경계와 별개) · 모든 결정 (null 포함) 을 decision 이벤트로.
- WAIT: 묶음 k (같은 예정 도착 8건) 의 첫 dispatch 직전, **ready head 있음 ∧ running 0 (관련 owner 전부 실제 AVAILABLE) ∧ k < first_n ∧ 누적 + wait ≤ cap ∧ 그 묶음 처음** 일 때만 고정 타이머 · 타이머 중 도착 = enqueue 만 (재시작/연장/취소 없음) · 120 s 경계 · 안전 중단만 타이머를 끊음 (잘린 dose 실제값) · busy/요청 없음 = 의도 WAIT 아님 · 개입 0 도 기록 (summary.wait.count 0).
- 단위 시험 사례 19개 = `policies_m8.json test_cases` 그대로 (`PolicyStudyM8Test`).
