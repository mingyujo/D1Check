## 3. 지표 (런마다 · 판마다 — P1j 와 같은 정의)

- m1 최고 SKIN 오차 (예측 − 실측, ℃)
- m2 창 끝 SKIN 오차 (℃) — 창 끝 = 그 런의 마지막 공통 시각
- m3 SKIN 궤적 MAE — 10 s 칸 평균 (℃)
- m4 첫 조임 시각 오차 (s) — 조임 = 그 런 판정기와 같은 정의 (GPU 는 N2 판정기 GPU 기준 · 칸 k + 뒤 3칸). 둘 중 하나 없으면 null + 이유
- m5 쌍 Δ (A − B) 최고 SKIN · 첫 조임 시각 — 예측 Δ vs 실측 Δ (부호 · |차|) — 세기 A/B 쌍이 있는 N1 · N2 만
- m6 **자원 판정 문구** (예: "B 낮음" · "차이 없음" · "엇갈림") — 그 묶음 판정기 출력 그대로, 예측 문구 = 실측 문구 여부

## 4. 정리 규칙 (결과 전 고정)

- **판정 이름은 두 가지만** 쓴다:
  - v2.2 행 → **"GPU 적합도 오차 (개발 자료)"** — 통과 / 실패 없음, 숫자만.
  - 각 판의 진짜 홀드아웃 행 → **"GPU 홀드아웃 오차 (판 ○ · 동결 예측)"** — 숫자 + 쌍이 있으면 P1j 블록 규칙 (부호 같음 ∧ |차| ≤ 1.0 ℃) 의 **통과 수 k / n 기술** (재현 판정 이름은 쓰지 않는다 — §0).
- 요약 숫자 (판마다 · GPU / NPU 따로): m1 평균 · |·| 최대 · m3 MAE 평균 · 범위 · m4 평균 |·| · null 수 · m5 k / n · m6 맞은 문구 수.
- **결론 문장에 쓸 수 있는 것은 이것뿐**: "GPU 에서 모형 오차는 ○ (NPU ○) 이었다 · 세기를 바꾼 GPU 쌍의 판정 문구는 ○ / ○ 맞았다". "GPU 정책 효과" · "GPU 검증됨" 은 쓰지 않는다.
- 결과를 본 뒤 런 목록 · 지표 정의 · 시작 상태 규칙을 바꾸지 않는다. 계산이 안 되는 칸 = "계산 불가" (분모에 남김).
