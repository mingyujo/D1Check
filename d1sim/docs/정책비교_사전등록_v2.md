## 5. KPI · 가드 · 지표 (v1 §5 고침)

1. **분모 (FG · BG 따로, 정책마다)**: planned · completed · on-time · late (완료됐지만 기한 넘김 — "지각 성공" = 성공 + miss 둘 다 표시) · failed · rejected · unfinished (horizon 끝에 남음). 삭제 금지. BG 는 청크 수와 **추론 수** 둘 다.
2. **가드 — 둘로 나눈다**:
   - **(a) 절대 기한 충족** (정책마다, 그 조건의 seed 10개 모두에서): FG 예정 요청 전부 on-time (late · failed · rejected · unfinished = 0) **그리고** BG 청크 전부 D_b 안 완료 (late · unfinished = 0). 임의 허용폭 없음 (0).
   - **(b) 상대 비악화** (기준 = `fixed-prio`): FG P95 (전체 분모, §5-3) ≤ 기준 × (1 + m_FG) · BG 기한 내 완료율 (예정 청크 분모) ≥ 기준 − m_BG (%p).
   - **기준선 자체가 (a) 를 못 지키는 조건** = "기준선 서비스 부적격" → 그 조건은 ② 판정에서 빼고 (분모에는 남긴다) 숫자만 기술. ② 의 "가드 통과" = (a) 와 (b) 둘 다.
3. **FG P95 = 전체 예정 분모 nearest-rank** `sorted[ceil(0.95·N_planned) − 1]`, 완료 못 한 요청 (late 는 실제 응답값, failed · rejected · unfinished 는 +∞) 을 넣어 정렬 → 미완료가 5 % 를 넘으면 P95 = +∞. **완료 표본만의 P95 는 보조로만** (완료 0 이면 null).
4. **열 지표 — 공통 관측창** [0, horizon] (모든 정책 같은 창): **주 = 최고 SKIN (Δ℃, 가장 강한 기준선 대비)** · 보조 = SKIN ≥ 38 / 40 / 42 ℃ 시간 (s) · 조임 시간 (s, NPU ×1.06 / GPU ×1.10) · 처리율 (완료 추론 / horizon).
5. **완료 시간 — 창과 따로**: 묶음마다 완료 시각 (마지막 청크 완료 − 묶음 도착) · 전체 BG 완료 시각 · **창 끝 SKIN (잔열)**. 열 이득을 주장하려면 ours 가 (i) BG unfinished 0 이고 (ii) 창 끝 SKIN ≤ 비교 대상 + 1.0 ℃ 여야 한다 — 아니면 "**창 밖으로 밀린 일·잔열 — 절감으로 세지 않는다**" 표시 (② 에서 "가져옴" 아님).
6. **선별 기준 계산 (코드로 고정)**: 조건 × 기준 정책 (`fixed-prio`) 마다 개발 seed 1–10 의 지표 값 x₁..x₁₀ → mean · sd (표본, ddof = 1).
   - FG P95 (s, 상대 비교): CV = sd / mean → **m_FG = max(0.05, 2·CV)** (비율 — 곱하는 상대 허용폭). mean = 0 · 값 중 +∞ · null → CV = null → m_FG = 0.05.
   - BG 기한 내 완료율 (비율 0~1, %p 비교): **m_BG = max(5 %p, 2·sd·100 %p)** (CV 를 쓰지 않는다 — 단위가 %p). sd null → 5 %p.
   - 처리율 (추론/s, 기술용): m = max(0.05, 2·CV) 상대.
   - ℃ 지표 = Δ 1.0 ℃ · s 지표 = 60 s (CV · % 금지).
   - 독립 표본 수 = seed 10 = **도착 표본 반복이지 독립 기기 세션이 아니다**.
7. 중단·결측 = v1 §5-4 그대로 (보존 실패 표시 · 그 조건 판정 안 함).

**판정 (조건마다, seed 중앙)**

- ① 차이 (개발 seed): 가장 강한 기준선 − ref-const 의 최고 SKIN Δ ≥ 1.0 ℃ 이고 ref-const 가 가드 통과 → "제한 참조 대비 차이 있음" (여지 전체가 아니다).
- ② 규칙 (홀드아웃 seed): ours 가드 통과 (a · b) **그리고** 가장 강한 기준선 − ours ≥ 1.0 ℃ **그리고** §5-5 (i)(ii) **그리고** 가드를 통과한 대조군 (4a · 4b) 중 어느 것도 ours 보다 1.0 ℃ 이상 낮지 않다 → "가져옴". 대조군이 ours 와 같은 이득 (차 < 1.0 ℃) → "가족 대조군도 같은 이득 — 규칙 고유 효과라고 쓰지 않는다".
- 개발 seed 결과는 ① 과 튜닝에만.

## 9. 폰 확인 (V3) — 범위를 줄인다 (v1 §9 고침, 조민규 필수 §9 · 중요 §6·9)

1. **이름 = "BG 부하율 타임라인 재생의 열 반응 확인"**. FG 도착 · FG 1.5 s 기한 · 온라인 정책 실행 · 전체 서비스 가드를 **폰에서 확인하지 않는다** (러너에 도착 경로 없음). 시뮬의 두 정책이 낸 BG duty 열을 체인으로 재생할 뿐이다.
2. **고르기**: v1 §9-1 규칙 그대로 (② "가져옴" 조건 중 Δ 가 큰 1~2개, 동률 규칙 같음). 단 **선택 이력을 보존한다** — 홀드아웃 24 조건 전부의 ② 판정 표 (분모) · 고른 조건 · 고른 이유를 V3 사전 등록에 그대로 옮긴다. 폰 자료는 새 관측이지만 **조건은 홀드아웃 성과로 골랐다** → 결과를 "일반 조건의 효과" · "무편향 평균" 으로 쓰지 않는다.
3. 재생·게이트·지표: v1 §9-2 · §9-3 그대로 (2블록 거울 · 밤 1005 게이트 · 최고 SKIN · t38/t40 · 조임 · 처리율). 각 런의 **직전 칸 · 직전 쉼 길이 · 블록 안 순서 · 게이트 값 (SKIN · AP · BAT · SOC) · 실내 진술** 을 표에 같이 둔다. 시작 상태 차이를 회귀 · 보정으로 지우지 않는다.
4. **작업량**: 재생 창 안 두 정책의 **완료 추론 수와 비 r = ours / 기준선** 을 늘 적는다. **r ≥ 0.95 를 "같은 작업량" 으로 부르지 않는다** — r < 1 이면 "ours 가 (1 − r) × 100 % 덜 함" 을 판정 문장 옆에 붙인다. V3 는 같은 작업량 효과를 주장하지 않는다 (같은 예정량·완료량·완료/tail 경계를 고정한 설계가 아니라서).
5. 판정 문구: 두 블록 모두 (기준선 − ours) 최고 SKIN Δ ≥ +1.0 ℃ → "BG 재생 열 반응 같은 방향 (기준 넘음, 작업량 비 r)" · 둘 다 > 0 · 하나라도 < 1.0 → "같은 부호, 기준 안" · 하나라도 ≤ 0 → "같은 방향 아님" · r < 0.95 → "작업량 차 큼 — 비교 기술만".
6. §1 e 에서 그 자원이 "전이 미확인" 이면 V3 결과는 관측으로만 기술하고 "시뮬 예측 확인" 으로 쓰지 않는다.
