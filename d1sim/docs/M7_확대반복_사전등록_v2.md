1. 조건 B · C 의 준비 부하는 요청 기반 (100건 · ≈ 75 s) — "연속 고정 부하" 가 아니다 · 준비 부하 자체의 세션 간 변동이 K 시작 상태에 들어간다 (그래서 반복 3 + 2).
2. 연속 HAL 은 호스트 읽기 (≈ 2.3 s · dumpsys 부하 소량) — 세션 `hal.csv` 와 두 겹 읽기 → 관측 부하 두 배 [E] · HAL 갱신 시각은 못 준다.
3. 앱 전력 공백 (세션 사이 · cooling 60 s 뒤) 은 APK 무변경의 대가 — 전력 냉각 곡선은 ≈ 105 s 까지만.
4. 항목 3 은 B 가 50 ms 간격이라 "동시" 가 아니다 — 조민규 JSON 과 다르면 (나).
5. 항목 4 는 블록 A/N 준비 (M6 블록 M 과 다름) · R4 (S) 와 같은 조건의 반복이지 "새 M6 조건" 은 아니다 (연결은 같은 APK 뿐).
6. 반복 3 + 2 는 설계 제안이지 검정력 근거가 아니다 (조민규 원문 그대로).
7. 실내 온도 없음 · 일상 사용 폰 · 블록이 다른 날 → 시간대 · 날짜 변동이 반복 변동에 섞인다 (분산 설계로 가르지, 제거는 못 함).
8. 조건 A 의 "유휴" 는 앱 추론 0 이지 폰 전체 유휴가 아니다 (백그라운드 미통제).
