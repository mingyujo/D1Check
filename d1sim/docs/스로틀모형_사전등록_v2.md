## 2. 형태 후보 (이름을 미리 — 출발점이지 정답 아님 [E])

### 2.0 공통 — 열 블록 v1 + 냉각 τ 분리

```
τ_f·dH_f/dt = G_f·(P−P_idle) − H_f      τ_s·dH_s/dt = G_s·(P−P_idle) − H_s      SKIN = T_start + H_f + H_s
τ_a·dH_a/dt = G_a[r]·(P−P_idle) − H_a   AP = SKIN + A_0 + H_a
냉각 비대칭 (새것): 노드 x 가 식는 중 (H_x > G_x·(P−P_idle)) 이면 τ_x → τ_x·c_x,  c_x ≥ 1,  x ∈ {f, s, a}   (c_x = 1 이면 v1 과 같다)
P = P_idle + (P0_r − P_idle)·s_r^α_r (실행 자원 r; idle 이면 P_idle; α·P0·L0 는 v1 값 [P-fit])
```
- 피팅: A 단계 = v1 Stage A 와 같은 목적함수 (실측 1 s 전력 입력 → SKIN 오차² 평균, 피팅 런 합동) 에 **탐침 구간이 든 런 (`m1`·`m1n_a`) 을 더해** G_f·G_s·τ_s·c_f·c_s 를 Nelder-Mead 고정 시작점으로; 그 뒤 G_a[r]·τ_a 격자·c_a (AP 잔차). τ_f = 34.4 [D] 고정 유지.
- 부하 변수 **u_r(t) = 최근 10 s 중 자원 r 이 실행한 초의 비율** (현재 초 포함, 1 s 격자) — d100 → 1 · d50 → 0.5 · d10 → 0.1 · d1 → 0 (1 s 격자에서 100 ms 창은 실행 0 으로 떨어진다 → 모형의 d1 = 완전 유휴, 전력 P_idle; 실측 d1 전력 +~0.06 W [E] 는 무시 — 기록).
- 제어기는 **자기 자원이 실행 중일 때만 전진** (v1 r2 규칙 유지 — M2r "쉬는 자원은 미리 조여지지 않는다").

### 2.1 V2-Lk — 부하 의존 연속형 (주 후보)

```
GPU (엔진별 CM / INT), 구동 센서 T_drv ∈ {SKIN, AP} — 둘 다 등록, 자료가 고른다 (B 단계 목적함수가 작은 쪽; 결과에 둘 다 보고)
  문턱 이동: T_on(u) = T_on + κ_G·(1 − u)
  arm: T_drv ≥ T_on(u) 가 d_on = 10 s 연속 (실행 초만 셈)   /   해제: T_drv < T_on(u) − h_G  (즉시 — u 의 10 s 창이 ~10 s 지연을 준다)
  깊이 (armed 일 때, 정적 지도): ratio = 1 + D_G·clip((T_drv − T_d0)/W_G, 0, 1) ;  s = 1/ratio   (released → ratio 1)
  파라미터 6: T_on · κ_G · h_G · T_d0 · W_G · D_G   (CM 세트: T_on·h·T_d0·W·D 는 m2_H1+m1 로, κ_G 는 **INT 세트의 m3 (d50)** 로 정해 CM 에도 같은 값 [E — 엔진 다름 표시])
NPU (CompiledModel), T_drv ∈ {SKIN, AP} 둘 다 등록
  계단 3개: ratio = 1 + a1·[arm1] + a2·[arm2] + a3·[arm3],  arm_i: T_drv ≥ T_i + κ_N·(1 − u) 가 d_on 10 s 연속 ;  해제 arm_i: T_drv < T_i + κ_N·(1 − u) − h_N (계단별 즉시)
  파라미터 7 + κ_N: T1 < T2 < T3 · a1 · a2 · a3 · h_N ;  **κ_N 은 자료로 정하지 못한다** → 하한만 (⑨: d10 해제 칸 T_drv 가 T1(0.1) 아래여야 하므로 κ_N ≥ (T_drv,해제 − T1 + h_N)/0.9) → 변형 §7
CPU4: v1 제어기 그대로 (AP 적분형, u 무관)
```
- 왜 이 형태인가 [E]: ⑨ (d10 에서 SKIN 41.4·AP 43.9 인데 해제) · ② (d50 진입 SKIN 38.1 vs d100 36.7~37.1 — 부하가 낮으면 더 뜨거워야 조인다) · ⑩ (d10 해제 SKIN 38.2 > d100 진입 37.1) 세 관측이 **같은 부호** (u 가 낮을수록 문턱이 높다). 깊이를 정적 지도로 두는 근거 = 페이싱 재가열 첫 칸 ×1.02 → 10 s 뒤 ×2.02 (깊이가 "기억" 되거나 온도의 함수) 와 M2r 뜨거운 GPU 10 s 뒤 ×2 [P] — 적분 K 형태는 홀드아웃에서 틀렸다 (`모형_홀드아웃_결과_1003.md` §4).
- GPU 구동 센서에 대한 사전 예상 [E]: AP 는 d100 가열 중 **내려가는데** 깊이는 올라간다 (42.8 → 41.0, ×1.1 → ×2.2 [P M1 r2]) → AP 정적 지도는 부호가 반대 → **SKIN 쪽이 뽑힐 것**. 틀리면 기록.

### 2.2 V2-Lb — 부하 문턱 이진형 (대조)

- V2-Lk 에서 κ = 0 으로 두고, **u_r < θ_r 이면 그 자원의 gate 를 강제 해제** (조임은 부하가 문턱 이상일 때만). 나머지 (정적 깊이 · h · d_on) 같음.
- θ_GPU: d50 은 조여지고 (M3 [P]) d10 은 풀린다 (M1 [P]) → θ_GPU ∈ (0.1, 0.5] — **0.3 으로 고정 [E 중간값]** (피팅 안 함). θ_NPU ∈ (0.1, 1] 은 자료로 못 정한다 → 변형 §7 (≤ 0.5 → 0.3 · > 0.5 → 0.75).
- 파라미터 수 = V2-Lk − κ + θ (θ 는 고정이므로 피팅 수는 하나 적다).

- **같은 방향 3번**: 한 형태를 같은 방향으로 3번 고쳐도 §4 를 못 맞추면 그 형태를 버리고 원장에 "무엇이 무엇을 망가뜨렸다" 한 줄. 형태·변형 시도마다 원장 한 줄 (채택·기각·미시도 모두).
- **채택 규칙 (지금 숫자로)**: ①~⑦ + ⑨~⑬ **12항목 통과 수 최다 형태 1개** (⑧ 은 표 — 세지 않음). 동률 → 피팅 파라미터 수 적은 쪽 → 그래도 같으면 V2-Lk → V2-Lb → V2-S. **최선 형태가 v1 (2/12) 보다 많지 않으면 "v2 미완"** — 그래도 최선 형태를 고정하고 예측은 동결한다.
- 선택에 안 쓴 형태의 예측도 같은 커밋에 "참고 — 선택에 쓰지 않음" 으로 동결 (`reference_forms`). **오늘 밤 자료로 형태·변형을 고르면 그 선택은 10/5 밤 자료로 다시 확인**한다 (오늘 밤이 선택 세트가 되므로 — `밤1004_사전등록_v1.md` §8).
- 사전 등록 전 피팅 결과 보기 금지 (이 문서 커밋이 먼저). 고정 규칙: 4단계 끝에 코드·파라미터·테스트를 커밋하고 SHA·시각을 §9 에.
- "κ ≈ 2 ℃" 류 수치 해석은 [E] 사후 가설 — 이 자료로 만든 가설은 이 자료로 검증 못 한다. 검증 = 오늘 밤 (5단계 동결) 과 10/5 밤.

|---|---|---|
| κ_NPU (V2-Lk) | **κ_lo** = ⑨ 하한 (피팅 뒤 수치로 적는다) · **κ_2** = 하한 × 2 · **κ_inf** = ∞ (d100 이 아니면 항상 해제 — "조임은 d100 전용") | N50P: R50-fast → κ_2 이상 쪽 (κ_lo 는 d50 에서 조임 유지를 예측할 수 있다 — 피팅 뒤 수치로) · R50-slow/none → κ_lo 쪽 · 자세한 대응은 5단계 예측 문서에 변형별로 |

## 8. 반대 해석 먼저 (ground-truth — 결과 전 목록)

1. ⑨ 는 "부하" 가 아니라 **숨은 빠른 센서** (NPU 자체 온도 — HAL 목록에 없음 [P `measure\s26\device\03_thermalservice_1.txt`: AP·BAT·CP·PA·SKIN·SUBBAT·USB 뿐, 냉각 장치 목록 비어 있음]) 로도 낼 수 있다: 부하를 내리면 그 센서는 수십 초 안에 식고 SKIN·AP 는 느리게 식는다. **수식으로는** "문턱이 u 에 따라 오른다" 와 "구동 온도가 u 에 따라 빨리 내려간다" 가 10 s 척도에서 같은 예측을 낸다 — 가를 수 있는 것은 d50 (N50P): 숨은 센서라면 d50 에서도 식어 R50-fast, 부하 문턱이라면 θ/κ 에 따라 다르다. **수식이 같다면 같다고 적는다** (결과 문서).
2. 통과 항목이 늘었다면 **파라미터를 늘려서**인가 — v1 GPU 제어기 4 (T_on·K·T_set·T_off) → V2-Lk 6 · NPU 5 → 7+κ. 파라미터 수를 표에 넣고, 반홀드아웃(본 자료) 격차를 나란히. 그래서 5단계 동결이 필요하다.
3. 본 자료에 맞춘 것인가 — 10/3 런 4개 중 2개 (`m1n_a`·`m1`) 가 피팅에 들어가므로 ⑨⑩ 의 반홀드아웃 (`m1n_b`·`m1g_r2`) 은 같은 밤·같은 설치본이라 격차가 작게 나온다고 미리 적는다.
4. ② 와 ⑨ 가 "같은 부호" 라는 것은 **엔진이 다른** 자료 (M3 Interpreter · M1-NPU CompiledModel) 를 합친 해석 — κ_GPU 는 Interpreter 로 정해 CompiledModel 에 쓴다 (표시).
5. 열 vs 공유 전력 한도 — 이 자료로 구분 불가 (v1 과 같음).
6. 1~2런 칸 · 밤 하나 · 시작 BAT 차이 (가열 속도 100~160 s 편차 [P]) — 계단 **시각** 은 어느 형태로도 ±20 s 로 맞추기 어렵다 (③ 이 실패해도 그것이 런 간 편차 때문인지 형태 때문인지 이 자료로 못 가른다 — 기록).
