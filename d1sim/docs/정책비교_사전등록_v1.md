## 3. 결론 문구 · 정책 사전 등록 (조민규 §3 1~7 대응)

1. **A24 와 섞지 않는다** — 이 등록은 S26 만. A24 미검증을 대신 PASS 처리하지 않는다.
2. **비교 조건 고정**: 같은 모델·정밀도·입력·시간 경계·부하 (같은 seed 의 같은 예정 도착·요청 수·기한·완료창) 에서만 정책을 비교한다. "최대 duty 에서 온도가 낮다" 와 "같은 요청을 더 적은 열로 완료" 를 섞지 않는다.
3. **status 0 + 처리율 감소는 OS 관리 부재 증거가 아니다.** `NpuManagerApprox` (`npumgr`) 는 **연구용 근사 정책 ID** — 실제 Android NPU Manager 를 재현·능가했다고 쓰지 않는다.
4. **버린 일은 절감이 아니다**: 같은 예정 도착·요청 수·기한·완료창. BG 를 horizon 밖으로 밀거나 버린 결과를 열 절감으로 세지 않는다 (§5 가드가 거른다). 실패·만료·미완료 분모와 tail (마지막 BG 기한 뒤 300 s) 은 이 문서로 고정.
5. **선별 기준 (screening — 측정 오차 한도·유의성·정책 우월성 기준 아님)**: % 지표 (FG P95 · 기한 내 완료율 · 처리율) m = max(5 %, 2·CV), CV = **개발 seed 1–10 사이 변동계수** (단위 = 그 지표 그대로 · 집계 대상 = 조건 × 정책마다 seed 10개의 그 지표 값 · 독립 런 수 = 10 · 기준 = §4 의 기준선 정책) · ℃ 지표 = **Δ 1.0 ℃** · s 지표 = **60 s** (밤 1005 와 같은 값). 섭씨에 % · CV 를 쓰지 않는다.
6. **회수율** = (기준선 − ours) / (기준선 − oracle), 최소화 지표 (주 지표 §5), 같은 단위·같은 가드 아래 — **분모 (기준선 − oracle) 가 선별 기준 (1.0 ℃) 보다 클 때만**, 아니면 `null` + 원래 차이. oracle 은 **성능 상한 (= 열 부담의 비용 하한)** 이고, 미래 도착을 아는 정책이라 온라인 구현 가능한 정책과 구분한다.
7. **결과 전 동결 목록**: 모델·입력 (§1) · 부하 구간·기한 (§2) · 정책 (§4) · KPI·가드·주 지표 (§5) · 중단/결측 (§5-4) · 선별 기준 (위 5) · seed 분할 (§6) · 모형 해시 (§7) · 결과별 결론 (아래). **이미 본 모형 개발 자료 (10/5 까지) 와 독립 정책 확인 (홀드아웃 seed · 폰) 을 구분한다.** 결과를 본 뒤 모형을 재적합하고 같은 홀드아웃을 "새 독립 확인" 이라 부르지 않는다.

| 4a | 같은 가족 대조군 `pace-d50` | BG 를 늘 d50 (기한 무시) · FG 선점 | 기존 `run_compare_v2.PacedNpuManager(0.5)` 와 같은 뜻 — 새 클래스로 duty 위상 통일 |
| 4b | 같은 가족 대조군 `pace-rand` | 같은 조건·seed 에서 ours 가 실제로 쓴 **평균 duty 와 같은 평균**을 갖는 무작위 duty (10 s 주기마다 {10,25,50,75,100} 에서 뽑음, 확률 = ours 의 실현 duty 분포, 난수 seed = seed + 1000) · 기한 무시 | 새 클래스 |
| 5 | **oracle** | **정보 범위: 모든 BG·FG 도착 시각 + 같은 모형 (시뮬레이터 자신)**. 계획 공간: BG 묶음마다 상수 duty (5³ = 125 조합) — 가드 (§5) 를 지키는 조합 중 주 지표 최소. = **이 정보·이 계획 공간 안의 성능 상한 (열 비용 하한)** — 전역 최적이 아니다 | 새 함수 |

- ours 튜닝 (개발 seed 1–10 만): margin_s ∈ {0, 30, 60} × offset ∈ {0, −0.5 ℃} = 6 설정. 고르는 규칙: 개발 조건 전부에서 가드를 지키는 설정 중 **조건별 seed 중앙 주 지표의 평균이 가장 낮은 것** (동률 → margin 작은 쪽 → offset 0). 고른 뒤 정책 코드 SHA 를 커밋 ("정책 동결") → 그 뒤 홀드아웃 seed 1회.
- **정책 = 코드 해시**: 정책 클래스는 내일 개발 seed 실행 전에 커밋한다. 정책 동결 커밋 뒤 코드를 고치면 새 판 (`_v2`) — 홀드아웃은 다시 열지 않는다.
- CPU 칸 없음 (S26 은 CPU 가 가장 빨리 뜨거워지고, 뜨거울 때 CPU 로 옮기는 정책을 쓰지 않는다 [D 조민규 회신 1004]).

## 5. KPI · 가드 · 주 지표 (조민규 §5 정의 그대로)

1. **response** = C_i − scheduled_arrival (보조: C_i − enqueue) · C_i = 결과 사용 가능 시각 (시뮬레이터 완료 시각). 완료 응답 **P95 = nearest-rank `sorted[ceil(.95·n) − 1]`**, 완료 0 이면 null · **분모 = 전체 예정 요청** · 실패·거절·만료·취소·미완료 삭제 금지 · **지각 성공 = 성공 + deadline miss 둘 다 표시**. FG: planned · completed · on-time · failed · unfinished · P95. BG: planned · completed · on-time · failed · unfinished (요청 = 128 추론 청크 단위).
2. **가드 (서비스)**: (a) FG P95 ≤ 기준선 FG P95 × (1 + m_FG) · (b) BG 기한 내 완료율 (예정 BG 청크 분모) ≥ 기준선 − m_BG (%p) · m = §3-5 (조건별 CV). **기준선 = 정책 1 `fixed-prio`** (서비스가 가장 강한 고정 배정). 가드 실패 정책의 열 지표는 기술만 (우열 판정에 쓰지 않는다).
3. **열 목적 지표** (따로 보고, 가중합 없음): **주 지표 = 최고 SKIN (Δ℃, 기준선 대비)** · 보조 = SKIN ≥ 38 / 40 / 42 ℃ 시간 (s) · 조임 시간 (s; 실행 초 중 배율 ≥ NPU ×1.06 / GPU ×1.10 — 밤 1005 문턱과 같음) · 처리율 (완료 추론 / horizon, 추론/s). J · 에너지 없음.
4. **중단·결측**: 보존 검사 (`d1sim/kpi.conservation`: 도착 = done + rejected + unfinished · 응답 = 대기 + 전환 + 실행 · 시작 ≥ 도착 · 자원별·전체 busy 구간 겹침 없음 · 전력 장부 [0, horizon] 연속 — 전력 장부는 잠정 W, J 보고 없음) 실패 런은 결과에서 빼지 않고 "보존 실패" 로 표시하고 그 조건은 판정하지 않는다 · 시뮬 예외 = 같은 처리.
5. 지속 가능 처리율·스로틀 기준: 조임 = 위 문턱 · warmup 제외 없음 (시뮬레이터는 warmup 이 없다; 실측 근거의 R0 는 warmup 뒤 처음 30 s).

**판정 (조건 c 마다, seed 중앙)**

- ① 여지 (개발 seed): 기준선 − oracle 의 최고 SKIN Δ ≥ **1.0 ℃** 이고 oracle 이 가드 통과 → "여지 있음".
- ② 규칙이 가져옴 (홀드아웃 seed): ours 가 가드 통과 **그리고** 기준선 − ours ≥ 1.0 ℃ **그리고** 가드를 통과한 대조군 (4a·4b) 중 어느 것도 ours 보다 1.0 ℃ 이상 낮지 않다 → "가져옴" · 대조군이 ours 와 같은 이득 (차 < 1.0 ℃) 이면 "가족 대조군도 같은 이득 — 규칙 고유 효과라고 쓰지 않는다" (2행 쪽) · 회수율 §3-6.
- 개발 seed 결과는 ① 과 ours 튜닝에만 쓴다. ② 는 홀드아웃 seed 에서만 판정한다.

3. 폰에서 **2블록 거울 순서** (블록 1 = 기준선 → ours · 블록 2 = ours → 기준선) · 게이트 = 밤 1005 와 같은 상한·하한 · 같은 지표 (최고 SKIN · t38/t40 · 조임 시간 · 처리율) · 같은 선별 기준.
4. **"같은 방향"** = 두 블록 모두 (기준선 − ours) 최고 SKIN Δ ≥ +1.0 ℃ → "같은 방향 (기준 넘음)" · 두 블록 다 > 0 이지만 하나라도 < 1.0 → "같은 부호, 기준 안" · 하나라도 ≤ 0 → "같은 방향 아님" (4행). BG 일 비 (ours / 기준선) ≥ 0.95 가 아니면 "같은 일 아님 — 비교 기술만".
