## 2. EffNet 체인으로 옮기기

- NPU 칸: 구간 `model = models/efficientnet_lite0_Samsung_E9965.tflite` (자산 있음 [P `npu-runner/src/main/assets/models/`]) · `input_spec lcg-rgb-127-128` · `model_prepare per_segment` — 체인 형식으로 표현 가능 [D]. **EffNet AOT 를 체인으로 돌린 적은 없다** (EffN420 은 단일 런) → `미확인` (dry-run + 짧은 스모크 필요).
- GPU 칸: EffNet 원본은 APK 자산에 없다 — 10/4 블록은 `npu_model_source /data/local/tmp/efficientnet_lite0.tflite` (절대 경로, SHA `6c7ab0a6…`) [P run_metadata] → 체인 구간 `model_path` (절대 경로) 로 표현 가능 [D :104~107 · NpuChain.kt:130]. orchestrator 의 체인 구간 모델 SHA 확인이 `model_path` 를 다루는지 `미확인` (체인 dry-run 은 자산 모델로만 해 봤다).
- **타임라인 → 구간**: 10 s 격자 duty 열을 런 길이 부호화 (같은 duty 가 이어지면 한 구간). duty 집합 {10, 25, 50, 75, 100} + 묶음 사이 쉼 = duty 1.
  - 길이: 등록 horizon = 마지막 BG 기한 + 300 s ≈ 2,400~3,100 s [E 생성기 기본값] — **Σ 3,600 s 안**. 단 900~1800 s 창만 재생한다면 더 여유.
  - 구간 수 예상 [E]: 기준선 (`fixed-prio`) = 묶음마다 d100 → 쉼 ≈ **6~7 구간**. `ours` = 묶음마다 기한 재계획 (10 s 마다) — duty 가 묶음 안에서 바뀌는 횟수에 달렸다. 묶음당 3~8 번이면 3 묶음 × (4~9) + 쉼 ≈ **15~30 구간** → 32 안이 될 수도, 넘을 수도 있다.
- **32 를 넘으면 (대안, 우선순위 순)**:
  1. **구간 묶기**: 같은 묶음 안의 짧은 duty 구간 (< 30 s) 을 시간 가중 평균 duty 에 가장 가까운 등록 duty 로 합친다 — 합친 뒤 시뮬로 같은 지표를 다시 내어 원 타임라인과 차이를 기록 (차이가 선별 기준보다 크면 그 조건은 V3 에서 뺀다).
  2. **재생 창 줄이기**: 900~1800 s 창 (묶음 1~2개) 만 재생 — 구간 수가 절반 안팎.
  3. 여러 체인 (슬롯) 으로 나누기 — **권하지 않는다**: 슬롯 사이 baseline 60 s · 냉각·게이트가 끼어 열 이력이 끊긴다.
- 정확도 한계 [D/E]: 구간마다 duty 주기가 새로 시작 (10 s 격자에 맞추면 위상 차 없음) · 전환 창 ~0.1~0.2 s + warmup 20 회 (구간 `warmup: 0` 으로 줄일 수 있다 [D :118]) · d1 은 완전 유휴가 아니다 · **FG 요청은 체인에 없다** (러너에 도착 경로 없음) → 폰 재생은 BG duty 레버만 — 서비스 가드 (FG P95) 는 폰에서 판정하지 않는다 (등록 §9 한계).
- 안전: 한 슬롯 안에서 안전 재게이트가 없다 — NPU EffNet d100 은 600 s 에서 BAT 42 비상이 있었다 (10/3) · 420 s 는 BAT 40.4 완주 [P `EffN420_결과_1004.md`]. 기준선 타임라인 (d100 300 s 묶음 × 3, 사이 쉼 ~600 s) 은 그 범위 근처 → 밤 프롬프트가 칸 길이·비상 한도를 다시 본다 [E].
