> 등록 `d1sim/docs/병행시뮬_사전등록_v1.md` (SHA-256 `81a5428d…`, 커밋 ① `2f31dea`) 이 P1l 에게 맡긴 세부. 이 파일은 커밋 ② (동결 예측과 함께, R4 결과 지표를 읽기 전) 에 들어간다. 이후 바꾸지 않는다.
> 표기: [P] 실측 · [D] 인용 · [E] 추정 · `미확인`.

## D1. AP 단계의 자원별 G_a 를 동시 실행에서 합치는 식 (등록 §1-1)

- 자원별 기여의 **합**: H_a 목표 = Σ_r G_a[r] · dP_r, dP_r = κ · g_r · (P_r(s_r) − P_idle) (r 실행 중일 때만). 빠른 · 느린 SKIN 노드 목표 = G_f · Σ dP_r · G_s · Σ dP_r. CPU 의 G_a = v2.2 `G_a['CPU4']`.
- 이유: 자원이 하나뿐이고 κ = g = 1 이면 v2.2 `ThermalV21.advance` 와 바이트 수준으로 같은 값 (`thermal_sum --selftest`). 바쁨 가중 평균은 두 자원 동시일 때 열 입력을 줄이므로 "단순 중첩 (M-sup)" 정의와 맞지 않는다.

## D2. 자원 "실행 중" 의 정의 (서비스 → 열)

- 가속기 (GPU · NPU): 요청의 `host_inference_start` ~ `host_inference_return` 구간.
- CPU: CPU 줄 (lane) 의 바쁜 구간 전체 (`dispatch` ~ `lane_available`) + 가속기 줄 요청의 나머지 구간 (디코드 · 전처리 · 출력 · 저장 · 해제 — 줄 스레드의 CPU 일).
- CPU 는 0/1 (어느 CPU 일이든 있으면 실행 중) — 두 CPU 일이 겹쳐도 2배로 세지 않는다. 겹침 효과는 g_CPU 와 κ 가 흡수할 수 있다 (반대 해석 3).

## D3. CPU 제어기 유무 — 쓰지 않는다 (CPU 조임 없음)

- v2.2 의 CPU4 제어기는 v1 적분 제어기 placeholder (Interpreter 1.4.2 · 4 스레드 · MobileNet d100 피팅, `T_off` placeholder) 이고, 요청 러너는 CompiledModel 2.2.0 · 1 스레드 · EfficientNet / EfficientDet 다. 엔진 · 스레드 · 모델이 모두 달라 옮기지 않는다.
- 그래서 CPU 처리시간 = R3 실측 분포 그대로 (조임 배율 1). R3 (짧은 창) 에 CPU 조임이 없었는지는 확인 범위 밖 — R4 (S) 600 s 지속에서 CPU 가 느려지면 모형은 그것을 내지 못한다 (한계 · 반대 해석에 적는다).

## D4. g_CPU 목적함수 (M-sup) · (g_CPU, κ) (M-κ)

- **열린 고리** — R3 16세션의 **실측 요청 단계 타임스탬프** 로 자원 활동을 만들어 열만 적분 (서비스 표본 잡음이 열 피팅에 섞이지 않게).
- 세션마다 공통창 안 HAL 표본 시각에서 (모형 AP − HAL AP)² 평균 → 16세션 평균을 최소화. 모형 AP 는 0.5 s 격자 경로를 선형 보간.
- M-sup: κ = 1, g_CPU ∈ [0.05, 5] (bounded Brent). M-κ: (g_CPU, κ) Nelder–Mead, M-sup 해 · κ = 1 에서 출발, g ∈ [0.05, 5] · κ ∈ [0.1, 3] (자름).
- g_GPU · g_NPU = v2.2 g_m (0.9113 · 0.9734) 그대로 (EffNet 분류). CPU 전력 = v2.2 `CPU4_interpreter` 전력 프로파일 s = 1 (P0 7.3615 W) × g_CPU.

## D5. 시작 상태 (등록 §1-5 "실제 시작 SKIN / AP / BAT")

- 모형은 **공통창 시작 (`common_boundary.start_ns`)** 에서 출발 (요청은 그 뒤 35 s 부터).
- SKIN0 · AP0 · BAT0 = 그 시각 이전 마지막 HAL 행. A0 (AP − SKIN 정상 차) = 세션 게이트 줄 (실행 전 유휴) 의 AP − SKIN. H_a(0) = (AP0 − SKIN0) − A0 — 준비 · warmup 이 남긴 AP 잔열이 v2.2 AP 시상수로 식는다.
- 몸체 초기 조건 = v2.2 그대로 (z = (SKIN0 − BAT0) − d_ref, H_s(0) = k_b z).

## D6. 처리시간 · 오버헤드 · 도착 지터 (등록 §1-4 "저장 · 큐 오버헤드")

- 요청 하나 = R3 실측 요청 하나의 단계 묶음 (prepare · execution · out · persist · release) 을 **통째로** 뽑는다 (단계 사이 상관 보존). 열쇠 = (문맥, 작업, 자원): 문맥 serial = CPU_URGENT · par_gpu = B2 · par_npu = S26_NPU_PARALLEL.
- 실행 (execution) 만 가속기 조임 배율 (배정 시각의 v2.2 제어기 ratio) 을 곱한다. CPU 단계 · 저장 · 해제는 배율 1.
- 응답 완료: 긴급 분류 = `output_ready`, 일반 탐지 = `persist_complete` (− 예정 도착). **줄 점유는 `lane_available` 까지** — 다음 요청은 그 뒤에야 배정 (응답 뒤 저장 · 해제가 줄을 붙잡는다).
- 배정 오버헤드: 도착 때 줄이 비어 있었으면 'arr' (실측 도착 → dispatch, 중앙 1.6 ~ 2.2 ms), 줄이 바빴으면 'gap' (앞 요청 `lane_available` → dispatch, serial 실측 중앙 0.5 ms) 표본. 병행 줄의 대기 사례는 R3 에 없어 serial 'gap' 분포를 같이 쓴다.
- 도착 지터 = 실측 (actual − scheduled) 를 작업별로 뽑는다.
- 3줄 규칙 (R5 ~ R8): 분류 GPU → par_gpu · 분류 NPU → par_npu · 분류 CPU → serial · 탐지 CPU → par_gpu ∪ par_npu 합친 분포. **3자원 동시 실측 없음 → 외삽**.

## D7. 규칙 정의 (등록 §5 R5 ~ R7)

- 대기 순서: R1 = 실제 도착 · ordinal / R2 · R3 · R4 · R5 · R7 = 긴급 먼저 → ordinal / R6 EDD = (예정 도착 + 기한) → ordinal.
- EFT (조민규 `EFT_REFERENCE`, `tools/d1_empirical_request_policy.py` @ `7475b18`): 맨 앞 요청 하나 (head-of-line) 를 **예측 응답이 가장 이른 줄**로. 동률 = CPU 먼저. 그 줄이 바쁘면 기다린다 (더 느린 빈 줄로 보내지 않음). 예측 = R3 중앙 단계 × 현재 ratio, 바쁜 줄의 끝 = 그 작업의 dispatch + 중앙 단계 (실제 끝은 규칙이 모름). **aging 은 없다** (조민규 `aging_ns` 는 그 PC 시뮬 설정 — S26 에 정의 없음).
- R7: EFT, 단 가속기 줄 r 은 "그 작업이 끝날 때의 예측 SKIN (장치 복제 위 한 작업 미리보기) ≥ r 의 첫 조임 문턱 (현재 u 에서) + offset" 이면 제외 — 남은 줄이 전부 기한을 못 지키면 제외하지 않는다. CPU 는 제어기가 없어 제외 대상 아님.
- R7 offset {0, −0.5} 고르기 (개발 seed 1 ~ 10 · 부하 4개 전부): ① 두 가드를 다 지킨 (부하 × seed) 수가 많은 쪽 → ② 최고 AP 평균이 낮은 쪽 → ③ 같으면 0.

## D8. Band → R8 로 옮김

- `BAND_HEFT_WHOLE_REQUEST_ADAPT_V1` (`tools/d1_external_rules.py` @ `7475b18` — 원 코드 출처 표기는 그 파일 머리) 의 결정은 줄 구조에 묶이지 않는다 (FIFO 창 · 작업별 첫 요청 · 최단 예상 지연 중 최대 · 바쁘면 그 줄 대기에 더하고 양보 · 줄 반환 때 EMA 0.1). → **R8 로 추가**. 기대 점유 초기값 = R3 중앙 단계 합. 동시 실행 합법성 = 줄마다 하나 (S26 줄 구조).

## D9. 확인 예측의 점 추정

- 세션마다 같은 시작 상태 · 예정 요청열 · 정책으로 **반복 20회** (seed 1001 ~ 1020 — 지터 · 단계 표본). 판정에 쓰는 예측값 = 각 지표의 **20회 중앙값** (P95 · 최고 AP 는 반복마다 계산한 뒤 중앙). 5 ~ 95 % 폭은 기술.
- 예측 파일에는 반복마다 1 s 경로 (SKIN · AP) 와 서비스 지표를 남긴다 — HAL 표본 시각에서의 값은 판정기가 같은 규칙으로 계산.

## D10. 실측 지표 정의 (4단계 `measure_r4.py` · 판정기)

- 창 = 공통창 [`start_ns`, `end_ns`] (C 120 s · S 720 s). HAL = `host/hal.csv` 의 그 창 안 행 (2 s 표본).
- **AP 최고 오차** = (HAL 표본 시각에서 모형 AP 의 최대) − (HAL AP 최대). **AP 10 s 경로 MAE** = 창 시작 기준 10 s 칸마다 (HAL 표본이 있는 칸만) |모형 AP 평균 − HAL AP 평균| 의 평균 (모형은 같은 표본 시각에서). SKIN 도 같은 방식 · 실측 SKIN 최고 ≥ 38.0 이면 "포화" 표시.
- **(S) SKIN 38 ℃ 도달 시각** = 처음 HAL SKIN ≥ 38.0 인 표본 시각 · 모형은 1 s 경로에서 처음 ≥ 38.0. 어느 쪽이든 없으면 null (기술).
- **긴급 P95** = 예정 긴급 요청 전부 (C 96 · S 1,500) 의 응답 (`output_ready` − `scheduled_arrival`) nearest-rank · 미완료 = +∞.
- **쌍**: 같은 블록 · 같은 `pair` 번호의 직렬 (CPU_URGENT) ↔ 병행 (B2 또는 S26_NPU_PARALLEL), 둘 다 유효일 때만. Δ = 병행 − 직렬. 부호: |Δ| < 0.05 ℃ (HAL 분해능 0.1 의 반) · |Δ| < 0.5 ms 는 0. 부호 일치 = 같은 부호 (0 은 0 끼리만).
- (S) 열 쌍 판정 = 블록 A (S) 4쌍 (등록 §2) · 블록 N (S) 의 남은 쌍은 기술.

## D11. 판정 산술 (등록 §4 글자 그대로의 구현)

- "세션 ≥ 75 %" = 기준 안 세션 수 / 유효 세션 수 ≥ 0.75 (85 % 도 같음). "쌍 부호 일치 ≥ 3/4 (내림)" = 일치 쌍 ≥ floor(0.75 × 쌍 수). "전부" = 모든 쌍.
- 서비스 판정은 확인 1 (R4 (C)) 만. R4 (S) 서비스 지표는 기술 (등록 §2).
- 판정 이름은 M-sup 만. M-κ 는 같은 표에 나란히. κ 가 [0.8, 1.2] 밖이면 "단순 중첩 가정 의심" 기술.

## D12. 열린 고리 기술 열 (프롬프트 3-4)

- "실측 바쁨으로 구동한 열린 고리 예측" 은 R4 실측 요청 타임스탬프가 필요하다 = 결과 자료. → 동결 파일에 넣지 않고 **4단계 판정 뒤** 기술 열로 계산한다 (판정에 안 씀).

## D13. 규칙 사다리 (등록 §5) 세부

- 요청열: R3 와 같은 꼴 (짝수 ordinal = 분류 urgent 기한 1.5 s · 홀수 = 탐지 normal 기한 6 s), 첫 도착 35 s.
  - (a) 192요청 × 간격 400 / 200 / 100 ms · 창 = max(120 s, 35 + 192 × 간격 + 50 s).
  - (b) 3,000요청 × 200 ms · 창 720 s.
- 시작 = SKIN 30.5 · A0 −1.0 · AP0 29.5 · BAT0 = SKIN − d_ref (v2.2 열 두 점 규칙 중 30.5 — 가상 부하).
- seed = 도착 지터 · 단계 표본 난수. 개발 1 ~ 10 = R7 offset 고르기만 · **확인 61 ~ 65 한 번**.
- 가드: ① 기한 내 완료 = 예정 전부 기한 안 (분모 = 예정 전부) ② 긴급 P95 ≤ 1,500 ms (긴급 기한). 둘 다 지켜야 "가드 통과".
- 지표: 최고 AP · 최고 SKIN (0.5 s 경로) · SKIN ≥ 38 ℃ 시간 (s) · 처리율 (완료 수 / (마지막 완료 − 첫 예정 도착), 요청/s) · 긴급 P95 · 에너지 (모형 입력 전력 적분 J — 기술만).
- 판독: 가드 통과 규칙끼리만 열 비교. 차이 (5 seed 평균) 가 선별 문턱 (℃ 1.0 · s 60 · P95 max(5 %, 2·CV)) 아래면 "차이 없음 (선별 문턱 아래)". 문턱 위여도 차이 < 해당 부품의 확인 오차 (열 = 확인 AP 경로 MAE 중앙 중 큰 쪽 · 서비스 = 확인 1 긴급 P95 |오차| 중앙) 이면 **"모형 오차 안 — 우열 미판정"**. R5 ~ R8 은 "외삽" 꼬리표.
