## 1단계 — 입력 설계 구현·정적 검증 완료

`experiments/competition_cost_20261017/competition_design.cjs`에서 48요청×분류비율25/50/75%×두 도착 패턴×두 참조부하의12조건을 만든다. 개발/확인용 입력seed를 별도 고정해 총24목록을 저장했다. 모든 작업에 긴급/일반을 배치하고, 요청별 납기 여유를 독립적으로 다양화한다. 작은 시차의 파형과 묶음 뒤 회복 간격을 함께 사용해 항상 두 자원이 포화되는 것만을 목표로 삼지 않는다.

각 요청은 실제 지원 C_M128/D_M128 프로필과 CPU/GPU 선택 범위를 유지한다. 기한은 기존 C2.2/D5초 참조의0.32/0.65/1배, 긴급0.7배이며, 무부하 공개 보수 점유 참조의1.25배보다 길도록 검사한다. 이 검사는 실제 납기 실현 가능성이나 SLA 인증이 아니다. 참조부하 역시 실제 두 자원 사용률 측정값이 아니다.

순수80 assertions를 통과했다. 시드 재현성·작업별 우선순위 교차·절대기한 순서 역전·인접 도착의 서로 다른 기한·관측창·기본 유효성을 검사했다. **정적 입력 특성 PASS와 실제 큐 경쟁/정책 차이 PASS는 구분한다.** EDF/RL 결과를 보고 조건을 고르거나 불리한 조건을 삭제하지 않는다.

- 입력/정적 검사: `results/COMPETITION_INPUTS_20261017_01/INPUTS.json`, `STATIC_TESTS.json`, `COMPLETE_STATIC.json`.
- 등록할 고정 증명용 조건: 확인seed의 index0/3/5/10, EDF와 고정 EP024 RL 각1회씩 총8 START. 이는 넓은24조건의 성능 입증이 아닌 입력 변화 진단이다. 기존 공유502/512의 잔10 안에서 최대510, 새 글로벌 예약0이다.
- 실행은 별도 소스/operation을 봉인하고 실제 own worker 슬롯·8GiB·공유 원장·lock을 확인한 뒤 한 번만 한다. 현재 입력 생성은 실제 환경0·새학습0이다.

## 2단계 — 기존 센서/단계 비용 근거 조사·구현 진행 중

현재 전류/charge 단위 미식별과 역사 J* 경계를 유지한다. 기존 자료에서 시각·자료형·부호·갱신·결측·idle/활동 구분을 검산하고, 식별 가능한 상태/병행/처리 단계 비용 항목을 추가한다. 미측정 wake/전환 비용이나 온도 계수를 임의로 만들지 않는다. 이번 범위는 앞서 합의한 비용 모형 보완이며 온도→처리속도/전력 피드백과 RL 재학습은 별도 단계다.

고정 역사 J*와 새 자료 기반 비용 추정은 구분하고, 같은 trace에서의 진단과 새로운 일정 평가를 나눈다. 새 모형은 세션 단위 검증과 지원 범위/불확실성을 보고한 뒤 채택 여부를 판단한다. 현재는 새 비용 모형 적합/검증 완료를 주장하지 않는다.

실행 중인 S26 owner를 중복 시작·중단하지 않는다. Python/전체 ZIP/무거운 적합은 own 슬롯이 빈 뒤 진행하고, 대기 중에는 입력 소스·경량 검사·문서를 준비한다. 최신 상태는 CONTINUE.json과 이 문서의 이후 완료 절을 따른다.
