# A24와 S26의 일반 납기 70퍼센트 조건에서 열과 에너지를 줄이는 탐색 계획

2026-10-14. 작업 ID는 `D1-SLO70-EXPLORATION`이며 현재 상태는 `PLAN_ONLY`다. 일반 요청의 기한 내 성공률이 70% 이상인 조건에서 총에너지와 시간평균 AP가 함께 감소하는 정책과 물리 조건을 찾는다. 사용자 마지막 수정에 따라 긴급 요청에는 이번 탐색의 별도 성공률 하한을 추가하지 않고 성공률과 지각을 모두 보고한다. 현재 문서는 설계안이며 구현·물리 적합·환경 실행·강화학습·예약은 각각 0회다.

실측은 처리시간·전력·열·초기 상태의 기준점으로 사용한다. 미측정 효과는 기기별 가정과 범위로 표현한다. 한 조합에서 큰 차이가 난다는 결과와 여러 가정에서도 개선이 유지된다는 결과를 구분한다. 결과물은 조건별 개선 지도와 후속 학습 영역이며 특정 휴대폰의 효과를 미리 정답으로 두지 않는다.

## 서비스와 비용의 판정

일반 성공률은 `기한까지 응답을 완료한 일반 요청 수 / 도착한 일반 요청 전체 수`다. 기한은 도착부터 계산하며 대기 중에도 진행한다. 늦은 완료·미완료·실행 실패를 분모에서 빼지 않는다. 일반 요청의 응답 끝점은 기존 PERSISTED, 긴급은 OUTPUT_READY를 따른다. 구현 시 기존 five-phase 원장과 끝점을 직접 대조한다.

요청 16개 중 70%는 최소 12개, 32개 중 70%는 최소 23개가 성공해야 한다. 정수 건수로 판정하고 화면에 반올림한 비율로 통과시키지 않는다. 긴급/일반 두 비율을 합쳐 일반 손해를 숨기지 않는다.

새 연구 계약의 주 납기는 기존 이 채팅의 기기별 설계를 유지하는 안으로 둔다. A24 긴급 2.20초·일반 5.00초, S26 긴급 0.80초·일반 2.00초다. 이번 일반 70% 조건은 성공률 조건이며 납기 시간을 결과에 맞춰 늘리는 절차가 아니다. 원 1.5/6초 판정과 기존 strict FAIL은 별도 legacy로 보존한다. 33번의 tight/standard/wide 납기와 자동으로 혼합하지 않는다.

주 비용은 전체 소비 J0~120초와 정확한 시간평균 AP35~180초다. 같은 초기 상태·도착·작업·환경 실현에서 ATC와 비교한다. 일반 납기를 놓쳐도 모든 작업을 실행하며 요청과 units가 120초 안에 전량 완료된 실행만 동일 작업량의 절감을 주장한다. 미완료 실행은 관측 소비와 완료량을 보고하고 동일 작업량 J/AP는 null로 둔다.

탐색 후보는 일반 성공률 70% 이상, 전량 완료, `평균 ΔJ120 < 0` 및 `평균 ΔAP35~180 < 0`을 함께 충족해야 한다. J180이 ATC보다 늘면 창 밖으로 비용이 이동한 상충으로 표시하고 공동 절감의 우선 후보에서 제외한다. ATC가 70% 미달이고 후보가 통과하면 서비스 개선과 비용을 별도로 설명한다. 둘 다 70%를 넘더라도 성공률이 떨어진 절감은 서비스와 비용의 상충으로 표시한다.

긴급 성공률·일반 성공률 변화, 응답 P95, 최고 AP와 고온 지속시간은 모두 공개한다. 기한 안 응답시간이나 P95 증가 자체를 벌점·탈락 조건으로 쓰지 않는다. 평균 AP만 낮고 최고 AP가 높은 후보는 그 손해를 표시하며 최고 AP까지 비악화한 후보를 우선 검토한다. 이번 계획에서 미측정 AP 값을 휴대폰 안전 온도로 확정하지 않는다.

## 실측과 가정을 연결하는 모형

모형은 세 층으로 구성한다. M0는 동결된 실측 기반 모형의 재현 대조다. M1은 같은 서비스 분포와 측정 전력·열을 기준으로 구성한 전력과 열의 연결 모형이다. M2는 M1의 미측정 계수를 여러 값으로 바꾼 탐색 집합이다. M0와 M1의 차이를 먼저 공개해 모형 변경 효과가 스케줄링 개선에 섞이지 않게 한다.

M1의 미측정 계수는 기존 원장에 따른 재생 오차와 합리적 경계로 정한다. 정책 격차나 PPO 승률로 물리 계수를 선정하지 않는다. 자료가 식별하지 못하는 자원별 성분은 하나의 최적값으로 확정하지 않고, 전체 측정 전력과 양립하는 여러 양수 분해를 유지한다. GPU/NPU의 적합 계수 0을 실제 무전력으로 해석하지 않는다.

### 실행시간과 전력

ASSIGNED부터 AVAILABLE까지 기존 다섯 단계를 유지한다. EXECUTING 단계의 남은 일량을 시간에 따라 적분하며 온도 변화가 실행 중 속도에 반영되게 한다. 선점·작업 이동은 하지 않는다. OUTPUT_READY 뒤의 저장·해제 점유도 소비와 자원 사용에 남긴다.

상대 실행속도는 `r(T)=clip(1-k*max(T_hot-T_on,0), r_min, 1)`로 제안한다. 실측 기준의 일량을 r에 따라 처리하고 병행 간섭이 있으면 속도를 추가로 줄인다. 아래 +10℃의 속도로 k를 정하며 하한 r_min은 A24 .50/S26 .60으로 제안한다. 이때 전력도 다음 식의 여러 가정으로 비교한다.

`P_exec(r,T)=P_static + P_dynamic*r^n + P_leak_ref*exp(eta*(T_hot-T_ref))`.

기준 속도 r=1과 기준 온도에서 세 성분의 합이 측정 기준 전력과 맞아야 한다. r은 OS가 자동으로 낮춘 성능의 대리값이며 PPO가 주파수를 직접 제어하는 행동은 아니다. n=0은 감속 시 실행 W 고정, n=1은 속도에 비례한 동적 전력, n=3은 더 강한 전력 감소를 가정한다. 같은 감속에서 소비가 늘어나는 경우와 줄어드는 경우를 모두 포함한다.

전체 전력은 resident 기저·현재 실행/후처리·공유 자원·병행 잔차·활성화 꼬리로 나눈다. 기존 모형에 이미 들어 있는 병행·꼬리 성분은 추가항과 중복해서 세지 않는다. 단계별 계수가 없으면 해당 성분을 가정으로 표시한다. 과도한 음의 잔차로 총전력이 음수가 되는 조합은 물리적으로 부적합한 입력으로 남긴다.

### 열과 냉각

빠른 내부 열 상태와 느린 표면 열 상태를 분리한 수동 RC 모형을 제안한다. 같은 전력과 시동·전환 에너지를 열 입력으로 쓰고 두 열 상태 사이 및 외부로의 방출을 계산한다. 구현 선택은 에너지 수지가 성립하는 두 절점 형태를 우선한다.

`C_hot*dT_hot/dt = eta_h*P - (T_hot-T_skin)/R_hs`.

`C_skin*dT_skin/dt = (1-eta_h)*P + (T_hot-T_skin)/R_hs - (T_skin-T_boundary)/R_sa`.

전체 저장열 변화와 외부 방출열의 합이 투입 에너지와 같아야 한다. AP 관측은 실측 추세에 맞춘 열 상태의 관측 함수이고 AP를 칩 접합 온도와 동일시하지 않는다. 기준 경계 온도와 초기 열 상태도 측정된 항목과 가정한 항목을 구분한다. 두 기기의 RC·초기값·AP 관측식은 각각 구성한다.

냉각 WAIT에서도 resident 기저와 활성화 꼬리 전력은 유지한다. 기다린다고 전력을 0으로 만들지 않는다. 초기에는 냉각이 빨라도 이후 느리게 식는 경우를 두 열 상태로 표현한다.

열 상태가 성능을 제한할 수 있다는 질적 근거는 [Android Thermal API 문서](https://developer.android.com/games/optimize/adpf/thermal)를 따른다. 아래 수치는 이 문서가 제공한 A24/S26 실측 계수가 아니라 이번 탐색의 공학적 가정이다.

## 기기별 탐색 범위 초안

아래 범위는 구현 전 확정할 제안값이다. 기준점의 추정값과 불확실성이 확보되면 절대값보다 상대 배율을 우선한다. 가정마다 근거 등급을 측정·기존 자료 추정·문헌의 구조·탐색 가정으로 표시한다. 범위 밖의 결과를 얻으려고 실행 중 계수를 넓히지 않는다.

| 축 | A24 제안 | S26 제안 | 비교할 효과 |
|---|---|---|---|
| 감속 시작 | 기준 내부 열 상태 위 +2/+4/+6℃ | 기준 내부 열 상태 위 +3/+5/+7℃ | 같은 부하에서 열 제한이 빨리/늦게 시작 |
| 감속 강도 | 시작점 +10℃에서 상대속도 .90/.75/.50 | 시작점 +10℃에서 .90/.80/.60 | 약/중/강 감속; backend별 민감도 별도 |
| 감속 때 전력 | n=0/1/3, 동적 비중 .4~.9 | n=0/1/3, 동적 비중 .4~.9 | W 고정과 전력 감소의 상충 |
| 경로 전력 불확실성 | 측정 기준 성분의 .8~1.2배 | 전체 측정과 양립하는 성분의 .6~1.4배 | 빠른 경로와 효율적인 경로가 다른 조건 |
| 병행 실행 감속 | 단독 대비 0/15/30% 시간 증가 | 0/10/25% 시간 증가 | 자원 공유에 따른 처리율 손해 |
| 병행 전력 잔차 | 기준 병행 전력 대비 -10/0/+20% | -10/0/+25% | 공유 절감과 추가 전력 모두 탐색 |
| 냉각 속도 | 기기별 기준 시정수의 .5/1/2배 | 자체 기준 시정수의 .5/1/2배 | 빠른/기준/느린 냉각 |
| 냉각 WAIT | 0/100/500ms, 누적 최대 5초 | 0/50/250ms, 누적 최대 3초 | 짧은 대기와 긴 대기의 순이득 |

누설 전력의 온도 민감도 0/.02/.04 per ℃와 냉간/따뜻한 초기 상태는 결합 탐색 및 확인에서 추가 민감도로 둔다. 이 숫자는 신뢰구간이나 폰의 추정값이 아니다. 자원별 분해가 없는 경우 전체 전력과 양립하는 후보 분해를 먼저 만들고, 예측 0인 GPU/NPU 성분을 단순히 배율로 곱하지 않는다.

A24는 분류 CPU/GPU·탐지 CPU, S26은 분류 CPU/GPU/NPU·탐지 CPU를 유지한다. 분류 두 건의 동시 실행과 3건 병행은 추가하지 않는다. 같은 기기·조건의 모든 정책은 같은 물리 계수와 지원 마스크를 사용한다.

## WAIT와 비교 정책

첫 비교군은 EDD·ATC·FIFO_READY·RR_READY·Greedy_READY·SPT·ENERGY_EDD·THERMAL_EDD의 8개다. RR_READY는 time quantum 없는 비선점 자원 순환 규칙이다. 마지막 두 규칙은 현재 합법 경로의 국소 에너지/열 대리값을 사용하는 기존 단순 비용 비교군이며 전체 미래 일정을 최적화하지 않는다.

기본 8개는 non-delay로 비교한다. 추가 2개는 같은 ATC에 짧은 WAIT 또는 긴 WAIT를 붙인 대조다. 기기별 두 WAIT quantum은 위 표의 값을 사용한다. 초기 기준점에서는 뜨거울 때, 이미 대기 중인 긴급 요청이 없을 때, 현재 일반 요청들의 예상 여유가 대기 길이와 추정 오차 여유보다 클 때만 WAIT를 허용한다. CPU를 포함한 실제 owner가 존재하면 그 점유를 유지한다.

새 도착·자원 해제·관측 갱신이 먼저 오면 WAIT를 끊고 현재 상태에서 재판단한다. 누적 한도는 요청한 대기 길이가 아니라 실제 경과시간으로 센다. 이 여유 필터는 기한 보장이 아니다. 진짜 미래 도착·실현 처리시간·사후 ATC 정답은 입력에 쓰지 않는다. 미측정 물리의 실제 내부 열 상태와 참 계수는 엔진에만 있고, 정책은 지연된 AP/전력 관측과 사전에 보정한 추정계수를 쓴다. 비용 규칙에도 참 미래나 정확한 비공개 계수를 주지 않는다.

WAIT가 있는 정책과 기본 non-delay 정책의 차이는 순서뿐 아니라 행동 공간 차이다. 따라서 주 비교와 별도로 ATC 대 ATC+WAIT의 효과를 보고한다. 후속 PPO를 학습하면 PPO non-delay와 PPO WAIT도 같은 가드에서 따로 비교한다. 이전 가중치를 새로운 행동 ABI에 그대로 넣지 않는다.

## 부하와 반복

주 탐색은 측정과 대응하기 쉬운 work_units=1·64요청·분류32/탐지32로 제안한다. 정상 steady 상대부하 .60, 경계 steady .95, 경계 burst .95, 높은 burst 1.20의 네 요청 조건을 사용한다. burst는 최대 8개 묶음이며 전체 도착 수와 같은 평균 명목부하를 맞춘다. 요청은35초부터 도착한다.

상대부하의 기준 용량은 분류를 지원 가속기, 탐지를 CPU에 고정 배정했을 때의 측정 명목 AVAILABLE 점유로 미리 계산한다. A24/S26의 도착 간격을 각각 정하며 같다고 해서 실제 이용률·기한 난이도가 같은 것으로 해석하지 않는다. 실제 큐 길이·선택 기회·자원 점유·병행·감속 발생 비율을 따로 측정한다.

확인에서는 새로운 도착 난수·초기 열 상태와 분류 비율 25/50/75%의 사전 등록된 조건 묶음을 사용한다. 후보 영역마다 네 묶음을 고정하며 중심 물리값의 두 묶음과 인접 물리값의 두 묶음으로 구성한다. 모든 묶음에 새 도착·환경seed를 사용한다. 작업량 배율은 이번 주 탐색에 넣지 않는다. 후속 장시간이나 units 확대는 별도 가정 대조로 남긴다. 비용 개선이 단일 낮은 부하나 하나의 작업 비율에만 나타나는지 공개한다.

같은 조건의 정책들에는 요청별/지원 경로별 같은 난수 quantile을 대응시킨다. 순서가 바뀌었다는 이유만으로 임의의 새로운 환경 샘플을 주지 않는다. 처리시간 pool·계수·입력·code·정책을 선정/확인 전에 SHA로 동결한다. 새로운 arrival 반복은 새로운 기기 측정자료가 아니다.

확인 후보 영역은 발견 결과에서 기기별 최대3개를 고른 뒤 고정한다. 공동 절감, 개선 크기, 불리한 조건에서의 성공률과 비용 손해를 함께 보고한다. 확인을 보고 다른 납기·계수·정책으로 다시 고르지 않는다. 후보가 없으면 확인을 강제로 진행하지 않고 공동 개선 영역 미확보로 종료한다. 후보가 적으면 실제 소비를 줄이고 미실행 계획을 남긴다.

확인에서는 각 후보 영역의 모든 새 조건묶음과 각 환경seed에서 일반 성공률이70% 이상인지 확인한다. 평균만70%를 넘으면 불안정한 경계 영역으로 표시한다. J/AP 변화는 같은 seed의 대응 차이를 집계하고 seed·조건묶음을 단위로 불확실성 구간을 계산한다. 요청 개수를 독립 실험 반복 수로 세지 않는다. 두 비용의 공동 감소가 확인에서 유지되는지와 온도/전력 가정의 인접 변형에서도 유지되는지를 함께 표시한다.

현재 호스트와 저장장치의 실제 처리량은 새 구현의 pilot로 측정하고 그 후 전체 wall/단계 예산을 등록한다. M1의 기준 모형 적합은 기기별 최대32후보·총64후보의 개발자료 판독으로 제안하며 환경 실행과 별도로 센다. 동시 환경 worker는 최대2로 제안하며 다른 채팅과 자원을 공유한다. checkpoint와 로그를 무수한 작은 파일로 저장했던 지연을 반복하지 않도록 원자료를 압축 묶음으로 저장하되 환경별 identity·SHA·실패·완료 경계를 복구할 수 있게 한다. 기존 PID·lock·자료를 건드리거나 기존 clock을 연장하지 않는다.
