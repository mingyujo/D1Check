# 스케줄링 선택에 반응하는 모바일 시뮬레이터 확장

2026-10-12 · D1-SCHED-DYNAMICS-17 · 구현 준비 단계

사용자 승인: 전문가를 구성하고 정책별 차이가 발생하는 모바일 환경으로 시뮬레이터를 발전시킨다. 모바일 시스템·산업공학·RL 전문가가 서로 분리한 소스에서 구현하고, root가 계약·소비·선정·최종 검증을 관리한다. 현재 동시 작업 ATC-LOAD-HEADROOM-16의 고정 A24 모형 부하 확대와 구분하며 그 원본·진행·원장을 수정하지 않는다.

## 목표와 근거 경계

목표는 같은 작업량의 순서·자원·병행 선택에 따라 이후 실행속도·에너지·온도·대기열이 달라지는 환경을 표현하는 것이다. 특정 정책의 개선 폭이나 PPO 우위를 보장하지 않는다. 기존의 여유 부하·동률·불리한 조건도 전량 보고한다.

기존 A24/S26 측정의 5단계 처리시간과 동결 J/AP 모형을 기기별 앵커로 사용한다. 온도에 따른 실행속도, 추가 병행 간섭·전력, 자원 활성화 비용은 아직 독립 측정으로 확인하지 못한 **탐색 가정**이다. 새 프로필은 hypothesis_only, strict_eligible=false, experiment_ready=false로 고정한다. A24 계수를 S26에 복사하지 않는다. S26의 외부 독립 전력/전하 장비는 담당자 보고상 이번에도 없으며, 내부 센서 J의 교차검사·별도 확인과 외부 기준 정확도를 구분한다.

출발 근거: `S26_PAIR_OBSERVER_RESULTS_20261012.md`, `S26_INTEGRATED_SIM_20261012.md`, `COMMON_DEADLINE_COMPARE_20261011.md`, `outputs/ATC_POLICY_SELECTION_20261012.md`. 모바일 열 상태가 성능을 제한한다는 일반 근거는 [Android Thermal API](https://developer.android.com/games/optimize/adpf/thermal)다. 문서의 일반 현상을 S26/A24의 실제 감속률이나 APK의 지원 사실로 전용하지 않는다.

## 실행 계약과 환경

- A24: 분류 CPU/GPU, 탐지 CPU, CG_DC만 최대2건. S26: 분류 CPU/GPU/NPU, 탐지 CPU, CG_DC/CN_DC만 최대2건.
- 비선점·동일 요청 중복 금지·실제 AVAILABLE까지 점유·긴급 OUTPUT_READY/일반 PERSISTED 응답과 자원 종료 분리.
- 선점, 자원 이동, 임의 냉각 대기, 탐지 GPU/NPU, 3건 병행, 새 APK/기기/외부전송0.
- 서비스120초, 자원이 실제 반환된 조건에서180초까지의 온도를 기록한다. 미완료는 전체 도착 분모에 남기고 같은 완료량 J/AP는 null 처리한다.
- 환경만 실제 work와 향후 사건을 보유한다. 정책은 도착한 미시작 요청·현재 owner/phase·현재 온도·관측 이력·개발 평균의 현재상태 추정치만 받는다. 전체 큐 미래 시뮬레이션이나 oracle 입력은 없다.

환경은 50ms 이하 구간에서 현재상태에 따른 처리율을 적분하고 단계 완료 경계를 처리한다. 현재 온도/최근 점유/동시 owner에 따른 속도 저하를 적용하며, 속도·추가 전력·활성 비용을 각각 제거한 ablation으로 효과를 분리한다. 25ms의 짧은 합성 궤적과 비교해 수치 수렴을 검사한다. 이를 휴대폰의 실제 타이머·선점 단위로 해석하지 않는다.

neutral은 새 엔진에서 속도 반응·추가 비용이0인 기준이다. 원 시뮬레이터와 동일하다고 부르려면 같은 원장의 별도 exact 검사가 필요하다. mild/full 및 thermal-only/parallel-only/activation-only는 수치·단위·상한·출처를 평가 전에 고정한다. 온도 기준값은 초기화 reference이지 실내온도 실측이 아니다.

`work_units=1..3`은 공개 작업량 입력으로 실행 단계만 배수 적용하는 가정이다. 배치 효율이나 실제 APK의 분할 추론을 측정한 것이 아니다. 모든 정책은 같은 입력과 작업량을 완료해야 하며 이 분모를 요청 수와 함께 보고한다.

## 후보·규칙·PPO

전체 도착·미시작 큐≤64, 조용한 절단0. 각 요청의 지원 route single 행동≤192+WAIT1=193. 현재 같은 시각에 재판단하며 합법적 병행을 채운다. 실행 가능한 행동이 있으면 WAIT를 operational mask에서 제외하고, 물리 마스크와 운영 규칙을 구분한다.

상태1455=요청64×22+자원3×9+global20, 행동193슬롯×32피처. global에 현재 지연된 전력·공개 이력으로 계산한 자원 활성 기억·과거 온도/전력 변화율을 포함한다. 차원은 코드 ABI에서 검산한다. oldweights·기존Adam 재사용0. padding은0피처/false mask, 실제 큐 상한 초과는 명시적 오류다.

규칙은 FIFO_READY/SPT/EDD/ATC/RR/GREEDY_READY_V17이며 Band/Triton은 새 비교에 포함하지 않는다. GREEDY_READY_V17은 고정 affinity가 막히면 현재 legal 대체 route를 쓰는 새 변형으로, 기존 resource-affinity WAIT 규칙과 동형이라고 부르지 않는다. ATC는 현재 추정 대표 경로의 점유 p/응답 r를 구분하고 w=긴급2/일반1·k2를 정책값으로 사용한다. 실제 지연 가격으로 해석하지 않는다.

PPO는 fresh3seed, 기존 native clipped surrogate·episode 균등 가중·Adam·RNG 저장 수학을 새 ABI에 재사용한다. 학습은 masked stochastic, 최종은 masked argmax다. 실제 업데이트·actor gradient/변경·부분 경험/optimizer/RNG 복원·모델 오류0을 확인한다. 단일 critic·gamma1·8episode/update·epoch4를 출발점으로 한다.

보상은 기존 원/선언 납기·응답·미완료 서비스 비용10배를 우선하고, 증분 J/10J 및 AP 초과온도 면적/(120℃s)를 보조로 넣는다. 가중치는 연구 선호값이며 물리/금전 가격이 아니다. 고정창 기본 소비를 보상에서 구분하되 평가에는 전체 J와 기본/증분/추가 J를 모두 보고한다. 사후 결과·온도 궤적은 학습 label에서만 사용하며 actor 입력·mask에는 주지 않는다. 개발 선정은 서비스 축부터 비교하여 덜 실행한 절감을 인정하지 않는다.

## 데이터·계산 예산·종료

여유/일정/버스트/작업량 혼합의4가족, 원1.5/6초와 변동 선언 납기를 분리한다. A24/S26의 공개 개발 평균으로 도착 활동창을 정규화하되 같은 기기·조건의 모든 정책에는 같은 예정 도착·작업·납기·잠재 work 난수를 제공한다. 작업량과 납기 label은 독립 hash다. 처리용량 근처와 여유 영역을 모두 포함한다.

train/dev/final은 도착·환경 난수 영역을 분리한다. action/shuffle RNG도 별도다. 최종 입력·프로필·소스·평가 기준을 실행 전에 동결하고 개발128/256 중 checkpoint와 대표를 최종 자료를 읽기 전에 선정한다. 확인 뒤 파라미터·PPO·대표·좋은 영역을 재선정하지 않는다.

초기 계획은 fresh3seed(1171/1181/1193)×128episode, 실제 개발 서비스/비용 개선 기회와 actor 안정성에 따라 최대256episode/seed다. 개발96조건×6규칙=576, 단계별96×3PPO=288(최대2단계), 최종96×9군=864, 단일 요인48×4군=192로 최대2,976환경·768학습이다. 상한3,100환경/7,200초·최종저장1,800초 reserve를 `registration.json`에 고정하고 시작부터 영수증에 기록한다. 남은 슬롯은 실제 추가 검증에만 영수증과 함께 사용한다. 그 등록 전 실제 학습·비교 환경0이다. 합성 solver/마스크/수학 검사는 물리 자료 적합이나 새 정책 환경과 별도 계수한다. 기기·APK·독립 외부 계측·기존 프로젝트 소비를0으로 덮어쓰지 않는다.

보고는 모든 seed/기기/부하/프로필에서 완료·작업량·원/선언 납기 위반·P95·총J/증분J·AP 시간평균35~180/peak·ATC 대비 조건별 손해·행동/배정/병행 차이·판단시간을 포함한다. PC 시간/전력을 휴대폰 시간/J로 바꾸지 않는다. neutral/mild/full의 차이와 ablation으로 환경 효과를 분리하고, 규칙 대비 PPO 효과는 같은 환경 안에서만 비교한다.

확장이 원모형보다 정책 차이를 크게 만들더라도 실제 기기 절감 검증은 아니다. 자료로 확인하지 못한 감속·간섭·전환 식과 같은 APK의 전량 완료 대응 측정이 남는 요청이다. 초기열과 gauge 관련 기존 요청을 이어가며 외부 장비 구매를 조건으로 요구하지 않는다.
