# 동적 스케줄링 환경 구현·비교

현재 상태에 따라 이후 처리속도·비용이 달라지는 별도 시뮬레이터를 구현했다. A24/S26의 시간·비용 앵커는 기기별로 보존하고, 열/부하 감속·추가 병행 비용·자원 활성화 비용은 탐색 가정으로 추가했다. 여유/일정/버스트/작업량 혼합, neutral/mild/full 전영역과 모든 모델을 비교했다.

새 상태1455·행동193×32, 현재 관측AP2초/전력.9초, 사건마다 전체 도착·미시작 큐를 다시 판단한다. 실제 AVAILABLE까지 점유하며 추론 중 선점은 추가하지 않았다. 새PPO3seed는 가중치·Adam·난수를 처음부터 생성하고 실제native PPO로 학습했다.

## 재현·표기 한계

새계수와수정된환경은 hypothesis_only이며 실제폰절감/외부전력정확도가아니다. 실제새도착과기존측정원장의재생을구분한다. 원17의부드러운프로필보다선택상충을넓힌별도18, 동시도착19는사용자추가지시에따른시연탐색이다.

독립전량물리마스크·owner·response·완료량·원/선언납기·비용산술과동결SHA를검산한다. root의raw sensor_age_s는키불일치로null이며관측지연동적전수재현을주장하지않는다. 전체NN입력/보상배열은persist하지않아전수forward/target독립재현은불가하다. 59부분체크포인트·실제native/Adam/RNG복원과source/pure검사로범위를한정한다. 최종별도CLI표본에서인과입력을보완검증한다.

raw의policy_cost_learning=False는기존형식표기다. 실제학습은phase=TRAIN/원장training/native·Adam로그로집계한다. 학습proxy열은0~120초초과온도면적이며최종AP35~180과다르다. 개발weighted선정은조건별서비스보장을뜻하지않으므로모든seed·조건손해·기한실패를그대로표시한다.

기존모형·weights·원판정·동시A24실험은보존했다. 실행코드와재현사용법은최종bundle README에있다.
