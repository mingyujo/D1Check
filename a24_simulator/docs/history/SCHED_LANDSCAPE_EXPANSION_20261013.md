# 스케줄링 격차 추가 확대

직전 환경의 총 에너지 격차가 약1~2%에 머물러, 정책 선택의 비용 상충을 더 넓힌 별도 탐색 환경을 구현한다. 기존 결과는 보존한다. 목적은 서로 다른 스케줄링의 결과를 관찰하는 것이며 추가 계수는 시연 가정이다.

새로운 실행 전력은 실제 EXECUTING 단계 동안 자원별로 CPU8W/GPU1W/NPU.4W를 더한다. 추가 에너지는 W×초로 적분하며 같은 전력이 추가 열의 입력이다. 열 반응은 이득3℃/W·시간상수20초, CPU 최근 부하 감속 계수2, 최대 감속4배다. CPU 작업 종류 전환 비용은 .15초/.8J다. 기존 활성화·병행·tail도 유지한다.

긴 CPU 탐지 작업만으로 모든 정책이 미완료가 되는 것을 줄이기 위해 새 환경의 탐지 실행 구간은 기존 neutral의 .35배로 복사한다. 분류 시간은 기존 strong의 값이다. 이는 가상 작업량 수정이며 원측정과 구분한다. 초기 온도·기저 전력·기존 비용 앵커는 그대로 두며 정책 이름에 따른 환경 보정은 없다.

current_neutral/current_strong/execution_tradeoff 3수준을 비교한다. 기기2×분류 비중2(32/64,48/64)×도착2(steady,16건 burst)×기한2×도착 난수2=32요청열을 각 수준에 동일하게 적용한다. 요청당 공개 작업량1~3, 도착35~95초, 서비스 관찰120초와 전량 AVAILABLE 후 냉각180초다. 원1.5/6초 기한과 개별 선언 기한을 따로 집계한다.

비교군은 FIFO_READY/SPT/EDD/ATC/RR_READY/GREEDY_READY_V17/PPO_TRANSFER다. 동일1455/193×32 상태·행동과 물리 마스크를 공유한다. PPO는 기존17의 개발 선정1171@128을 고정 전이하며 추가 학습0이다. 새 전력 계수를 학습하거나 자원별 비용을 사전에 알고 있는 PPO로 해석하지 않는다. 미래 요청·실현 처리시간·미래 비용을 입력하지 않는다.

총672환경을 A24 전체336/S26 도착 난수별168×2의 독립 PC worker로 나눈다. 각 worker는 Torch1스레드와1,800초 예산을 갖고, 서로 다른 환경만 실행한다. 판단 PC 시간은 동시 worker 영향을 받으므로 이전 단일 worker나 휴대폰 비용과 직접 비교하지 않는다. 기존17~19의 소스·ZIP·가중치·원자료와 다른 진행 변경은 보존한다.

모든 조건의 완료량·미완료·원/선언 기한·총J·증분J·AP 평균/peak·자원 배정·판단 비용을 보고한다. 같은 작업량 J/AP는 미완료일 때null로 둔다. 에너지 격차의 평균/최대와 최소 정책 에너지 대비 비율을 함께 표시하며, 전량 완료 조건 수와 전체 분모를 보존한다. 큰 격차가 특정 환경 또는 추가 비용 항에서 생겼는지도 분해한다. 환경 격차와 PPO 우위는 따로 판단한다.
