## 1. 실제 구현과 실패에서 출발한다

- 원 `IE_ENERGY_AP_LIST_V2`는 `tools/d1_ie_candidates_v2.py`의 `list_pick()`이다. EDD 앞8요청의 단건/병행/대기를 **전체 현재 큐의 EDD 후속예측**으로 비교한다. 단순 작업 리스트만 읽는 정책이 아니다. 이번 새 정책은 그 후속예측 경로를 재사용하지 않고 원정책을 별도 비교군으로 보존한다.
- 기존109/68·32슬롯 PPO/DDQN은 실제 지원 행동의 마스크를 사용했고, v2에서는 영구 BASE 가산점도 제거했다. 따라서 마스킹/가산점 제거 자체를 새 기여로 주장하지 않는다. v2의64episode/3seed는 성능 적격성을 통과하지 못했지만 수렴 완료/강화학습 일반의 실패는 아니다.

- 기존 성공3조건의 원장을 읽어 과업 내 FIFO와192/192 완료를 확인했다([원장 확인](results/list_candidate_rl_design_01/prior_list_inventory.json)). 원본에는 판단 의도가 없어 자발적 대기와 자원 반환 대기를 구분할 수 없다. 두head 축약의 일부 근거이며 새 후보로 같은 일정을 재현했다는 증거는 아니다.
- 종단 AP를 강제한 최신 정책은 개발24조건 모두 Band와 같아졌다. 새 설계는 예측 AP/J 비악화나 종단 조건으로 선택을 모두 지우지 않는다. 원식 g=0이며 h를 새로운 부하별 잔열 특징으로 추가하지 않는다. T의 열 관성과 기존 초기화는 유지한다.

## 2. 역할과 산업공학 대응

```mermaid
flowchart LR
    Q[도착한 요청과 공개 점유] --> L[작업별 FIFO 리스트·납기·여유·호환성]
    L --> C[단건·병행·유한 지연의 실제 후보]
    C --> P[Masked PPO 재정렬]
    L --> H[서비스 우선 리스트 L0]
    H --> F[동률·관측불가 시 복귀]
    P --> X[원 실행 ABI와 실제 용량 재검사]
    F --> X
    X --> K[전체 요청·AP·J·응답 평가]
```

같은 작업의 입력/출력·서비스 예측·기한offset이 현재 조건에서 같다는 제한을 활용해 **가장 먼저 도착한 분류 C_head와 탐지 D_head**를 대표로 삼는다. 뒤의 요청은 큐에 그대로 보존한다. 동일 과업 FIFO는 이번 모델의 범위 제한이며 서로 다른 입력/기한/품질의 일반 최적성을 주장하지 않는다.

EDD·응답여유(`기한−현재시각−예상응답`)·전체 lane 완료 ECT·단일자원 작업의 유연성을 후보 설명과 선택 특징에 넣는다. SPT/EDD 등 이름만 다른 규칙이 같은 첫 실행을 만들면 합친다. RL은 규칙 이름 자체가 아니라 **서로 다른 실제 실행·지연 효과**를 선택한다.

기본/복귀 `LIST_SERVICE_FIRST_PC_V3`(L0)은 현재 실제 실행 가능한 head 중 EDD 순으로 고르고, 현재 빈 지원 자원 중 예상5단계 lane 완료가 가장 빠른 자원을 고른다. 동점CPU·도착/ordinal/ID를 고정한다. 탐지와 분류GPU가 동시에 지원될 때 즉시 병행은 한 원자 후보로 표현한다. 선두 작업이 물리적으로 막혔으면 실행 가능한 다른 head를 보며, 아무것도 가능하지 않을 때만 공개 사건을 기다린다. L0는 기존 EDD+ECT/V2 리스트와 다른 새 제한적 리스트 ID다.

## 3. 행동은 작고 실제로 달라야 한다

분류CPU/GPU·탐지CPU·CG_DC만 허용하며 최대2건, 비선점·실제5단계 lane 반환을 유지한다. CPU주파수/전력제한/NPU/모델교체/요청삭제는 없다. 10종 템플릿 중 한 시점의 최대8실행 후보를8슬롯에 넣는다. 두head와 유한credit에 제한된 공간이지 물리적으로 가능한 모든 일정은 아니다.

| 후보 | 의미 |
|---|---|
| `C_CPU_NOW` | 현재 head 분류를 빈CPU로 즉시 배정 |
| `C_GPU_NOW` | 현재 head 분류를 빈GPU로 즉시 배정; 동시에 탐지CPU가 가능한 경우 아래 병행/지연 후보로 대체 |
| `D_CPU_NOW` | 현재 head 탐지를 빈CPU로 배정; 동시에 분류GPU가 가능하면 즉시병행 후보로 합침 |
| `PAIR_NOW` | C_head GPU와 D_head CPU를 같은시각에 배정; 둘째는 재검사/commit이고 별도 actor 표본이 아님 |
| `C_GPU_DEFER_D_SHORT/FULL` | 분류GPU는 즉시 시작하고, 현재 탐지CPU 추가 배정은 유한 timer까지 보류한 뒤 재판단; 탐지의 미래 배정은 예약하지 않음 |
| `D_CPU_DEFER_C_SHORT/FULL` | 탐지CPU는 즉시 시작하고, 현재 분류GPU 추가 배정은 유한 timer까지 보류한 뒤 재판단; 분류의 미래 배정은 예약하지 않음 |
| `DEFER_ALL_SHORT/FULL` | 실제 즉시배정 대안이 있지만 이번 배정을 짧게 보류; 이미 실행 중 작업은 계속됨 |

두 지연 설정0.125/0.25초는 **우리의 제안 제어값**이며 논문 원값/실측 계수가 아니다. 순수지연은 남은credit·현재 가장 이른기한·120초끝으로 제한한다. 혼합지연은 실제 첫dispatch로 갱신된credit을 사용하고, 보류하는 head의 현재기한/120초끝으로 제한한다. 양 방향을 넣어 하나의 즉시 병행 패턴을 암묵적으로 강제하지 않는다. 같은 timer가 되면 합친다.1ns 이하 지연은 제거한다.

추가지연 credit은 실제dispatch 사이 누적0.25초다. 실제 양의 대기시간만 차감하고 phase/도착/반복callback으로 충전하지 않는다. 새 도착·lane 소유 변경·timer는 재판단을 유발하고, 제한된 지연 중 phase만 바뀌면 관측을 갱신하며 잔여timer를 유지한다. 같은시각 pending dispatch/둘째commit 중에는 재추첨하지 않는다. **지연은 전체폰 냉각을 뜻하지 않는다:** 다른lane 실행과 대기 중 J도 비용에 포함한다.

마스크는 실제 lane/지원/호환성/요청존재와 제어credit/timer 가능성을 검사한다. 미래 실제도착·실현비용·온도 한도를 사용하지 않는다. 예측상 불리한 AP/J를 이유로 물리적으로 가능한 선택을 전부 제거하지 않는다. 안전/서비스의 실제 보장은 없고 최종 KPI로 판정한다. 관측이 같을 때 같은 행동 효과는 재사용하며 zero-time 무한호출·중복배정을 검증한다.

## 4. 관측56·후보28과 한 단계 비용 특징

관측은 글로벌14+두head18+두lane16+최근도착8=56이다. 각 후보28은 실행종류/선택량8·두head긴급성6·점유/잔여여유6·J/AP와유효성6·L0/예측지원2다. 정확한 순서/단위는 기계 계약에 고정한다.

- 글로벌: 현재/남은 공통시간, 클래스별 큐 길이, 실제 점유, 지연credit, 후보 수, 추정AP와 과거grid최고·이미 관측한 긴급응답 개수/P95·긴급/일반실패. 응답count0은 P95불명으로 처리하고 공개응답phase를 놓치면 추정시간으로 채우지 않는다.
- head/lane: 공개도착·현재기한·예상응답/완료·지원·phase·경과시간. 실제 잔여실행시간은 받지 않는다.
- 최근8도착: 마지막도착 age·관측간격 평균/최소/표준편차·과업비율·개수/유효성. true trace family·다음 도착·전체 미래요청 수는 없다. 큐/공개lane에서 새ID를 관측해 업데이트하며 actor를 호출하지 않는 사건에서도 누락하지 않는다.
- 후보 비용은 **현재 실행 중 작업과 이번 즉시 배정/지연의 짧은 구간만** 원계수로 계산한다. 미배정 큐의 완료순서를 짜거나 Band/EDD suffix를 예측하지 않는다. 현재busy잔여가 모델로 계산 불가면 유효성0/표시null이며 실제값이나 다른기기 값으로 대체하지 않는다.

후보구간 J는 작업량/구간이 서로 다를 수 있어 전체 비용 순위가 아니다. 선택요청 수·남은큐·예상지연과 함께 특징으로만 주고 학습/평가는 전체 예정요청·공통120초 J를 사용한다. tensor의0 padding+유효성flag는 미측정 비용0이라는 뜻이 아니며 보고서는null이다. 현재모형의h는 계산에 남기되 독립적인 부하정보처럼 actor에 넣지 않는다. 지원되는 초기화/추정AP가 없으면 L0로 복귀한다.

actor의 추정AP·과거최고는 공개 점유/phase/경과시간과 동결 평균모형으로 별도 갱신한다. 학습 보상에 쓰는 실현 AP곡선·실현 문맥을 그 특징 계산에 전달하지 않는다. 공개 센서처럼 실제 관측 가능한 AP 입력을 추가하려면 입력 계약을 별도로 개정한다.

## 5. 알고리즘과 목적함수

주후보 `LIST_CANDIDATE_CONSTRAINED_PPO_V3`는 **기존 native masked PPO**다. SB3를 중복 구현/설치하지 않는다. 공유MLP는 state56→64→64, 후보28→32→32, 결합96→64→1 score와6critic(16,455파라미터)이다. rule ID별 전용head 대신 후보 특징을 공유한다. actor 마지막층0/유효후보 균등으로 시작하고 평가 동률은L0다. 고정 BASE 가산점/영구0.9 prior/행동수별중복 탐색 질량은 없다. 기존109/68 weights·Adam은 새schema에 로드하지 않는다.

**원 연구의 서비스 유지·열주목적/에너지보조를 반영한 새 학습 목적 버전**이다. 기존v2의 J보상/AP제약 목적과 별도 기록하고 순수 알고리즘 변경 효과로 해석하지 않는다. 표면온도는 미지원이므로 당장은 같은 모형AP만 학습한다.

`A`=35…180초1초grid최고AP, `J`=0…120초기기전체J, `F`=예정−완료, `U/N`=전체도착 기준 긴급/일반실패, `P`=긴급P95다. 동일 학습trace의 독립 L0 종료 결과를0으로 표기한다.

```text
R_AP = (A0 - Aπ) / 1°C
g = [(Jπ-J0)/1J, Fπ-F0, Uπ-U0, Nπ-N0, (Pπ-P0)/1500ms]
actor objective = E[R_AP - sum(lambda_i * g_i)]
lambda_next = clip(lambda + 0.01 * mean(valid signed g), 0, 100)
```

1°C/1J/1500ms는 단위척도이며 온도 한도/새SLA가 아니다. 비용의양의부분만으로 λ를올리는 기존구조와 달리 signed차이를사용해 개선시 λ감소도가능하게한다. 초기λ는J1/미완료10/긴급1/일반1/P951을제안한다. Lagrangian PPO이며 **CPO를구현한것이나그논문의보장**은아니다. 평균제약학습은모든조건의제약준수를보장하지않는다.

희소보상은 과거grid최고증분으로 분해한다. 첫grid M0, 마지막의관측최고Mlast에서 `r_i=−(Mnext−Mprev)/1°C`, terminal에 `(A0−M0−(Aπ−Mlast))/1°C`를 더하면 합이정확히R_AP다. 보조모형으로 상상한 개선을 reward에 넣지 않는다. 미완료 등으로 전체AP/J가null이면 해당채널학습을차단하고 실제미완료/실패비용은유지한다. 값을0성능으로보고하지않는다.

원 EDD+ECT PPO에도 AP 증분의 telescope 검사가 이미 있다. 이 보상 분해는 새 기여가 아니다. 새로 비교할 부분은 축소한 실제 후보 공간·공개 도착 이력·AP 주목적과 signed 제약의 결합이며, 기존 알고리즘 대비 순수 효과를 분리한 실험으로 표현하지 않는다.

이산사건/유한episode의γ=1·Monte Carlo return을 유지한다. 경과시간/대기/실행을 실제공통창 적분에 포함하며 사건수로할인하지않는다.0시간dispatch는reward/가상시간을만들지않는다. 물리mask는 rollout시의 복사본으로PPO ratio를계산하고 강제단일선택은 actor/entropy에서제외한다. Adam3e−4·clip0.2·epoch4·batch256·entropy0.01·value0.5·gradclip0.5·targetKL0.03은 기존구현을따르는 출발제안이며 최적hyperparameter라고주장하지않는다.

## 6. 비교·gate·예산 제안

1. **구현전/작은검증:** 후보중복·기한/지원·원자commit·zero-time·credit·데이터유효성·reward합·보존을확인한다. 기존 리스트성공일정의 새bank표현가능성과 관측된과거에서선택을구별할정보가있는지점검한다. 물리선택이대부분동일하거나새bank에서서비스유지공동이득을만들여지 근거가없으면학습을시작하지않는다. 사후oracle진단은온라인정책과분리한다.

## 7. 실제 구현 전에 남은 것
