## 2. 구현한 관계와 미측정 일정의 의미

최종 사용 단위는 **A24 통합 시뮬레이터 하나**다. 기본 처리시간·AP 후보는 `combined`이며, 같은 입력·초기 상태·모형·비용 규칙에서 정책을 바꿔 비교한다. C252/L64/M128은 이 엔진에 넣는 작업 묶음이고, 기존 자료만/M8만/통합의 세 적합 모드는 자료 기여를 확인하는 검증 대조다. 정책마다 유리한 열·에너지 계수를 따로 배정하지 않는다. 새 개선 HTML을 사용 입구로 제공하고 원 HTML은 이력으로 보존한다.

완료된 180개 저장행에서도 처리시간 모형 digest는 `2aae3116…`, AP 모형 SHA는 `8bad218b…`, 역사 비용 profile SHA는 `e886b848…` 각각 한 개로 확인했다. 검증 69개의 fold별 모형은 학습 제외 검증용이며 기본 운영 모형을 여러 개로 나눈 것이 아니다.

처리시간은 dispatch→실행 시작→output→persist→worker release→AVAILABLE의 **한 요청 전체 5단계 벡터**다. C 응답은 output, D 응답은 persist이며, 도착·큐·dispatch·응답과 자원 반환을 분리한다. queue 대기를 service 시간으로 학습하지 않는다.

사건 엔진은 공개 도착·우선순위·납기·현재 큐·현재 소유권으로 배정한다. 지원 CPU/GPU 조합, 최대 2건, 비선점·AVAILABLE 경계를 유지한다. 공개 상태에서 시작한 합류/이탈은 남은 진행에 영향을 주지만 과거 완료시각을 고치지 않는다. 미관측 간섭·controller 비용을 조용히 0으로 확정하지 않고 진단 가정이나 UNKNOWN을 표시한다.

열은 실행 활동과 실제 사전 AP/이력에서 직접 적합한다. 통계적 평형은 주변온도가 아니며, 후보 시간상수는 식별된 물리 상수로 인증하지 않는다. HAL AP는 표면온도나 에너지가 아니다. 새 일정의 **예측된 활동 경로**를 넣어 AP를 계산하므로 관측 일정만 재생하는 기능에 머물지 않는다.

새 도착 패턴에 정확히 같은 과거 recipe가 없다는 이유만으로 모든 예측을 금지하지 않는다. 공통 task/model/route/센서와 실제 support에 기초한 전용을 허용하되 범위·가정·미확인을 남긴다. 임의 사용자 요청은 공개 도착·기한·작업·입력/모델 식별로 별도 등록할 수 있으며, 미측정 입력의 timing 참조에는 `EXPLICIT_UNMEASURED_INPUT_TRANSFER`가 필요하다. 교차 모델 전용을 자동 허용하지 않는다. 임의 요청 UI/입력 예시의 실제 실행 완료를 주장하지 않으며, 실제 새 실행은 남은 공유 START와 새 등록을 필요로 한다.

### Timing pool 전용과 정책 계약

G005 설정은 `family=combined, estimator=empirical, feature_mode=exact_public, strict=true, bank_mode=TASK_BINDING_TRANSFER`다. 정확한 bank 문맥 풀이 있으면 우선 사용하고, 없을 때는 **bank만 제외한 나머지 task/route/protocol/device·모델·입력·호환 문맥이 같은 풀**의 전용을 허용한다. 이것을 동일 workload 전체의 독립 실측 정확도 확인으로 표현하지 않는다. bank 전용 모드, 선택 pool/support 참조와 외삽·미확인 조건을 함께 읽어야 한다.

미측정 비교는 FIFO_SERIAL_CG, FIFO_PAIR_CG, FIFO_WAIT_CG, ATC, MOBILE_DEADLINE_ENERGY의 5종이다. 모바일은 공개 납기·처리시간과 기존 A24 조건부 경로 비용을 쓰는 명시적 규칙이다.

관측 ORDER는 공개 소스 선언에 맞춘 **EDD·전역 직렬·C_GPU/D_CPU 고정 경로·SERIAL** adapter를 쓴다. 원 V3는 공개 EDD를 미확인으로 차단했으므로 과거 잘못된 FIFO 성과를 교체했다고 표현하지 않는다. PAIR_G에 근거 없는 원자적 동시 시작·SAME_GROUP 제약을 추가하지 않는다. READY_QUEUE rolling/global FIFO/current-lane 예측과 전체 scheduler 본문 미확인을 남긴다. WAIT dose/ready 상태/저장 경계 검사가 가능한 범위와 설치된 전체 scheduler 재현을 구분한다.

해당 전체 코호트를 학습에서 제외한 timing 설정과 selected combined CV의 해당 AP fold 모형을 사용한다. 전 자료 최종 적합 AP 모형을 검증에 쓰지 않는다. 공개 도착·기한·초기 정보에서 timing→큐/배정/활동→AP를 먼저 만들고 관측과 비교한다.

**숫자 오차가 있는 범위를 먼저 밝힌다.**

| 저장 지표 | 숫자 집계 범위 | 세션 MAE의 동일가중 평균 |
|---|---|---:|
| 도착→응답 지연 오차 | **45/69세션**, 유효 요청 **6,920개** | **0.100241149초** |
| 예측된 활동을 넣은 AP 오차 | **45/69세션**. 이45개 내 대상 **3,436행** 중 적격 **3,392행**, UNKNOWN **44행** | **0.354416419℃** |

이 절의 AP 0.354416℃와 앞 절 통합 AP 0.435772℃는 대상 45개/110개 및 세션/코호트 가중이 다르다. 두 값을 나눠 전체 일정 예측으로 정확도가 개선됐다는 비율을 만들지 않는다.

응답은 scheduled arrival→C output/D persist이므로 앞 절의 dispatch 기준 service MAE와 다르다. 큐·AVAILABLE·정시 수·미완료·P95 오차는 각 적격 분모·실제 관측 종료시각·연속 추적 여부를 함께 보고한다. 응답 결측을 실제 미완료로 확정하지 않고 식별되지 않은 수 오차·하한은 null로 남긴다. 예측/관측 요약은 가능한 경우 실제 관측 종료에 맞춘 저장 값을 사용하며, 원 분석의 180초 기본값과 실제 창을 혼동하지 않는다.

같은 자료의 사후 전체 코호트 제외 검증이며 fresh 실기기 확인이 아니다. CV 선정 낙관성과 bank 전용·활동 domain·초기 이력·부분 창 조건을 유지한다. 이45개로 전체180개 미측정 조건이나 실제 정책 효과를 인증하지 않는다.

## 6. 미측정 조건을 포함한 180개 예측·공통 seed·모든 효과와 손해

사전 계획은 **5정책 × 3입력 묶음 × 3도착 패턴 × 2납기 조건 × 2seed = 180개**다. 도착은 original/dense0.65/burstbucket2s, 납기는 original/relative0.65, seed는 20261016·20261017이다. 관측69와 합친 **249는 계획 분모**이며 성공 저장 행 수의 보장이 아니다.

저장 계보의 `novel_grid`는 이 가상 일정 묶음의 등록 이름이다. 원 도착·원 납기를 유지한 기준 대조도 포함하므로 180개 모두를 새로운 실측 조건이나 독립 실기기 확인으로 세지 않는다. 변형 도착·납기 및 정책의 미측정 조합을 예측하는 기능과 기준 대조의 재사용을 구분한다.

같은 공개 입력·초기 상태·seed의 정책끼리 공통 잠재 표본을 쓴다. 지원 풀이 달라지면 선택 표본은 달라질 수 있다. 두 seed를 독립 실기기 반복이나 신뢰구간 표본으로 해석하지 않는다. 초기 상태/템플릿이 다르면 같은 도착·납기 이름만으로 쌍을 만들지 않고 comparison_group_id를 따른다.

FIFO 세 종류는 C_GPU/D_CPU 고정 경로지만 ATC와 모바일 규칙은 C의 CPU/GPU 선택도 바꿀 수 있다. 입력·seed가 같아도 경로·GPU 점유·완료 작업량이 같다고 가정하지 않는다. 순서·큐·WAIT만의 효과와 경로 선택을 포함한 정책 차이를 실제 배치·점유에서 구분한다.

모든 조건·seed·정책의 완료/미완료, 정시 수와 긴급/일반·작업별 분모, 전체 요청 P95와 완료 요청 P95, AP 평균·peak·정확180초 AP/실제 요약 창, 점유와 모든 손해를 보존한다. 유리한 조건만 고르지 않는다.

- 가상180 START/COMPLETE/FAIL/사전 UNKNOWN: **180/180/0/0**. 모두 **공통 180초 이내** 응답·AVAILABLE 완료, 미완료0이며 드레인 210초에도 남은 작업이 없다.

- 정책 선정/최종 승격: **미실시. 같은 평가 결과로 재선정하지 않음.**

## 7. 인과·에너지·새 RL의 미확인 경계

판단에는 현재까지 공개된 상태만 넣는다. 미래 도착을 알고 배정하거나 실현 완료시간·미래 AP를 정책 입력으로 쓰지 않는다. 그래도 관측 관계를 고정해 가상 개입하는 모형이므로 순서/배정/병행/WAIT 차이가 인과적으로 식별된 실기기 효과라는 뜻은 아니다. 정책 행동, 시간 support/전용, 열 domain/초기 이력의 반응 가정을 구분한다. 작은 정책 차이가 오차보다 작거나 문맥·모형에 따라 순위가 바뀔 수 있다.
