## 조건과 비교 범위

A24는27, S26은전력28/열27의 별도 실측 기반 개발프로필을 유지했다. 양기기 모두64건(분류32/탐지32)을 사용한다. batch8은3.2초마다8건, batch16은3.2초마다16건, all64는64건 동시 도착이다. 위3조건은작업량1·분류긴급1.5초/탐지일반6초다.

mixed_overload는.12초간격·작업량1/3/2/1/2/3/1/1반복·분류/탐지각긴급/일반을섞고,기한1/.75/.5배를 적용했다. 전체긴급32/일반32이며 원기한과선언기한을각각보고한다. 여러요인을동시에바꾼탐색이므로개별인과효과를분리한실험은아니다. 작업량비례처리시간은가정이며 burst도새실기기확인없다.

각기기×4조건×2환경seed×7정책=112환경. 기기안에서는정책별동일요청/초기/물리/환경seed다. 같은요청열을두기기에사용한것이동일상대부하를뜻하지는않는다. 정책이름에따른물리보너스/불이익은없다. 신규학습/계수fit/기기/APK0, 고정PPO만추론했다.

## 해석과 다음 발전 방향

이번에는 비용과 서비스 손해를 함께 보이게 했다. 에너지가낮아도기한실패/미완료가많으면그교환관계를표에유지한다. 유효에너지를비교하려고실패행을삭제하지않는다. 모든seed의metrics와원장/결정은comparison.json및raw에보존했다. 완료량차이가생기면0~120초소비와완료작업량을함께보고하며null비용을0으로치환하지않는다.

정책순서차이가작은조건도그대로남겼다. EDD와ATC가같은결과이면그사실을보존한다. 작은물리비용차이를크게보이도록계수나축을조작하지않았다. 더큰발열/전력차이가필요하면자원속도/전력상충·열이력민감도를별도탐색프로필로등록하고실측프로필과구분해야한다. 이번결과는실측보정모형에서부하선택만으로드러난차이다.

## 검증·재현

원27/28 프로필·고정가중치·ZIP SHA불변,전112환경legal선택/future_input표시/최대2허용병행/owner와AVAILABLE/응답분리/고정PPO상태불변을검사했다. 112raw SHA·metrics·7168요청수대조PASS. 시작전문법검사실패1은등록/환경시작전수정했고실제환경실패로세지않는다. 독립기기확인0,예약재생성/외부전송0이다.

repro는기존28실행코드와새요청4종을동결했다. 예:

```powershell
python -m tools.d1_s26_refine28_cli --profile profiles/A24.json --requests inputs/all64.json --policy ATC --environment-seed 963300101 --out ../runs30/A24_all64_ATC.json.gz
python -m tools.d1_s26_refine28_cli --profile profiles/S26.json --requests inputs/mixed_overload.json --policy PPO --checkpoint PPO_1171_ep128.pt --dependencies PPO_dependencies.json --environment-seed 963300101 --out ../runs30/S26_mixed_PPO.json.gz
```
