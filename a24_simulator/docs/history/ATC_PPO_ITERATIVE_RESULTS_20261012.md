# ATC＋PPO 연결 발전 실험 결과 — 2026-10-12

**Greedy는 독립 비교군으로 유지했고, 제안 정책 안의 Greedy 중재·혼합과 EFT 사용을 제외했다.** 두 차례의 유한 실험에서 실제 PPO 24모델을 학습하고 확인했다. 채택 기준을 만족한 모델은 없었다. 가장 유망한 ATC 점수 보정 모델은 작은 모형 비용 절감과 긴급 P95 손해를 함께 냈으므로 **미채택**이다.

이 문서는 08·09의 최신 결정이다. 과거 05~07 및 원 설계의 EFT 포함 결과·실패를 삭제하거나 소급 바꾸지 않는다. 기존 앱 기본 정책과 `experiment_ready=false`는 유지한다.

## 제안과 비교군의 분리

| 역할 | 이번 정의 |
|---|---|
| 제안 | 현재 대기 요청 ATC 후보 → 물리 마스크 → 학습된 PPO의 요청/CPU·GPU/허용 병행 선택 |
| Greedy | 실측 ABBA 점유 중앙값으로 미리 고정한 모델별 선호 자원 + 자원별 FIFO. 바쁘면 기다림 |
| 자원 RR | 도착 순서로 현재 실행 가능한 요청, 지원·가용 자원을 CPU/GPU 순환. 실제 dispatch에서만 순환 포인터 이동 |
| FIFO 고정/READY | 고정된 지원 경로와 전역 선두/현재 ready 순서를 비교. READY에서도 EFT를 쓰지 않음 |
| EDD·ATC 규칙 | 해당 요청 순위 + 고정 CPU→GPU 합법 경로 순서. 예측 완료 최소화 없음 |

Greedy/RR/FIFO 출력·권장 자원은 제안의 입력·행동 중재·복귀로 사용하지 않는다. ATC의 대표 처리 경로는 **고정 CPU 기준**이며, 성능 자료로 Greedy 선호 경로를 호출하는 방식이 아니다. ATC 내부 teacher도 현재 합법성을 확인하는 고정 경로 순서다. EFT 신규 비교·선택·콜백 재생 0회다. Band/Triton 새 비교도 없다.

## EDD·ATC와 롤링 확인

09의 EDD와 ATC 비학습 규칙은 최종32조건의 실행 일정과 위 지표가 같다. 전체 대기 큐를 읽는 계약과 제한 없는 요청 접근을 유지했지만 실제 큐가 작아 top4 안에 대부분 들어가고, 긴급/일반 납기와 처리시간 순위가 실행 선택을 달리 만들지 못했다. 이 동일성은 ATC의 일반적 무효나 EDD의 보편 우위를 뜻하지 않는다. 현재 자료에서 ATC k/w 추가 튜닝은 하지 않는다. ATC 고유 후보 효과와 PPO의 자원/병행 선택 효과를 분리하며 **EDD 후보＋직접 PPO는 향후 독립 대조로 남긴다.**

## 현재 권고와 후속 설계

ATC＋PPO 결합은 유지하되, 가장 유망한 구현 방향은 **ATC 점수＋PPO 보정**이다. 실제 행동 변화와 소량 모형 비용 절감을 확인했으나 아직 채택할 정책은 아니다. 강한 행동 prior는 변화가 거의 없고, 약한 prior/자원 학습만으로는 GPU 선택 편중·seed 불안정이 생겼다.

후속은 단순히 학습량을 늘리기보다 (1) 긴급 요청의 GPU/병행 변경 위험을 관측으로 학습하는 P95 비용·credit, (2) 더 다양한 새 개발 조건의 조건별 보호, (3) 변경 빈도와 각 변경의 사후 서비스/비용 기여를 먼저 설계한다. 추가 보호를 구현할 경우 물리 mask와 별도 운영 규칙을 구분하고 비교군과 공정하게 공개한다. 지금 확인에서 나빴던4조건만 차단하거나 모델을 다시 고르는 방식은 쓰지 않는다. 이 회차는 완료·중단하며, 이후에는 새 개발/학습/최종 자료와 유한 예산을 사전 고정한 별도 회차가 필요하다.

실측 CPU 분류 donor4/GPU188/탐지CPU192의 비대칭과 같은 동결 A24 모형을 쓰는 한계가 남았다. 비용 변화가 작아 기기 모형 불확실성/운영 판단 비용을 해결하기 전 폰 개선을 예고할 수 없다. S26은 별도 인계·모형/품질/비용 적격성을 따르며 이번A24 결과를 S26 증거로 전용하지 않는다. 이번 결과 판정에 필요한 사용자 추가 결정은 없다.
