# D1Check 후속 비교군: FIFO와 기본 이종 자원 배정 규칙

2026-10-11. 작업 MOBILE-BASELINE-SELECTION-01. 상태: 비교군 방향 변경 확정 / 모바일 규칙 선정 제안. 기준 소스 12d64923be824ce4c88fca074fbe38820f5a7d25.

사용자는 앞으로 Band·Triton을 비교군에서 제외하고 FIFO와 모바일 스케줄링을 사용하기로 했다. 모바일 규칙은 SPT처럼 단순하고 설명 가능한 기본 휴리스틱을 원한다. **추천은 FIFO 요청 순서 + EFT(Earliest Finish Time) 자원 배정이다.** 이 추천은 사용자 선택으로 확정된 정책이나 구현 완료가 아니다.

이번에는 문헌·기존 코드 확인과 문서만 작성했다. 신규 학습 0회, 신규 시뮬레이션 실험 0회, 새 물리 모형 적합 0회, 정책 코드 변경 0건, APK 설치·ADB·기기 실행 0회다. 과거 실험·소비·FAIL·사용자 변경은 보존한다.

## 1. 무엇을 비교하는가

요청을 고르는 순서와 자원을 배정하는 규칙은 서로 다르다. FIFO/SPT/EDF만 지정하면 CPU/GPU 배정이 아직 정의되지 않는다. EFT만 지정하면 여러 대기 요청 중 어떤 요청부터 배정하는지도 추가로 정해야 한다.

| 규칙 | 핵심 판단 | 이번 목적과의 관계 |
| --- | --- | --- |
| FIFO | 먼저 도착한 요청을 먼저 검토 | 단순 순서 기준 |
| SPT | 예상 처리시간이 짧은 요청을 먼저 검토 | 산업공학 순서 기준. CPU/GPU 배정 규칙은 별도 필요 |
| MET(Minimum Execution Time) | 선택한 요청을 단독 처리시간이 가장 짧은 지원 자원에 배정 | 가장 단순한 이종 자원 배정. 현재 자원 대기 때문에 선택이 불리해질 수 있음 |
| EFT | 선택한 요청의 자원 대기를 포함한 예상 완료 시각이 가장 이른 경로 선택 | 자원 점유와 CPU/GPU 속도 차이를 함께 다루는 기본 비교군으로 추천 |
| EDF + EFT | 절대 응답 기한순 요청 검토 후 EFT 배정 | 서비스 중심 보조 대안. 순서와 배정 효과가 함께 바뀌므로 주 비교군 선정 후 별도 의미 부여 |

EFT를 ‘모든 Android 앱이 쓰는 표준 정책’이라고 부르지는 않는다. 임베디드 이종 SoC 런타임인 [CEDR 원 논문](https://doi.org/10.1145/3529257)은 RR/MET/EFT/ETF/HEFT 계열을 별도 기본 스케줄러로 제공한다. 모바일 추론의 [Partition-Aware Scheduling 연구](https://arxiv.org/html/2609.14213v1)는 HEFT의 가장 이른 종료 자원 배정을 설명하지만 operator DAG·분할 실행 수준이다. D1Check는 그 기본 배정 원리를 요청 단위로 적용하는 제안이며 원 시스템 재현이 아니다.

Android의 [EAS 공식 문서](https://android.googlesource.com/kernel/common/+/refs/heads/android-mainline/Documentation/scheduler/sched-energy.rst)는 CPU 에너지 모델을 통한 CPU 선택을 다룬다. 이번 앱의 요청 선택·CPU/GPU 배정과 계층이 달라 직접 대조군으로 선택하지 않는다.

## 2. 추천 비교 구성

| 실행군 제안 | 요청 순서 | 자원 배정 | 해석 |
| --- | --- | --- | --- |
| FIFO-FIXED | 작업별 FIFO 선두 중 도착순 | 결과를 보기 전에 고정한 task별 경로 | 단순 정적 기준 |
| FIFO-EFT | 같은 FIFO 순서 | 선택한 요청의 예상 자원 종료가 가장 빠른 지원 경로 | 위 기준과의 차이는 주로 동적 배정과 그에 따른 자원 대기 |
| DIRECT-PPO | 현재 ATC/EDD 후보와 보충 규칙 | 물리적으로 허용된 요청·자원·병행·자원 대기 선택 | 기본 규칙 이상의 서비스·비용 이득 유무 |

FIFO-FIXED의 정확한 task/backend 표는 아직 미확정이다. 현재 검증된 CPU 직렬 배정과 분류 GPU/탐지 CPU 고정 배정을 확인하고, 개발 자료에서 사전 규칙으로 한 설정을 고정해야 한다. 최종 확인 결과가 좋은 설정을 사후에 고르지 않는다. FIFO를 임의로 CPU 전용·직렬에 묶고 상대 정책에만 GPU·병행을 주지 않는다. 동일한 물리 지원과 AVAILABLE 계약을 제공하되 각 정책이 그 지원을 이용하는 방법이 다를 수 있다.

ATC/EDD 후보 bank가 실제로 계속 같으면 DIRECT-PPO는 EDD 후보로 표기하고 중복 학습하지 않는다. 향후 EDF+EFT나 SPT+EFT를 보조군으로 넣으면 같은 배정 규칙 아래의 순서 효과를 분리할 수 있다. 이번에는 비교군을 추가 실행하지 않는다.

## 3. D1Check용 EFT의 최소 의미

선택한 FIFO 선두 요청 i의 지원 자원 r별로 다음을 계산하는 방안을 제안한다.

\[
\widehat F^{\mathrm{occ}}_{i,r}(t)
=\widehat S_{i,r}(t)+\widehat p^{\mathrm{occ}}_{i,r}(t),\qquad
r^*=\arg\min_r\widehat F^{\mathrm{occ}}_{i,r}(t).
\]

- 예상 시작 시각 S는 현재 실행 중인 요청의 공개 단계·잔여 점유 추정과 허용 병행 조합으로 계산한다. 단순히 서로 다른 CPU/GPU이므로 동시 실행 가능하다고 처리하지 않는다.
- p_occ는 dispatch부터 실제 AVAILABLE까지의 측정 기반 5단계 점유시간 추정이다. 모델 inference 시간만으로 대체하지 않는다. 응답 시각은 분류 OUTPUT_READY, 탐지 PERSISTED 경계로 별도 기록·평가한다.
- 미래 도착·미래 실제 처리시간·미래 J/AP를 사용하지 않는다. 미시작 큐 전체를 가상 실행하거나 자원별 미시작 요청을 예약해 drain 예측을 만들지 않는다. 현재 실행 중 작업과 이번 한 요청까지만 추정한다.
- 최선 경로가 바쁘면 기존 계약의 자원 대기를 사용하고, 새 도착·실제 AVAILABLE·자원 타이머마다 다시 판단한다. 예측 시각 도달만으로 lane을 해제하지 않는다. 공개 추정이 초과되었거나 결측이면 실제 사건까지 기다리며 잔여를 0으로 채우지 않는다.
- 시작한 요청은 비선점·이동 불가다. 분류 CPU/GPU, 탐지 CPU와 검증된 CG_DC만 사용하고 NPU·탐지 GPU·새 병행·임의 냉각 대기는 추가하지 않는다.
- 같은 작업의 뒤 요청을 앞지르지 않는다. 작업별 선두 사이의 동점은 arrival/ordinal/id, backend 동점은 사전 고정 CPU 우선으로 처리하는 안이다. 두 FIFO 비교군에 선두 차단·건너뛰기 규칙을 동일하게 정의한다.

예시로 CPU가 비어 있고 GPU는 0.5초 뒤 사용 가능하며, 선택한 분류 요청의 점유 추정이 CPU 0.4초/GPU 0.2초라면 EFT는 지금 CPU를 고른다. GPU의 단독 속도만 보지 않고 0.4초와 0.7초의 예상 종료를 비교한다. 이 숫자는 규칙 설명용 가정이며 A24/S26 측정값이 아니다.

## 4. 기존 코드 재사용과 변경 경계

- `tools/d1_ie_dispatch.py`의 FIFO 순서와 ECT 배정은 가까운 기존 경로다. ECT가 요청 단위 자원 종료를 최소화한다는 점에서 EFT 적용의 출발점이 될 수 있으나 직접 그대로 새 계약이라고 선언하지 않는다.
- `tools/d1_empirical_request_policy.py`의 지원 검사·공개 단계와 현재 실행 중 작업 추정·한 요청 배정은 검토 후 재사용 가능하다. 같은 파일의 `rollout/score`는 전체 큐 미래 실행·J/AP를 계산하므로 새 비교군 판단 경로에 연결하지 않는다.
- `tools/d1_atc_direct_policy.py`의 task FIFO 선두·물리 지원/소유 검사·실제 사건 재판단은 공유 대상이다. 기존 90/7/23 차원이나 PPO 가중치는 규칙 선정만으로 변경하거나 타 정책에 전용하지 않는다.
- FIFO-EFT는 HEFT의 DAG 우선순위·전체 DAG 배정, CEDR의 자원별 미래 큐 예약, Band/Triton 구현 전체를 이식하는 방안이 아니다. 정확한 명칭은 ‘FIFO + 요청 단위 EFT 적용’으로 한다.

## 5. 평가와 과거 결과의 처리

후속 비교는 동일 도착·실현 처리시간·물리 지원·초기 상태·관측창에서 시행한다. 전체 도착 기준 완료/미완료, 긴급 응답 P95와 기한 실패, 일반 기한 내 완료율·실패, J·AP, 판단시간을 조건별로 보고한다. 빠른 평균이나 완료 요청 P95만으로 실패 증가를 가리지 않는다.

사용자의 비교군 변경은 과거 Band/Triton 포함 strict FAIL을 지우거나 새 기준의 PASS로 바꾸라는 뜻이 아니다. 미래 실험의 참조 집합 변경은 별도 평가 계약 버전으로 사전 기록하고, 기존 서비스 수치·epsilon·물리 계약을 자동 완화하지 않는다. 기존 기본 정책을 이번 선정 상담으로 교체하지 않는다. 과거 결과는 이력으로 남기며 새로운 주 비교의 순위 증거로 합치지 않는다.

아직 필요한 결정은 모바일 규칙 EFT 채택 여부다. 채택 후 FIFO의 고정 배정·동점/선두 차단 규칙과 후속 유한 실험 계약을 구체화한다. 이 문서 작성으로 새 구현·학습·실험 예산이 생기지 않는다.
