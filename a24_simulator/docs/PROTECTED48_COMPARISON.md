## 무엇을 보완했는가

- **구조:** 사건 기반 롤링→ATC 후보→RL 요청/CPU/GPU/WAIT 선택을 유지한다. `ATC_RESIDUAL_RL`로 ATC/비용 prior를 명시적으로 더하고 신경망이 잔차를 학습한다. 원 JOINT family는 prior logits를 사용하지 않았으므로 이 차이를 기록한다.
- **납기 보호:** 현재 공개 명목 처리/점유와 owner 경과시간으로 위험을 계산한다. 여유가 적은 긴급·일반 요청을 우선하고, 현재 가능한 긴급 납기를 불가능하게 만들 행동·불필요한 WAIT·느린 경로를 제한한다. 예측 기반 보호이며 실제 납기 보장 정리는 아니다. 분류/탐지 모두 CPU/GPU는 계속 허용하고, 임박한 납기 상황에서만 위험 행동을 제한한다.
- **보상:** 공통 창의 작업 증분과 AP 상승을 실행 구간별로 배분한다. 긴급/일반 미달·지각·미완료를 별도 비용으로 두고, 큐 지연 potential을 합계 보존 차분으로 추가했다. 최고/끝 온도 손해도 보존한다. 미래 성과는 학습 label에만 사용한다.
- **학습:** 모두48요청인64에피소드, 분류25/75%×일정/몰림×참조부하0.50/0.85/1.20의12조건이다. 기존 EP032 신경망 가중치만 초기화에 사용했고 새 Adam/행동·셔플 RNG/seed20261033으로 시작했다. 새 학습 환경 seed20262101..164를 사용한다.
- **선정/평가:** DEV8조건에서 EP24/48/64를 비교했다. 세 CP의 DEV 행동·성적이 같아 사전 동률 규칙으로 EP24를 선택했다. 그 뒤 미사용 모형 seed20264001/2의24조건을 평가했다. 기존 RL alpha0.95와 보완 RL alpha1.0을 구분하며 같은 요청/잠재 조건은 유지했다. 평가 후 재선정·추가 튜닝0이다.
- **EDF:** 절대 납기→예정 도착→ordinal→요청ID, 빈 CPU/GPU 배정, 둘 다 비면 CPU 우선이다. 최단 예상 응답·에너지·온도를 선택 기준으로 쓰지 않는다.

## RL 자체의 추가 기여와 작은 차이의 이유

첫 seed12조건에 같은 보호·ATC/비용 prior를 적용하되 NN 선택을 끈 대조군을 두었다. 양쪽576/576 정시 완료, 보완 RL은 대조군보다 평균 **0.002754J* 감소**했으나 평균AP **0.000601℃ 증가**했다. 소비/열 각각 개선3·동률6·악화3조건으로, **학습된 RL이 열·에너지 모두를 더 줄였다는 우위는 입증되지 않았다.** 보호/prior를 포함한 전체 개편 효과를 전부 RL 학습 효과라고 부르지 않는다.

새24조건의 탐지 GPU 배정은 기존 RL246→보완157건으로 줄었고 EDF도157건이다. 탐지 CPU는330→419건으로 EDF와 같아졌다. 분류 CPU/GPU는 EDF386/190 대 보완394/182로 일부만 다르다. 신경망이 바뀌었지만 세 DEV CP는 같은 행동을 했고, 평가에서도 EDF와 자원 배정이 가까워졌다. EDF가 이미 전량 정시 완료하는 이 조건에서는 추가 절감 여지가 작다.

공통 기저는 총소비의 약78.2%다. 기저를 제외해 보더라도 작업 증분 개선은0.20%로 작다. 따라서 작은 차이를 기저 하나만으로 설명하지 않는다. 보완판의 근접위험 `critical_request` 발동은0회, 다른 가능한 긴급 납기를 보호하는 등 제거한 후보는32건이었다. 임박 긴급 강제선택의 효과가 이 평가에서 독립적으로 확인됐다고 하지 않는다. WAIT는 모든 비교 정책에서0초였다.
