## 해석

같은48개 혼합 요청을 반복했고 분류/탐지50:50·긴급25%·도착률·상대 납기를 유지했습니다. 작업 구간은 첫 도착35초~마지막 도착+15초로 정책 간 같고, 기저1.2043999317W*를 그대로 포함했습니다. 길이를 늘리면 고정 꼬리 구간의 비중은 줄지만, 같은 도착률에서는 기저 비중이 약 일정 수준에 수렴합니다. 기저 비중 감소는 총소비 자체 감소나 RL 고유 우위가 아닙니다.

열·총소비·증분·납기 중 하나가 좋아졌다는 이유로 공동목표를 PASS 처리하지 않습니다. 완료 응답 P95·긴급·미응답·미완료·지각 하한·peak/종료+180초 AP는 HTML 두 번째 표와 전체JSON/CSV에 함께 있습니다.

## 모형과 정책 경계

원 timing/병행/열 계수·비용 모형·기저·EP024 NN과 보상은 변경하지 않았습니다. 두 작업 모두CPU/GPU, 최대2자원·비선점·AVAILABLE까지 점유입니다. EDF는 최단 예상 응답 경로 없는 납기 우선+빈 자원 CPU우선입니다. RL은 rolling+ATC 후보+공개 상태 긴급 보호+고정 NN의 요청/자원/WAIT입니다. 후보24/가중치/WAIT 누적12초 cap을 유지했습니다.

새 서버 제한 해제나 장시간 재학습을 완료한 것은 아닙니다. 별도 CLI 실험은 큐 검증 상한·시간창·판단 횟수를 늘리고, 중복 과거 로그를 줄이고 같은 AP지수식을 인과 누산했습니다. 원 서버256개/180초는 보존 버전입니다.

210초 밖 관측 범위, 기존180초 정책 학습 범위를 벗어난 시간 입력과 긴 horizon은 외삽입니다. 온도→처리시간·전력/스로틀링·장시간SOC 변화는 미식별이며 새로 만들지 않았습니다. 미측정 D_GPU 등은 전이 가정/0..2배 증분 민감도(통계CI 아님)가 있습니다. **J*는 미교정 조건부 비용, 실측J/에너지오차/CI null·폰RL미검증·physicalgoal/projectfalse입니다.** 이번 최대값은 사용자 요청으로3,072개에 제한한 검증 최대입니다.6,144/12,288개는 실행0이며 이론상 최대/실기기 운전 보증이 아닙니다.

384개만 원 미저장 EDF실패 identity를 퇴역하고 별도새20261782 표본 두 정책을 사용했습니다. 나머지 길이는 공통20261781 잠재 key로 prefix 표본을 유지했습니다. 결과를 본 뒤 좋은 조건만 택하거나 원 실패를 성공으로 바꾸지 않았습니다. 같은 사이클 진단이며 여러 seed 독립 확인은 아닙니다.
