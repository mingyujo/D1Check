EDF에도 롤링이 들어가 있나?

현재 구현은 네 정책 모두 사건이 생길 때 현재 큐를 다시 판단한다. 요청이 큐에 들어오거나 처리 단계·자원 AVAILABLE이 바뀌면 다음 배정을 고른다. 따라서 사건 기반 재선택은 공통 실행 방식이다.

EDF 자체가 미래 구간 전체를 최적화하는 롤링 호라이즌은 아니다. 현재 ready 큐에서 절대 납기가 가장 이른 요청을 선택한다. 이번 ‘롤링+ATC’도 사건마다 ATC 점수를 다시 계산하는 구조이며, 다단계 미래 일정 최적화·미래 도착·실현된 미래 겹침을 쓰지 않는다.

두 작업 모두 CPU/GPU 배정 가능, 자원 최대2개·비선점·AVAILABLE까지 점유한다. EDF/FIFO는 최단 예상 응답 경로를 쓰지 않는다. ATC는 명목 시간으로 자원도 선택하므로 ATC와 나머지의 비교를 순서만의 인과 대조라고 해석하지 않는다.

RR은 분류/탐지 큐를 요청 하나씩 번갈아 선택하고 각 큐 내부는 FIFO다. 빈 큐는 건너뛰며 CPU 우선·AVAILABLE까지 비선점이다. 시간분할 선점 RR이나 동일 사용시간 보장이 아니다.
