# 다중자원 S26 엔진 — MULTI001_G004

현재 실제 실행/감사 상태는 [진행 문서](../../docs/MULTIRESOURCE_PROGRESS_20261017.md)를 확인한다. 이 설명은 구현 계약이며 최종 결과 PASS를 대신하지 않는다.

## 하나의 연결된 모형

기존·M8 원 처리단계 벡터 8,636개, 조건부 처리시간 모형, 신규 R21 초기 열 이력과 기존·신규 적격 AP/전력 자료를 같은 엔진에 연결했다. 228세션을 검토해 AP210·전력209세션이 별도 재보정에 사용됐다. R21 전력 비적격2건을 삭제하지 않고 AP에는 남겼다. 별도 56fit과 독립 분석식·KKT·블록 제외 예측 감사는 `calibration/`에 보존한다. 정책 실행 안에서 새 fit/RL은 없다.

분류 CPU/GPU/NPU와 탐지 CPU가 자원을 선택한다. 탐지 CPU와 분류 CPU는 같은 물리 슬롯을 공유한다. GPU와 NPU에도 슬롯은 각각 하나다. 슬롯은 dispatch부터 실제 AVAILABLE까지 예약하며 비선점이다. 최대1/2/3은 동일 모형의 구조 비교다. CPU 전·후처리 서비스와 CPU INFER는 하나의 FCFS 공유 CPU 서버를 사용한다. 장치의 관측 wall time을 CPU 사용률로 오인하지 않도록 서비스 prefix와 passive residual을 분리한다.

열 상태와 동시 INFER 상태가 처리 진행률에 반영된다. 고정 활동 구간의 AP 해석식을 이용한 midpoint 적분과 완료 사건 근찾기를 쓴다. P0는 dt.005/.0025 결과를 대조한다. 응답(긴급 output_ready·일반 readback_end)과 worker_release·AVAILABLE을 따로 남긴다.

AP는 양의 활동 가열항과 초기 이력항을 쓰고, API 전력은 비음수 가산 모형이다. 원 비용 feature는 관측 wall phase의 연관 대리값이며 하드웨어 전력 분해가 아니다. CPU 대기 전이, 새 분류 pair/triple 및 센서 지연은 가정이다. LOW/CENTRAL/HIGH는 구조 민감도이며 실측 신뢰한계가 아니다. NPU 계수0도 물리적 소비전력0을 뜻하지 않는다.

## 공정 비교의 범위

FIFO·EDF·ATC 모두 같은 자원 후보, 같은 실제 슬롯 마스크, 같은 센서 공개 정보, 같은 롤링 자원 배정기를 쓴다. 따라서 비교는 **공통 롤링 배정 위에서 순서 기준의 기여**를 분리한다. 전체 롤링 제어기 유무 비교나 Android 커널 재현은 아니다. ATC는 기존 k=2 공식이다. 자발 WAIT·새 RL은 이번 단계에서0이다.

128요청·긴급0.8초/일반2초 기한은 모든 군에 동일하다. C_ONLY/MIX, 동시 도착4/8/16/32, 초기 이력3개, 추출 stream4개, 슬롯상한3개, 구조모형3개를 포함한다. 신규 요청은 합성이며 R21 실측 요청을 그대로 재실행한 것으로 부르지 않는다.

P072→DEV576의 공통 배정기 단일선정→동결 이후 freshEVAL2592 순서다. `NO_THERMAL_HARM`이라는 후보명은 명목 예측 제약을 뜻하며 실제 열 무손해 보장은 아니다. EVAL을 보고 정책·배정기·계수·기한·분모를 다시 선택하지 않는다. 납기·완료 손해가 있는 절감을 개선으로 인정하지 않는다.

## 파일 지도

- `source/MULTI001_G004/`: 그대로 보존한 생산·순수시험·독립 저장 궤적 감사 소스. `multi_simulator.cjs`가 엔진, `multi_actions.cjs`가 순서와 배정, `nominal_rollout.cjs`가 공개 입력 예측, `multi_cost.cjs`·`midpoint_work.cjs`가 비용·진행 적분이다.
- `PACKET.json.gz`: 원 시간벡터·조건부 시간모형·AP/전력 모형·초기 이력·계보를 함께 봉인한 입력. 압축 해제 바이트 SHA는 `COPY_RECEIPT.json`에 있다.
- `registration/`: 원 등록·예산·자원/측정/가정 계약·순수시험 및 준비 증거. 경로는 원PC의 역사적 실행 기록이다. 복제해서 원 운영 pipeline을 그대로 재실행하지 않는다.
- `calibration/`: 재보정 소스·56fit·정규화 자료·OOF·독립 검산. 원자료/미사용 사유는 사용 원장으로 추적한다.
- `../../data/ARCHIVES.json`: 기존 측정·정책 역사 아카이브. 기존 릴리스는 그대로 보존한다.
- 최종 표·뷰·새 raw/실패 아카이브 위치는 전수감사 후 같은 폴더에 추가한다. 현재 미생성 결과를 완료로 추정하지 않는다.

## 재현과 수정

저장 결과 열람·원자료 SHA 검산과 새 정책 환경 실행을 구분한다. 원 운영 Python/PowerShell의 절대 경로는 원PC 계보이고, 새 PC에서는 새 경로/공동 예산·잠금·identity를 등록한 별도 세대가 필요하다. `prepare.cjs`는 초기 생성 역사이며 자동 재실행 진입점이 아니다. 실험 identity가 이미 START됐다면 원 raw/prepared/RNG/영수증의 정확 복구만 검토하고 새 이름/seed로 성공을 채우지 않는다.

기존 G001/G002/G003의20 P0완료와3단계 수치 실패를 보존했다. G004는 새 소스·입력 계보로 적분을 개선했으며 수치 허용치를 완화하지 않았다. 원3328 공동예약 중20+3240=3260소비 예정, 잔여68이다. 복제본이 추가 실행 예산을 부여하지 않는다.

실측 예측 오차와 새 병행 가정 때문에 합성 정책 격차를 실제 기기 절감 인증으로 해석하지 않는다. 처리시간·동시 진행·공유CPU·열·에너지는 같은 엔진 안에서 연결됐지만 미측정 경로의 식별까지 완료된 것은 아니다.

### 정규화 자료의 적격성 열

`calibration/MATERIALIZED_SESSIONS.json.gz`는 원 보정 입력의 바이트 복사다. 그 안의 이전 `target_eligible` 설명만으로 전력 적격성을 판단하지 않는다. 최종 사용 여부와 단위 비적격 사유는 같은 폴더 `results/USE_LEDGER.json`과 `SESSION_USE.json`, 실제 fit/OOF 원장에 있다. R21의 단위 비적격2건은 전력 fit에서 제외되고 AP는 보존된다. 원 입력을 소급 수정하지 않았다.

### 범위 확인: 순서와 수치 검증

현재 C_ONLY는 긴급 분류128, MIX는 긴급 분류96·일반 탐지32다. 작업 종류와 우선순위가 교차하지 않으므로 EDF·ATC의 동률/격차를 임의 작업×우선순위 조합에 일반화하지 않는다. 저장된 요청별 자원·배정·응답 변경 수와 대기 경쟁을 함께 읽는다. 새로운 교차 우선순위 실험이 필요하면 응답 경계/표본 전이 근거부터 새 입력·예산에 등록하며 기존 EVAL을 다시 선정에 쓰지 않는다.

P0의 dt.005/.0025 수치 쌍 검사는 CENTRAL·B16·초기이력0에서 세 정책·슬롯1/2/3·두 배정 후보를 검사한다. 뒤의 전수 감사는 전체 조건의 저장 활동과 진행률·공개 입력·비용을 재계산하지만, 모든 EVAL 조건의 시간 간격 수렴 또는 실기기 물리 정확도를 인증하지는 않는다.
