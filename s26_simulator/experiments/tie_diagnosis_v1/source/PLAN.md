# S26 동일 선택의 원인 진단

사용자 요청: FIFO·EDF·롤링 ATC의 선택이 같은 이유를 정책, 시뮬레이터, 요청 부하로 구분한다.

기존 FAIR001_G001과 SIM002_G001은 변경하지 않는다. 새 정책 환경·Simulator·CostState·NN·fit·optimizer는 0이며 예산 추가는 0이다. 소비된 identity를 재실행하지 않는다. 저장된 공개 관측과 명목 모델로 선택 함수만 재생한다. 결과 파일은 이 새 출력 계보에서만 만든다.

사전 진단 항목:

1. 48개 기존 우리 정책 raw와 96개 비교군 raw·입력/소스 SHA 및 감사 결과를 결합한다. 정책 ID가 실제로 다른 선택 함수를 호출하는지 코드와 공개 상태 재생으로 확인한다.
2. 전체 DISPATCH 상태에서 전역 대기열과 실제 실행 가능한 대기열을 구분한다. 단일/복수 후보, task·priority 혼합, AVAILABLE·지원 pair에 의한 후보 제거, FIFO/EDF/ATC 순위와 납기 위험 필터를 계수한다.
3. 요청의 task×priority, 상대기한, 도착 간격/몰림, 동일 task 내부의 처리시간 예측/기한 순위를 확인한다. 전역 FIFO와 dispatchable FIFO의 의미 차이도 보고한다.
4. 고정 명목 J/AP proxy·정규화 목적값, 실제 관측 AP에 따른 시간 예측, NPU/GPU/CPU 허용 후보와 선택을 조사한다. 예측 proxy와 실현 J를 혼동하지 않는다.
5. 모든 저장 선택에서 WAIT 조건 각각과 동시 충족 여부를 계수한다. 기록되지 않은 NONE 호출은 관측하지 못한 것으로 명시한다.
6. 기존 저장된 직렬/병행 GPU 비교의 같은 scenario·stream·단계 표본 대응을 확인한다. 일정 차이를 엔진이 지워버리는지 기존 raw/곡선으로 확인한다. 이 비교를 새 정책 우위로 사용하지 않는다.
7. 기존 명목 모델만 쓰는 합성 공개 상태에서 선택 함수 분기(이전 일반 탐지 대 새 긴급 분류, NPU 점유 마스크, CPU/GPU 후보 강제 가용성, 냉각 WAIT)를 확인한다. 이는 단위/구조 진단이며 새 부하의 완주·J/℃ 예측이 아니다. 합성 상태는 실제 정책 평가에 섞지 않는다.

보고에는 직접 관측, 소스 구조상 설명, 미확인 물리 정확도와 보완 제안을 분리한다. 원인별 기여율이나 실기기 인과효과를 임의 추정하지 않는다. 추가 부하/물리/정책 실험이 필요하면 별도 새 등록에서만 진행한다.
