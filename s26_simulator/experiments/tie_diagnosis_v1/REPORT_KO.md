# S26 세 정책이 같은 선택을 한 원인 · 2026-10-16

**직접 원인은 공통 자원 배정기와 현재 부하×가용 자원 마스크의 조합이다.** 자원 배정은 같은 알고리즘이 같은 NPU를 골랐고, 순서 선택은 실행 가능한 요청끼리 기한·명목 처리시간이 같아서 FIFO·EDF·ATC가 같은 결과를 냈다. 이번 동률을 정책 ID가 무시되었거나 모든 일정 차이가 열·에너지 계산에서 지워진 결과로 해석할 근거는 확인되지 않았다. 실제 기기 모형의 정확도와 정책 개선 여지는 별도로 남아 있다.

새 정책 환경·Simulator·CostState·NN·학습·fit·optimizer·추가 예약은 모두 0이다. 기존 48개 우리 정책과 96개 비교군 raw, 공개 관측과 동결 명목 모델, 과거 직렬/병행 48쌍을 사용했다. 이전 성공/실패·원장·정책/물리 소스·입력은 모두 보존했다.

## 2. 순서 차이가 사라진 정확한 지점

48조건 ×128요청 =6,144회 DISPATCH를 전수 확인했다.

| 단계 | 횟수 |
|---|---:|
| 대기 요청이 여러 개 있음 | 2,209 |
| 대기열에 분류·탐지가 함께 있음 | 1,835 |
| 가용성 적용 전 전역 FIFO·EDF 선두가 다름 | 349 |
| 실행 가능한 요청이 여러 개 있음 | 1,551 |
| 그 1,551회에서 같은 종류·priority·절대기한 | 1,551 |
| 실행 가능한 후보에 분류·탐지가 함께 있음 | 0 |
| 실행 가능한 후보에서 FIFO·EDF 순위가 다름 | 0 |
| 실제 ATC 선택이 실행 가능한 FIFO 선두와 다름 | 0 |
| 후보의 예측 납기 위반/최대 지연이 0보다 큼 | 0 |

현재 지원 마스크는 분류 GPU 또는 NPU와 탐지 CPU의 2건 조합이다. 분류끼리 2건, 분류 CPU+탐지 CPU, 3건 병행은 현재 구현/증거 범위에서 허용하지 않는다. 한 종류가 점유 중이면 다음 실행 가능 후보는 다른 종류로 제한된다. 관측한 상태에서 두 종류가 동시에 경쟁 가능한 선택 시점은 없었다.

FIFO 비교군의 정확한 의미도 중요하다. **현재 시작 가능한 ready 요청 중 FIFO**이며, 막힌 전역 선두를 기다리며 다른 가용 경로를 함께 세우는 strict 전역 FIFO가 아니다. 전역 FIFO 선두가 막혀 다른 요청을 선택한 시점은 571회, 전역 EDF 선두가 막힌 시점은 600회였다. 이 동작은 등록/코드와 일치하며 실제 전체 dispatch 순서를 전역 FIFO라고 부르면 안 된다.

부하는 128건 전부 분류 긴급96/탐지 일반32이며 각각 상대기한0.8/2초다. M128은 8건씩0.537155초 간격, SMOOTH128은1건씩 약0.063443504초 간격으로, 두 부하 모두 첫 요청~마지막 요청 간격은8.057325초다. 동일 종류 안에서 다른 상대기한이나 공개된 모델/크기별 명목 처리시간이 없다. 여러 후보가 남은 시점에서는 같은 batch·같은 절대기한까지 겹쳤다. 따라서 현재 관측에서는 EDF와 ATC의 순위 정보가 도착/ordinal 순위에 새로운 차이를 만들지 않았다.

실제 응답 후 남은 납기 여유는 전체 요청 최소0.335511초, 평균0.900106초였다. 이는 현재48조건의 관측값이며 모든 다른 부하의 여유나 보편적 납기 보장을 뜻하지 않는다. 이번 문제를 단순히 '모든 부하가 가볍다'로 일반화하지 않는다.

## 3. 왜 모든 분류 요청이 NPU인가

NPU가 에너지 proxy까지 가장 낮아서가 아니다. 예를 들어 첫 명목 모델의 값은 다음과 같다.

| 분류 route | 단일 요청 에너지 proxy J | 열 면적 proxy ℃·s | 정규화 J+열 점수 |
|---|---:|---:|---:|
| CPU | 0.253418 | 1.441369 | 0.887110 |
| GPU | 0.143113 | 1.088930 | 0.599969 |
| NPU | 0.154333 | 0.961053 | 0.570229 |

GPU의 J proxy는 NPU보다 낮고 NPU의 열 proxy는 GPU보다 낮다. 현 정규화 합산 목적에서는 NPU 점수가 더 낮다. 이 관계는 분류 배정4,608회 전부 유지됐고 예측 납기 위험도 둘 다0이었다. NPU가 시간 예측상 최속이 아니었던 경우도2,514회였으므로, '최속 자원을 그냥 고른 결과'도 아니다.

이 값은 정책 계획용 고정 단일 요청 섭동 예측이며 실제 요청당 계측J나 세션 전체 절감량이 아니다. 기준 명목 처리시간은30℃에서 CPU 약64.454ms/GPU63.997ms/NPU65.707ms 점유로 비슷하다. 추론 외 단계와 실제 표본·현재 온도·병행은 실제 실행 시간에 별도로 반영된다.

현재 정책은 매 사건에서 도착한 요청을 다시 점검하고 한 건을 선택하는 롤링 규칙이다. 현재 요청들의 한 단계 납기 점검→ATC 요청 선택→동일 위험순위의 자원 열·에너지 비교 순서다. RL이나 다단계 조합 탐색을 이 실험의 성과로 포함하지 않는다.

## 4. 왜 WAIT도 같은가

6,144회 저장된 선택 시점에서:

- 소유 중인 작업이 없는 시점634회.
- 초기 AP+0.5℃ 초과5,888회.
- 명목 여유>0.1초6,144회.
- 최근 센서 기울기 <−0.01℃/s 조건은0회. 실제 기울기 범위는 +0.004092~+0.956335℃/s.

따라서 이번에는 냉각 조건이 모든 WAIT를 차단했다. 이 규칙은 이미 식고 있을 때 추가 대기를 허용하므로 온도가 오를 때 먼저 쉬어서 미래 발열을 줄이는 결정을 평가하지 못했다. 다만 저장 trace에는 성공 DISPATCH/WAIT만 있고 NONE 호출 전체는 없으므로 위 횟수는 기록된 선택 시점을 분모로 한다.

## 5. 정책 분기와 엔진 감도 검사

원 함수/모델을 바꾸지 않고 합성 공개 상태6개×정책3개=18회 선택 함수 검사를 했다.

- 먼저 도착한 일반 탐지와 나중 긴급 분류를 함께 실행 가능하게 주면 FIFO는 탐지, EDF·ATC는 분류를 선택했다. 0.8/2초 상대기한은 유지했다.
- NPU 점유 마스크를 주면 모두 탐지만 선택했다.
- 가용 분류 후보를 CPU/GPU/NPU 각각으로 제한하면 해당 route를 선택했다.
- 냉각·열·여유 조건을 충족한 상태에서는 모두 WAIT0.05초를 선택했다.

이는 정책이 같은 함수로 잘못 연결되었거나 특정 route에 강제 고정되었다는 가설을 해당 검사 범위에서 배제한다. 새 완주 시뮬레이션이 아니므로 이 합성 상태의 J/℃·납기 성과는 산출하지 않았다.

시뮬레이터 쪽은 기존 GPU 직렬 FIFO와 GPU 병행 FIFO의48쌍을 재확인했다. 매 쌍의 입력·stream·요청별 route/whole-vector 처리시간 표본은 같았지만 일정·활동·곡선·J·평균 AP는48쌍 전부 달랐다. pair−serial 차이는 평균 −84.498474J/−0.591817℃였다. 이것은 저장된 **엔진 감도 대조**이며, 자원/병행 조건이 다른 과거 대조군이므로 우리 정책의 동일 조건 우위로 인용하지 않는다. 납기 손해와 전량 완료는 동봉 표에 그대로 남겼다.

## 6. 시뮬레이터/예측에서 남은 보완 지점

1. **비교의 의미를 좁혀 기록한다.** 현재0차이는 '같은 배정기 아래 순서 정책 차이 없음'이다. 전체 제안 방식의 기여를 보려면 같은 자원 후보·관측·마스크를 유지하면서 자원 결정 알고리즘의 기여를 별도 ablation으로 분리해야 한다. 비교군을 약하게 고정하거나 이 결과를 숨기지 않는다.
2. **선택이 경쟁하는 부하가 필요하다.** 기존 두 부하는 보존하고, 같은 자원을 두고 서로 다른 기한·공개된 처리 요구가 경쟁하는 새 부하를 별도 등록한다. 새 task×priority/모델·크기 계약을 추가할 경우 실측 근거와 전이 가정을 구분해야 한다. 미관측 미래 표본을 정책에 주지 않는다. 기존 평가를 새 정책 선정에 재사용하지 않는다.
3. **계획용 비용/WAIT 개선 후보를 분리한다.** 현재 AP·실제 점유·후속 요청을 고려한 기한제약 짧은 탐색과, 냉각 관측 이전에도 미래 납기·비용을 평가하는 WAIT 후보를 별도 정책 계보에서 검증할 수 있다. 이 진단에서는 새 정책을 선정하거나 물리 계수를 수정하지 않았다.
4. **물리 정확도는 별도 검증한다.** 고정 추론 회귀에서 이번 관측 AP범위5.863℃의 시간 변화 연관은 CPU+2.861%, GPU−1.285%, NPU−0.039%, 탐지CPU+7.902%다. NPU의 열→속도 연결은 매우 약하며 GPU 부호도 단조 열저하 법칙이 아니다. 이는 관측 연관 회귀이며 인과적 DVFS 식별이 아니다. 미채택 단계 전이 보완 및 기존 R21 API-J MAE37.53J/AP MAE0.612℃도 그대로 남아 있다. 계수를 키워 우위를 만들지 않는다.

따라서 지금은 **ATC 연결 누락을 고치는 단계보다, 비교에서 공유한 최적화 기능과 실제 의사결정 경쟁을 분리해 실험을 설계하는 단계**다. 시뮬레이터는 확인한 일정 차이에 반응하지만, 그 반응의 실기기 정확도가 충분한지는 여전히 검증 대상이다.

## 7. 증거·재현 범위

- 모든 등록 입력·원 소스·원장 SHA는 전후 불변이다. CPU/GPU/NPU 지원범위·물리·납기·분모·예산·학습 경험·자동화 상태 변경0.
