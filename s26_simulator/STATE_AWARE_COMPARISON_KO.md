# S26 현재 온도·점유 반영 배정과 순서 경쟁 비교

2026-10-17 발행 · 실험 STATE001_G001 · 새 학습/RL/fit/실기기 측정 0

**배정기 보완과 300건 실행·전수 검산을 마쳤지만, 롤링+ATC의 EDF 대비 추가 절감은 0이다.** 실제 순서 경쟁이 생기자 FIFO와는 달라졌고, 납기는 EDF와 롤링+ATC가 모두 지켰다. 새 배정기는 기존 배정기 대비 에너지를 조금 줄이는 대신 온도를 높였다. 따라서 열·에너지 공동개선으로 채택할 근거는 확보하지 못했다.

## 같은 새 배정기에서의 공정 비교

분류 CPU/GPU/NPU, 탐지 CPU, 지원된 CG_DC/CN_DC 최대 2건 병행, 비선점·실제 AVAILABLE 조건과 긴급 0.8초/일반 2초를 세 정책에 똑같이 제공했다. 두 경쟁 부하 × 실측 초기 이력 3개 × 공통 합성 draw 4개로 정책당 24조건이다. 각 조건은 128요청(U112/N16)이며 전체 3,072요청/정책을 분모에 남겼다.

| 정책 | 전128건 납기 충족 조건 | 요청 납기 준수율 | 평균 API J0~180 | 평균 AP35~180 | 평균 최고 AP | 미완료 |
|---|---:|---:|---:|---:|---:|---:|
| FIFO + 상태 배정 | 10/24 | 98.861% | 184.109736 J | 32.472098℃ | 39.409408℃ | 0 |
| EDF + 상태 배정 | 24/24 | 100.000% | 184.275174 J | 32.472116℃ | 39.408546℃ | 0 |
| 롤링+ATC + 상태 배정 | 24/24 | 100.000% | 184.275174 J | 32.472116℃ | 39.408546℃ | 0 |

- EDF 대비: 추가 J 절감 **0%**, AP 감소 **0℃**. 전체 48조건(기존 대조 부하 포함)의 dispatch·활동·온도/전력 곡선까지 동일했다.
- FIFO 대비: 롤링+ATC가 납기를 모두 지킨 반면 FIFO는 35건 늦었고, 전량 납기 충족은 10/24조건이었다. 롤링+ATC의 평균 에너지는 0.165438J **증가**했다. 열·에너지 절감 우위로 부르지 않는다.
- 두 정책 모두 전128건 납기를 지킨 FIFO 비교는 COMPETE_B의 10쌍뿐이다. 이 부분에서도 ATC는 평균 0.085074J 증가, AP는 약 0.000098℃ 증가였다. 실패한 나머지 조건은 전체 표/CSV에 그대로 남겼다.

## 배정기만 바꾼 효과

같은 롤링+ATC 순서에서 STATIC(기존 명목 비용)과 STATE(현재 공개 상태 전망)를 비교했다. 양쪽 모두 경쟁 부하 24/24조건의 납기·전량완료를 지켰다.

| 배정기 | 평균 J0~180 | 평균 AP35~180 | 평균 최고 AP | 실제 분류 선택 |
|---|---:|---:|---:|---|
| 기존 STATIC | 184.785347 J | 32.377058℃ | 37.583497℃ | NPU |
| 새 STATE | 184.275174 J | 32.472116℃ | 39.408546℃ | GPU |

에너지는 0.510173J(0.2761%) 감소했지만, 평균 AP는 0.095057℃, 최고 AP는 1.825049℃ 증가했다. 새 배정기를 공동개선 완료판으로 승격하지 않고 별도 실험에 보존한다. 원 src/와 기존 동결 모형은 유지한다.

부하별로도 에너지 효과의 방향이 달랐다. COMPETE_A는 기존 ATC 대비 1.323910J 감소했지만, COMPETE_B는 0.303563J 증가했다. 평균 AP는 양쪽 모두 상승했다. 따라서 위 평균 0.2761%를 모든 경쟁 부하에서 일관된 에너지 이득으로 해석하지 않는다. 기존 M128 대조에서도 J가 약 0.269692 증가했고, SMOOTH128 대조에서는 약 2.851280 감소했다. 세부 조건을 합쳐 유리한 결과만 남기지 않았다.

## 실제 달라진 점과 남은 원인

1. **현재 상태를 실제로 사용한다.** 이미 전달된 AP와 공개된 owner/과거 앱 단계로 과거 활동을 복원하고, owner의 명목 잔여 단계에 후보를 추가한 J/열 전망을 계산했다. 추정 반납은 실제 AVAILABLE 마스크를 바꾸지 않는다. 미래 실제 도착·처리 표본·응답·센서는 사용하지 않았다. 동일 상태 정보와 지원 후보를 FIFO·EDF·ATC에 제공했다.
2. **순서 경쟁은 실제로 생겼다.** ATC가 만든 경쟁 부하의 실행 가능 후보 중 긴급/일반 혼합과 FIFO·EDF 선두 불일치가 각각 384회였다. ATC는 FIFO와 384회 달랐지만 EDF와는 0회 달랐다. 이 부하에서 ATC의 실제 선택이 EDF와 같아 추가 이득이 없었다. 전역의 모든 ATC가 EDF와 같다는 주장은 아니다.
3. **현재 가중합은 열 증가를 허용한다.** 주비교 ATC의 분류 4608건 모두 GPU/NPU를 계산했고 GPU를 골랐다. 4608건 모두 GPU의 예측 J는 더 낮고 열면적은 더 높았다. 열이 악화되지 않아야 한다는 별도 제약 없이 정규화 J+열 합이 작아 GPU가 이겼다. 즉 상태 입력 누락은 보완했지만, 공동개선 조건을 강제하는 목적함수는 아니다. 관측 AP 31.411718~39.086546℃ 범위에서도 선택 교차는 없었다.
4. **전망값은 실측 인과 효과가 아니다.** GPU 추가의 owner-only 대비 한계 J가 음수인 선택은 3515건이었다. 이는 회귀·이력 상호작용의 총비용 차분이며 음의 실제 전력이나 공짜 추론을 뜻하지 않는다. 기존 물리 모형의 전이 정확도와 함께 검토해야 한다. 더 큰 격차를 만들려고 계수나 기준정책을 불리하게 바꾸지 않았다.

다음 개선의 근거는 열 악화 금지/에너지 제약을 갖는 다목적·제약 배정과 대기 큐 전체 전망을 별도 개발 입력에서 검토하는 것이다. 이번 관찰 결과에 맞춰 정책을 다시 골라 같은 평가에 재적용하지 않았다.

## 입력·예측의 경계

- 기존 M128/SMOOTH128 대조는 U96/N32, 새 경쟁 부하는 U112/N16이다. 경쟁 부하는 같은 탐지 CPU에 먼저 도착한 일반과 뒤의 긴급이 함께 기다리게 했다. 긴급 탐지는 실측한 일반 탐지의 전체 처리 단계 벡터를 재사용하고 측정된 output_ready를 응답으로 쓰는 **전이 가정**이다. POST/readback/release/AVAILABLE는 그대로 진행한다. 새 실측 표본으로 세지 않는다.
- 모형은 기존·신규 자료를 연결한 공통 plant이며 시간/AP/API 전력 계수는 이번에 바꾸지 않았다. 원 측정 단계 벡터 8,636개에 긴급 탐지 전이 view 1,216개를 별도 표시했다. 원 측정 pool에서는 view를 제외해 중복 가중하지 않는다.
- 현재 J는 배터리 API 단위 가정, 온도는 AP 센서의 모형 예측이다. 기존 R21 재현 오차(API-J MAE 약 37.53J, AP MAE 약 0.612℃)가 남아 있다. 여기서 작은 정책 차이가 실물에서 정확하다고 인증한 것이 아니다.
- 후보 전망의 정책 계산에 드는 실제 모바일 지연/J는 식별되지 않아 plant에 청구하지 않았다. host 세션 벽시계 평균은 STATIC ATC 0.677초, STATE ATC 1.237초이며 I/O/운영 검사까지 포함하므로 휴대폰 정책 지연으로 환산하지 않는다.
- 원 raw의 evidence.resource_selection은 부모에서 상속된 오래된 보조 라벨이다. 원 raw를 덮어쓰지 않았고 실제 routing_contract·후보·dispatch·독립 재생으로 실행 정책을 확인했다.
- 4개 합성 draw 벡터의 조건부 재표집 범위는 실기기 독립 표본 CI나 전체 물리 불확실성을 뜻하지 않는다.
