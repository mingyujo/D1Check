# 사건 기반 롤링·ATC·PPO의 에너지와 온도 공동 절감 검증37

2026-10-14. 작업 ID `ROLLING-ATC-RL-37`. 구현·기기별3seed 학습·고정 최종 확인은 완료했고 결과는 아래 결과 절에 있다. 큰 공동 절감 목표는 미달이다. ACT는 앞서 정의한 ATC(Apparent Tardiness Cost)로 해석한다.

사용자의 목표는 FIFO·GREEDY·RR 대비 의미 있는 에너지와 온도 감소를 논리적으로 설명하고 대회에 사용할 재현 자료를 완성하는 것이다. 이를 검증 가설로 등록한다. 결과에 맞춰 비교군의 행동, 모형 계수, 납기, 입력을 바꾸거나 손해 조건을 숨기지 않는다. 대회 규정의 허용 증거 수준은 별도 확인 대상이며 시뮬레이션 결과를 휴대폰 실측 개선으로 쓰지 않는다.

## 운영 구조와 구현

```mermaid
flowchart LR
 E[도착·AVAILABLE·관측 사건] --> S[현재 상태 갱신]
 S --> A[ATC 상위6 + 실행 가능한 유형별 선두]
 A --> M[물리 실행 가능성 마스크]
 M --> P[고정 PPO 추론]
 P --> D[요청·CPU/GPU/NPU 배정]
 D --> R[동일 시각 재판단으로 허용된 병행 구성]
 R --> E
```

현재 도착한 전체 미시작 요청을 ATC로 검토하고 상위6개와 분류·탐지 유형별 가장 오래 기다린 실행 가능 요청을 중복 제거해 최대8개를 남긴다. 자원이 막힌 높은 순위가 실행 가능한 요청을 모두 밀어내는 경우를 막는 보완이다. FIFO 전체 큐 계약은 새 RL에 강제하지 않는다. FIFO_READY 비교군은 기존 의미대로 유지한다.

ATC 점수는 `log(w/p_occ) − max(d−t−p_response,0)/(k×mean_p_occ)`다. k=2, 긴급/일반 w=2/1은 정책 입력의 중요도이며 실제 지연 비용 추정이 아니다. 대표 경로는 현재 지원 경로 중 추정 응답시간이 가장 짧은 경로, 동점은 점유시간과 CPU/GPU/NPU 순서다. p_occ는 실제 AVAILABLE까지의 명목 점유시간, p_response는 긴급 OUTPUT_READY/일반 PERSISTED까지의 명목 시간이다. 경로별 5단계 실측 분포와 현재 지연된 관측으로 추정하고 미래 전체 큐를 시뮬레이션하지 않는다.

8요청×3backend+자원대기 최대25행동, 행동당32특성, 상태215특성이다. 요청은21특성×8슬롯, 자원27특성, 전역20특성으로 유도했다. 기존 고정 PPO의 193행동/1455차원이나 가중치를 재사용하지 않는다. 기존의 legacy 납기 특성을 제거하고 현재 단일 경로 비용 대리값2개를 추가한다. 시간6초, 전력10W, 에너지1J 등으로 정규화하며 [-10,10] clip, 패딩0과 mask=false를 사용한다. 비용 대리값은 기존 보정 기준과 현재 관측에 따른 국소 추정이며 새 모형의 참 전력이나 미래 온도를 알려주는 oracle이 아니다.

단일 요청을 배정한 뒤 동일 시각에 상태와 마스크를 다시 만들므로 기존 허용 병행을 구성할 수 있다. 이미 시작한 요청은 중단·이동하지 않는다. 응답 후에도 AVAILABLE까지 자원을 점유한다. A24는 C_CPU/C_GPU/D_CPU, S26은 C_CPU/C_GPU/C_NPU/D_CPU 및 C_GPU 또는 C_NPU와 D_CPU의 두 작업 병행만 지원한다. 미지원 탐지GPU, 분류 두 건 병행, 3자원 실행, 요청 삭제, 의도 냉각 WAIT를 추가하지 않는다. 자원 대기는 실행 가능한 행동이 없고 실제 점유자가 있을 때만 허용한다.

새 사건마다 다시 판단하는 사건 기반 온라인 스케줄링이며 미래 계획 구간을 최적화하는 정식 rolling horizon은 아니다. 비교군도 동일한 사건 루프에서 실행하므로 비용 차이를 '롤링 단독 효과'라고 주장하지 않는다. ATC_TOPK 비학습 대조와 함께 후보+학습+배정 결합 효과를 판독한다.

## 모형 근거와 비교군

기존36의 기기별 M0_frozen35와 M1_coupled를 byte SHA 그대로 사본으로 사용한다. 신규 물리 적합·계수 변경0이다. M0는 기존 실측 보정 개발 근사, M1은 이미 본 aggregate power와 수동RC에 적합한 근사이며 자원별 전력 분해·결합 형태가 독립 확인된 물리값은 아니다. 이번에는 M2 감속/추가전력/초기열 주입 가정을 쓰지 않는다. 기기별 계수를 혼합하지 않고 M0와M1 결과를 따로 보고한다.

FIFO_READY는 현재 실행 가능한 가장 오래된 요청을 가장 빠른 응답 경로로 배정한다. GREEDY_READY_V17는 가장 오래된 실행 가능 요청에 명목 점유시간 선호 경로를 우선한다. RR_READY는 요청 순서를 유지하면서 backend 선호를 순환한다. 이는 비선점 자원 순환 규칙이며 Android CPU time quantum RR을 재현한다는 뜻은 아니다. FIFO/GREEDY가 실제로 같은 행동을 만들면 중복 여부를 그대로 표시한다. 비교군을 일부러 느리게 만들거나 잘못된 자원에 배정하지 않는다.

ATC_TOPK, ENERGY_EDD, THERMAL_EDD도 강한 비학습 진단 대조로 포함한다. 주 결론은 세 사용자 비교군 각각과의 대응 차이를 사용한다. 하나와 비교해 이긴 결과를 세 비교군 전부의 승리로 확대하지 않는다.

## 학습·개발·최종 확인

기기별 fresh 초기NN/빈Adam/독립 행동·shuffle RNG의3seed(3701/3709/3719)를 학습한다. 네트워크와 clipped/episode-weighted PPO 업데이트 코드는 기존 native 구현을 재사용하지만 상태·행동·보상 ABI는 새로 고정한다. 경험8개씩 update하고32/64/128episode checkpoint를 개발용 요청에서 평가해 seed별 checkpoint를 선정한다. 같은8경험의 환경과 입력을 대응시켜 행동 난수로 인한 비용 신호를 얻되 실제 결과를 온라인 입력으로 제공하지 않는다.

보상 비용은 긴급 납기 실패율×10, 일반 실패율×4, 미완료율×50, 행동에 무관한 resident 기준을 뺀 J120/10J, 평균AP35~180의 기준 차이/.1℃, 최고AP38℃ 초과의 약한 대리 비용(.2×초과/.5℃)이다. 모두 학습용 공학적 가중치이며 배터리 수명/고온 안전 한계의 측정값이 아니다. 38℃는 대리 기준이지 기기 안전 온도가 아니다. J와 서비스 비용은 사건별 결과로 분배하고 냉각 포함 AP는 마지막 경험에 귀속한다. gamma=1 누적 보상이 등록 비용으로 정확히 합쳐지는지 검산한다. 사후 결과는 targets에만 사용하며 choose/build에는 들어가지 않는다.

개발 평가의 고정 service+J+AP 점수로 checkpoint를 선정한 뒤 SHA를 동결하고, 새 arrival seed와 새 environment seed의3대응 반복으로 최종 확인한다. 최종 행동은 argmax, FINAL에서 학습/재선정0이다. 저장된 train/confirm 실측 처리시간 pool을 구분하지만 새 난수는 새 휴대폰 측정자료가 아니다. 3반복은 소규모 확인이며 통계적 확증을 과장하지 않는다.

## 입력과 평가

64/128/192/240요청, 분류25/50/75%, batch8/16/24, 상대부하.75~1.15의 사전 고정6조건을 사용한다. 도착 간격은 명목 C_GPU/D_CPU 병목 점유시간으로 산출한다. 개별 작업은 기존 실측 unit1이며 작업량을 임의 배율로 키우지 않는다. 납기는 A24 긴급2.2초/일반5초, S26 긴급.8초/일반2초에 ±10% 입력 변동을 준 공학 시나리오다. 실제 사용자 arrival/SLA로 주장하지 않는다. 납기 실패도 전부 평가에 넣는다.

주 비용은 전체J0~120초와 AP35~180초 평균/최고, J180도 함께 판독한다. 모든 요청이 실제 AVAILABLE까지 완료된 동일 작업량에서만 절감을 주장한다. 미완료는 소비·완료량·실패를 남기고 동일 작업량 절감에는 쓰지 않는다. 긴급·일반·전체 실패율, 자원 배정량, 병행시간, 큐 크기, 합법 행동 수, 후보 생성/추론/전체 PC 판단시간 평균·P95·최대를 보고한다. 판단의 휴대폰 소비·지연은 아직 측정되지 않았다.

5~10% J 감소와 관측 오차보다 큰 AP 감소는 원하는 목표이다. 등록6조건의 모든 손해와 전체 평균, 결과 후 고른 시연 조건을 분리한다. 두 비용 공동 감소·서비스 변화·J180 비용 이동을 같이 표시한다. RL이 실패하면 '감축을 입증했다'고 쓰지 않고 부족한 범위와 개선 후보를 남긴다.

## 해석의 범위

발표 문구는 실제 통과한 기기·모형·합성 부하·비교군 범위를 명시한다. 소프트웨어/새 PPO 학습/재현 검증 완료와 폰에서 절감 확인은 구분한다. 큰 개선 없는 기기, ATC나 비용 규칙이 더 나은 경우, 긴급/일반 납기 손해, seed 불안정을 숨기지 않는다. 에너지 총량만으로 배터리 수명 증가를 계산하지 않는다. M0/M1의 차이를 기기 특성의 확정된 차이라고 말하지 않는다.

이 구현의 롤링은 사건 기반 재판단이다. 비교군도 같은 사건 루프를 쓰므로 RL 결합 효과를 롤링 단독 효과로 주장하지 않는다. RR_READY를 선점형 OS RR이라고 설명하지 않는다. 판단 PC 시간은 폰 추론 소비가 아니다.

정확한 센서 변화폭/정책ΔJ·ΔAP의 기기 검증과 실제 PPO 추론 오버헤드는 별도 측정이 필요하다. 이미 얻은 자료를 확인자료로 다시 적합하지 않았고 원 동결본을 보존했다.
