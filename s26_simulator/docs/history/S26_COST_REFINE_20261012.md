## 기존 사실과 가설

## 유한 후보와 선정

새 ABI `s26-task-activity-cost-v3`는 현재 실제 자원 점유만 사용한다. 기저 후보는 기존 `(CPU,GPU,NPU,h)`와 작업 분리 `(C_CPU,D_CPU,C_GPU,C_NPU,h)`다. h=바쁜 줄이 하나라도 있으면1, 완전 유휴에는 exp감쇠한다. 선점·경로 이동·최대2건·CG_DC/CN_DC·응답과 AVAILABLE 분리 유지다. 대표적 모델 입력에는 미래 요청·실제 미래 처리시간·전체 큐 rollout·미래 센서가 없다.

P=P0+a·phi. P0 후보는 기존 사전30초 평균과 시작 전[-10,0]초 유효 전력 표본 중앙값이다. 중앙값은 준비 순간의 큰 전력에 대한 강건 초기값 가설이며 사전 전력을 임의 보정한 측정 J로 바꾸지 않는다. 실제 J는 원 µA×mV 식과 원2.5초 gap 검사를 유지한다.

전력 후보: 기저2×P0 정의2×tau[.1,.5,2,5,15]×ridge[0,.1,1]=60; 각4fold+전체=300fit. 선정은 세트 균등 CV J 절대상대오차 평균→5초창 RMSE→후보 순번이다. 계수[0,10]W boxridge는 수치 보호 범위이며 원5W 공식 판정을 완화하지 않는다.

열은 선정 기저/tau 고정, 1pole/2pole mix[1,.6], beta[.01,.03,.06,.12,.25], ridge3, 초기화2=60후보/센서다. 기존 `R+(T0-R) exp(-beta*t)`와 사전 마지막10초 센서 선형회귀 기울기 s를 쓰는 `T0+A(1-exp(-beta*t))`, A=clip(s/beta,-5,+5)℃를 비교한다. 사전 추세를 유한 냉각/가열 잔류항으로 쓰는 가정이며 주변온도 측정이나 온도→서비스 감속 모형이 아니다. 부하 열 응답은 기존 fast/slow 필터·느린시정수10배·비음수 gains[0,60]℃다. AP/SKIN 각각300fit. 선정은 세트 균등 CV `MAE+.25*abs(peak error)`→후보 순번이다.

총 예정900fit/cap1000, 1worker·active900초·저장/감사120초. 구현 불변조건 실패 시 중단하고 실패도 원장에 기록한다. 8환경 이내 smoke 외 새 요청 실험·PPO 학습0. 기존 일정 재평가는 새 서비스 환경으로 세지 않는다. PC 시간은 폰 판단 비용이나 에너지가 아니다.
