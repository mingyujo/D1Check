## 바로잡은 전제

## 구현한 보완

`capabilities.py`는 task/backend/priority/자료 계보별 경로 허용과 자원 호환성, timing/energy/thermal 근거를 분리한다. `BoundCapabilityView`는 V2의 실제 routes/feasible와 근거 목록을 교차검사한다. 실제 AVAILABLE 전에는 lane을 반환하지 않고 미검증 pair·중복·3건 실행을 허용하지 않는다. 단독 실행 가능성과 현재 에너지·열 비용 식별을 서로 대신하지 않는다.

`HistoricalTimingView`는 A24 탐지 GPU까지 포함하는 과거 CAL03 4-cell의 실제 32개 공동 5단계 벡터를 연결한다. 개발/확인 각각 cell당 한 세션·4개 상관 요청이며 이미 본 자료다. 별도 직렬 시간 진단만 허용하고, 현재 V2 비용 엔진에 끼워 넣거나 J/AP를 0으로 채우면 거부한다. 과거 확인 자료를 새 독립 확인으로 부르지 않는다.

A24 탐지 GPU는 과거 delegate·작은 이미지 등가성·시간 벡터의 근거가 있다. 과거 CC_DG 고정 episode의 전력/AP 자료도 있으나, 현재 APK·짧은 요청·증분 비용·전환·병행으로의 전이는 검증되지 않았다. 과거 paired J의 방향이 뒤집힌 사례도 남아 있다. S26 탐지 GPU는 delegate 생성/warmup 근거와 실제 요청 호출 0을 구별한다. 탐지 NPU는 미검증이며 하드웨어 불가능으로 판정하지 않는다. 근거 원본의 현재 로컬 부재와 공유 추출본의 SHA 재검증도 구별한다. 상세는 `CAPABILITY_EVIDENCE.json`을 따른다.

현재 비용 미식별 경로를 실제 절감 후보로 승격한 것은 아니다. 현재 계수에 탐지 GPU를 임의로 추가하거나 GPU 전력을 유리하게 정하지 않았다. 경로·pair·비용의 새 검증 자료가 들어오면 별도 등록에서 확장할 수 있는 인터페이스를 마련했다.

## V2에서 실제로 좁은 부분

`headroom.py`는 M1 P1의 고유 624개 원기록을 읽어 원장 구간으로 에너지를 독립 적분했다. 총 48개 기기/조건/반복, 240개 서비스 alpha 셀, 완전 618행·미완료 6행을 보존했다. 전체 J 재구성 최대 잔차 약 0.00000123J, 병행 점유 잔차 0초다. 이 분석은 기존 비학습 정책의 관측 범위이며 새 FINAL·최적해·물리 불확실성 검증이 아니다.

FIFO_READY의 24조건 합계에서 180초 기저비는 A24 88.0332%, S26 48.0008%다. 분류 GPU 비율은 A24 44.0182%, S26 0%(CPU/NPU 사용)로 인용 V5와 다르다. 낮은 부하를 포함하는 해당 묶음의 비율이며 실제 기기 한계나 모든 조건의 비율로 전용하지 않는다.

95% 적격 FIFO의 A24 19조건 중 10조건은 현재 고정 180초 기저와 비음수 나머지 비용이라는 모형 안에서 나머지를 전부 없애도 총 10% 절감에 미달한다. S26의 해당 20조건에는 이 경우가 없다. 이는 개별 조건에 대한 낙관적 상한이지, 서비스까지 만족하는 최적 일정이나 전체 FINAL의 조건별 평균 목표 판정이 아니다. 서로 다른 부하를 합친 pooled 10%에 필요한 비기저 삭감 83.5643%/19.2311%도 참고 분해로만 남긴다.

95% 긴급/일반 서비스·전량완료를 만족하는 관측 규칙의 조건 내 J/AP 범위를 공개했다. 에너지 최소와 AP 최소 정책은 다를 수 있다. request→backend가 완전히 같은 1,240쌍 중 104쌍에서 J 차이가 있지만 46쌍은 context/실현 벡터도 달랐다. 단순 backend 건수나 이 원자료만으로 순서·대기 단독 효과를 주장하지 않는다. 최종 권위는 `HEADROOM_GUARDED_V2/HEADROOM_AUDIT.json`이 연결하는 보고서·전체 행·배정 쌍·조건표다. 최상위의 최초 분석은 이력으로 그대로 보존한다.

## 남은 제약과 후속 검증

기저를 제어하려면 resident/유휴 진입·wake/reload의 시간·에너지·잔열·서비스 손해가 필요하다. 현재 자료로 이를 제어 가능한 기저라고 재명명하거나 일정 비율로 끄지 않는다. 현재 탐지 GPU의 비용을 확인하려면 같은 APK/runtime/resident와 계측 조건의 idle→DG→idle, CC→CC_DG→CC, 실제 5단계·전체 요청 분모가 필요하다. 저주기 센서 한 점으로 짧은 요청별 에너지를 식별했다고 보지 않는다.

구체적 누락 항과 경로 승격 조건은 `MINIMUM_EXTENSION_REQUIREMENTS.json`에 정리했다. 추가 기기 명령·APK·전송·측정 예약을 실행하지 않았다. 새 자료를 확보할 경우 절대 온도 적합만 보지 않고 대응 정책 ΔJ/ΔAP의 부호·크기·불확실성·최악 조건·서비스 손해를 개발 후 동결한 새 확인 자료로 검증해야 한다. 현재 효과가 작다는 이유로 계수·seed·보상·목표를 바꾸지 않는다.

별도 CAUSAL 816환경은 기존 감독의 순차 실행을 유지한다. 순서/배정/WAIT 처방과 S26 잠재 벡터·subphase context 통제로 원인을 구별하며, 원 V2 FINAL 전수 감사와 worker 종료 후에만 시작한다. 원 V2·CAUSAL·본 선택 공간 분석을 모두 판독한 뒤 필요한 새 계보 보완과 한국어 보고를 끝낸다. 이번 구현만으로 에너지·열 개선 완료를 선언하지 않는다.
