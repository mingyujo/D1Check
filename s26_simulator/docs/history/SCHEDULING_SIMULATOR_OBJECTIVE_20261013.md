# A24·S26 시뮬레이터 최우선 목표

2026-10-13 사용자 명시 지시: **스케줄링별 차이가 크게 드러나는 시뮬레이터를 만드는 것이 가장 중요한 목표**다. A24와 S26 모두 적용한다.

- 요청 순서, CPU/GPU/NPU 배정, 허용된 병행이 에너지·온도·납기 실패·지각·완료율에 만드는 차이를 탐색한다. NPU는 S26 지원 경로만 사용한다.
- 납기 실패와 과부하도 정식 평가 범위다. 시연 선택에 '모든 정책 납기 실패0'을 필수 조건으로 적용하지 않는다. 그 기준을 사용한29회차는 과거 기록으로 보존한다.
- 에너지/발열/서비스 각각 차이가 큰 조건을 따로 제시한다. 전체 조건 평균·전조건표와 결과를 보고 고른 시연을 구분한다. PPO가 이기는 것을 성공 조건으로 두지 않는다.
- 정책별 비교는 동일 도착·작업·기한·물리·초기상태·환경난수에서 수행한다. 정책 이름에 직접 비용 보너스/불이익을 주지 않는다.
- 실측 기반 기기별 모형과 탐색 가정(부하·작업량·자원 특성 등)을 버전과 근거로 구분한다. 가정에서 크게 나온 격차를 실제 폰 효과로 보고하지 않는다.
- 비용이 낮아진 이유가 미완료/거절/지연이면 함께 표시한다. 실패를 제거하거나 기한을 결과에 맞춰 완화하지 않는다. 동일 완료 작업량과 전체 도착 기준 결과를 함께 본다.
- 현재 실측 정확도 보정은 이 목표를 뒷받침하는 작업이다. 보정만 완료하고 기기별 부하/스케줄링 민감도 비교를 빠뜨리지 않는다.
- 다른 채팅의 학습·동결본·원자료·실패를 보존하며 이 작업은 별도 출력과 실행 원장을 사용한다. 사용자가 삭제한 매시간 예약은 재생성하지 않는다.
