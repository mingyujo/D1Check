# S26 작은 정책 차이의 원인과 모형 보완

작은 열·에너지 차이는 **비슷한 정책 행동과 구 모형의 식별 한계가 겹친 결과**다. 스케줄링 이벤트가 비용 계산에서 사라진 산술 오류는 발견하지 못했다. 최신 실측으로 열·전력 예측 모듈을 따로 구현해 평균 예측오차를 줄였지만, 모든 세션의 개선이 확인되지는 않아 실험 후보로 제공한다.

## 확인한 원인

1. IE와 한 단계 대조 PREFIX1은 120쌍의 실제 일정·비용이 같았다. 현재 후보는 최대 6개였고 SMOOTH 분류는 GPU 경로만, M128 분류는 GPU/NPU, 탐지는 CPU라는 시간자료 범위다. 더 깊은 탐색이 실제 행동을 바꾸지 못했다. 이 범위를 하드웨어 한계로 확대하지 않는다.
2. M8 38 DEV 세션·6,096요청은 실행시간 추출에만 쓰였다. 열·전력은 이전 77세션의 REFINE26/RISK를 재사용했다. 두 모형의 GPU/NPU 직접 전력이 0이면 해당 열 입력도 0이 되는 구조였다. 실제 GPU/NPU가 전력·열을 쓰지 않는다는 뜻은 아니다.
3. 정책의 명목 Eproxy와 Q는 실제 비용의 CPU 최근활동, owner 합집합과 꼬리, 초기 열 이력 및 열 커널을 그대로 최소화하지 않는다. 확률 탐색 TRAIN과 argmax 평가도 다르다. 768 TRAIN 중 758행에서 납기 예산을 넘었고 dual은 증가했으므로 제약학습이 없었다고 해석하지 않는다.

기존 α=0.95 저장 276행의 원 CostState와 독립 11항 J·초기/7항 AP 분해는 최대 절대오차 9.17×10⁻¹¹로 일치했다. 수치 검산 PASS가 물리 예측 정확성을 인증하지는 않는다. 현재 원인 진단과 재계산은 α=0.95 범위이며 과거 5서비스 결과는 기존 통합보고에 보존한다.

## 구현한 보완

- AP를 전력계수에 묶지 않고 실제 host-call·시작/저장/해제·owner 활동에서 직접 예측한다. CPU60 준비 12,044호출도 실제 구간으로 포함한다.
- 초기 HAL 시각을 common0으로 옮기지 않는다. 명령 완료상한과 실제 과거 표본을 써서 초기 온도·기울기의 미래정보 유입을 막는다.
- 전력은 API µA/mV 가설의 조건부 관측 공간으로 따로 적합한다. AP ℃, 전력 W, 누적 에너지 J 오차를 구분하며 없는 J 오차를 W×180으로 채우지 않는다.
- 과거 센서의 값·나이·기울기·known 상태, 현재 phase·실제 AVAILABLE와 최근 활동을 구분하는 공개관측 모듈을 구현하고 17개 순수 사례를 통과했다. 기존 PPO 입력 ABI에 자동 접합하지 않았다.
- 고정된 새 모형을 기존 276일정에 연결했다. 1,104회 수치 예측이며 정책·요청·응답·완료 시각은 바꾸지 않았다. 새 비용을 보고 기존 정책을 재선정하지 않았다.
