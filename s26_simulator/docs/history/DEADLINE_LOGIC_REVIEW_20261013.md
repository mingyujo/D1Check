# A24·S26 납기 설정 논리 검토 — DEADLINE-LOGIC-REVIEW-32

2026-10-13. 대상은 본 채팅의27~31 모형/실험과 원1.5초/6초 계약이다. 다른 채팅의D1-COST-LEARNING-METHODS-27에서 사용하는 새SLO와 혼합하지 않는다. 정책 코드·납기·가중치·실측 모형을 변경하지 않았고 신규 시뮬레이션·학습·적합·기기 실행0이다. 기존자료 정적 용량 산술만 수행했다.

## 판정

**1.5초/6초는 등록된 동일 연구 조건으로서는 논리적 일관성이 있지만, 실제 앱 요구에서 도출된 SLA는 아니다. 64건 동시 도착·작업량3배 조건은 대부분의 납기 실패가 구조적으로 불가피해 대표 서비스 비교로는 불충분하다.** 이는 납기 숫자 자체의 보편적 오류나 과부하 실험을 삭제해야 한다는 뜻은 아니다.

현재 정의의 장점은 도착부터 응답까지 같은 시간을 평가하고, 정책별로 납기를 바꾸지 않으며, output_ready 응답과 AVAILABLE 점유 종료를 분리하는 것이다. 기존 결과 재현과 정책 변경의 효과 분리에도 고정 조건은 유용하다.

약점은 사용자 허용 지연의 근거 부재, 단일 작업 기준의 여유를 큰 burst까지 적용한 점, 작업량과 기기별 속도에 따라 상대 난도가 바뀌는 점이다. 납기 실패율이90%일 때 낮은 실패율을 만들기 위해 사후 값을 늘리는 것은 독립 검증이 아니다.

## 원래 숫자의 근거

`REQUEST_PPO_QUEUE_RULES_20261006.md` §7은 사용자/제품 SLA를null로 명시한다. §9는2026-10-06 사용자 요청에 따라 분류 도착→output_ready1.5초, 탐지 도착→persist_complete6초를 기존 등록 비교로 유지한다.

당시 개발 CPU 문맥 평균 응답의 최대는 분류156.179931ms, 탐지620.151684ms다. 1.5/6초는 각각약9.604/9.675배다. 이는 **사후 공학적 일관성 점검**이며 원선정 근거나 사용자실험·P95·WCET·납기 보장으로 소급하지 않는다.

같은 절대 납기를 A24/S26에 적용하는 것은 동일 서비스 목표의 기기 비교라면 가능하다. 그러나 각 기기의 처리시간 대비 동일한 난도라는 뜻은 아니다. 기기별 정규화 납기는 처리능력 대비 정책 탐색이며 동일 사용자 경험의 비교와 구분한다.

또한 일반 납기가 긴급보다4배 길어도 당시 탐지 CPU가 분류보다약4배 오래 걸려 상대 처리시간 여유는 거의 같다. 긴급/일반의 의미는 절대 지연·평가 경계·정책 가중치에서 정의돼야 하며,6초라는 숫자만으로 일반에 더 넓은 정규화 여유를 줬다고 할 수 없다.

## 과부하 조건의 정적 필요조건 검사

31의overload64는 시각0에 긴급 분류48건/일반 탐지16건, 각work_units3이다. 동시 최대2지만 허용 병행은 분류GPU/NPU+탐지CPU이므로 **분류끼리는 병행할 수 없고, 탐지도 CPU에서 직렬**이다. 최대2를 모든 요청의 처리용량2배로 계산하면 안 된다.

가장 낙관적인 frozen confirm 샘플의 최소 점유p_occ와 최소 응답p_resp를 독립 선택하고, 시동/감속/다른 작업 간섭을0으로 둔다. 같은 작업n건 모두 시각0에 도착하면 마지막 응답의 필요 하한은 `(n−1)p_occ+p_resp`다. 서로 다른 경로에서 각각 최소값을 취하므로 실행 가능한 일정을 구성한 값이 아니라 넉넉한 필요조건이다.

## 후속 연구의 추천 설계 — 아직 적용하지 않음

1. 원1.5/6초는절대납기대조로보존한다. 기존보고·학습·strict결과를새기한으로소급합격처리하지않는다.
2. 별도연구에는처리시간정규화기한을추가한다. 예: `D_i=alpha_priority × C_ref(device,task,public work_units)`이며절대기한은항상`arrival_i+D_i`다. 참조는정책선택이나최종관측과무관하게동결개발벡터에서정한다. 기존§7처럼공통CPU참조를쓰면느린경로를택해서납기를늘리는현상을막는다. 최단지원경로를참조로쓰는대안도가능하지만같은계약안에서섞지않는다.
3. C_ref는execution구간만work_units만큼늘리고긴급앞2/일반앞3구간으로응답을산정한다. 점유시간은큐용량검사에따로사용한다. 참조평균은WCET나보장이아니다. 과거전체큐의미래실행을돌려납기를만들지않는다.
4. alpha는예를들어긴급2/4/8,일반4/8/16의유한교차grid로먼저등록한다. 수치는민감도제안이며이번에채택한정답이아니다. 사용자가실제요구를주면그절대납기를또한유지한다.
5. 같은부하에서기한만바꾸는축과,같은기한에서도착집중도/작업량만바꾸는축을분리한다. 여유/경계/과부하를전부평가하고불가능/가능witness/미확인을구분한다. 필요조건초과여부는정책결과전산술로분류하며,통과가가능성보장은아니다.
6. 경계조건은미리정한개발설계에서고르고고정확인자료에서는재선정하지않는다. 모든기한/부하cell을남기며'차이가좋게나온납기'만보고하지않는다. 정상비용상충과극한과부하비용상충을각각설명한다.

실제제품납기가없는현재추천은 **기존절대납기대조 + 작업량·기기처리시간정규화민감도 + 부하강도축의교차비교**다. 납기를무조건길게만드는것도,일률실패0을요구하는것도추천하지않는다. 현재31의big-gap탐색과연결하면서서비스포화로정책차이가묻히는구간을구분할수있다.
