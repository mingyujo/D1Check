# S26 상대부하를 A24와 맞춘 비교

기존20은 A24 일정 도착의 명목부하 .7에 비해 S26은30초 최소 도착 구간 때문에 .247~.503이었다. 일부 S26 버스트도8초 하한 때문에 .989에 머물렀다. 이번에는 대응 A24의 .7/1.1을 목표로 S26 도착 구간만 조정한다.

정의는 기존 current_neutral 공개 평균으로 계산한 `max(CPU 탐지 점유 합, 가장 빠른 가속기 분류 점유 합)/활동구간`이다. 이는 명목 부하이며 실제 열·배정·감속을 반영한 자원 활동률을 같게 만든다는 뜻은 아니다. 이전20의 모든 처리시간·전력·열·감속 가정과 CPU/GPU/NPU 지원, PPO 가중치, 물리 환경 난수는 유지한다.

S26 새구간은 `명목 용량/A24 목표 부하`이며, 각 도착은 `35초+(기존 도착−35초)×새구간/기존구간`으로 옮긴다. 요청 ID·종류·작업량·중요도·상대 납기·ordinal은 그대로다. 절대 납기는 바뀐 도착+같은 상대 납기로 정의한다. 동일 난수의 경로/문맥 표본을 공유하지만 열·병행 문맥이 바뀌어 실현 처리시간은 달라질 수 있다.

원96조건 중30개의 S26 조건만 바뀐다. 7정책으로210새환경, seed별84/126환경을2개 독립 PC worker·각1,200초·Torch1로 실행한다. 원672개 결과는 SHA로 재사용하며 재실행하지 않는다. 변경 후672역할 행은 새210+재사용462이고, 전후 합1,344역할 행을1,344새환경으로 세지 않는다. 패키지 고정 추론2회는 별도 신규 환경으로 기록해 총212회 상한을 둔다.

비교군은 FIFO_READY/SPT/EDD/ATC/RR_READY/GREEDY_READY_V17/PPO_TRANSFER다. 기존17의 개발 선정1171@128을 고정 추론하며 새 학습/native/Adam0이다. 전체 조건의 완료량·미완료·원/선언 납기·120초 총J·AP35~180·peak·CPU/GPU/NPU 실행/점유시간과 추가 비용을 비교한다. 전량 미완료는 같은 작업량 J/AP를null로 두고 prefix 소비와 완료량을 보존한다.

전후 각 기기의6규칙 평균 최대−최소 격차와 변화량을 보고한다. 좋아진 조건만 추리지 않으며 변화 없는 A24는 원래 결과 그대로 보여준다. 프로필·가중치를 이 결과에 맞춰 다시 조정하지 않는다. 모형과 부하설정의 영향 분석이며 실제 휴대폰 정확도 확인이나 PPO 학습효과로 취급하지 않는다.

입력생성은 `tools/d1_sched_relative_load_cases.py`, 실행은 `tools/d1_sched_relative_load_study.py`다.20코드는 파일을 수정하지 않고 process 내부 경로·작업ID·예산만 별도로 설정해 재사용한다. 동결된20 소스/가정/ZIP/가중치와 사용자 미커밋 변경을 보존한다. 이번 새 비용적합·기기·APK·외부전송0이다. 근거/원장/결과는 `outputs/D1-SCHED-RELLOAD-21`과 `work/D1-SCHED-RELLOAD-21`에 저장한다.
