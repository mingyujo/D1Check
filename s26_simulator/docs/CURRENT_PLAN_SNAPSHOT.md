# S26 기존·신규 실측 통합 동적 시뮬레이터

2026-10-16 최신 사용자 승인: 기존·신규 실측을 합쳐 처리시간·지원 병행·열에 따른 속도 변화가 연결되는 하나의 S26 시뮬레이터를 구현하고, 같은 엔진 안에서 사건 기반 롤링+ATC+RL·EDF·FIFO의 납기·열·에너지를 비교한다. 직접 식별되지 않는 부분도 근거 있는 추정·예측을 허용한다. 추정이나 가정을 실측·인과적 물리 식별로 표시하지 않는다.

## 목표와 완료 조건

모든 예정 긴급 요청은 예정 도착 후0.8초, 일반 요청은2초까지 원 계약의 응답을 완료하고 전량완료해야 한다. 이 조건을 만족한 정책 사이에서 열·에너지를 줄인다. 납기 위반을 절감량과 교환하거나 요청을 버리는 정책은 개선으로 채택하지 않는다. 채택 가능한 정책이 없으면 그대로 보고한다. API 전력의 절대 J 미교정, AP와 표면온도의 차이, 과거 개발 자료라는 경계를 유지한다.

완료는 자료 포함·제외 원장 → 통합 처리시간/병행/온도 모형과 검증 → 공통 동적 엔진 → 새 RL 학습/DEV-only 선택·SHA동결 → 새 평가에서 EDF/FIFO 비교 → 전수 소비·SHA·상태·산술·NN/체크포인트 감사 → 화면/전체 결과·손해·불확실성·한국어 보고 순서다. 소스 작성이나 실행 종료만으로 완료하지 않는다.

## 한 엔진의 구성

1. 전체207세션/88,688요청을 원 분모로 유지한다. 동일 physical session의 중복 사본을 새로운 표본으로 더하지 않는다. 기존97 legacy·46 M7·61 M8와 gauge3의 계약을 구분한다. 추론 구간의 정확한 모델/입력/route/runtime 및 운영 조건을 연결하고, 준비/저장/readback은 해당 계약의 자료만 사용한다. 구 자료에 없는 readback을0으로 채우지 않는다.
2. 주 예측 대상은 dispatch→AVAILABLE 전체 단계와 host inference의 진행률이다. 실행시간은 source/model/route별 계층적 회귀로 추정하며 사전 AP·관측 병행을 설명변수로 사용한다. AP/병행 효과의 부분 풀링과 앱별 오프셋은 전이 가정으로 표시한다. 실제 추론중 AP가 거의 관측되지 않는 시간 해상도에서 속도를 갱신하는 것은 준정상 속도 가정이며 실측된 DVFS 법칙이 아니다.
3. AP·API전력은 기존·M8 통합 bundle을 그대로 가져와 인과적인 현재 활동량에 따라 갱신한다. AP 변화가 추정 실행속도에 영향을 주고, 변경된 실행·점유가 다시 활동량/열·전력에 반영되도록 연결한다. 선형 비용 모형의 구조와 단위 경계를 숨기지 않는다.
4. 실제 지원 C_CPU/C_GPU/C_NPU/D_CPU, 비선점, 응답/반납 분리, CG_DC/CN_DC 최대2만 허용한다. 관측된 동시 추론/owner overlap의 영향을 회귀에 연결한다. 탐지 GPU/NPU·GPU와NPU 동시 실행·3건 병행·임의 idle 제거는 추가하지 않는다.
5. 추정 효과의 중앙값과 근거 범위, 열 결합을 끈 대조를 함께 비교한다. 데이터로 얻은 범위 또는 명시한 공학적 전이 가정만 사용하고 정책 차이를 키우기 위해 계수를 바꾸지 않는다. 모든 예측에 measured/estimated/assumed/unsupported 출처를 남긴다.

## 정책과 동등 조건

- EDF는 현재 ready 요청의 절대기한, FIFO는 도착/ordinal/ID로 선택한다. 두 정책에 같은 공개 명목값과 공통 자원 배정기를 제공하고, 같은 지원 병행/비선점 제약을 적용한다. EDF를 전역 직렬로 제한한 약한 대조와 우리의 병행 정책을 같은 조건이라고 부르지 않는다. FIFO=FCFS이며 별도 정책으로 중복하지 않는다.
- 주정책은 사건 기반 롤링 후보 구성+ATC 우선도+RL의 요청/지원 route/허용 WAIT 선택이다. 기존 CP는 의미가 달라진 새 엔진의 학습 결과로 재명명하지 않고 새 source/output에서 학습한다. 미래 도착·실현 duration·latent·미래 AP를 정책에 노출하지 않는다.
- 납기 예측 필터와 실제 무위반 검증을 구분한다. 유한 지각 벌점만으로 하드 납기 보장을 주장하지 않는다. 이미 본 기존 평가로 새 정책을 재선정하지 않는다.

## 자료 검증과 추정 경계

회차 전체를 뺀 검증에서 기존·신규, task/route, 직렬/병행, 초기 열 상태의 오차와 미지원/검열을 모두 보고한다. 정책 선택은 별도 합성 DEV에서만 하고, 새 EVAL 입력은 선택 전에 SHA로 봉인한다. 같은 폰의 과거 자료 교차검증을 새 독립 폰 확인으로 부르지 않는다. AP가 관측된 경우의 조건부 timing 오차와 예측 AP를 넣은 폐루프 오차를 별도로 평가한다.
